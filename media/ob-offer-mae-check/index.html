OfferBoxのオファーは、送ったあとに取り消して書き直す、という使い方を前提にしないほうが安全です。宛名の取り違えや、別の学生のプロフィールから引いた一文は、学生にとって「読まずに送った」証拠に見えます。結論から言うと、送る前のチェックは、文面だけでなく「相手」「文面」「名義と企業ページ」「承認されたあとの受け皿」「記録」の5つの段で見ます。毎回すべてを長く見るのではなく、毎回見る項目と、週に一度見る項目を分けて、数分で終わる形にします。 この記事では、5つの段のチェック項目、誰がいつ見るか、チェックを形だけにしない工夫、やりがちな失敗を整理します。文面の言い回しの細かい失敗はオファー文面でやりがちな失敗で、文面の中のセルフチェックとあわせて書きました。この記事は、その外側も含めた送信前の点検です。

この作業の目的｜「送ってから気づく」をなくす

送ったあとに気づく失敗は、次のような形をとります。

  • 宛名や大学名が、別の学生のものだった
  • 承認されたのに、面談の枠が無く、返信が遅れた
  • 文面で触れた仕事が、企業ページの説明と食い違っていた
  • 同じ学生に、別の担当者が重ねて送っていた
  • 送った記録が残っておらず、承認が来たときに誰の文面か分からなかった

文面の質の問題は一部で、多くは運用の段で起きます。チェックリストの目的は、送る前の数分で、こうした失敗の芽を拾うことです。

段1｜相手：この学生に送ってよいか

最初に、文面より先に「この相手でよいか」を見ます。

  • [ ] 募集の「こんな人」と、プロフィールの重なりを一言で言えるか
  • [ ] 卒業年度と、募集の対象の年度が合っているか
  • [ ] 以前に同じ学生へ送っていないか（管理表で確認）
  • [ ] 社内の別の担当者が、同じ学生に送っていないか
  • [ ] 学生の希望（勤務地・業界・職種）と、本文で重ねられない差が無いか

重なりを一言で言えないなら、文面を整えても承認されにくい相手です。送る相手の決め方はOfferBoxのターゲット設計で書きました。

段2｜文面：この学生のための文面になっているか

文面は、言い回しの細部より、取り違えと抜けを先に見ます。

  • [ ] 宛名、大学名、学部が、この学生のものか
  • [ ] 書き出しで触れたプロフィールの一文が、この学生のものか
  • [ ] 型から差し替える箇所が、すべて埋まっているか（空欄や記号が残っていないか）
  • [ ] 承認したあとに何が起きるか（面談の形、誰が出るか）が書いてあるか
  • [ ] 読み終えて、学生がする行動が1つに絞られているか

取り違えは、型を使って複数の学生に続けて書くときに起きやすいので、宛名と書き出しの一文は毎回声に出して読むくらいの気持ちで見ます。個別に変える箇所の考え方はオファー文面の個別化で書きました。

いま使っている媒体の運用の相談だけでも構いません。送る前の点検をどこまで社内で持つか、一緒に整理します。

運用の相談をする

段3｜名義と企業ページ：学生が次に見るものと揃っているか

オファーを読んだ学生は、名義の人と企業ページを確かめます。

  • [ ] 名義の社員が、文面で名乗った仕事をいまもしているか（異動や退職が無いか）
  • [ ] 名義の社員が、面談に出られる状態か
  • [ ] 文面で触れた仕事や制度が、企業ページの説明と食い違っていないか
  • [ ] 企業ページの情報が古くなっていないか（募集の終わった職種、過ぎた日程）

この段は、オファーごとに毎回見るより、週に一度まとめて見るほうが続きます。企業ページの整え方は企業ページの作り方で書きました。

段4｜受け皿：承認されたら、すぐ返せるか

送る前に、承認されたあとのことを確かめます。ここを飛ばすと、良い文面ほど承認が溜まります。

  • [ ] 今週と来週の面談の枠が、返信する人の手元にあるか
  • [ ] 承認を見る担当と、見る時間帯が決まっているか
  • [ ] 返信の型と、面談の案内の型があるか
  • [ ] 担当が不在の日の代理が決まっているか
  • [ ] 今週送る数が、面談の枠で受けられる数を超えていないか

承認からの返信の体制は承認からの連絡を早くする体制、送る数の決め方はオファー送信ペースの決め方で書きました。

エージェントベストの見解

これをやる前に、先に決めておくことがあります。チェックリストのうち、「毎回見る項目」と「週に一度見る項目」の分け方です。当社は3媒体すべての販売パートナーとしてOfferBoxの契約後の運用を見ていますが、チェックリストを作ったのに使われなくなる会社は、項目を全部、毎回見る形にしています。オファーごとに十数項目を見るのは続かず、数週間で誰も開かなくなります。毎回見るのは、宛名と書き出しの一文、差し替え箇所の抜け、送信の記録、の数項目に絞る。名義の社員の状況、企業ページの情報、面談の枠は、週の初めに一度まとめて見る。こう分けると、オファー1件あたりの点検は短く済み、週に一度の点検で運用の段の失敗も拾えます。チェックリストは、項目の多さより、続く形にできるかで効き目が決まります。

段5｜記録：送ったことを残したか

送った直後に、管理表へ残します。

  • [ ] 送った日、学生、名義、使った型を書いたか
  • [ ] 書き出しで触れたプロフィールの一文を書いたか（承認後の返信と面談で使う）
  • [ ] 社内の他の担当者が見られる場所に書いたか

記録があれば、承認が来たときに、どの文面で何に触れたかがすぐ分かります。返信も面談も、その一文から始められます。記録の使い方は週次レビューのやり方で書きました。

誰が、いつ見るか

チェックは、書いた本人が見るのが基本です。そのうえで、次のように分けます。

場面見る人
毎回の点検（宛名・書き出し・差し替え・記録）書いた本人
運用を始めたばかりの時期本人に加えて、人事がもう一度見る
名義を社員に借りている場合名義の社員が、送る前に一度読む形にするか、事前に了承を取る
週に一度の点検（名義・企業ページ・面談枠）人事

二人で見る形は、運用が安定したら外してかまいません。いつまでも二重にすると、送る速さが落ちます。

申込前に、運用に必要な時間の見積もりだけでも聞いてみませんか。送る前の点検に要る時間も含めて考えます。

エージェントベストの見解

外に出す場合の線の引き方です。当社がOfferBoxの運用代行で送信を担うとき、相手の確認、文面の取り違えと抜けの点検、送信の記録までは当社の手順に入っています。ただし、段3と段4の一部は企業に残ります。名義の社員がいまも同じ仕事をしているか、面談に出られる状態かは、社内の人の動きを知っている側でないと分かりません。面談の枠も、出すのは面談する社員です。代行に出した会社で起きやすいのは、文面の点検は丁寧なのに、名義の社員が異動していたことに気づかずに送り続ける形です。代行に出すときは、「名義の社員の異動・不在と、面談の枠は、週の初めに企業から共有する」と最初に決めておきます。点検の手順は外に出せても、社内の事情は外に出せません。

まとめ

  • 送る前の点検は、相手・文面・名義と企業ページ・受け皿・記録の5つの段で見る
  • 文面は言い回しより、宛名と書き出しの取り違え、差し替え箇所の抜けを先に見る
  • 承認されたあとの面談の枠と返信の体制を、送る前に確かめる
  • 毎回見る項目と、週に一度見る項目を分け、続く形にする
  • 代行に出しても、名義の社員の状況と面談の枠は社内から共有する

よくある質問

チェックリストは、紙と管理表のどちらで持つのがよいですか

管理表の中に持つほうが続きます。送った記録を書く同じ場所に、毎回の点検の項目を並べておけば、記録と点検が一度に終わります。週に一度の点検は、週次の見直しの議題に入れておくと忘れにくくなります。

送ったあとに、宛名の間違いに気づきました

送ったオファーの扱い（取り消しや訂正ができるか）は、管理画面と媒体の案内で確認してください。そのうえで、承認された場合は、最初の返信で間違いを率直にお詫びします。言い訳を重ねず、短く伝えるほうが受け止められやすいです。

名義の社員に、毎回文面を確認してもらうべきですか

毎回でなくてもかまいません。名義を借りる前に、型と書き方の方針を本人に見せて了承を取り、運用を始めた最初の数通だけ確認してもらう形が続きやすいです。名義の社員の書き方を揃える考え方はオファー文面テンプレートを作るときの注意で書きました。
