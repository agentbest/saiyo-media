エンジニアの長期インターン生の最初の1か月｜任せる仕事と育て方

エンジニアの長期インターン生を受け入れたあと、最初の1か月で何を任せるかは、多くの会社が手探りで決めています。忙しいチームほど、とりあえず課題を一つ渡して様子を見る、という始め方になりがちです。結論から言うと、最初の1か月は「環境構築と読む」「小さな修正」「小さな機能」の三段で任せる範囲を広げ、毎回のレビューを育成の中心に置くと、学生が早く一人で動けるようになります。 この記事では、Infraで採用したエンジニアの長期インターン生を受け入れる会社に向けて、週ごとの任せ方と育て方を整理します。

最初の1か月で目指す状態を先に決める

受け入れの計画を立てる前に、1か月が終わったときに学生がどうなっていればよいかを一文で決めます。たとえば「チームの開発の流れに沿って、小さな機能の追加を一人で最後まで進められる」といった形です。

この一文があると、週ごとに何を任せるかの判断がぶれません。逆に、目指す状態が決まっていないと、目の前の手が空いた作業を学生に渡すことになり、1か月後に何ができるようになったのかが本人にも会社にも分かりません。

目指す状態を決めるときは、次の三つを確かめます。

  • 一人で進められる範囲：どの大きさの作業なら、途中で聞かずに進められるか
  • チームの流れ：ブランチの切り方、レビューの出し方、マージまでの手順を守れるか
  • 聞き方：詰まったときに、何をどこまで調べてから聞けばよいかが分かっているか

独り立ちまでの段階の考え方は長期インターンのオンボーディングで、初日と最初の週の組み方は長期インターン初日の受け入れで整理しています。この記事では、エンジニア職に特有の部分に絞ります。

週ごとの任せ方

最初の1か月は、次のような段階で組むと無理がありません。週の区切りは設計上の例で、学生の稼働日数に合わせて伸び縮みさせます。

  1. 一週目：環境構築と、既存コードを読む：開発環境を手順書に沿って整え、つまずいた箇所を手順書に書き足してもらう。既存のコードを読み、分からない箇所を質問のリストにまとめる
  2. 二週目：小さな修正：画面の文言の修正、小さな不具合の修正など、影響の範囲が狭い変更を担当する。ここで初めてレビューを通す流れを経験する
  3. 三週目：少し大きな修正：複数のファイルにまたがる修正や、テストの追加。既存の書き方に合わせることを覚える
  4. 四週目：小さな機能の追加：仕様の確認から実装、レビュー、反映までを一人で進める。設計の方針は事前にレビュー担当と話す

一週目の「手順書に書き足してもらう」は、効果の大きい任せ方です。学生にとっては最初の成果になり、会社にとっては次の受け入れの準備になります。新しく来た人がつまずく箇所は、長くいる社員には見えなくなっているからです。

受け入れの最初の1か月で何を任せるか、週ごとの組み方から一緒に考えます。相談だけでも構いません。

権限の渡し方

エンジニアの受け入れで慌てやすいのが、アカウントと権限です。初日にすべてを渡すと事故の心配が増え、渡すのが遅れると学生が手を止めて待つことになります。段階に合わせて渡す範囲を決めておきます。

時期渡す範囲の例
初日チャット、タスク管理、ソースコードの閲覧、開発環境
二週目ブランチの作成とレビューの依頼、検証用の環境
慣れてから本番に近い環境の閲覧。本番への反映は社員が行う、など

本番の環境や利用者の情報に触れる範囲は、社員と同じ基準で考えるより、一段慎重に決めておくほうが学生も安心して働けます。扱う情報の範囲は、雇用契約や誓約書の中で確認しておきます。情報の管理の考え方は長期インターン生の情報管理でもまとめています。

エージェントベストの見解

最初の1か月で受け入れが止まる会社に共通するのは、「最初の課題が大きすぎる」ことです。現場のエンジニアは、学生の力を見たいという気持ちから、まとまった機能を最初に渡しがちです。学生は質問の仕方も分からないまま一人で抱え、二週間ほど進捗が見えない状態が続きます。現場は「思ったより手が遅い」と感じ、学生は「何も教えてもらえない」と感じる。このすれ違いは、学生の力ではなく、課題の大きさで起きています。当社が勧めるのは、最初の課題を「その日のうちにレビューまで出せる大きさ」にすることです。小さな変更でも、レビューを通して反映されるまでの流れを一度経験すると、学生はチームの進め方を体で覚えます。力を見るのは、その流れに乗れてからで十分です。

レビューを育成の中心にする

エンジニアの長期インターンでは、研修の時間を別に取るより、日々のレビューで育てるほうが続きます。レビューを育成に使うために、次の三つを決めておきます。

  • 返す速さの目安：レビューの依頼から、どのくらいで最初のコメントを返すか。学生は待っている間、次の作業に進めない
  • コメントの書き分け：「直してほしい」「できれば直す」「参考まで」を分けて書く。全部が同じ重さに見えると、学生は何から直せばよいか分からない
  • 理由を添える：なぜその書き方がよいかを一言添える。理由が分かると、次から同じ指摘が減る

加えて、週に一度、短い振り返りの時間を取ります。その週のレビューで多かった指摘を一緒に見直し、次の週に意識することを一つ決めます。個別の指摘を、学生が自分で使える考え方に変える時間です。振り返りの進め方は長期インターン生との1on1も参考になります。

つまずきの見つけ方と戻し方

最初の1か月で起きやすいつまずきは、外から見えにくいのが特徴です。次のような様子が出たら、早めに声をかけます。

  • 進捗の報告が「進んでいます」だけになる：どこまで進んだかを具体的に言えないときは、詰まっていることが多い
  • レビューの依頼が来ない：完成させてから出そうとして、一人で抱えている
  • 質問が急に減る：聞きにくくなっている、または聞き方が分からなくなっている

声をかけるときは、責める形にせず、作業を一段小さく分け直します。「今日はこの関数だけ直してレビューに出してみよう」と範囲を絞ると、止まっていた手が動き出すことがあります。つまずいたときに前の段階に戻すことは、失敗ではなく計画の調整です。

勤務の時間や学業との両立に関わる調整が必要になることもあります。インターン生の労働時間や学業への配慮には法令で定められた項目や指針がありますので、詳しくは社会保険労務士や公式の案内で確認してください。

レビューの時間が足りない、受け入れの人数を増やしたい。体制の見直しもご相談いただけます。

運用の相談をする

社内の分担

エンジニアの受け入れは、レビュー担当一人に任せきりにすると続きません。次のように分けておきます。

  • レビュー担当：日々のレビュー、週の振り返り、任せる作業の選定
  • チームの責任者：目指す状態と段階の決定、権限の承認、月の終わりの評価
  • 年の近い社員：開発以外の相談、チームの慣習の説明
  • 人事・総務：契約、勤怠、端末の貸与の手続き

エージェントベストの見解

当社は長期インターンの募集を支援する立場で、受け入れが続く会社と続かない会社の違いを見てきました。違いが出るのは、1か月が終わったときの振り返りを、学生と一緒にやるかどうかです。続く会社は、最初に決めた「目指す状態」に照らして、できるようになったことと、まだのことを学生と一緒に確かめます。そのうえで、次の1か月の目指す状態を学生にも書いてもらいます。続かない会社は、1か月目が終わっても特に区切りを置かず、そのまま日々の作業が続きます。学生は自分が伸びているのか分からなくなり、別の会社の長期インターンに目が向きます。区切りを置くのは、評価のためというより、学生が次の目標を持つためです。1か月目の終わりに一度、短い時間でもこの場を設けてください。

まとめ

  • 最初の1か月で目指す状態を一文で決め、週ごとの任せ方をそこから組む
  • 環境構築と読む、小さな修正、少し大きな修正、小さな機能の順に範囲を広げる
  • 最初の課題は、その日のうちにレビューまで出せる大きさにする
  • レビューは返す速さ、コメントの重さの書き分け、理由の添え方を決めて育成の中心にする
  • 1か月の終わりに学生と一緒に振り返り、次の目指す状態を決める

よくある質問

未経験に近い学生でも、同じ段階で進めてよいですか

段階の順番は同じで構いませんが、一つひとつの期間を長めに取ります。一週目の「読む」に時間をかけ、分からない言葉を調べてまとめる作業を厚くすると、二週目以降の修正に入りやすくなります。

レビュー担当が忙しく、返すのが遅れてしまいます

返す速さの目安を、担当者が守れる形で決め直します。毎回すぐ返せないなら、「午前に出したものは夕方までに見る」のように時間を区切ると、学生も待つ間の段取りが立てられます。担当を二人にして交代で見る形もあります。

1か月で目指す状態に届かなかったら、どうすればよいですか

届かなかった理由が、課題の大きさなのか、稼働の時間なのか、聞き方なのかを学生と一緒に確かめます。理由に合わせて次の1か月の段階を組み直せば十分です。受け入れ後に早く辞めてしまうのを防ぐ考え方は長期インターン生がすぐ辞めるときに見直すことでまとめています。
