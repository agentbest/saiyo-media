「運用代行に出すと、どこまでやってもらえるのか」「出したら自社は何もしなくてよいのか」という質問を受けます。**結論から言うと、代行に出せるのは「作業」で、出せないのは「判断」です。読む、書く、送る、返信する、記録する、率を置き直す、は作業なので出せます。誰を採るか、譲れない条件は何か、会うか、選考に進めるか、内定を出すか、は判断なので出せません。** 作業を出し、判断を持つ。この線で分けると、代行に出しても運用は自社のものであり続けます。この記事では、OfferBoxの運用の各段階を作業と判断に分け、代行に出せるもの、出すと危ないもの、段階的に出す順番、代行との週次、戻すときの引き継ぎを整理します。自社運用と代行の一般的な違いは[媒体を自社で運用するか代行に出すかの違い](/media/hikaku-baitai-vs-daikou/)、代理店の代行の型は[代理店に運用まで頼めるか](/media/kh-dairiten-unyou/)で書きました。この記事はOfferBoxの運用に絞った各段階の線引きです。当社もOfferBoxの運用代行を行っているので、当社の線引きも書きます。

## この作業の目的｜代行に出しても、運用を自社のものにする

代行に出す目的は、送る時間が取れない会社が、送る作業を外に出して、承認と面談を回すことです。ところが、出し方を間違えると2つの失敗が起きます。

1つは「丸投げ」です。人物像も条件も代行に任せると、面談に来た学生が社内の期待とずれ、面接官が「思っていた人と違う」と感じ、代行を切ります。もう1つは「出し切れない」です。作業まで自社で抱えたまま代行に相談だけしていると、送る時間が取れない状態は変わらず、止まります。

作業を出し、判断を持つ。この線引きが、代行に出しても運用が自社のものであり続ける条件です。

## 手順1｜各段階を「作業」と「判断」に分ける

OfferBoxの運用の各段階を、作業と判断に分けます。判断は自社、作業は代行に出せます。

| 段階 | 判断（自社） | 作業（代行に出せる） |
|---|---|---|
| ターゲット設計 | 何人を、どの職種で、何が譲れないか | 決まったものを検索条件に落とす。[ターゲット設計](/media/ob-target-sekkei/) |
| ペルソナ | 採りたい学生像を条件・志向・行動で決める | 型と質問で引き出す。決めるのは企業。[ペルソナの作り方](/media/ob-persona/) |
| 検索 | 譲れない条件を決める | 条件を設定し、件数を送る数と読む時間で調整する |
| 読む | 「自社の仕事で何が求められるか」をペルソナに書く | 自由記述を読み、触れる一文を拾い、記録する。[プロフィールの読み方](/media/ob-profile-yomikata/) |
| 書く | 仕事の中身と名義の口調を現場の言葉で確認する | 冒頭を書く。テンプレートの共通部分を下書きする |
| 送る | 送る時期と山を採用計画から決める | 送る。ペースを面談枠から逆算する |
| 返信 | 面談枠を出す | 承認に当日返信し、候補を出し、日程を確定する。[承認後の連絡](/media/ob-shounin-go/) |
| 面談 | 面談する。選考に進めるかを決める | 面談前の情報を1枚にする。面談後のフォローの連絡 |
| 選考 | 面接する。段階ごとの目的を決める。合否を決める | 結果連絡と次の段階の日程調整 |
| 内定 | 内定を出す。承諾の条件を聞く。話せる場に出る | 連絡の骨格を回す。記録する |
| 記録・レビュー | 止まっている段階の特定と、直すことの決定（代行と一緒に） | 記録をつける。率を置き直す。週次の資料を作る。[KPI設計](/media/ob-kpi-sekkei/) |
| 更新 | 仕事の中身と人の変化を伝える | テンプレートと企業ページの下書きを直す |

表を見ると、代行に出せる作業は多く、自社に残る判断は「決める」「会う」「伝える」に集約されます。

## 手順2｜代行に出すと危ないもの

判断の中でも、出すと運用が崩れるものを挙げます。

- **人物像を決めること**：代行が決めると、面談に来た学生がずれる。代行は聞いて整理する側
- **譲れない条件を決めること**：代行が緩めると条件外の学生に送り、厳しくすると対象が残らない。決めるのは面接官と人事
- **仕事の中身を書くこと**：代行が想像で書くと、面談で「文面と違う」となる。現場の言葉で確認する
- **面談と面接**：代行は出られない。名義の人と面接官が出る
- **面談枠を出すこと**：代行は面接官の予定を押さえられない。枠が出なければ、返信に候補を書けない
- **選考に進めるか、内定を出すかの判断**：代行が関わる余地は無い

「仕事の中身を書くこと」は、作業に見えて判断です。何をどう書くかは、現場にしか分からないからです。代行は下書きし、現場が直す形にします。

### エージェントベストの見解

相談で最も多い思い込みは、「運用代行に出せば、採用の作業から解放される」というものです。実際には、代行に出しても、決める・会う・伝えるの3つは残ります。当社がOfferBoxの運用代行を受けるとき、最初の打ち合わせで「当社がやること」と「企業にやっていただくこと」を表にして渡すのは、この思い込みを最初に解くためです。当社は3媒体すべての販売パートナーとして契約後の運用を見ていますが、代行に出して「効かなかった」となった会社の多くは、面談枠が出ない、面談の結果が戻らない、人物像が決まらない、のどれかで、代行の作業の質ではなく、自社に残る判断が止まっていた会社です。代行に出すなら、残る判断に時間を使う。残る判断とは、決める・会う・伝える。この3つに集中できる分、自社運用より判断の質は上がります。作業を出して、判断に集中する。それが、代行を使う意味です。

## 手順3｜段階的に出す順番

最初から全部の作業を出す必要はありません。止まっている作業から、段階的に出します。

1. **読んで書いて送る**：最も時間がかかる作業。1人で回らない会社は、まずここから。自社は返信と面談を持つ
2. **返信と日程調整**：毎日見られない会社は、次にここ。面談枠を週の初めに代行に渡す
3. **記録と率の置き直し、週次の資料**：数字を整理する時間が無い会社は、ここも出す。見るのは自社
4. **テンプレートと企業ページの下書きの更新**：年に数回の更新を代行が下書きし、現場が直す
5. **面談前の情報整理と、面談後のフォローの連絡**：面談そのものは自社だが、前後の連絡は出せる

逆に、最後まで出さないのは、人物像、譲れない条件、面談、面接、内定の判断です。ここが出た時点で、運用は自社のものでなくなります。

どの作業を出すかは、[人事1人でOfferBoxを回す運用設計](/media/ob-hitori-jinji/)で書いた「止まる作業だけ外に出す」の考え方と同じです。

## 手順4｜代行との週次の持ち方

代行に出しても、週次レビューは自社と代行で一緒に持ちます。持ち方は[週次レビューのやり方](/media/ob-shuukan-review/)で書きました。代行の場合に足すことを並べます。

| 項目 | 代行がやること | 自社がやること |
|---|---|---|
| 記録の事前共有 | 段階ごとの数と日数、目標との差、止まっている段階の候補を資料にして送る | 読んでおく |
| 止まりの確認 | 送ったか、返信したかを報告 | 面談が翌週に入っているかを確認 |
| 原因の切り分け | 文面・条件・見に来た先の観点で案を出す | 面談枠・返信の体制・面接官の観点で判断 |
| 翌週に直すこと | 文面と条件の変更を担う | 面談枠と体制の変更を担う |
| 面談の結果 | 記録する | 戻す（面接官から聞いて代行に伝える） |

「面談の結果を戻す」が、代行との週次で最も大事です。代行は送ることはできても、会った結果は自社しか知りません。戻らないと、代行は条件と文面を直せず、自社は「代行が改善しない」と感じます。

## 手順5｜代行から自社に戻すときの引き継ぎ

代行を頼んでいた作業を、自社に戻すことがあります。担当が増えた、時間が取れるようになった、代行の契約が終わる。戻すときに引き継ぐものを、代行を頼む前に確認しておきます。

- **文面のテンプレート**：共通部分、型、冒頭の空欄の指示。企業の名義で送っている文面なので、企業のもの
- **検索条件と、その根拠**：どの条件で、なぜそう設定したか
- **管理表**：送った学生、触れた一文、承認、面談、結果
- **割合の実績と、送信計画**：いまの率と、残りの期間の計画
- **効いた文面と条件の記録**：何が効いて何が効かなかったか
- **週次の記録**：止まった週と、直したこと

この引き継ぎは、[運用を担当者間で引き継ぐ方法](/media/ob-tantousha-hikitsugi/)で書いた「判断の元」と同じものです。代行に頼むときに、「やめるときにこれを書面でもらえるか」を確認しておきます。確認の仕方は[代理店に聞くべき質問](/media/kh-dairiten-shitsumon/)で書きました。当社の場合、代行の期間中も管理表と記録は企業と共有し、やめるときはテンプレートと条件と記録をまとめて渡します。

## やりがちな失敗

| 失敗 | 何が起きるか | 直し方 |
|---|---|---|
| 人物像まで代行に任せる | 面談に来た学生が社内の期待とずれる | 人物像は自社。代行は聞いて整理 |
| 仕事の中身を代行が想像で書く | 面談で「文面と違う」となる | 代行が下書き、現場が直す |
| 面談枠を出さない | 代行が候補を書けず、返信が遅れる | 週の初めに枠を渡す |
| 面談の結果を戻さない | 代行が条件と文面を直せない | 面談のたびに戻す |
| 全部を一度に出す | 何が止まっていたか分からない | 止まっている作業から段階的に |
| 出し切れない | 送る時間が取れない状態が変わらない | 読んで書いて送るを、まず出す |
| 週次を代行任せにする | 面談枠と体制の話が決まらない | 一緒に持つ |
| やめるときの引き継ぎを確認しない | テンプレートと記録が残らない | 頼む前に確認する |

最も多いのは、「面談の結果を戻さない」です。代行に出したあと、自社の作業は減りますが、「戻す」だけは残ります。

## 当社の線引き

当社がOfferBoxの運用代行を受けるときの分担を、参考として置きます。

| 当社がやること | 企業にやっていただくこと |
|---|---|
| ペルソナの型と質問で引き出す | 人物像を決める |
| 検索条件の設定と調整 | 譲れない条件を決める |
| 自由記述を読み、触れる一文を拾い、冒頭を書く | 仕事の中身と名義の口調を確認する |
| テンプレートの共通部分の下書き | 現場の言葉に直す |
| 送る。ペースを面談枠から逆算する | 面談枠を週の初めに出す |
| 承認に当日返信し、日程を確定する | 面談する。結果を戻す |
| 面談前の情報整理、面談後のフォローの連絡 | 選考に進めるか決める |
| 記録、率の置き直し、週次の資料 | 週次に出て、面談枠と体制を決める |
| テンプレートと企業ページの下書きの更新 | 仕事と人の変化を伝える |
| やめるときにテンプレート・条件・記録を渡す | ― |

企業の時間は、決める・会う・伝えるに集中します。この形で、送る時間が取れない会社でも、承認と面談が回ります。

### エージェントベストの見解

自社で持つべきなのは、どこまでか。当社が線を引くなら、「決める・会う・伝える」の3つです。決めるのは人物像と譲れない条件と選考の合否、会うのは面談と面接、伝えるのは仕事の中身と面談の結果と社内の変化。この3つは、当社が代われないからではなく、代わると運用が企業のものでなくなるから、企業に残します。逆に、読む・書く・送る・返信する・記録する・置き直す・下書きする、は当社が代わっても運用の中身は変わりません。企業の名義で、企業のペルソナで、企業の仕事の中身で送るからです。代行に出すかどうかを迷っている会社には、この表を見て「決める・会う・伝えるに、週に何時間使えるか」を考えてもらいます。それが取れるなら、代行に出しても運用は企業のものです。取れないなら、代行に出しても止まります。

## まとめ

- 代行に出せるのは作業（読む・書く・送る・返信・記録・置き直し・下書き）、出せないのは判断（決める・会う・伝える）
- 人物像、譲れない条件、仕事の中身、面談と面接、面談枠、合否は、出すと運用が崩れる
- 止まっている作業から段階的に出す。まず読んで書いて送る、次に返信、次に記録
- 週次は自社と代行で一緒に持つ。面談の結果を戻すことだけは、代行に出しても残る
- やめるときの引き継ぎ（テンプレート・条件・管理表・記録）を、頼む前に確認する

## よくある質問

### 代行に出せば、社内の時間はゼロになりますか

なりません。決める・会う・伝えるの3つは残ります。人物像と条件を決める、面談と面接に出る、面談の結果と社内の変化を代行に伝える。この3つに週に使える時間があるかが、代行に出して回るかどうかを決めます。

### 代行の文面が、自社の言葉になっていない気がします

仕事の中身の部分は、現場の言葉で確認する形になっているかを見ます。代行が想像で書くと一般的になります。当社の場合、共通部分と仕事の中身は下書きを現場に直してもらい、冒頭は企業のペルソナに沿って当社が書きます。直す工程が無いなら、契約の形を見直します。

### 御社の運用代行は、どこまでやってもらえますか

この記事の「当社の線引き」の表のとおりです。読む・書く・送る・返信・記録・率の置き直し・下書きの更新を当社が行い、人物像・条件・面談・面接・合否・面談枠・結果を戻すことは企業が行います。やめるときは、テンプレートと条件と記録をまとめて渡します。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
