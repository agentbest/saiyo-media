募集記事のタイトルを変えたら反応が良くなった気がする。でも、本当に効いたのか分からない。**結論から言うと、募集記事を差し替えて比べるときは、仮説を1つ立て、変えるのは1要素だけにし、月の「話を聞きに来た数」で前後を比べ、記録を残します。閲覧の数で判断せず、同時に複数を変えず、週で判断しません。** この3つを守らないと、「何が効いたか分からないまま変え続ける」状態になります。この記事では、比べる目的、仮説の立て方、変える要素の選び方、並行と期間分けの使い分け、見る指標、期間の揃え方、記録、効いた型の戻し方、やりがちな失敗、分担を整理します。複数パターンを作る考え方は[募集記事を複数パターン作る理由](/media/wt-boshu-fukusu/)で書きました。この記事は、そのパターンの「どちらが効くか」を確かめる方法です。

## この作業の目的｜「気がする」を「分かった」に変える

募集記事の改善は、感覚で行われがちです。「このタイトルのほうが良さそう」「写真を変えたら増えた気がする」。感覚で変え続けると、効いたものと効かなかったものが混ざり、次の卒年に同じことを繰り返します。

差し替えて比べる目的は、「効いた型」を記録として残し、次のパターンとテンプレートに戻すことです。1要素ずつ、期間を揃えて、数で比べる。地味ですが、これだけで「気がする」が「分かった」に変わります。

OfferBoxで「変更は1つずつ」「率は月次で」と書いたのと同じ考え方です。考え方は[週次レビューのやり方](/media/ob-shuukan-review/)で書きました。

## 手順1｜仮説を1つ立てる

比べる前に、「何を変えると、何が起きるはずか」を1つ書きます。

| 仮説の型 | 例 |
|---|---|
| タイトルの型 | 「職種名だけ」から「何をする人を探しているか」に変えると、開かれて話を聞きに来る数が増える |
| カバー写真の場面 | 集合写真から仕事中の場面に変えると、開いた候補者が本文で離れなくなる |
| 「こんなことやります」の深さ | 「ゆくゆくは」中心から「最初の数ヶ月」中心に変えると、話を聞きに来た候補者の面談での話が具体的になる |
| 「なぜ」の書き方 | 会社の理念の繰り返しから「なぜ今この募集か」に変えると、候補者が自分の役割を語る |
| 「求める動き方」の書き方 | 経験の羅列から行動の型に変えると、合わない候補者が減り、合う候補者が来る |

仮説が無いまま変えると、結果を見ても「良かった・悪かった」しか言えず、次に活きません。仮説があると、「タイトルの型が効いた」と記録できます。

## 手順2｜変えるのは1要素だけ

比べる期間に変えるのは、1要素だけです。タイトルと写真を同時に変えると、どちらが効いたか分かりません。

1. **変える要素を1つ決める**：仮説に対応する要素
2. **他の要素は固定する**：本文、写真、条件、会社ページ。比べる期間は触らない
3. **会社ページとストーリーの更新も、比べる期間はできるだけ止めない程度に**：止めると会社ページに来る人が減り、募集記事の数も動く。通常の更新は続け、大きな変更は避ける
4. **募集の状況が変わったら、比較を中断する**：「なぜ」の理由が変わった、配属先が変わった。条件が変わった比較は成立しない
5. **1要素の比較が終わってから、次の要素へ**

「1要素」の単位は、タイトル全体、写真1枚、「こんなことやります」の段落、のように、独立して差し替えられる範囲です。タイトルの一語だけを変える比較は、差が小さすぎて読めません。

### エージェントベストの見解

媒体を比べたり募集記事を見直したりするときに、閲覧の数で判断しようとする会社は多いのですが、閲覧は「開かれた」までで、「話を聞きに来た」ではありません。当社は3媒体すべての販売パートナーとしてWantedlyの契約後の運用を見ていますが、閲覧が増えたのに話を聞きに来る数が変わらなかった、という比較は珍しくありません。煽りのタイトルや目を引く写真は、開かれても本文で離れます。当社がWantedlyの募集記事を比べるときは、閲覧ではなく、月の「話を聞きに来た数」で前後を見ます。加えて、面談の最初に「募集記事のどこを読んで来ましたか」と聞き、変えた要素が読まれているかを確かめます。数と言葉の両方で見ると、「開かれたが読まれていない」と「読まれて来た」を分けられます。閲覧は参考まで。判断は、来た数と、来た人の言葉で。

## 手順3｜並行するか、期間で分けるか

比べ方は2つあります。媒体の仕様で、同じ職種の募集記事を同時に複数出せるかどうかで決まります。出せるかどうかは、管理画面と媒体の案内で確認します。

| 方法 | 使える場合 | 進め方 | 注意 |
|---|---|---|---|
| 並行 | 同じ職種で複数の募集記事を同時に出せる | 1要素だけ違う2本を同時に出し、同じ期間で比べる | 候補者が両方を見ることがある。タイトルが違えば別の募集に見える。似すぎると混乱する |
| 期間で分ける | 同時には出せない、または1本に絞りたい | 型Aを1ヶ月、型Bを1ヶ月、のように順に出す | 時期で候補者の動きが変わる。同じ長さの期間で、時期の影響が小さい範囲で |

並行のほうが時期の影響を受けませんが、候補者が両方を見て混乱する可能性があります。期間で分けるほうが単純ですが、時期の違いが混ざります。どちらでも、期間を揃えることが条件です。

## 手順4｜見る指標と、期間の揃え方

見る指標は2つです。

- **月の「話を聞きに来た数」**：募集記事から会社に話を聞きに来た人の数。開いた数ではなく、来た数
- **面談で聞く「どこを読んだか」**：変えた要素が読まれているか。「タイトルで開いた」「最初の数ヶ月を読んで来た」など

閲覧の数が見えるなら参考にしますが、判断には使いません。週の数字も使いません。分母が小さく、時期で動くからです。

期間の揃え方を並べます。

1. **同じ長さの期間で比べる**：1ヶ月なら1ヶ月ずつ
2. **時期の影響が小さい範囲で**：候補者が動く時期の山と谷をまたがない。時期の考え方は、OfferBoxの[送る時期と時間帯の考え方](/media/ob-soushin-timing/)と同じ
3. **募集の状況を揃える**：比べる期間に、「なぜ」の理由や配属先が変わらない
4. **来た数が少なすぎる場合は、期間を延ばす**：数件の差で判断しない。同じ長さで延ばす
5. **差が出なければ、「どちらでもよい」と記録する**：それも結果。時間をかけない

## 手順5｜記録し、効いた型をテンプレートに戻す

比べた結果を記録し、テンプレートに戻します。

| 記録する項目 | 内容 |
|---|---|
| 仮説 | 何を変えると何が起きるはずか |
| 変えた要素 | 型Aと型Bの内容 |
| 期間 | いつからいつまで、並行か期間分けか |
| 話を聞きに来た数 | 型ごと、月ごと |
| 面談で聞いた「どこを読んだか」 | 型ごとの答え |
| 結果 | 効いた／差が無い／逆だった |
| テンプレートへの反映 | どの層のどの部分を、どう変えたか |

効いた型は、3層のテンプレートの該当する層に戻します。タイトルの型が効いたなら「パターンごとに変える部分」の型に、「なぜ」の書き方が効いたなら「軸ごとに変える部分」の型に。戻しておくと、次のパターンを作るときに、効いた型から始められます。テンプレートの3層は[募集記事を複数パターン作る理由](/media/wt-boshu-fukusu/)で書きました。

記録は、担当が変わっても引き継げる形にします。「去年、タイトルをこう変えたら効いた」が記録に無いと、次の卒年に同じ比較を繰り返します。

## 手順6｜比べる順番

何から比べるかの順番を置きます。効く幅が大きいものから。

1. **タイトル**：一覧で開かれるかどうかを決める。効く幅が最も大きい
2. **「こんなことやります」の深さ**：開いた候補者が来るかどうかを決める
3. **カバー写真**：タイトルと合わせる前提で、場面の違い
4. **「なぜ」の書き方**：来た候補者の面談での話し方が変わる
5. **「求める動き方」の書き方**：合う候補者と合わない候補者の比率が変わる

タイトルと「こんなことやります」で差が出なければ、他の要素で差が出ることは少ないです。この2つを先に比べます。

## やりがちな失敗

| 失敗 | 何が起きるか | 直し方 |
|---|---|---|
| 仮説を立てずに変える | 結果が次に活きない | 何を変えると何が起きるはずかを1つ書く |
| 複数の要素を同時に変える | 何が効いたか分からない | 1要素だけ |
| 閲覧で判断する | 開かれても来ない型に寄る | 話を聞きに来た数で |
| 週で判断する | 分母が小さく、時期で動く | 月で |
| 期間の長さを揃えない | 比べられない | 同じ長さで |
| 比べる期間に募集の状況が変わる | 比較が成立しない | 中断して、揃ってから |
| 記録を残さない | 次の卒年に同じことを繰り返す | 仮説から結果まで記録 |
| 効いた型をテンプレートに戻さない | 次のパターンで活きない | 該当する層に戻す |
| 差が出ないのに比べ続ける | 時間の無駄 | 「どちらでもよい」と記録して次へ |

最も多いのは、「複数の要素を同時に変える」です。改善したい気持ちが先に立つと、タイトルも写真も本文も一度に変えたくなります。

## 社内の分担

| 作業 | 誰が |
|---|---|
| 仮説を立てる | 人事 |
| 変える要素を書く | 人事（配属先に聞く部分は配属先） |
| 出す・差し替える | 人事 |
| 話を聞きに来た数を月で集める | 人事 |
| 面談で「どこを読んだか」を聞く | 面談に出る人 |
| 記録し、テンプレートに戻す | 人事 |

面談に出る人の負担は、「どこを読んだか」を最初に聞くだけです。運用代行や代理店が支えられるのは、仮説の候補、比べる順番、記録の型、テンプレートへの戻し方までです。代理店の代行の範囲は[代理店に運用まで頼めるか](/media/kh-dairiten-unyou/)で書きました。

### エージェントベストの見解

これをやる前に、先に決めておかないと比較が空回りすることがあります。「面談の最初に『募集記事のどこを読んで来ましたか』と聞く」ことを、面談の型に入れておくことです。当社がWantedlyの運用の相談で募集記事の比較の話をするとき、数は集めているのに、来た候補者が「何を読んで来たか」を聞いていない会社が多くあります。数だけだと、「型Aのほうが来た」までしか分からず、「型Aのタイトルで開いて、最初の数ヶ月を読んで来た」までは分かりません。後者が分かると、次に何を変えるかが決まります。聞くのは一言で、面談の最初に入れれば済みます。この一言が、比較の結果を「数」から「理由」に変えます。数と理由の両方が揃って初めて、テンプレートに戻せる型になります。

## まとめ

- 募集記事を差し替えて比べるときは、仮説を1つ立て、変えるのは1要素だけ、月の「話を聞きに来た数」で前後を比べる
- 閲覧と週の数字で判断しない。開かれても来ない型に寄る
- 同時に複数出せるなら並行、出せなければ期間で分ける。どちらも同じ長さで、時期と募集の状況を揃える
- 面談の最初に「どこを読んで来たか」を聞き、数と理由の両方で見る
- 仮説から結果まで記録し、効いた型を3層のテンプレートの該当する層に戻す。差が出なければ「どちらでもよい」と記録して次へ

## よくある質問

### 閲覧の数は見なくてよいのですか

参考にはしますが、判断には使いません。閲覧は「開かれた」までで、開かれても本文で離れれば、話を聞きに来ません。判断は、月の「話を聞きに来た数」と、面談で聞く「どこを読んだか」で行います。

### 来る数が少なくて、比べられません

同じ長さで期間を延ばします。数件の差で判断すると、偶然に左右されます。延ばしても差が出なければ、「どちらでもよい」と記録して、次の要素に移ります。差が出ないことも、記録として次に活きます。

### 募集記事の比較は、御社に相談できますか

できます。当社は、仮説の候補、変える要素の選び方、比べる順番、記録の型、効いた型をテンプレートに戻す整理を支えられます。差し替えと、面談で聞くことは企業が行ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、Wantedlyの募集記事の整備を支えています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
