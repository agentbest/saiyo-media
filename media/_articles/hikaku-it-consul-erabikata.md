ITコンサルタントを新卒で採る会社が媒体を選ぶとき、最初にぶつかるのは「『ITコンサル』の名前で募集すると、コンサル志望の学生は大手の戦略の像で、SE志望の学生は開発の像で来て、面談で『業務を分解して、客先と開発の間に立って合意させ、要件を文書にする』と聞いてどちらも『思っていたのと違う』と離れる。情報系で絞ると足りず、広げるとコンサル志望とSE志望が混ざって文面が書けない」という問題です。**結論から言うと、「ITコンサル」の名前では、学生は戦略か開発のどちらかの像で来て、間に立つ仕事を聞いて離れます。媒体を選ぶ前に自社の「間」の位置（戦略寄りか、業務寄りか、開発寄りか）と客先常駐の範囲を決め、情報系とプログラミング経験をあればよい条件に置き、「業務を分解した・人の間に立って合意させた・仕組みで手間を減らした」の行動で探します。送る型は行動で絞って現場のコンサルタントの名義で、記事を置く型は案件の一日と常駐先での立場を、比べられる場は大手の「成長環境」の体験談に対して企業ページに間の位置と常駐の範囲と最初の年を先に書きます。** コンサルタント全般の選び方は[コンサルタントの採用媒体の選び方](/media/hikaku-consultant-erabikata/)で書きました。この記事はITコンサルタントに絞ります。

## ITコンサルタントの採用で、起きること

| 会社の状態 | 採用で起きること | 媒体との相性 |
|---|---|---|
| 「ITコンサル」の名前だけで募集する | コンサル志望は戦略の像、SE志望は開発の像で来て、間に立つ仕事でどちらも離れる | 間の位置を職種名より先に書く。[ワンキャリアでITコンサルタントを募集するときの掲載とスカウト](/media/oc-it-consul-keisai/) |
| 情報系・プログラミング経験で絞る | 足りない。広げると志望が混ざって文面が書けない | 専攻と経験をあればよい条件に置き、行動で絞る。[OfferBoxでITコンサルタント志望の学生を見つける検索の考え方](/media/ob-it-consul-target/) |
| 大手の言葉（戦略・成長環境・優秀な仲間）を真似る | 大手と比べられ、面談で「大手と何が違うのか」に答えられない | 自社の間の位置と案件の取り方で書く |
| 客先常駐の範囲が書かれていない | 「自社にいると思っていた」と入社後に離れる | 常駐の有無と範囲と期間を先に書く |
| 最初の年が書かれていない | 提案の像で来て、資料と議事録の年だと「思っていたのと違う」 | 最初の年の仕事を時期で書く |

## 判断軸を、ITコンサルタントに当てる

| 軸 | ITコンサルタントでの見方 |
|---|---|
| 対象（誰に届くか） | 専攻と志望職種を見ない。「間」の位置で求める行動を決める。業務寄りなら「業務を分解した・手順を書いた」、開発寄りなら「仕組みで手間を減らした」、どちらも「人の間に立って合意させた」。文系のコンサル志望と情報系のSE志望の両方から、行動で探す |
| 型（送るか、来るか、比べられるか） | 送る型は、行動で絞って現場のコンサルタントの名義で「あなたの人の間に立って合意させた経験を読んで」と一人に書ける。来る型は、案件の一日と、常駐先での立場と、最初の年の資料と議事録の話を記事で通年で。比べられる型は、大手の「成長環境」「優秀な仲間」の体験談に対して、企業ページに間の位置と常駐の範囲と最初の年を先に書けるかで |
| 課金（費用の性格） | 各媒体の公式ページで現在の条件を確認。この記事では書かない |
| 運用工数（誰の時間が要るか） | 現場のコンサルタントが名義と面談を持つ時間。常駐先にいると日中の面談が組めないので、面談の枠を常駐先と先に合意しないと運用が止まる |

軸の詳しい見方は[掲載型とスカウト型の違い](/media/hikaku-keisai-vs-scout/)、[共感型と条件型の媒体の違い](/media/hikaku-kyoukan-vs-jouken/)で書きました。ITコンサルタントでは、「対象」を専攻ではなく間の位置で決めた行動で絞ることと、「運用工数」を常駐先との合意で確保することが、他の職種と違います。

### エージェントベストの見解

相談で最も多い思い込みは、「ITコンサルは情報系の学生か、コンサル志望の学生に送ればよい。大手と同じ『成長環境』で書けば届く」というものです。当社は3媒体すべての販売パートナーとして、ITコンサルタントの採用の相談を受けますが、情報系で絞った会社は対象が足りず、コンサル志望に広げた会社は大手の戦略の像の学生が来て、大手の言葉を真似た文面は面談で「大手と何が違うのですか」と聞かれて答えられません。ITコンサルタントの仕事の中心は、客先の業務を分解し、客先と開発の間に立って合意させ、要件を文書にすることです。この行動は、情報系にも文系にも書かれています。当社が最初にお願いするのは、絞る条件から専攻とプログラミング経験を「あればよい条件」に下げ、「業務を分解した・人の間に立って合意させた・仕組みで手間を減らした」を「優先する条件」に上げ、文面から大手の言葉を消して、自社の間の位置と案件の取り方で書くことです。

## 学生が、確かめること

- **「間」の位置**：戦略寄りか、業務寄りか、開発寄りか。客先と開発の間のどこに立つか。「ITコンサル」の名前では分からない
- **客先常駐の範囲**：常駐があるか。どの期間か。常駐先で自社の誰と一緒か。一人で常駐するか
- **最初の年に何を任されるか**：資料の作成か、議事録か、業務の調査か、テストか。提案はいつからか
- **案件の決まり方**：元請けか、大手の下か。誰が案件を取ってくるか。自分で取る日が来るか
- **大手との違い**：大手のITコンサルと、この会社で、間の位置と案件の規模と任される時期がどう違うか

## この条件なら、どれを先に検討するか

| 会社の条件 | 先に検討する型 | 理由 |
|---|---|---|
| 行動で絞り、現場のコンサルタントの名義で「あなたの人の間に立って合意させた経験を読んで」と一人に書ける | 企業から送る型（OfferBox） | 専攻と志望を見ずに、文系のコンサル志望と情報系のSE志望の両方から探せる。[ITコンサルタント向けのオファー文面](/media/ob-it-consul-offer-bunmen/) |
| 現場のコンサルタントが、案件の一日と常駐先での立場を自分の言葉で書ける | 通年で記事を置く型（Wantedly） | 「戦略」「開発」の像を、間に立った案件の記事で置き換える |
| 体験談があり、企業ページに間の位置と常駐の範囲と最初の年を先に書ける | 学生が並べて比べる場（ワンキャリア） | 大手の「成長環境」に対して、入る前に間の位置と最初の年が分かる会社として読まれる |
| 間の位置と常駐の範囲が決まっていない | どれも先ではない | 案件を持つ責任者と決めてから |
| 面談の枠を常駐先と合意できていない | どれも先ではない | 承認から面談までの間に他社で決まる |

どれか一つが正解ではなく、行動で絞れるか、現場が書けるか、体験談があるかで、先に検討するものが変わります。

## 組み合わせ

- **送る型と記事を置く型を組み合わせる**：文面で合意させた経験を読んだ一文を、記事で案件の一日と常駐先での立場を。[OfferBoxとWantedlyの併用](/media/ob-heiyou-wantedly/)
- **コンサルタント全般・SIerの構造と重ねる**：[コンサルタントの採用媒体の選び方](/media/hikaku-consultant-erabikata/)、[SIer業界の採用媒体の選び方](/media/hikaku-sier-erabikata/)、[コンサルティング業界の採用媒体の選び方](/media/hikaku-consul-erabikata/)。開発寄りならSIerの学生の探し方が近い
- **面談の聞き方の型を、揃える**：「何を作ったかより、手順をどう分解したか、合意しない二者の間で何をしたか、手作業を何に置き換えたか」。ケース面接の型を大手から借りない
- **内定前に、常駐先の一日を見せる**：常駐先での立場と、議事録の実物と、最初の年の資料を。[内定辞退が続くときの見直し方](/media/ob-naitei-jitai/)
- **代行と組み合わせるなら、絞る作業と文面の下書きまで。読んで直すのは現場のコンサルタント**：[媒体と代行の違い](/media/hikaku-baitai-vs-daikou/)

## 見せ方｜「ITコンサル」ではなく、間のどこに立ち、どこに常駐し、最初の年に何をするか

- **「ITコンサル」「戦略」「成長環境」「優秀な仲間」を消す**：戦略の像で来て、大手と比べられる
- **間の位置を、職種名に**：「〇〇業界の業務を分解して要件にするコンサルタント」「△△の導入で客先と開発の間に立つコンサルタント」。戦略寄りか業務寄りか開発寄りかを先に
- **客先常駐の範囲を、最初に**：「常駐は〇〇の期間。自社の先輩と一緒。一人での常駐は□年目から」。無いなら無いと
- **最初の年を、時期で**：「最初の年は業務の調査と議事録と資料。要件の一部を任せるのは△年目から。提案は□年目から」。議事録が多いなら、議事録で客先の業務を覚えると、意味を書く
- **案件の決まり方を、実態で**：「元請けが〇割、大手の下が△割」の形は自社の実態で。この記事では書かない。大手の下があるなら、隠さない
- **大手との違いを、間の位置と規模で**：「大手は戦略から、当社は業務から。案件は小さいが、最初の年から客先の会議に出る」。大手を下げずに、違いを書く

## 社内の分担

| 作業 | 誰が |
|---|---|
| 間の位置、常駐の範囲、最初の年、案件の決まり方を決める | 案件を持つ責任者 |
| 面談の枠を常駐先と合意する | 責任者。書く前に |
| 行動で絞る条件 | 現場のコンサルタントが作り、人事か代行が絞る |
| 文面と記事 | 現場が話し、人事が書き、本人が確認 |
| 名義と、オファーの一文 | 現場のコンサルタント |
| 面談 | 責任者と現場。聞き方の型を揃えて。ケースの型を大手から借りない |
| 「大手と何が違うか」に答えられたかの記録 | 人事。答えの一文を揃えて |

運用代行や代理店が支えられるのは、絞る条件の型、絞る作業、文面の下書き、記録の型までで、間の位置の決定、常駐先との合意、名義、面談は社内が担います。代理店の代行の範囲は[代理店に運用まで頼めるか](/media/kh-dairiten-unyou/)で書きました。

### エージェントベストの見解

ITコンサルタントの採用で、申し込んだあとに運用が止まる会社に共通するのは、現場のコンサルタントが常駐先にいて、面談の枠が組めないことです。人事が承認を集めても、名義の現場が日中は客先の会議で、夜は資料で、面談の候補日が出せず、承認から面談までの間に学生は他社で決まります。当社が案内するのは、送り始める前に、名義になる現場の面談の枠を、常駐先の責任者と週に何回どの時間に置くかを合意し、その枠の数から送る数を逆算することです。枠が少ししか取れないなら、送る数を減らし、絞る条件を強くして、一人ひとりに現場の名義で書きます。枠に合う数を送って全員に現場が会う状態のほうが、「思っていたのと違う」が減り、内定後の辞退が減ります。

## まとめ

- 「ITコンサル」の名前では、コンサル志望は戦略の像、SE志望は開発の像で来て、間に立つ仕事を聞いてどちらも離れる。間の位置（戦略寄りか業務寄りか開発寄りか）と客先常駐の範囲を先に決める
- 情報系とプログラミング経験はあればよい条件に。「業務を分解した・人の間に立って合意させた・仕組みで手間を減らした」の行動で、文系のコンサル志望と情報系のSE志望の両方から探す
- 大手の言葉（戦略・成長環境・優秀な仲間）を真似ない。自社の間の位置と案件の取り方で書き、大手を下げずに違いを書く
- 送る型（OfferBox）は行動で絞って現場の名義で、記事を置く型（Wantedly）は案件の一日と常駐先での立場を、比べられる場（ワンキャリア）は大手の体験談に対して企業ページに間の位置と常駐の範囲と最初の年を先に
- 現場の面談の枠を常駐先と先に合意し、その数から送る数を決める

## よくある質問

### 案件の多くが大手の下です。書くと学生が来なくなりませんか

隠して入社後に知られるほうが、「下請けだった」と体験談に書かれて次の年の学生が離れます。「大手の下の案件もある。その案件では〇〇の範囲を担い、元請けの案件では△△まで担う」と、案件の形ごとに担う範囲を書きます。範囲が書かれていれば、間に立つ仕事に惹かれる学生は来ます。

### 情報系の学生が集まりません。プログラミングの条件を外してよいですか

外します。ITコンサルタントの中心は、業務を分解し、間に立って合意させ、要件を文書にすることで、プログラミングは入社後に必要な範囲で覚えられます。文系の学生にも「手順を書き直した」「二者の間で合意させた」の行動は書かれています。専攻と経験を「あればよい条件」に下げ、行動で絞ると、対象が広がります。

### ITコンサルタントの媒体選びは、御社に相談できますか

できます。当社は、絞る条件の型、絞る作業、文面の下書き、記録の型を支えられます。間の位置の決定、常駐先との合意、名義、面談は、社内で担ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、ITコンサルタントの媒体選びと運用を支えています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
