スカウトを複数の人で回すと、一人で回すときには無かった問題が出ます。同じ学生に別の募集から送ってしまう、送る人ごとに文面のトーンが違う、受諾が来たのに誰が返すか決まっていない、台帳が人ごとに分かれて全体が見えない、体験談を誰も読んでいない。ワンキャリアでは、これらが体験談に「社内で連携していない会社」と書かれます。**結論から言うと、チームでスカウトを回すには、募集ごとに「読んで書く人」を一人置き、受諾対応と体験談を読む役を人事一か所に集め、型と見本・台帳・避ける言葉・返信の型・面談の型・「選考で何を見るか」の一文を共通にします。送る枠は各自で持ち、週の確認は人事一人で短く、月の会で一か所を直します。新しい人には型と見本と台帳の場所を渡し、負担の偏りを台帳で見ます。チームの大きさは、面接の枠で決まります。** この記事では、チームで起きる失敗、役割の置き方、共通にするもの、週の回し方、新しい人の渡し方、偏りの見方、チームの大きさ、分担を整理します。人事と現場の分担の基本は[ワンキャリアのスカウトを誰が送るか](/media/oc-scout-tantou/)、一人で回す場合は[人事1人でワンキャリアのスカウトを回す方法](/media/oc-scout-hitori/)で書きました。

## この作業の目的｜人が増えても、学生から見て「一つの会社」に見える状態にする

チームで回す目的は、送れる数を増やすことと、各募集をその職種の入社してまもない社員が担うことです。ただし、学生から見れば、送り主が誰でも「同じ会社からの連絡」です。

目的は、人が増えても、文面のトーンが揃い、受諾への対応の速さが揃い、同じ学生に重ねて送らず、面談の型が揃い、「選考で何を見るか」の一文が全員で同じ、という状態を保つことです。「一つの会社」に見えなくなると、増やした分だけ、体験談に書かれます。

## チームで起きる失敗

| 失敗 | 何が起きるか |
|---|---|
| 同じ学生に、複数の募集から送る | 学生に「社内で連携していない」と分かる。体験談に書かれる |
| 送る人ごとに文面がばらつく | 会社のトーンが定まらない |
| 「選考で何を見るか」の一文が、送る人ごとに違う | 学生が企業ページと照らして「どれが本当か」 |
| 受諾を誰が返すか決まっていない | 「誰かがやる」で放置。体験談に「返信が遅かった」 |
| 台帳が人ごとに分かれる | 全体の段の数が出ない。重複も見えない |
| 送る人が、受諾対応も面談も台帳も全部やる | 忙しい人ほど止まる |
| 体験談を誰も読まない | 「テンプレだった」に気づかず、全員が同じ形で送り続ける |
| 反応が送る人に戻らない | 「自分の送った分がどうなったか」が分からず、続かない |
| 新しい人が、口頭で引き継がれる | 型と台帳を知らず、自己流になる |

最も多いのは、最初の「同じ学生に複数から送る」です。台帳が共通でないと、防げません。

## 役割の置き方

| 役割 | 誰が | 何をするか |
|---|---|---|
| 読んで書く人 | 募集ごとに一人（その職種の入社してまもない社員） | 週の枠で、プロフィールを読み、学生の一文と重なる点を書き、送る。話す場に出る |
| 受諾対応の人 | 一人（人事） | 全募集の受諾を受け、翌日までに返し、学生の都合に合わせた日程を組む。通知を集める |
| 体験談を読む人 | 人事（受諾対応の人と同じでよい） | 週の確認で新しい体験談を読み、要点を送る人全員に共有する |
| 整える人 | 人事 | 型と見本、絞り込み、台帳、週と月の見直し、反応を戻す |
| 見直しに出る人 | 責任者 | 月の会で、配分と直す一か所を決める |
| 面接に出る人 | 面接官全員 | 「何を見るか」の一文を知り、掲載どおりに面接する |

「読んで書く人は募集ごとに一人」と「受諾対応と体験談を読むのは全体で一人」が、役割の中心です。ワンキャリアでは「体験談を読む人」が一人いて、その要点が送る人全員に届く形が要ります。

### エージェントベストの見解

相談で最も多い思い込みは、「人を増やせば、送れる数が増えて、結果も増える」というものです。当社は3媒体すべての販売パートナーとして、ワンキャリアのスカウトの運用を見ていますが、人を増やした会社で最初に起きるのは、送る数が増えることではなく、同じ学生への重複と、文面のばらつきと、受諾対応の抜けと、「何を見るか」の一文の不揃いです。台帳と型が共通になっていないまま人を増やすと、一人で回していたときより、学生から見た印象は下がり、それが体験談に書かれます。当社がチーム運用の相談を受けるとき、最初にやるのは、人を増やす前に、台帳を一つにし、型と見本を一つの置き場に置き、受諾対応と体験談を読む役を一人に決めることです。この三つが揃ってから人を増やすと、増えた分だけ送れます。

## 共通にするもの

| 共通にするもの | 中身 | 置き場 |
|---|---|---|
| 型と見本 | 募集ごとの型（変えない部分）、受諾が来た見本、避ける言葉 | 一か所。企業ページの写しと隣に。[ワンキャリアのスカウト文面のテンプレート管理](/media/oc-scout-template/) |
| 「選考で何を見るか」の一文 | 企業ページの選考の流れから。面接に出る人全員が知っている | 型の中と、面接の型 |
| 台帳 | 誰に、誰が、どの募集で、いつ送ったか。受諾、面談、選考の段。体験談への言及 | 一つのファイル |
| 返信の型 | 前向き・質問・選考の確認・条件・断り | 受諾対応の人が使う |
| 面談の型 | 流れ、聞くこと・聞かないこと、最後の選択肢 | 話す人全員に。[スカウト経由の初回面談の設計](/media/oc-scout-mendan/) |
| 体験談の要点 | 新しい体験談で分かったこと | 送る人全員に共有 |
| 送る前のチェック | 学生の一文があるか、選考の一文が企業ページと同じか、話す場か選考か | 読んで書く人全員に |

「共通にする」は、「全員が同じ文面を送る」ことではありません。変えない部分と、面談の型と、台帳と、体験談の要点が共通で、学生の一文と重なる点は各自が書きます。

## 週の回し方

- **送る枠は、各自が自分の予定に持つ**：全員で同じ時間に送らない。読んで書く人ごとに、週に一度の枠
- **送ったら、台帳に一行**：その場で。送り主、学生、募集、一文
- **受諾対応の人は、毎日決まった時間に台帳と通知を見る**：翌日までに返す
- **週の確認は、人事一人で短く**：受諾への対応の速さ、新しい体験談、設定の誤り。会は開かない。[ワンキャリアのスカウトの受諾率を毎週見直す方法](/media/oc-scout-review/)
- **新しい体験談の要点を、送る人全員にその週に共有する**：「テンプレだった」があれば、全員が読める数を見直す
- **月の会で、読んで書く人と責任者も出て、一か所を直す**：段ごとの数、配分、型の一か所
- **反応は、人事が読んで書く人に個別に戻す**：「〇〇さんの文面で受諾が来て、面談まで進みました」「体験談に『自分のことを読んでくれていた』と書かれていました」

「読んで書く人は週の会に出なくてよい」が、現場の負担を減らす要点です。現場に頼むのは、読んで書くことと話す場だけです。

## 新しい人が入るときの渡し方

1. **型と見本と、避ける言葉と、送る前のチェック**：一枚に
2. **「選考で何を見るか」の一文と、企業ページの該当箇所**：文面と面接がずれないように
3. **台帳の場所と、書き方（送ったら一行）**
4. **担当する募集と、その企業ページの「最初の1年」**：読んでもらう
5. **自社の体験談の要点**：学生が何を読んでいるかを知ってから書く
6. **最初の数通は、人事が確認してから送る**：型に沿っているか、学生の一文があるか
7. **面談の型と、聞かないこと**：話す場に出る前に
8. **最初の受諾と面談の結果を、早く戻す**：「やる意味」を最初に

「最初の数通は人事が確認」で、自己流を防ぎます。「自社の体験談の要点を先に渡す」が、ワンキャリアで加わる項目です。

## 負担の偏りの見方

- **送った数を、送り主ごとに月で見る**：特定の人に偏っていないか
- **話す場の数を、話す人ごとに見る**：面談の枠を超えていないか
- **送らない週が続く人がいないか**：枠が取れていないか、上司の合意が消えていないか
- **受諾対応の人の、対応までの時間**：一人で受けきれているか。超えているなら、送る数を減らすか、対応する人を増やす
- **体験談への言及を、送り主ごとに見る**：「自分のことを読んでいた」と「テンプレだった」が、どの送り主の文面に対応するか
- **偏りが見えたら、募集の配分を変える**：[ワンキャリアのスカウト通数の配分](/media/oc-scout-tsuusuu-haibun/)

「体験談への言及を送り主ごとに見る」は、ワンキャリアのチーム運用に特有の見方です。文面の質の差が、体験談に現れます。

## チームの大きさの考え方

- **読んで書く人の数は、募集の数まで**：募集より多くても、担当する募集が無い
- **受諾対応は、一人で受けきれる数まで送る**：受けきれなくなったら、対応する人を増やすより、送る数を減らすほうが先
- **人事が「整える」と「体験談を読む」に集中できる大きさ**
- **面接に出る人の枠の合計が、全体の上限**：チームが大きくても、面接の枠が無ければ送れない
- **小さく始めて、台帳で回っていることを確かめてから増やす**

「面接の枠の合計が上限」は、一人で回すときと同じ原則です。チームの大きさは、送る人の数ではなく、面接に出られる枠で決まります。

### エージェントベストの見解

これをやる前に、先に決めておかないとチームが機能しないことがあります。「受諾対応と体験談を読む役を、一人に集める」ことです。当社がワンキャリアのスカウトのチーム運用を支えるとき、読んで書く人が複数いる会社で、受諾の通知がそれぞれの送り主に届き、対応の速さがばらつき、体験談を誰も読んでいない状態をよく見ます。受諾が早い人の学生は面談に進み、遅い人の学生は離れ、体験談には「返信が遅かった」と書かれ、それを誰も読んでいない。当社が最初にお願いするのは、通知を一か所に集めて受諾対応を一人にすることと、その人が週に体験談を読んで要点を全員に流すことです。読んで書く人は複数でよく、返す人と読む人は一人。この形が、学生から見て「一つの会社」に見える条件です。

## まとめ

- チームで回す目的は、人が増えても学生から「一つの会社」に見えること。重複、文面のばらつき、受諾対応の抜け、「何を見るか」の不揃い、体験談の読み落としを防ぐ
- 役割は、募集ごとの読んで書く人、受諾対応と体験談を読む人事一人、整える人事、月の会に出る責任者、「何を見るか」を知る面接官全員
- 型と見本・「何を見るか」の一文・台帳・返信の型・面談の型・体験談の要点・送る前のチェックを共通にし、置き場を一か所に
- 送る枠は各自、週の確認は人事一人で、体験談の要点をその週に全員へ、月の会で一か所。反応は個別に戻す
- 新しい人には一枚と体験談の要点を渡し、最初の数通は人事が確認。偏りは台帳と体験談への言及で見て、大きさは面接の枠で決まる

## よくある質問

### 読んで書く人ごとに、受諾の来やすさが違います

台帳で、送り主ごとの学生の一文を並べて見ます。具体の濃さが違うなら、受諾が来ている人の文面を見本として全員に渡します。体験談への言及も送り主ごとに見て、「テンプレだった」に対応する送り主がいれば、その人の読める数を見直します。受諾対応の速さが違うなら、対応を一人に集めていないことが原因です。

### 人事が一人で、整える役と受諾対応と体験談を読むのを全部持てません

受諾対応と体験談を読むことは人事に残し、整える役の一部（絞り込みの条件、台帳の集計、型の更新、体験談の要点の整理、見直しの材料）を外部に頼むか、責任者と分けます。受諾対応と体験談を読むことだけは、毎日と毎週社内で見る人が要ります。それも無理なら、送る数を減らします。

### ワンキャリアのスカウトのチーム運用は、御社に相談できますか

できます。当社は、役割の置き方の設計、共通にするものの作成、週と月の回し方の型、新しい人に渡す一枚、偏りの見方の型、体験談の要点の整理を支えられます。読んで書くこと、受諾対応、話す場、配分の決定、体験談を読んで分けることは、企業が行ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、ワンキャリアのスカウト運用を支えています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
