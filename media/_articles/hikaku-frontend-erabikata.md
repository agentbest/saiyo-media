フロントエンドエンジニアを新卒で採る会社が媒体を選ぶとき、最初にぶつかるのは「使っているフレームワークの名前で絞って送り、承認されない。承認されても、学生は『フロントエンドもバックエンドもやりたい』と言い、面談で『デザインは誰が決めるのですか』『どこまでが自分の担当ですか』に答えられず、入社後に『画面の修正ばかりで設計に関われない』と離れる」という問題です。**結論から言うと、学生は自分を「フロントエンド」で分けておらず、フレームワーク名で絞ると届きません。新卒をフロントエンドに絞って採るのか、Webエンジニアとして採って入社後に分けるのかを先に決め、「画面を作って人に使ってもらった・使いにくいと言われて直した・デザインと実装の間で決めた」の行動で探します。送る型は行動で絞ってフロントエンドの先輩の名義で、記事を置く型は画面ができるまでの分担とレビューの一日を、比べられる場は「技術面接で何を聞かれたか」の体験談に対して企業ページに作っている画面とレビューの仕組みを先に書きます。** エンジニア全般の選び方は[エンジニアの採用媒体の選び方](/media/hikaku-engineer-erabikata/)で書きました。この記事はフロントエンドに絞ります。

## フロントエンドエンジニアの採用で、起きること

| 会社の状態 | 採用で起きること | 媒体との相性 |
|---|---|---|
| フレームワーク名で絞る | 学生の多くは授業や独学で触った範囲で、名前では自分のことだと思わない | 名前をあればよい条件に置き、行動で絞る。[OfferBoxでエンジニア志望の学生を見つける検索の考え方](/media/ob-engineer-target/) |
| 絞って採るか、入社後に分けるかを決めていない | 「フロントエンド募集」で来た学生が入社後にバックエンドに回され、「聞いていた話と違う」 | 先に決めて、決めたとおりに書く |
| デザインは誰が決めるかが書かれていない | デザイナーがいない会社で「デザインも自分で」と入社後に知る | デザイナーの有無と分担を書く。[Wantedlyでフロントエンドエンジニアを採る募集記事の書き方](/media/wt-frontend-boshu/) |
| レビューする人が書かれていない | 「レビューが無く、一人で直していた」が体験談に書かれる | 誰が、どの観点で、いつ見るかを書き、時間を先に確保 |
| 最初の年が書かれていない | 新しい画面を設計する像で来て、既存の画面の修正だと離れる | 最初の年に任される画面を時期で書く |

## 判断軸を、フロントエンドエンジニアに当てる

| 軸 | フロントエンドエンジニアでの見方 |
|---|---|
| 対象（誰に届くか） | フレームワーク名と専攻を見ない。「画面を作って人に使ってもらった・使いにくいと言われて直した・デザインと実装の間で決めた」の行動で探す。情報系だけでなく、独学とデザイン寄りの学生を含める。絞って採るなら画面を作った行動を、入社後に分けるならWebエンジニアの行動で広く |
| 型（送るか、来るか、比べられるか） | 送る型は、行動で絞ってフロントエンドの先輩の名義で「あなたの使いにくいと言われて直した経験を読んで」と一人に書ける。来る型は、画面ができるまでの分担と、レビューの一日と、技術を選び直した話を記事で通年で。比べられる型は、「技術面接で何を聞かれたか」の体験談に対して、企業ページに作っている画面とレビューの仕組みを先に書けるかで |
| 課金（費用の性格） | 各媒体の公式ページで現在の条件を確認。この記事では書かない |
| 運用工数（誰の時間が要るか） | フロントエンドの先輩が名義と面談と技術面接を持つ時間と、入社後にレビューする時間。開発の締切と重なるので、枠を先に固定しないと運用が止まる |

軸の詳しい見方は[掲載型とスカウト型の違い](/media/hikaku-keisai-vs-scout/)、[共感型と条件型の媒体の違い](/media/hikaku-kyoukan-vs-jouken/)で書きました。フロントエンドでは、「対象」を分けて採るか入社後に分けるかで変えることと、「運用工数」にレビューの時間を含めることが、他の職種と違います。

### エージェントベストの見解

相談で最も多い思い込みは、「フロントエンドは、自社で使っているフレームワークを触ったことのある学生に送ればよい」というものです。当社は3媒体すべての販売パートナーとして、エンジニアの採用の相談を受けますが、フレームワーク名で絞った会社は、対象が少ないうえに、名前で絞った文面が技術の一覧になり、学生に「自分は経験が浅いから違う」と読まれます。新卒の学生は、授業や独学で触った範囲で、自分を「フロントエンド」「バックエンド」で分けていません。「画面を作って友人に使ってもらった」「使いにくいと言われて直した」「デザインと実装の間で、どちらに寄せるかを決めた」の行動は、フレームワークの名前が違っても、フロントエンドで使う行動と同じです。当社が最初にお願いするのは、絞る条件からフレームワーク名を「あればよい条件」に下げ、行動を「優先する条件」に上げ、その前に「新卒をフロントエンドに絞って採るのか、Webエンジニアとして採って入社後に分けるのか」を決めることです。これを決めずに「フロントエンド募集」で出し、入社後にバックエンドに回すと、体験談に書かれます。

## 学生が、確かめること

- **どの画面を、誰のために作るか**：自社のサービスか、受託か。使う人は誰か。「フロントエンド」の名前では分からない
- **デザインは誰が決めるか**：デザイナーがいるか。いないなら、誰が決めるか。デザインと実装の間で決めるのは誰か
- **バックエンドとの分担**：どこまでが自分の担当か。APIは誰が決めるか。分担が無いなら、無いと
- **レビューは誰が、どう**：誰が、どの観点で、いつ見るか。「レビューが無い」が最も多く体験談に書かれる
- **最初の年に任される画面**：既存の画面の修正か、新しい画面の一部か。設計に関わるのはいつからか

## この条件なら、どれを先に検討するか

| 会社の条件 | 先に検討する型 | 理由 |
|---|---|---|
| 行動で絞り、フロントエンドの先輩の名義で「あなたの使いにくいと言われて直した経験を読んで」と一人に書ける | 企業から送る型（OfferBox） | フレームワーク名と専攻を見ずに、独学とデザイン寄りの学生にも届く。[エンジニア向けのオファー文面](/media/ob-engineer-offer-bunmen/) |
| フロントエンドの先輩が、画面ができるまでの分担とレビューの一日を自分の言葉で書ける | 通年で記事を置く型（Wantedly） | エンジニアが読みに来る場で、「修正ばかり」の像を分担とレビューの記事で置き換える。[Wantedlyでフロントエンドエンジニアにスカウトを送る文面](/media/wt-frontend-scout/) |
| 体験談があり、企業ページに作っている画面とレビューの仕組みを先に書ける | 学生が並べて比べる場（ワンキャリア） | 「技術面接で何を聞かれたか」の体験談に対して、入る前に画面とレビューが分かる会社として読まれる。[ワンキャリアでエンジニアを募集するときの掲載とスカウト](/media/oc-engineer-keisai/) |
| 絞って採るか入社後に分けるかが決まっていない | どれも先ではない | 開発の責任者と決めてから |
| レビューする時間が確保できていない | どれも先ではない | 「レビューがある」と書いて無いと、体験談に書かれる |

どれか一つが正解ではなく、行動で絞れるか、先輩が書けるか、体験談があるかで、先に検討するものが変わります。

## 組み合わせ

- **送る型と記事を置く型を組み合わせる**：文面で直した経験を読んだ一文を、記事で分担とレビューの一日を。[OfferBoxとWantedlyの併用](/media/ob-heiyou-wantedly/)
- **デザイナーの探し方と重ねる**：[デザイナーの採用媒体の選び方](/media/hikaku-designer-erabikata/)。デザイン寄りの学生の中に、実装まで自分でした学生がいる
- **技術面接の聞き方の型を、揃える**：「何を使ったかより、使いにくいと言われて何を直したか、デザインと実装の間で何を決めたか」。作ったものを見せてもらい、その場で一緒に読む。[エンジニア向けのスカウト文面](/media/kh-bunmen-engineer/)
- **内定前に、レビューを見せる**：実際のレビューの記録と、画面ができるまでの分担の実物を。[内定辞退が続くときの見直し方](/media/ob-naitei-jitai/)
- **代行と組み合わせるなら、絞る作業と文面の下書きまで。読んで直すのはフロントエンドの先輩、技術面接は社内**：[媒体と代行の違い](/media/hikaku-baitai-vs-daikou/)

## 見せ方｜「フロントエンドエンジニア」ではなく、どの画面を誰と作り、誰が見るか

- **フレームワーク名の一覧を、職種名と文面の最初にしない**：一覧は「経験が浅いから違う」と読まれる。名前は一度だけ、後ろで
- **どの画面を誰のために作るかを、職種名に**：「〇〇（サービス）の△△の画面を、□□の人のために作るフロントエンド」
- **絞って採るか、入社後に分けるかを、最初に**：「入社からフロントエンド」か「Webエンジニアとして入り、△か月目にフロントエンドかバックエンドを決める」か。決めたとおりに書く
- **デザインの決め方と分担を、書く**：「デザイナーが〇人。画面の案はデザイナー、実装の判断はエンジニア。間で決めるのは□□」。デザイナーがいないなら、いないと
- **レビューを、時間まで**：「レビューは先輩が〇〇の観点で、出したその日に見る。見る時間は決めてある」。無いなら、無いと。「レビュー文化がある」と書いて無いと体験談に書かれる
- **最初の年を、時期で**：「最初の〇か月は既存の画面の修正。修正で画面の癖と使う人を覚え、△か月目に画面を一つ任せる」。修正が多いなら、意味を書く

## 社内の分担

| 作業 | 誰が |
|---|---|
| 絞って採るか入社後に分けるか、最初の年、デザインの分担、技術の選び直しの決め方を決める | 開発の責任者 |
| レビューする時間を確保する | 開発の責任者。書く前に |
| 行動で絞る条件 | フロントエンドの先輩が作り、人事か代行が絞る |
| 文面と記事 | 先輩が話し、人事が書き、本人が確認 |
| 名義と、オファーの一文 | フロントエンドの先輩 |
| 面談と技術面接 | 責任者と先輩。聞き方の型を揃えて。作ったものを一緒に読む |
| 辞退と「思っていたのと違う」の記録 | 人事。何が違ったかを分けて |

運用代行や代理店が支えられるのは、絞る条件の型、絞る作業、文面の下書き、記録の型までで、絞るか分けるかの決定、レビューの時間の確保、名義、技術面接は社内が担います。代理店の代行の範囲は[代理店に運用まで頼めるか](/media/kh-dairiten-unyou/)で書きました。

### エージェントベストの見解

フロントエンドの採用で、掲載と文面を直した後に起きることを、当社は先にお伝えしています。「最初の年は既存の画面の修正。デザイナーはいない。レビューは週に一度」と正直に書くと、承認とエントリーは減ります。減るのは、新しい画面を自分の設計で作る像を持っていた学生です。その一方で、面談で「思っていたのと違う」が減り、入社後に「修正ばかり」「レビューが無い」と体験談に書かれることが減ります。減ったのを見て一覧に戻すと、承認は戻りますが辞退と離職も戻り、体験談に残ります。当社が案内するのは、承認の数ではなく「技術面接で作ったものを一緒に読めた数」と「内定後の辞退の数」で効果を見ることです。見る場所を決めてから、掲載を直します。

## まとめ

- 学生は自分を「フロントエンド」で分けておらず、フレームワーク名で絞ると届かない。名前はあればよい条件に置き、「画面を作って人に使ってもらった・使いにくいと言われて直した・デザインと実装の間で決めた」の行動で探す
- 新卒をフロントエンドに絞って採るか、Webエンジニアとして採って入社後に分けるかを先に決め、決めたとおりに書く
- 学生が確かめるのは「どの画面を誰のために・デザインは誰が決めるか・バックエンドとの分担・レビュー・最初の年・技術の選び直し」。レビューする時間は書く前に確保する
- 送る型（OfferBox）は行動で絞って先輩の名義で、記事を置く型（Wantedly）は分担とレビューの一日を、比べられる場（ワンキャリア）は技術面接の体験談に対して企業ページに画面とレビューの仕組みを先に
- 掲載を直すと承認は減る。効果は技術面接で作ったものを読めた数と辞退の数で見て、一覧に戻さない

## よくある質問

### デザイナーがいません。書くと学生が来なくなりませんか

「デザインも自分で決める」と隠して入社後に知られるほうが、体験談に書かれます。「デザイナーはいない。画面の案は〇〇が作り、エンジニアが使いやすさを決める。デザインに興味がある人には向く」と実態で書くと、デザイン寄りの学生が来ます。いないことを、向く人の条件に変えます。

### 新卒をフロントエンドに絞って採るべきですか

先輩がいてレビューできるなら絞って採れます。いないなら、Webエンジニアとして採り、入社後に本人の行動を見て分けるほうが「聞いていた話と違う」を防げます。どちらでもよいのですが、決めたとおりに書くことが要ります。

### フロントエンドエンジニアの媒体選びは、御社に相談できますか

できます。当社は、絞る条件の型、絞る作業、文面の下書き、記録の型を支えられます。絞るか分けるかの決定、レビューの時間の確保、名義、技術面接は、社内で担ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、エンジニアの媒体選びと運用を支えています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
