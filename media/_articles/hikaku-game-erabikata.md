大手のパブリッシャー、受託のデベロッパー、運営型（ライブ運営）の会社、中小のスタジオ、ゲーム関連のサービスが、新卒を採る。ゲームは、プランナー、エンジニア、デザイナー、運営、QA（品質管理）で採用の形が違い、パブリッシャーと受託と運営型で仕事の中身が違う。学生の「ゲームが好き」は、この業界を見る学生のほぼ全員が持っていて、絞る条件にならない。大手は知られていて応募が多く、受託と中小のスタジオは知られていない。**結論から言うと、ゲーム業界は「ゲームが好き」を絞る条件から外し、「作った・完成させた・人に遊ばせて直した」の記述とポートフォリオで絞ります。職種と、「作る」仕事か「数字を見て回す」仕事かを一行にし、運営型は作る仕事ではないことを、受託は関わったタイトルを出せる範囲で、隠さず書きます。大手は学生が並べて比べる場で職種ごとの選考情報と実態を、受託と中小は専門学校と情報系・美術系の学生に作った経験で絞って送る型か、開発の一日を記事で読んでもらう型を先に検討します。** この記事では、ゲーム業界の採用構造、判断軸の当て方、学生が確かめること、職種と作る・回すの一行、条件ごとにどれを先に検討するか、組み合わせ、見せ方、分担を整理します。3媒体の全体像は[OfferBox・Wantedly・ワンキャリアの違いと選び方](/media/hikaku-3baitai/)で書きました。数値と料金は書きません。優劣は断定しません。

## ゲーム業界の採用構造と、媒体との相性

| 区分 | 採用の形 | 媒体との相性 |
|---|---|---|
| 大手パブリッシャー | 知られている。応募が多い。職種別に採り、ポートフォリオと課題で選ぶ | 比べられる場で職種ごとの選考情報と実態を。応募の数を成果と見ない |
| 受託のデベロッパー | 学生に知られていない。関わったタイトルが出せないことも。エンジニアとデザイナーが中心 | 出せる範囲でタイトルを一文に。作った経験で絞って送る型 |
| 運営型・ライブ運営 | 「作る」より「数字を見て回す」。運営とプランナー。イベントの運用 | 「作る仕事ではない」を一行に。「数字を見て直した」の記述で絞る |
| 中小のスタジオ | 少人数。一つのタイトルで知られる。代表や現場が採用 | タイトルの一文と開発の一日の記事。作った経験で送る型 |

| 業界の特徴 | 採用で起きること | 媒体との相性 |
|---|---|---|
| 「ゲームが好き」は全員が持っていて、絞る条件にならない | 「好き」で応募が集まり、作った経験がない | 「作った・完成させた・遊ばせて直した」の記述とポートフォリオで |
| 職種で採用の形が違う（プランナー、エンジニア、デザイナー、運営、QA） | 一つの文面で全職種に送り、どの職種にも届かない | 職種ごとに一行と文面を分ける |
| 運営型は「作る」仕事ではない | 「作りたい」で来て、数字とイベントの運用で離れる | 「回す仕事」を最初に |

## 判断軸を、ゲーム業界に当てる

| 軸 | ゲーム業界での見方 |
|---|---|
| 対象（誰に届くか） | 「ゲームが好き」「ゲームを作りたい」の記述は多く、絞る条件にならない。絞るのは「一人か少人数で作って完成させた・人に遊ばせて直した・ゲームジャムや作品展に出した」の記述と、ポートフォリオの有無。専門学校と情報系・美術系の学生が媒体に登録しているかを仕様で確認する |
| 型（送るか、来るか、比べられるか） | 大手は「比べられる」型が使える。受託・中小は「比べられる」型で大手と並ぶと候補に入りにくく、「送る」型で作った経験で絞ってタイトルと開発の実態を先に渡すか、「来る」型で開発の一日を読んでもらう |
| 課金（費用の性格） | 各媒体の公式ページで現在の条件を確認。この記事では書かない |
| 運用工数（誰の時間が要るか） | 開発の若手はマイルストーンの前で動けない。ポートフォリオを見る時間と名義と面談に固定する。送る型は作業を外に出せるが、ポートフォリオの読み込みは現場が支える |

### エージェントベストの見解

相談で最も多い思い込みは、「ゲーム業界は人気で応募が多いから、媒体は要らない」というものです。当社は3媒体すべての販売パートナーとして、ゲームの会社の相談を受けますが、応募が多いのは「ゲームが好き」の学生で、その中で「作って完成させた」経験のある学生は一部です。大手は応募の中から選べますが、受託と中小のスタジオには「好き」の学生も届かず、届いても作った経験がありません。応募の数は「好き」の学生の数で、作った経験のある学生の数ではありません。当社が受託と中小のスタジオに勧めているのは、「ゲームが好きな方へ」ではなく、「一人か少人数で作って完成させた・人に遊ばせて直した」の記述で絞り、最初の一文に「当社が関わったのは〇〇（出せる範囲で）で、あなたの△△（作品）を見て送っている」と置くことです。作った経験で絞ると、承認は減りますが、ポートフォリオを持つ学生が来て、面談で作品の話ができます。

## 学生が、確かめること

- **職種と、作るか回すか**：プランナーか、エンジニアか、デザイナーか、運営か、QAか。「作る」仕事か「数字を見て回す」仕事か
- **関わるタイトル**：受託なら出せる範囲でどのタイトルか。運営型ならどのタイトルの運営か
- **開発の実態**：マイルストーンの前の勤務、リリース前、運営型のイベントの運用の実態
- **最初の年に何をするか**：QAやデバッグから始まるか、いきなり開発か、運営の補助か

## この条件なら、どれを先に検討するか

| 会社の条件 | 先に検討する型 | 理由 |
|---|---|---|
| 大手パブリッシャーで、学生に知られ、職種ごとにクチコミと選考情報が付いている | 学生が並べて比べる場（ワンキャリア）で職種ごとの選考情報と実態を | 比べる対象に入っている。開発の実態と最初の年とクチコミをずらさない |
| 受託・中小で、専門学校と情報系・美術系の学生に「作った」の記述で絞って会いたい | 企業から送る型（OfferBox） | ポートフォリオと「完成させた」の記述で絞れる。タイトルを出せる範囲で先に渡せる。作業を外に出せる |
| 運営型で、「作りたい」ではなく「数字を見て直した」で運営を採りたい | 企業から送る型（OfferBox） | 「回す仕事」を一行にして、「数字を追った・人を動かした」の記述で絞れる |
| 開発の若手が、開発の一日とリリースの日を自分の言葉で書ける | 通年で記事を置く型（Wantedly） | 「好き」で来る学生に、開発の一日とマイルストーンの実態を先に読んでもらえる。[Wantedlyでエンジニアを採る募集記事の書き方](/media/wt-engineer-boshu/) |
| 職種と作る・回すの一行が、まだない | どれも先ではない | 一行を分けてから。「ゲームが好きな方へ」では「好き」だけが集まる |

どれか一つが正解ではなく、大手か受託・中小か、職種、作るか回すかで、先に検討するものが変わります。

## 組み合わせ

- **専門学校と情報系・美術系の学校との関係と、媒体を組み合わせる**：推薦と作品展で会った学生に媒体で送らない。媒体は学校で会えない学生に。[OfferBoxと大学キャリアセンター経由の採用の併用](/media/ob-heiyou-daigaku-kyara/)
- **受託・中小は、送る型と記事を置く型を組み合わせる**：文面で「あなたの〇〇（作品）を見て」を、記事で「開発の一日」と「リリースの日」を。[OfferBoxとWantedlyの併用](/media/ob-heiyou-wantedly/)

## 見せ方｜「ゲームが好き」ではなく、作った経験と、作るか回すか

- **職種と、作るか回すかを、最初の一文で**：「この募集はプランナーで、〇〇を作る仕事です」「この募集は運営で、〇〇の数字を見てイベントを回す仕事です」
- **「ゲームが好き」を求めない一文を**：「好きは前提で、作って完成させた経験を読みたい。ポートフォリオを見て送っている」
- **関わったタイトルを、出せる範囲で**：「当社が関わったのは〇〇（出せる範囲で）」。出せないなら「〇〇のジャンルの△△の部分」
- **開発の実態を、隠さず**：「マイルストーンの前は〇〇、リリース前は△△、運営型はイベントの前に□□」。数値は実態で。この記事では書かない
- **最初の年に何をするかを、正直に**：「最初はQAとデバッグから」「最初から〇〇の担当」

| 作業 | 誰が |
|---|---|
| 職種と作る・回すの一行と、開発の実態・最初の年・タイトルの一枚 | 経営と人事、開発の責任者 |
| 出せるタイトルの範囲の確認（パブリッシャーとの契約） | 経営とプロデューサー |
| 専門学校と情報系・美術系の学校との関係 | 開発の責任者と人事 |
| 大手か受託・中小か、職種で、先に検討する型を決める | 人事と責任者 |
| 「こんな人」（完成させた・遊ばせて直した・数字を見て直した）の整理 | 人事と開発の責任者 |
| 送る型なら、検索・下書き・送信・一次返信 | 人事、または代行（ポートフォリオの読み込みは現場が支える） |
| 記事を置く型なら、開発の若手が一日を話し、整えるのは人事か外に | 若手と人事 |
| ポートフォリオを見る、個別の一文、名義、面談 | 開発の若手とリード |

- **開発の若手に頼むのは、ポートフォリオを見ること・名義・面談の三つ。マイルストーンを避けて**：[OfferBoxの運用に現場社員を巻き込む方法](/media/ob-genba-makikomi/)

運用代行や代理店が支えられるのは、一行の型、一枚の型、文面と記事の型、送る型の作業、記事を整える部分までで、一行の中身、タイトルの開示、開発の実態の開示、ポートフォリオの評価、名義の選定、面談、学校との関係は企業が行います。代理店の代行の範囲は[代理店に運用まで頼めるか](/media/kh-dairiten-unyou/)で書きました。

### エージェントベストの見解

送り始めたあと、最初の年で起きることに共通するのは、「好きを仕事に」「〇〇（人気タイトル）の会社」で承認や応募が付き、面談か入社後に、運営型なら「作る仕事ではない」こと、最初の年がQAとデバッグであることを知って離れることです。当社はOfferBoxの運用代行を受けているので、ゲームの会社の承認から面談までを見ていますが、職種と作る・回すと最初の年の仕事を文面に書かず、人気タイトルの名前で書いている会社が多く、その言葉で来た学生は、自分が何をするかを面談で初めて知ります。当社がゲームの会社に勧めているのは、最初の一文に「この募集は〇〇（職種）で、△△を作る（回す）仕事。最初の年は□□」と置き、「あなたの作品の〇〇を見て」を現場の名義で足すことです。書いて来た学生は、作るか回すかと最初の年を知ったうえで来ていて、最初のマイルストーンで辞めません。

## まとめ

- ゲーム業界は、「ゲームが好き」を学生のほぼ全員が持っていて、絞る条件にならない。応募の数は「好き」の数で、作った経験のある学生の数ではない。「作った・完成させた・人に遊ばせて直した」の記述とポートフォリオで絞る
- プランナー・エンジニア・デザイナー・運営・QAで採用の形が違い、パブリッシャー・受託・運営型で仕事が違う。職種と「作る」か「数字を見て回す」かを一行にし、運営型は作る仕事ではないことを、受託はタイトルを出せる範囲で、最初の年を隠さず
- 大手は並べて比べる場で職種ごとの選考情報と実態を。受託・中小は専門学校と情報系・美術系の学生に作った経験で絞って送る型か、開発の一日とリリースの日を記事で読んでもらう型を先に
- 専門学校と学校の推薦・作品展・ゲームジャムを主にし、媒体は学校で会えない学生に。ポートフォリオを見る時間が運用工数の中心
- 開発の若手に頼むのはポートフォリオを見ること・名義・面談で、マイルストーンを避けて固定

## よくある質問

### 「ゲームが好き」で絞ってはいけませんか

絞る条件にはなりません。この業界を見る学生のほぼ全員が「好き」で、「好き」で絞ると応募は集まりますが、作った経験のない学生が多くを占めます。「一人か少人数で作って完成させた・人に遊ばせて直した・作品展に出した」の記述とポートフォリオの有無で絞り、「好きは前提で、作った経験を読みたい」と文面に書くと、作品を持つ学生に届き、面談で作品の話ができます。

### 受託で、関わったタイトルを出せません

出せる範囲で書きます。パブリッシャーとの契約で名前を出せないなら、「〇〇のジャンルの△△の部分」「□□の規模のタイトルの開発」のように、ジャンルと担当した部分と規模で書けば、学生には十分に見えます。出せる範囲はプロデューサーが契約で線を引き、その範囲で一文を作ります。「ゲームの受託開発」の一語に戻すと、開かれません。

### ゲーム業界の媒体選びは、御社に相談できますか

できます。当社は、一行の型、一枚の型、文面と記事の型、送る型の作業、記事を整える部分を支えられます。一行の中身、タイトルの開示、開発の実態の開示、ポートフォリオの評価、名義の選定、面談、学校との関係は、企業が行ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、3媒体を並べてご案内しています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
