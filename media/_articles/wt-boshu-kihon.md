Wantedlyの募集記事を、求人票と同じ感覚で書く会社は多いものです。職種名、仕事内容、応募資格、待遇。これを埋めて公開する。ところが、Wantedlyの候補者は、募集記事を「応募するか」ではなく「話を聞きに行きたいか」で読みます。**結論から言うと、募集記事の基本構成は、会社ページの「なにを・なぜ・どうやって」をこの募集の職種に絞って書き、そこに「この募集で何をやるか」「誰と」「求める動き方」「条件」を足し、「まず話を聞きに来てほしい」で締める形です。求人票の項目を埋めるのではなく、会社の「なぜ」とこの募集をつなげます。** この記事では、募集記事の位置づけ、基本構成、会社ページとの分担、書く順番、やりがちな失敗、分担を整理します。会社ページの書き方は[会社ページで最初に書くこと](/media/wt-kaisha-page-kihon/)で書きました。募集記事の項目の仕様には触れず、書き方の考え方だけを書きます。

## この作業の目的｜「応募」ではなく「話を聞きに行きたい」を作る

求人票は、条件を見て応募するためのものです。Wantedlyの募集記事は、読んで「この会社の、この仕事の話を聞いてみたい」と思ってもらうためのものです。入口が違うので、書くことが違います。

求人票では、条件の正確さと網羅性が要ります。募集記事では、「なぜこの仕事があるのか」「この仕事で何をするのか」「誰とやるのか」が、候補者の言葉で分かることが要ります。条件は隠しませんが、中心ではありません。

募集記事の目的は、候補者が「まず話を聞きに行こう」と動くことです。応募の決断は、話を聞いたあとで足ります。この動き方は[OfferBoxとWantedlyの違い](/media/hikaku-offerbox-wantedly/)で書きました。

## 手順1｜基本構成

募集記事を、次の順で組みます。

| 部分 | 書くこと | 会社ページとの違い |
|---|---|---|
| タイトル | 職種名ではなく、「何をする人を探しているか」が一言で分かる。[募集タイトルの付け方](/media/wt-boshu-title/) | ― |
| 冒頭 | この募集が生まれた理由を一言。「〇〇を始めるので、△△をやる人を探している」 | 会社の「なぜ」ではなく、この募集の「なぜ」 |
| なにをやっているのか | 会社の事業を、この職種に関係する範囲で | 会社ページは全体、募集記事は職種の範囲 |
| なぜやるのか | 会社の「なぜ」と、この募集がどうつながるか | 会社ページの「なぜ」を繰り返さず、つなぐ |
| どうやっているのか | この職種のチームの様子、仕事の進め方、1日の流れ | 会社ページは会社全体、募集記事はこの職種のチーム |
| この募集で何をやるか | 入った人が最初にやること、数ヶ月後にやること、関わるプロジェクト | 募集記事だけにある部分 |
| 誰と | 一緒に働く人。名前と、その人が何をしている人か | メンバーの紹介につなげる |
| 求める動き方 | 経験や資格ではなく、行動の型。「こういう場面で、こう動ける人」 | バリューの実例につなげる |
| 条件 | 勤務地、働き方、契約の形。隠さず、正確に | 求人票と同じ正確さで、ただし中心ではない |
| 締め | 「まず話を聞きに来てほしい」。応募ではなく、話を聞くことへの誘い | ― |

「この募集で何をやるか」が、募集記事の中心です。会社ページに無い、この募集だけの情報です。ここが薄いと、募集記事は会社ページの繰り返しになります。

## 手順2｜会社ページと重複させず、入口を分ける

募集記事と会社ページは、読まれる順番が決まっていません。募集記事から会社ページへ行く候補者も、会社ページから募集記事へ行く候補者もいます。どちらから読んでも成立し、かつ同じ文章が2回出てこない形にします。

1. **会社の「なぜ」は、会社ページに任せる**：募集記事では「詳しくは会社ページで」と一言添え、この募集との関係だけを書く
2. **職種のチームの様子は、募集記事に書く**：会社ページの「どうやっているのか」は会社全体、募集記事はこのチーム
3. **メンバーの紹介は、会社ページに任せる**：募集記事では「誰と」の名前を出し、会社ページの紹介につなげる。選び方は[会社ページに載せるメンバーの選び方](/media/wt-kaisha-page-member/)
4. **バリューの実例は、募集記事の「求める動き方」につなげる**：バリューの言葉ではなく、この職種でその動き方がどう要るか。書き方は[会社ページでバリューを言葉にする方法](/media/wt-kaisha-page-value/)
5. **ストーリーは、募集記事から参照する**：この職種の人が書いたストーリーがあれば、「この仕事の日常はこちら」と示す

会社ページを書く前に募集記事を書くと、募集記事に会社の説明が全部入り、長くなります。会社ページが先、募集記事はそれを前提に、が順番です。

### エージェントベストの見解

相談で最も多い思い込みは、「募集記事は求人票と同じで、条件を正確に書けばよい」というものです。実際には、Wantedlyの候補者は募集記事を「応募するか」ではなく「話を聞きに行きたいか」で読み、条件より「この募集で何をやるか」「誰とやるか」を見ています。当社は3媒体すべての販売パートナーとしてWantedlyの契約後の運用を見ていますが、求人票をそのまま貼った募集記事には、話を聞きに来る候補者がほとんど来ません。条件は正確でも、「なぜこの募集があるのか」「入ったら何をするのか」が無いからです。逆に、条件の記載は最小限でも、「この募集で何をやるか」が具体的な募集記事には、候補者が来ます。求人票の項目を埋めることと、募集記事を書くことは、別の作業です。求人票がある会社ほど、それを貼りたくなりますが、貼る前に「この募集で何をやるか」を書けているかを見ることを勧めます。

## 手順3｜「この募集で何をやるか」を具体的に書く

募集記事の中心を、場面で書きます。

- **最初にやること**：入社して最初の数ヶ月で、何をするか。研修か、いきなり現場か、誰と組むか
- **その後にやること**：数ヶ月後、1年後に、何を任されるか。分かる範囲で
- **関わるプロジェクトや顧客**：具体的な名前が出せなければ、種類と規模感で
- **この募集が生まれた理由**：事業が広がった、人が異動した、新しいことを始める。理由があると、候補者は自分の役割を想像できる
- **難しさ**：この仕事で大変なこと。隠さない。「〇〇が難しい」と書いてある募集記事は、候補者に信じられる

「最初にやること」が、最も読まれる部分です。候補者は「入ったら自分は何をするのか」を知りたいからです。「幅広い業務」「ゆくゆくは」では、想像できません。

## 手順4｜求める動き方と、条件

「求める人」を、経験や資格の羅列ではなく、行動の型で書きます。考え方は、OfferBoxの[募集要項の書き方](/media/ob-boshu-youkou/)で書いた「求める人物は行動の型で」と同じです。

| 書き方（避ける） | 書き方（型） |
|---|---|
| 「主体性のある方」 | 「分からないことを自分で調べて、それでも分からなければ人に聞ける」 |
| 「〇〇の経験3年以上」 | 経験が要るなら書く。ただし「その経験で、こういう場面をどう動いたか」を面談で聞くと添える |
| 「コミュニケーション力」 | 「顧客の言葉を、自分の解釈で言い換えずに社内に伝えられる」 |
| 「成長意欲」 | 「うまくいかなかったとき、何を変えたかを語れる」 |

条件（勤務地、働き方、契約の形、給与の扱い）は、隠さず正確に書きます。共感で来た候補者が、面談のあとで条件を知って辞退するのは、双方にとって残念です。共感型でも条件は書く、という考え方は[共感型と条件型の媒体の違い](/media/hikaku-kyoukan-vs-jouken/)で書きました。ただし、条件は募集記事の中心ではなく、最後に置きます。

## 手順5｜書く順番

募集記事は、上から順に書きません。次の順で書くと、中心が薄くなりません。

1. **「この募集で何をやるか」を先に書く**：最初にやること、その後、理由、難しさ。ここに最も時間を使う
2. **「誰と」を書く**：一緒に働く人の名前と、何をしている人か
3. **「求める動き方」を書く**：この仕事で要る行動の型を、活躍している人から
4. **「なにを・なぜ・どうやって」を、職種に絞って書く**：会社ページを前提に、この職種の範囲で。会社の「なぜ」は会社ページへ
5. **条件を書く**：正確に
6. **冒頭を書く**：この募集が生まれた理由を一言に
7. **締めを書く**：「まず話を聞きに来てほしい」
8. **タイトルを最後に**：冒頭と「何をやるか」を一言に縮める。付け方は[募集タイトルの付け方](/media/wt-boshu-title/)

「この募集で何をやるか」を先に書くのは、OfferBoxの文面で「本文の共通部分を先に、冒頭を後に」と書いたのと同じ理由です。中心を先に固めると、周りが短くなります。

## やりがちな失敗

| 失敗 | 何が起きるか | 直し方 |
|---|---|---|
| 求人票をそのまま貼る | 「話を聞きに行きたい」にならない | 「この募集で何をやるか」を書く |
| 会社ページと同じ文章を繰り返す | 長くなり、この募集の情報が薄い | 会社の「なぜ」は会社ページへ。募集記事は職種の範囲 |
| 「幅広い業務」「ゆくゆくは」 | 最初にやることが想像できない | 最初の数ヶ月を具体的に |
| 求める人が経験と資格の羅列 | 自分が合うか判断できない | 行動の型で |
| 条件を隠す | 面談のあとで辞退 | 隠さず、最後に |
| 条件を中心にする | 求人票になる | 中心は「何をやるか」 |
| 難しさを書かない | 建前に読まれる | 大変なことを1つ |
| 上から順に書く | 中心が薄くなる | 「何をやるか」から書く |
| 締めが「ご応募ください」 | 応募の決断を求めて重い | 「まず話を聞きに来てほしい」 |

最も多いのは、最初の「求人票をそのまま貼る」です。求人票がある会社ほど、こうなります。

## 社内の分担

| 作業 | 誰が |
|---|---|
| 「この募集で何をやるか」の材料 | 配属先の責任者（人事が聞いて書く） |
| 「誰と」の名前と紹介 | 配属先のチーム（本人の同意） |
| 「求める動き方」 | 人事（活躍している人の行動から。責任者に確認） |
| 「なにを・なぜ・どうやって」の職種版 | 人事（会社ページを前提に） |
| 条件 | 人事（正確に確認） |
| 冒頭・締め・タイトル | 人事 |
| 責任者が直す | 配属先の責任者 |
| 募集の開始と終了で更新する | 人事 |

配属先の責任者の時間は、「何をやるか」を話すことと、書いたものを直すことの2つです。書くのは人事です。運用代行や代理店が支えられるのは、構成の型、聞く質問、下書きの整理までで、「何をやるか」の実態は配属先にしか出せません。代理店の代行の範囲は[代理店に運用まで頼めるか](/media/kh-dairiten-unyou/)で書きました。

### エージェントベストの見解

これをやる前に、先に決めておかないと募集記事が書けないことがあります。「この募集で、入った人が最初の数ヶ月に何をするか」を、配属先の責任者が言えることです。当社がWantedlyの運用の相談で募集記事を見るとき、会社の説明と求める人の条件は書けているのに、「入ったら何をするか」が「幅広い業務」で終わっている記事が多くあります。配属先に聞くと、決まっていないか、人事に伝わっていないかのどちらかです。決まっていないなら、募集記事を書く前に決めます。伝わっていないなら、人事が配属先に「最初の3ヶ月、この人は何をしますか」と聞きます。この1つの質問の答えが、募集記事の中心になります。答えが無い募集記事は、どれだけ会社の説明が良くても、候補者に「自分の役割」が見えず、話を聞きに来ません。

## まとめ

- 募集記事は求人票ではなく、「話を聞きに行きたい」を作るもの。条件は隠さないが中心ではない
- 構成は、冒頭（この募集のなぜ）→なにを・なぜ・どうやって（職種の範囲）→この募集で何をやるか→誰と→求める動き方→条件→まず話を聞きに来てほしい
- 会社の「なぜ」とメンバーの紹介は会社ページに任せ、募集記事は職種のチームと「何をやるか」に絞る
- 「この募集で何をやるか」から書き始め、タイトルは最後に。最初の数ヶ月を具体的に、難しさも
- 求める人は経験の羅列ではなく行動の型で。締めは「応募」ではなく「話を聞きに」

## よくある質問

### 求人票があるので、それを載せてはだめですか

条件の部分は求人票の正確さで書いて構いませんが、そのまま貼ると「話を聞きに行きたい」にはなりません。「この募集で何をやるか」「誰と」「なぜこの募集があるか」を足し、条件は最後に置きます。求人票は材料であって、募集記事そのものではありません。

### 会社ページと募集記事で、同じことを書いてしまいます

会社の「なぜ」とメンバーの紹介は会社ページに任せ、募集記事では「詳しくは会社ページで」と添えて、この募集との関係だけを書きます。募集記事に書くのは、この職種のチームの様子と、「この募集で何をやるか」です。会社ページを先に書き、募集記事はそれを前提に書くと、重複が減ります。

### 募集記事の作成は、御社に相談できますか

構成の型、配属先に聞く質問、下書きの整理は当社が支えられます。「この募集で何をやるか」の実態と、条件の確認は、企業が行ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、Wantedlyの募集記事の整備を支えています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
