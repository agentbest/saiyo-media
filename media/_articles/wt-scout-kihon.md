Wantedlyには、募集記事を出して候補者が来るのを待つ使い方と、会社から候補者に直接スカウトを送る使い方があります。スカウトを送れば候補者が来る、と考えて始めると、返信が来ずに止まります。**結論から言うと、Wantedlyのスカウトは「応募してください」の依頼ではなく、「あなたのプロフィールのここを読んで、この募集の話をしたい」という誘いです。送る前に会社ページと募集記事が整っていること、誰に送るかを募集記事の「こんな人」から決めること、何を送るかを「相手のどこを読んだか・なぜこの募集か・話す場」の3つで組むこと、が基本です。** この記事では、Wantedlyのスカウトの位置づけ、送る前に整えるもの、誰に送るか、何を送るか、やりがちな失敗、返信が来たあと、送る人と件数の考え方、分担を整理します。スカウトの送信の仕組みや上限はプランで異なり変わることがあるので、現在の仕様は管理画面とヘルプで確認してください。この記事は、運用の考え方の話です。

## この作業の目的｜「話を聞きに来てほしい」を、相手ごとに送る

Wantedlyの候補者は、募集記事を読んで「話を聞きに行く」を押します。スカウトは、その動きを会社の側から起こすものです。「うちの募集を見て、話を聞きに来ませんか」を、相手ごとに送ります。

このとき、相手が見るのは、スカウトの文面と、そこからたどる会社ページと募集記事です。文面が良くても、会社ページが空なら、相手は動きません。スカウトの目的は、「文面を読んで会社ページと募集記事を見に行き、話を聞きに行くを押す」までを起こすことです。

スカウトと掲載の使い分けは[掲載型とスカウト型の違い](/media/hikaku-keisai-vs-scout/)で書きました。

## 送る前に整えるもの

スカウトを送る前に、次の3つが整っているかを見ます。

1. **会社ページ**：なにを・なぜ・どうやって、が書かれている。スカウトを受け取った人は、まず会社ページを見る。書き方は[会社ページの基本](/media/wt-kaisha-page-kihon/)
2. **募集記事**：スカウトで誘う先の募集記事が、「なにを・なぜ・どうやって・こんな人」で書かれている。書き方は[募集記事の基本](/media/wt-boshu-kihon/)
3. **ストーリー**：最低でも数本。一緒に働く人の話が読める。書き方は[ストーリーの基本](/media/wt-story-kihon/)

整っていない状態で送ると、文面で興味を持った人が会社ページで離れます。スカウトは、コンテンツが整ってから始めます。

## 誰に送るか｜募集記事の「こんな人」から決める

送る相手は、募集記事の「こんな人」に書いたことから決めます。

- **募集記事の「こんな人」を、検索の条件に置き換える**：経験、職種、いまの状態（転職を考えているか）、興味のある分野
- **プロフィールを読んで、「こんな人」に合うかを見る**：条件で絞ったあと、1人ずつプロフィールを読む。読まずに送ると、文面が相手に合わない
- **「この人に、この募集の話をしたい」と言える人だけに送る**：言えない人には送らない
- **絞り込みの詳しい考え方**：[スカウト対象の絞り方](/media/wt-scout-target/)

「1人ずつプロフィールを読む」が、送る前の作業の中心です。読まなければ、次の「何を送るか」が書けません。

### エージェントベストの見解

これは順番の話です。当社は3媒体すべての販売パートナーとしてWantedlyの契約後の運用を見ていますが、「スカウトの返信が来ない」という相談で、文面より先に確かめるのは会社ページと募集記事です。文面を整えても、スカウトを受け取った人がたどり着く会社ページが空で、募集記事が条件だけなら、返信は来ません。逆に、会社ページとストーリーが整っている会社は、文面が短くても、相手が会社ページを読んで返信します。当社が勧める順番は、会社ページ、募集記事、ストーリー数本、その次にスカウトです。スカウトを先に始める会社は、返信が来ない理由を文面に求め、文面を何度も直しますが、直すべきは文面の先にあるものです。スカウトは、コンテンツが整ってから開ける入口です。

## 何を送るか｜3つの要素

文面は、次の3つで組みます。

| 要素 | 書き方 |
|---|---|
| 相手のプロフィールのどこを読んだか | 「〇〇の経験を読みました」「△△に興味があると書かれていたので」。相手にしか書けない一文を、最初に |
| なぜこの募集の話をしたいか | 相手のどこと、募集のどこが重なるか。「この募集の□□は、あなたの〇〇の経験がそのまま活きます」 |
| 話す場の案内 | 「まずは話を聞きに来てもらえませんか。オンラインで、〇〇（職種）の△△が仕事の話をします」。応募ではなく、話す場へ |

3つを、短く書きます。長い文面は読まれません。会社の説明は書かず、会社ページに任せます。募集記事の内容も、要点だけで、詳しくは募集記事に任せます。

「相手にしか書けない一文」が最初にあるかどうかで、読まれるかが決まります。誰にでも送れる文面は、誰にも読まれません。この考え方は、OfferBoxのオファー文面と同じで、詳しくは[OfferBoxのオファー文面の基本](/media/ob-offer-bunmen-kihon/)で書きました。

## やりがちな失敗

| 失敗 | 相手からどう見えるか |
|---|---|
| テンプレを一斉に送る | 「誰にでも送っている」と分かる。読まれない |
| 条件だけを書く | 求人票。Wantedlyで受け取る文面ではない |
| 会社の説明が長い | 会社ページに書いてあることを読まされる |
| 「ぜひ応募してください」 | 応募の依頼。話す段階を飛ばしている |
| 相手のプロフィールを読んでいない | 経験と合わない募集を送られる |
| 会社ページが整っていないのに送る | 文面で興味を持っても、会社ページで離れる |
| 送りっぱなしで、返信への対応が遅い | 返信した人が待たされて離れる |
| 煽り（「限定」「特別に」） | 信用されない |

最も多いのは、最初の「テンプレの一斉送信」です。送る数を増やせば返信も増える、と考えた結果です。返信は、数ではなく、相手ごとの一文で決まります。文面の具体は[スカウト文面の書き方](/media/wt-scout-bunmen/)で書きましたが、この記事の3つの要素が土台です。

## 返信が来たあと

返信は、「話を聞きに行きたい」の意思表示です。応募ではありません。

1. **早く返す**：返信から時間が空くと、相手は他の会社に動く
2. **話す場を、すぐ提案する**：日程の候補を出す。オンラインで短く
3. **話す人は、募集記事に出ている人か、その職種の人**：人事だけの面談は、スカウトの文面と違う
4. **面談では、募集記事に書いたことを話す**：文面と記事と面談が揃っていることが、信用になる
5. **面談後の動きを、その場で伝える**：次に何があるか

「早く返す」が、返信のあとの最も大きな差です。スカウトを送る人と、返信に対応する人が違う場合、返信の通知が対応する人に届く形にしておきます。

## 送る人と件数の考え方

- **送る数は、プロフィールを読める数で決める**：読まずに送る数を増やさない。読める数が、送れる数
- **送るのは、募集記事に出ている人か、人事**：その職種の人が送ると、文面に仕事の具体が入る。人事が送るなら、その職種の人に文面を見てもらう
- **返信に対応できる数に収める**：返信が来たのに対応できないなら、送る数が多すぎる
- **週に決まった時間を取る**：まとめて読み、まとめて送る。日々少しずつより、続く
- **送信の上限や仕組みは、プランと時期で異なる**：管理画面で確認する

「読める数が送れる数」が原則です。送る数を目標にすると、読まずに送ることになり、返信が減ります。

## 社内の分担

| 作業 | 誰が |
|---|---|
| 会社ページ・募集記事・ストーリーを整える | 人事 |
| 「こんな人」を検索の条件に置き換える | 人事と、その職種の責任者 |
| プロフィールを読む | 人事か、その職種の人 |
| 文面を書く（相手ごとの一文） | 読んだ人 |
| 送る | 人事か、その職種の人 |
| 返信に早く対応する | 決めた1人（通知が届く形に） |
| 面談で話す | 募集記事に出ている人か、その職種の人 |

運用代行や代理店が支えられるのは、送る前のコンテンツの確認、絞り込みの条件の設計、文面の型、返信対応の流れの設計までで、プロフィールを読むこと、相手ごとの一文、返信への対応、面談は企業が行います。代理店の代行の範囲は[代理店に運用まで頼めるか](/media/kh-dairiten-unyou/)で書きました。

### エージェントベストの見解

発注する側の会社が誤解しやすいのは、「スカウトの送信を代理店に頼めば、話を聞きに来る人が増える」という点です。当社がWantedlyのスカウトの支援をするとき、当社が出せるのは絞り込みの条件と文面の型までで、「相手のプロフィールのどこを読んだか」の一文は、その仕事を知っている社内の人が書いたほうが、相手に届きます。当社が代わりに書くと、文面は整いますが、面談でその職種の人が話す内容とずれます。当社が最初にお伝えするのは、「送る数ではなく、読んで書ける数で運用する」ことと、「一文は社内の人が書く」ことです。当社は、読む時間を減らす絞り込みと、書く時間を減らす型を用意します。読むことと書くことは、社内に残します。

## まとめ

- Wantedlyのスカウトは「応募の依頼」ではなく「あなたのここを読んで、この募集の話をしたい」の誘い
- 送る前に、会社ページ・募集記事・ストーリー数本を整える。文面の先で離れないように
- 誰に送るかは、募集記事の「こんな人」から決め、1人ずつプロフィールを読む
- 何を送るかは、相手のどこを読んだか・なぜこの募集か・話す場の案内、の3つを短く
- テンプレの一斉送信、条件だけ、会社の説明が長い、応募の依頼、が返信が来ない文面。返信には早く対応し、読める数が送れる数

## よくある質問

### スカウトを送っても、返信が来ません

文面より先に、会社ページと募集記事を見ます。スカウトを受け取った人は会社ページを見に行くので、そこが空だと返信しません。会社ページが整っているなら、文面に「相手のプロフィールのどこを読んだか」の一文があるかを見ます。無ければ、テンプレと読まれています。

### 送る数を増やせば、返信も増えますか

読まずに送る数を増やしても、返信は増えません。返信は、相手ごとの一文で決まります。プロフィールを読める数が、送れる数です。返信に対応できる数も上限になります。

### Wantedlyのスカウトの運用は、御社に相談できますか

できます。当社は、送る前のコンテンツの確認、絞り込みの条件の設計、文面の型、返信対応の流れの設計を支えられます。プロフィールを読むこと、相手ごとの一文、返信への対応、面談は、企業が行ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、Wantedlyのスカウト運用を支えています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
