ストーリーの写真は、会社ページや募集記事の写真と、役割が少し違います。会社ページの写真は「会社の空気」、募集記事のカバー写真は「この職種の仕事の空気」を一覧で伝えるもので、ストーリーの写真は「記事に書いた場面」を見せるものです。**結論から言うと、ストーリーの写真は、記事を書いてから、書いた場面に対応するものを撮ります。自然光で、普段のままを、たくさん撮って選び、記事内の枚数は少なくし、キャプションで場面を補います。写真が無くても記事は出し、あとから足せます。** この記事では、ストーリーの写真の役割、撮る順番、撮り方、枚数とキャプション、写真が無いときの判断、同意、型ごとの注意、誰が撮るか、やりがちな失敗、分担を整理します。写真の基本は[会社ページの写真の選び方](/media/wt-kaisha-page-photo/)と[募集記事のカバー写真の選び方](/media/wt-boshu-shashin/)で書きました。この記事は、ストーリーに絞った話です。

## この作業の目的｜書いた場面を、読む人に見せる

ストーリーは、1本に1つの場面を書きます。写真の目的は、その場面を読む人に見せることです。「先月の会議で意見が割れた」と書いた記事なら、その会議の場面。「〇〇さんが初めて1人で提案に行った日」なら、〇〇さんが仕事をしている場面。

記事と関係の無い写真（集合写真、オフィスの外観、イベントの乾杯）は、場面を見せません。装飾のための写真は、無いほうが記事の場面が伝わります。

## 手順1｜記事を書いてから、写真を撮る

写真を先に撮ると、記事に合わない写真を無理に使うことになります。順番は、記事が先です。

1. **記事を書く**：場面が決まる
2. **書いた場面に、どの写真が要るかを決める**：会議の場面なら会議、仕事の場面なら仕事中。1本につき1つか2つ
3. **その場面を撮る**：同じ場面が再現できるとき（次の会議、次の仕事中）に、普段のままを撮る
4. **撮れないなら、近い場面で代える**：過去の会議は撮れないが、同じ部屋で同じ人が話している場面なら近い
5. **記事に入れて、キャプションを付ける**：写真だけでは場面が分からないので、一言添える

「同じ場面を再現できるときに撮る」が要点です。記事に書いた出来事そのものは、過去なので撮れません。同じ人が同じ場所で同じ仕事をしている場面なら、記事の場面として読まれます。

## 手順2｜撮り方

撮り方の基本は、会社ページの写真と同じです。ストーリーで特に守ることを並べます。

| 守ること | 理由 |
|---|---|
| 自然光のある時間に撮る | 暗い写真は場面の空気を暗くする |
| 普段のままを撮る。片づけない、着替えない | 記事の場面と写真の場面が違うと、記事も疑われる |
| カメラを意識させない。少し離れて、たくさん撮る | 自然な表情は、たくさんの中にしか無い |
| 加工しない | 明るさの調整程度。作った写真に見せない |
| 人が写っている写真を選ぶ | 場面は、人がいて初めて場面になる。物や場所だけの写真は装飾になる |
| 顔が見える写真を優先し、本人が望まなければ手元や横顔 | 人が見えるほど場面が伝わる。ただし本人の意向が先 |
| 横向きを基本に | ストーリーの中で収まりがよい。縦横の比率は管理画面で確認する |

プロに頼む必要はありません。社内の誰かが、昼間に、普段の仕事中を数十枚撮れば、選べる写真は出ます。プロに頼むなら、「撮影用に整えない。普段の仕事を撮ってほしい」と伝えます。

### エージェントベストの見解

これをやる前に、先に決めておかないと写真が記事に合わないことがあります。「記事を書いてから写真を撮る」順番です。当社がWantedlyの運用の相談でストーリーを見るとき、写真が先に撮られていて、記事がその写真に合わせて書かれている会社があります。イベントで撮った写真があるからイベントの記事を書く、集合写真があるから会社紹介の記事を書く。この順番だと、記事の題材が「写真があるもの」に偏り、候補者に届く「1つの場面」の記事が減ります。当社は3媒体すべての販売パートナーとしてWantedlyの契約後の運用を見ていますが、ストーリーが読まれている会社は、記事を先に書き、写真は場面に合わせてあとから撮っています。写真が無ければ無いまま出し、翌週に撮って足す。写真が記事を決めるのではなく、記事が写真を決める。この順番を守ると、写真のために記事の題材が歪みません。

## 手順3｜枚数とキャプション

ストーリーの写真は、少ない枚数で足ります。

- **1本につき、1枚から数枚**：場面が1つなら、写真も1つか2つ。多いと、記事が写真の説明になる
- **記事の最初に1枚**：場面を最初に見せる。一覧のサムネイルにもなることが多いので、場面が一目で分かるものを
- **記事の途中に、場面が変わるところで1枚**：「そのあと、〇〇の場面で」と話が移るところに
- **最後に、写真は要らない**：締めは文で
- **キャプションを付ける**：「〇月の定例会議。この日、△△の意見で□□が変わった」。写真だけでは伝わらない場面を一言で。ただし長くしない
- **写真の並びは、記事の時系列に合わせる**：先の場面の写真を、あとに置かない

「写真は少なく、キャプションで補う」が、ストーリーの写真の基本です。写真を並べて記事を長く見せるより、1枚と一言のほうが場面が伝わります。

## 手順4｜写真が無いときの判断

写真が無いから記事を出せない、という状態を作りません。

1. **写真が無くても、記事は出す**：ストーリーの中心は文。写真は補い
2. **翌週に、場面を再現できるときに撮って足す**：記事は公開後に写真を足せる
3. **どうしても撮れない場面は、近い場面か、手元・場の写真で**：会議の場面なら、その会議室の様子。仕事の場面なら、使っている道具の手元
4. **フリー素材で埋めない**：候補者は一目で分かり、記事も疑われる
5. **写真が無い記事が続くなら、撮る人を決める**：手順6で

写真が揃うまで公開を待つと、ストーリーの頻度が落ち、途切れます。頻度を守る考え方は[ストーリーの更新頻度の決め方](/media/wt-story-hindo/)で書きました。写真より、途切れないことが先です。

## 手順5｜同意と、型ごとの注意

写っている人の同意は、会社ページと同じで、写真を見せてから取ります。ストーリーでは、型ごとに注意が加わります。

| 型 | 写真の注意 |
|---|---|
| 社員インタビュー | 話している場面より、その人が仕事をしている場面。インタビュー中の写真は「取材」に見える。手順は[社員インタビューを書く手順](/media/wt-story-interview/) |
| 入社エントリー | 入社式や記念写真ではなく、いまの仕事の場面。本人が「入る前と後」を語る記事に、いまの姿を |
| 代表の考え | 代表が話している場面か、判断した現場の場面。演台や講演の写真は「偉い人の話」に見える |
| 事業の裏側 | 顧客、取引先、機密が写らないように。画面、資料、ホワイトボードの文字に注意。書き方は[事業の裏側を書く方法](/media/wt-story-jigyo/) |
| カルチャー | 記事に書いた場面（会議、決める場面、新しい人の最初の週）。集合写真ではなく |
| 社内イベント | 準備や裏方の場面。酒、私的な場面、家族が写る場面は載せない。全員の同意。注意は[社内イベントを書くときの注意](/media/wt-story-event/) |

「事業の裏側」の写真は、写り込みに注意します。画面に顧客名、机の上に取引先の資料、ホワイトボードに数字。撮る前に片づけるのではなく、撮ったあとに写り込みを確認し、あれば使いません。

## 手順6｜誰が撮るか

写真を撮る人を、決めておきます。決まっていないと、「撮る人がいない」で写真が無い記事が続きます。

- **記事を書く人（人事）が撮る**：記事の場面を最も分かっている。書いた場面を撮りに行く
- **1行を拾う人が撮る**：拾った出来事の場面を、そのときに撮っておく。「今週あったこと」の1行に写真を添える。集める仕組みは[会社ページを更新し続ける仕組み](/media/wt-kaisha-page-koushin/)
- **各チームに撮る人を1人置く**：仕事中の場面を、月に数枚撮ってもらう。溜めておけば、記事を書いたときに選べる
- **プロに頼むなら、年に一度、普段の仕事中をまとめて**：会社ページと募集記事とストーリーで共通で使える場面を、一度に

「拾う人が撮る」が、最も自然です。出来事があったときに、1行と1枚をセットで残しておくと、記事を書くときに写真が揃っています。

## やりがちな失敗

| 失敗 | 何が起きるか | 直し方 |
|---|---|---|
| 写真を先に撮って、記事を合わせる | 題材が写真に偏る | 記事を書いてから撮る |
| 記事と関係の無い写真を載せる | 場面が伝わらない | 書いた場面の写真だけ |
| 枚数が多い | 記事が写真の説明になる | 1本に1枚から数枚 |
| キャプションが無い | 写真の場面が分からない | 一言添える |
| 写真が揃うまで公開しない | 頻度が落ち、途切れる | 無いまま出し、あとで足す |
| フリー素材 | 記事が疑われる | 無いほうがまし |
| インタビュー中の写真 | 取材に見える | 仕事中の場面 |
| 事業の裏側で顧客や機密が写り込む | 問題になる | 撮ったあとに写り込みを確認 |
| イベントの酒の場面 | 「飲み会の会社」 | 準備や裏方の場面 |
| 撮る人が決まっていない | 写真が無い記事が続く | 拾う人が撮る |

最も多いのは、最初の「写真を先に撮って記事を合わせる」です。手元にある写真から記事を考えると、こうなります。

## 社内の分担

| 作業 | 誰が |
|---|---|
| 記事の場面に要る写真を決める | 記事を書く人（人事） |
| 撮る | 拾う人、各チームの撮る人、または人事 |
| 選ぶ | 人事（記事の場面に合うかで） |
| 写っている人の同意 | 人事が本人に写真を見せて |
| 写り込み（顧客・機密）の確認 | 人事と、事業の裏側なら責任者 |
| キャプション | 人事 |
| プロに頼む場合の手配 | 人事（「普段を撮る」と伝えて） |

運用代行や代理店が支えられるのは、記事の場面に要る写真の整理、選ぶ軸、キャプションの案、型ごとの注意の確認までで、撮ることと同意は企業が行います。代理店の代行の範囲は[代理店に運用まで頼めるか](/media/kh-dairiten-unyou/)で書きました。

### エージェントベストの見解

自社で持つべきなのは、どこまでか。当社がWantedlyのストーリーを支えるとき、記事に要る写真の整理、選ぶ軸、キャプションの案、写り込みの確認の観点は当社が出せます。ただし、「撮る」ことは、社内の人にしかできません。外部の当社が撮りに行くと、社員はカメラを意識し、普段の場面になりません。当社が勧めるのは、「今週あったこと」の1行を拾う人が、そのときに1枚撮っておく仕組みです。1行と1枚がセットで溜まっていれば、記事を書くときに写真を探さず、当社が記事に整えるときも場面に合った写真を選べます。撮るのは企業、選んで整えるのは当社。この分担で、写真が無い記事も、記事に合わない写真も減ります。

## まとめ

- ストーリーの写真は「記事に書いた場面」を見せるもの。記事を書いてから、その場面を撮る
- 自然光で、普段のままを、たくさん撮って選ぶ。加工せず、人が写っているものを
- 1本に1枚から数枚。最初に1枚、場面が変わるところに1枚、キャプションで場面を補う
- 写真が無くても記事は出し、あとで足す。フリー素材で埋めない
- 型ごとの注意（インタビューは仕事中、事業の裏側は写り込み、イベントは裏方）を守り、拾う人が1行と1枚をセットで残す

## よくある質問

### 記事に書いた出来事は過去で、写真が撮れません

同じ人が同じ場所で同じ仕事をしている場面を、次の機会に撮ります。過去の会議は撮れなくても、同じ会議室で同じ人が話している場面なら、記事の場面として読まれます。撮れるまでは、写真無しで出して構いません。

### 写真が無い記事を出すと、見栄えが悪くありませんか

ストーリーの中心は文で、写真は補いです。写真が無くても、場面が具体的に書かれていれば読まれます。写真を待って公開が遅れ、頻度が落ちるほうが、会社ページに来る人を減らします。出してから、あとで足せます。

### ストーリーの写真の選定は、御社に相談できますか

できます。当社は、記事の場面に要る写真の整理、選ぶ軸、キャプションの案、写り込みの確認の観点を支えられます。撮ることと、写っている人の同意は、企業が行ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、Wantedlyのストーリーの整備を支えています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
