ストーリーは、一覧の中でタイトルと写真だけが見えます。候補者は、タイトルで「読むか」を決めます。ところが、ストーリーのタイトルは「社員紹介vol.3」「〇〇について」「イベントレポート」のような、分類の名前になりがちです。**結論から言うと、ストーリーのタイトルは「誰の、何が起きた場面か」が一言で分かる形で付け、本文の場面を書いてから縮めて作ります。分類の名前は、記事を整理する側には便利でも、候補者には「何の話か分からない」タイトルです。** 抽象語と煽りを避け、募集している職種の候補者に向けた言葉で書きます。この記事では、タイトルの役割、開かれる型と開かれない型、作る手順、候補者に向けた言葉、型ごとの付け方、閲覧ではなく来た人の言葉で見る理由、やりがちな失敗、分担を整理します。募集記事のタイトルは[募集タイトルの付け方](/media/wt-boshu-title/)で書きました。ストーリーのタイトルは、それと役割が違い、「募集の内容」ではなく「記事の場面」を伝えます。

## この作業の目的｜一覧で「読む理由」を一言で渡す

候補者がストーリーの一覧を見るとき、見えるのは会社名、タイトル、写真の一部です。タイトルが「社員インタビュー第3回」だと、何の話か分からず、読む理由がありません。「入社2ヶ月目、初めて1人で提案に行った日」だと、場面が見え、読む理由が生まれます。

タイトルの役割は、記事を分類することではなく、「読む理由を一言で渡す」ことです。この考え方は、OfferBoxの件名や募集記事のタイトルと同じで、「開く理由を一言で」です。

## 手順1｜開かれる型と、開かれない型

| 開かれる型 | 例（型） | なぜ開かれるか |
|---|---|---|
| 誰の、何が起きた | 「入社2ヶ月目、初めて1人で提案に行った日」 | 場面が見える |
| 迷いや失敗が分かる | 「新規事業を、一度止めた理由」 | 本音が読めそうだと分かる |
| 決めた場面が分かる | 「先月の会議で、入社1年目の意見で決め方を変えた話」 | 動きが見える |
| 候補者の問いに答える | 「未経験で入って、最初の月に詰まったこと」 | 自分の問いだと分かる |
| 意外な組み合わせ | 「営業が、開発の打ち合わせに毎週出ている理由」 | 続きが気になる |

| 開かれない型 | なぜ開かれないか |
|---|---|
| 「社員紹介vol.3」「メンバーインタビュー」 | 分類。何の話か分からない |
| 「〇〇について」「〇〇のこと」 | 話題は分かるが、場面が無い |
| 「イベントレポート」「社員旅行に行きました」 | 報告。読む理由が無い |
| 「挑戦」「成長」「想い」 | 抽象語。どの会社にも書いてある |
| 「必見」「限定公開」「衝撃」 | 煽り。信用されない |
| 「【〇〇】△△｜□□」のような記号だらけ | 広告に見える |
| 長すぎて一覧で切れる | 肝心の場面が見えない |

開かれない型の共通点は、「場面が無い」ことです。分類、話題、報告、抽象語、煽りは、どれも「誰の何が起きたか」を伝えていません。

## 手順2｜本文を書いてから、縮める

タイトルは先に付けません。本文の場面を書いてから、その要約として作ります。

1. **本文を書く**：1本に1つの場面。書き方は[ストーリーの基本](/media/wt-story-kihon/)
2. **本文の中で、最も場面が分かる一文を探す**：「入社2ヶ月目に、初めて1人で提案に行った」のような
3. **その一文を、一覧で切れない長さに縮める**：「誰の」「何が起きた」の2つが残るように
4. **迷いや失敗が本文にあれば、それをタイトルに出す**：「一度止めた」「詰まった」「割れた」。本音が読めそうだと伝わる
5. **募集している職種の候補者が、自分のことだと思う言葉になっているかを確かめる**：手順3で
6. **抽象語と煽りが入っていないかを見る**

先にタイトルを付けると、本文と内容がずれます。タイトルに「失敗」とあるのに、本文は成功談。開いた候補者は「タイトルと違う」と感じます。本文が先、タイトルはあと。この順番は、募集記事のタイトルと同じです。

### エージェントベストの見解

相談で最も多い思い込みは、「ストーリーのタイトルは、記事を整理しやすいように、連番や分類で付けるものだ」というものです。「社員紹介vol.5」「事業紹介シリーズ」。社内で記事を管理する側には分かりやすいのですが、候補者には「何の話か分からない」タイトルです。当社は3媒体すべての販売パートナーとしてWantedlyの契約後の運用を見ていますが、面談で候補者が「あのストーリーを読んで来た」と言うとき、挙がるのは「〇〇さんが初めて1人で提案に行った話」のように、場面で覚えられている記事です。「社員紹介vol.5」を覚えている候補者はいません。タイトルは、社内の整理のためではなく、候補者が開いて覚えるためのものです。連番と分類は、管理画面の中で使い、タイトルには場面を出す。それだけで、同じ記事の読まれ方が変わります。

## 手順3｜募集している職種の候補者に向けた言葉

同じ場面でも、誰に読ませたいかで、タイトルの言葉が変わります。テーマの決め方で書いた「誰に読ませたいか」を、タイトルにも使います。考え方は[ストーリーのテーマの決め方](/media/wt-story-theme/)で書きました。

| 読ませたい候補者 | タイトルの言葉 |
|---|---|
| 未経験でこの職種を目指す学生 | 「未経験で入って」「最初の月に」「学生時代に〇〇だった私が」 |
| 経験者で仕事の中身を知りたい人 | 「前職で〇〇をしていた人が、この会社の△△で詰まったこと」 |
| 会社の考え方を見ている人 | 「〇〇を断った理由」「一度止めた話」 |
| 一緒に働く人の空気を知りたい人 | 「意見が割れた会議で」「新しく入った人の最初の週に、周りがしたこと」 |
| 業界未定で仕事内容で選びたい人 | 業界の言葉を使わず、仕事の場面で。「顧客に〇〇と言われた日」 |

「学生時代に〇〇だった私が」のように、候補者の状態を最初に置くと、「自分のことだ」と思って開きます。会社の側から「わが社の」と始めるタイトルは、候補者の側から見て自分のことではありません。

## 手順4｜型ごとの付け方

ストーリーの6つの型ごとに、タイトルの付け方の要点を置きます。

| 型 | 付け方 | 例（型） |
|---|---|---|
| 社員の話 | 誰が（状態）、何が起きた（場面） | 「入社2ヶ月目、初めて1人で提案に行った日」 |
| 代表の考え | 何を決めた・断った・迷った | 「〇〇の依頼を断った理由」。書き方は[代表の考えを書く方法](/media/wt-story-daihyo/) |
| 事業の裏側 | どの案件で、何が起きた | 「〇〇の案件で、最初の提案が通らなかった話」。[事業の裏側を書く方法](/media/wt-story-jigyo/) |
| カルチャー | どの場面で、どう動いた | 「意見が割れた会議で、こう決めた」。[カルチャーを伝える書き方](/media/wt-story-culture/) |
| 入社の話 | 入る前と後で、何が違った | 「入る前に想像していた〇〇と、実際の△△」。[入社エントリーを書いてもらう方法](/media/wt-story-nyusha/) |
| 出来事 | 出来事の裏で、誰が何をした | 「〇〇の準備で、意見が割れた話」。[社内イベントを書くときの注意](/media/wt-story-event/) |

どの型でも、「起きたこと」が入っているかを確かめます。入っていなければ、分類の名前に近づいています。

## 手順5｜閲覧ではなく、来た人の言葉で見る

タイトルの良し悪しを、閲覧の数で判断しません。理由は、募集記事のタイトルと同じです。

- **煽りのタイトルは閲覧が増えるが、話を聞きに来ない**：開かれても、本文で離れる
- **見るのは、面談で聞く「どのストーリーを読みましたか」**：場面で覚えられているタイトルが、届いたタイトル
- **タイトルの型を試すなら、月で、1要素だけ**：本文と同時に変えない。試し方は[募集記事を差し替えて比べる方法](/media/wt-boshu-abtest/)の考え方と同じ
- **公開後にタイトルだけを直してよい**：本文はそのままで、タイトルを場面が分かる形に直すと、古い記事も読まれる

「古い記事のタイトルを直す」は、見落とされやすい改善です。過去の「社員紹介vol.3」を「〇〇さんが初めて1人で提案に行った日」に直すだけで、記事は読まれ始めます。

## やりがちな失敗

| 失敗 | 何が起きるか | 直し方 |
|---|---|---|
| 「社員紹介vol.3」のような分類 | 何の話か分からない | 誰の、何が起きた |
| 「〇〇について」 | 場面が無い | 起きたことを入れる |
| 「イベントレポート」 | 報告。読む理由が無い | 裏で誰が何をしたか |
| 抽象語（挑戦・成長・想い） | どの会社も同じ | 場面の言葉 |
| 煽り（必見・衝撃） | 信用されない。閲覧は増えても来ない | 事実の場面 |
| 先にタイトルを付ける | 本文とずれる | 本文を書いてから縮める |
| 会社の側から始める（「わが社の」） | 候補者のことではない | 候補者の状態から |
| 長すぎる | 一覧で切れる | 「誰の」「何が起きた」だけ残す |
| 閲覧で判断する | 煽りに寄る | 来た人の言葉で |
| 古い記事のタイトルを直さない | 良い記事が埋もれる | 場面が分かる形に直す |

最も多いのは、最初の「分類のタイトル」です。記事が増えるほど、整理のために連番を付けたくなります。整理は管理画面で、タイトルは場面で。

## 社内の分担

| 作業 | 誰が |
|---|---|
| 本文を書く | 人事（または書き手） |
| 最も場面が分かる一文を探し、縮める | 書いた人 |
| 候補者に向けた言葉かを確かめる | 人事 |
| 抽象語と煽りのチェック | 書いた人と別の1人 |
| 面談で「どのストーリーを読んだか」を聞く | 面談に出る人 |
| 古い記事のタイトルを直す | 人事 |

運用代行や代理店が支えられるのは、開かれる型の提供、本文から縮める作業、古い記事のタイトルの直し案までで、本文と、来た人の言葉を聞くことは企業が行います。代理店の代行の範囲は[代理店に運用まで頼めるか](/media/kh-dairiten-unyou/)で書きました。

### エージェントベストの見解

媒体を比べたり運用を見直したりするときに、ストーリーの閲覧の数でタイトルの良し悪しを判断しようとする会社は多いのですが、閲覧は「開かれた」までで、「話を聞きに来た」ではありません。当社がWantedlyの運用でタイトルを見直すときは、面談で候補者が「どのストーリーを読んで来ましたか」に答えた記事を並べ、そのタイトルの型を見ます。挙がる記事のタイトルは、例外なく場面が入っています。閲覧が多い記事のタイトルが挙がるとは限らず、イベントの記事は閲覧が多くても挙がりません。タイトルの効果は、閲覧ではなく、候補者が覚えているかで測るものです。覚えられるタイトルは、場面のタイトルです。連番や分類は、誰にも覚えられません。

## まとめ

- ストーリーのタイトルは「誰の、何が起きた場面か」が一言で分かる形。分類・話題・報告・抽象語・煽りは開かれない
- 本文を書いてから、最も場面が分かる一文を縮めて作る。先に付けると本文とずれる
- 迷いや失敗が本文にあればタイトルに出す。募集している職種の候補者の状態から始める
- 型ごとに「起きたこと」が入っているかを確かめる。入っていなければ分類に近い
- 閲覧ではなく、面談で聞く「どのストーリーを読んだか」で見る。古い記事のタイトルも場面が分かる形に直す

## よくある質問

### 記事が増えてきたので、連番で整理したいです

整理は管理画面の中で行い、タイトルには場面を出します。連番のタイトルは、社内で記事を探すには便利でも、候補者には何の話か分かりません。「社員紹介vol.5」を「〇〇さんが初めて1人で提案に行った日」に変えるだけで、同じ記事が読まれるようになります。

### タイトルを変えたら閲覧は増えましたが、話を聞きに来る人が増えません

煽りの言葉で開かれている可能性があります。開いた候補者が本文で離れているなら、タイトルと本文がずれています。タイトルを本文の場面の要約に戻し、閲覧ではなく面談で聞く「どのストーリーを読んだか」で見ます。

### ストーリーのタイトルの見直しは、御社に相談できますか

できます。当社は、開かれる型の提供、本文から縮める作業、古い記事のタイトルの直し案を支えられます。本文と、来た人の言葉を聞くことは、企業が行ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、Wantedlyのストーリーの整備を支えています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
