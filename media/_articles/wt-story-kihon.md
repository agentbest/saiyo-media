Wantedlyには、会社ページと募集記事のほかに、ストーリーがあります。「ストーリーとは何を書く場所なのか」「ブログと何が違うのか」という質問を、始めたばかりの会社から受けます。**結論から言うと、ストーリーは「会社の日常と考えを、場面で書く記事」で、候補者が会社ページに来る理由を作るものです。広報のブログでも、募集の告知でも、会社の宣伝でもありません。1本に1つのことを、具体的な場面で書き、月に数本を足し続けます。** 会社ページが入口、募集記事が職種の話、ストーリーが日常と考え。この3つが揃って、Wantedlyの会社の見え方ができます。この記事では、ストーリーの位置づけ、題材の型、1本の書き方、1本目、長さと書き手、頻度、会社ページと募集記事との関係、やりがちな失敗、分担を整理します。会社ページは[会社ページで最初に書くこと](/media/wt-kaisha-page-kihon/)、募集記事は[募集記事の基本構成](/media/wt-boshu-kihon/)で書きました。

## この作業の目的｜候補者が「会社ページに来る理由」を作る

会社ページは、候補者が自分から探して来る場所ではありません。何かをきっかけに来て、読んで、募集を見ます。そのきっかけが、ストーリーです。

ストーリーは、会社の日常の一コマ、代表の考え、社員の話を書いた記事で、会社ページの外にいる候補者の目に触れます。読んで「この会社は」と思った候補者が、会社ページに来て、募集を見て、「話を聞きに行きたい」と動きます。この流れは[WantedlyとGreenの違い](/media/hikaku-wantedly-green/)で書きました。

ストーリーが無いと、会社ページに来る理由が無く、募集記事も動きません。ストーリーの目的は、会社ページに来る理由を作り続けることです。

## 手順1｜ストーリーが「ではない」もの

何を書く場所かを掴むには、何ではないかを先に置くと分かりやすいです。

| ストーリーではないもの | なぜ違うか | 代わりに |
|---|---|---|
| 広報のブログ、プレスリリース | 対外的な発表は、候補者に「会社の日常」を見せない | 発表の裏で、誰が何をしたかを書く |
| 募集の告知 | 「〇〇を募集しています」は募集記事の役割 | 募集の理由になった出来事を書き、募集記事へつなぐ |
| 会社の宣伝、実績の自慢 | 候補者は宣伝を読みに来ない | 実績の裏の、うまくいかなかった場面も含めて書く |
| 制度の説明 | 制度は会社ページに書く | 制度を使った人の、実際の1日を書く |
| 長い社史 | 読まれない | 転機になった1つの場面を書く |

共通するのは、「会社が言いたいこと」ではなく「候補者が知りたい日常と考え」を書く、という違いです。

## 手順2｜題材の型

ストーリーの題材は、大きく6つの型に分かれます。それぞれの書き方は、この後の記事で1つずつ書きます。ここでは型だけを置きます。

| 型 | 何を書くか | 候補者が得るもの |
|---|---|---|
| 社員の話 | ある社員の、なぜこの会社に来て、いま何をしていて、何が大変か。手順は[社員インタビューを書く手順](/media/wt-story-interview/) | 一緒に働く人の像 |
| 代表の考え | 代表が最近考えたこと、決めたこと、迷ったこと。書き方は[代表の考えを書く方法](/media/wt-story-daihyo/) | 会社の判断の軸 |
| 事業の裏側 | ある案件やプロジェクトで、何が起きて、どう動いたか。書き方は[事業の裏側を書く方法](/media/wt-story-jigyo/) | 仕事の実態 |
| カルチャー | 社内でよくある場面、決め方、揉めたときの解決の仕方。書き方は[カルチャーを伝える書き方](/media/wt-story-culture/) | 働く空気 |
| 入社の話 | 入社した人が、入る前に何を思い、入って何が違ったか。頼み方は[入社エントリーを書いてもらう方法](/media/wt-story-nyusha/) | 入社後の自分の想像 |
| 出来事 | 社内のイベント、新しく始めたこと、失敗したこと。注意は[社内イベントを書くときの注意](/media/wt-story-event/) | 会社の動き |

どの型でも、書くのは「1つの場面」です。「社員の話」なら、その社員の1日か、1つの案件。「代表の考え」なら、1つの判断。型を横断して全部を書こうとすると、会社紹介になります。次に何を書くかの決め方は[ストーリーのテーマの決め方](/media/wt-story-theme/)で書きました。

## 手順3｜1本に1つのことを、場面で書く

ストーリー1本の書き方の基本です。

1. **1本に1つのこと**：1つの場面、1つの判断、1人の話。2つ以上を詰めない
2. **場面から書き始める**：「〇月、△△の案件で、□□が起きた」。会社の説明から始めない
3. **誰が、何を見て、何を思い、どう動いたか**：抽象語ではなく、行動と感じたことで
4. **うまくいかなかったことも書く**：良いことだけの記事は、候補者に建前と読まれる
5. **読んだ候補者が「自分ならどうするか」と考えられる形で終える**：教訓でまとめない。場面を置いて終える
6. **会社ページか募集記事へ、一言で誘導する**：「この仕事の募集はこちら」「会社の考えは会社ページに」

抽象語を場面に置き換える考え方は、[会社ページで最初に書くこと](/media/wt-kaisha-page-kihon/)や[会社ページでバリューを言葉にする方法](/media/wt-kaisha-page-value/)で書いたのと同じです。ストーリーは、その「場面」を1本ずつ書く場所です。

### エージェントベストの見解

相談で最も多い思い込みは、「ストーリーは会社のブログだから、広報や宣伝を書く場所だ」というものです。実際には、Wantedlyの候補者は、ストーリーを「この会社の日常はどうか」を知るために読んでいて、プレスリリースや実績の紹介は読み飛ばします。当社は3媒体すべての販売パートナーとしてWantedlyの契約後の運用を見ていますが、会社ページに人が来ているストーリーは、「先月、〇〇の案件で△△が起きて、□□がこう動いた」のような、1つの場面を書いた記事です。「〇〇を受賞しました」「△△を発表しました」の記事には、候補者は来ません。ストーリーは、会社が言いたいことを書く場所ではなく、候補者が知りたい日常を書く場所です。この違いを最初に押さえると、何を書くかで迷わなくなります。

## 手順4｜1本目は、「なぜ」の場面から

最初のストーリーは、会社ページと同時に公開します。この順番は会社ページの基本の記事で書きました。1本目の題材は、会社ページの「なぜやるのか」の場面を、少し詳しく書いたものが向いています。

- **会社ページの「なぜ」で触れた場面を、1本のストーリーにする**：「〇年前、代表が△△を見て、□□と思った」を、そのときの状況、迷い、決めたことまで
- **代表が話し、人事が書き起こす**：書き方は[会社ページでミッションを伝える書き方](/media/wt-kaisha-page-mission/)と同じ
- **1本目で完璧を目指さない**：更新の起点として出す
- **2本目以降は、題材の型を変える**：1本目が代表の考えなら、2本目は社員の話、3本目は事業の裏側、のように

1本目が「なぜ」の場面だと、会社ページの「なぜ」と一貫し、候補者はストーリーから会社ページに来て、同じ話を深く読めます。

## 手順5｜長さ、書き手、頻度

| 項目 | 目安 |
|---|---|
| 長さ | 1つの場面を書き切れる長さ。長いほどよいわけではない。読み切れる長さで |
| 書き手 | 人事が、本人に聞いて書く。本人が書ける場合は本人でもよいが、書けなくてよい |
| 頻度 | 月に数本から。続く数で。本数より、途切れないこと |
| 公開の判断 | 本人が確認したら出す。完成を待たない |
| 更新 | 古くなったストーリーは残してよい。日付があるので、古いことは伝わる |

「人事が聞いて書く」が、書き手の基本です。社員に「書いて」と頼むと止まります。「話して」と頼み、人事が書き、本人が直す。この分担は、会社ページのメンバー紹介と同じです。書き手を社内で増やす方法は、この後の記事で書きます。

頻度は、ネタを集める仕組みで決まります。週に一度1行を拾う仕組みは[会社ページを更新し続ける仕組み](/media/wt-kaisha-page-koushin/)で書きました。1行が溜まっていれば、月に数本は書けます。

## 手順6｜会社ページと募集記事との関係

3つは、それぞれ役割が違い、互いに参照し合います。

| 場所 | 役割 | 他からどう参照されるか |
|---|---|---|
| 会社ページ | 入口。「なにを・なぜ・どうやって」と人 | ストーリーから「会社の考えはこちら」。募集記事から「会社全体はこちら」 |
| 募集記事 | 職種の話。「この募集で何をやるか」 | ストーリーから「この仕事の募集はこちら」。会社ページから募集一覧 |
| ストーリー | 日常と考え。1つの場面 | 募集記事から「この仕事の日常はこちら」。会社ページのメンバー紹介から「この人の話はこちら」 |

ストーリーは、会社ページと募集記事に「場面」を供給する役割も持ちます。会社ページのバリューの実例、募集記事の「どうやっているのか」の1日、メンバー紹介の「いま何を」は、ストーリーで詳しく書いた場面を短く引いたものになります。ストーリーが溜まるほど、会社ページと募集記事が具体的になります。

## やりがちな失敗

| 失敗 | 何が起きるか | 直し方 |
|---|---|---|
| 広報や宣伝を書く | 候補者が来ない | 日常の1つの場面 |
| 1本に全部を詰める | 会社紹介になる | 1本に1つのこと |
| 会社の説明から始める | 読まれない | 場面から始める |
| 良いことだけ | 建前と読まれる | うまくいかなかったことも |
| 教訓でまとめる | 説教に見える | 場面を置いて終える |
| 社員に「書いて」と頼む | 止まる | 「話して」と頼み、人事が書く |
| 完成を待って公開しない | 会社ページに来る理由が無い | 起点として出す |
| 会社ページや募集記事へ誘導しない | 読んで終わる | 一言で誘導 |
| 最初の月に多く書いて息切れ | 途切れる | 月に数本から |

最も多いのは、最初の「広報や宣伝を書く」です。

## 社内の分担

| 作業 | 誰が |
|---|---|
| 題材を集める（週に一度1行） | 現場に近い人 |
| 月に一度、書く題材を選ぶ | 人事と代表 |
| 本人に話してもらう | 本人 |
| 書く | 人事 |
| 本人が直し、公開に同意する | 本人 |
| 会社ページと募集記事へつなぐ | 人事 |
| 場面を会社ページと募集記事に引く | 人事 |

本人の負担は、「話す」と「直す」の2つです。運用代行や代理店が支えられるのは、題材の型の提供、聞いた話を記事に膨らませる下書き、会社ページと募集記事へのつなぎ方までで、話すことと確認は企業が行います。代理店の代行の範囲は[代理店に運用まで頼めるか](/media/kh-dairiten-unyou/)で書きました。

### エージェントベストの見解

これをやる前に、先に決めておかないとストーリーが続かないことがあります。「1本に1つのことを書く」と決めることです。当社がWantedlyの運用の相談でストーリーを見るとき、最初の数本は書けたのに続かない会社の記事は、1本に会社の説明、事業の紹介、社員の紹介、募集の告知が全部入っています。全部入っているから、1本を書くのに時間がかかり、次を書く気力が残りません。当社が勧めるのは、「先週、〇〇があった」を1本にすることです。1つの場面なら、聞くのも書くのも短時間で済み、月に数本が無理なく続きます。1本に1つと決めると、書くことが減るのではなく、書ける本数が増えます。ストーリーは、1本の重さより、続く本数で会社ページに人を呼びます。

## まとめ

- ストーリーは「会社の日常と考えを場面で書く記事」で、候補者が会社ページに来る理由を作るもの。広報のブログでも募集の告知でもない
- 題材の型は、社員の話・代表の考え・事業の裏側・カルチャー・入社の話・出来事。どの型でも1本に1つの場面
- 場面から始め、行動と感じたことで書き、うまくいかなかったことも入れ、教訓でまとめず、会社ページか募集記事へ一言で誘導する
- 1本目は会社ページの「なぜ」の場面を、代表が話して人事が書く。完成を待たずに出す
- 書き手は人事が聞いて書く。月に数本から、途切れないことを優先する。会社ページと募集記事はストーリーの場面を引いて具体的になる

## よくある質問

### ストーリーに何を書けばいいか分かりません

「先週、社内で何があったか」を1つ思い出します。会議で決めたこと、顧客に言われたこと、うまくいかなかったこと、新しく始めたこと。それを、誰が何を見て何を思いどう動いたかで書けば、1本になります。題材を集める仕組みは、会社ページの更新の記事で書きました。

### ストーリーは、会社の実績や受賞も書いてよいですか

実績そのものではなく、その裏で誰が何をしたかを書けば、ストーリーになります。「〇〇を受賞しました」は広報の記事で、候補者は読みません。「受賞した△△の案件で、□□がこう動いて、こういうことがあった」なら、候補者は読みます。

### ストーリーの作成は、御社に相談できますか

できます。当社は、題材の型の提供、聞いた話を記事に膨らませる下書き、会社ページと募集記事へのつなぎ方を支えられます。本人に話してもらうことと、確認は企業が行ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、Wantedlyのストーリーの整備を支えています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
