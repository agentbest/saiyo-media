ワンキャリアのイベントのKPIを置きたい。ところが、参加者数と申込数をKPIにし、満足度のアンケートで良し悪しを決め、回をまとめて足し、目標値を置いて毎回「未達」の表になり、面談以降を見ず、体験談を見ず、入口を分けない。**結論から言うと、見るのは「参加者数」ではなく、回ごとの「来た人のうち近い人の数」「当日に次の場を申し込んだ数」「参加後に面談へ進んだ数」と、「体験談に『回のとおりだった』と書かれたか」です。入口（体験談からの流れ・スカウトの締め）で分け、目標値ではなく回ごとの変化で見て、回の型を一つ直します。申込数と満足度は参考の数で、KPIにしません。** この記事では、KPIで起きる失敗、見る段、四つのKPI、ワンキャリアに独自の指標、入口で分けること、変化で見ること、細い段と直す場所、台帳、上司への報告、分担を整理します。掲載のKPIは[ワンキャリアの掲載のKPI](/media/oc-keisai-kpi/)、スカウトのKPIは[ワンキャリアのスカウト運用のKPI](/media/oc-scout-kpi/)、母集団のKPIは[母集団形成のKPI](/media/kh-boshudan-kpi/)で書きました。

## この作業の目的｜「回が効いたか」を、参加者数ではなく「その後」で答えられる状態にする

イベントの目的は、来た学生が確かめて、次の場に進むことです。参加者数は、その手前の数で、多くても次に進まなければ効いていません。KPIは、「回が効いたか」に答える数で、「その後」（次の場・面談・体験談）にあります。

目的は、KPIを「回の当日の数」から「回の後の数」に置き直すことです。

## KPIで、起きる失敗

| 失敗 | 何が起きるか |
|---|---|
| 参加者数や申込数を、KPIにする | 多く集める運用に寄り、社員と話せず、次に進まない。煽りに寄る |
| 満足度で、見る | 「楽しかった」は次に進む理由ではない。満足度が高くて進まない回がある |
| 回を、まとめて足す | どの回（種類・出た人・時期）が効いたかが見えない |
| 目標値を置いて、未達の表になる | 直す場所ではなく「足りない」だけが見える |
| 面談以降を、見ない | 回で終わり、母集団に効いたかが分からない |
| 体験談を、見ない | ワンキャリアで最も長く効く数を見ていない |
| 入口を、分けない | 体験談からの流れとスカウトの締めのどちらが近い人を連れてきたかが見えない |

共通するのは、「測りやすい数」（参加者数・満足度）をKPIにしていることです。

## 見る段

| 段 | 何を数えるか | 意味 |
|---|---|---|
| イベントページが読まれる | 閲覧（管理画面で見られる範囲で） | タイトルと一覧での見つかり方の結果 |
| 申込 | 申込の数と、入口（体験談からの流れ・スカウトの締め） | ページの中身と入口の結果。参考の数 |
| 参加 | 来た数 | 申込後の案内の結果。参考の数 |
| 近い人 | 来た人のうち、「こんな人」に近い人 | 告知と入口が近い人を集めたか。ここからKPI |
| 次の場の申込 | 当日に次の場を申し込んだ数 | 回の中身と当日の案内の結果 |
| 面談 | 参加後に面談へ進んだ数 | 回が母集団に効いたか |
| 面談以降 | 面談から先の進み方 | 回経由の人が、他の入口より進むか |

「近い人」から下が、KPIです。上の三つは参考の数で、動かなくなったときに見ます。段の考え方は[ワンキャリアの掲載のKPI](/media/oc-keisai-kpi/)の「見る段」と同じです。

### エージェントベストの見解

相談で最も多い思い込みは、「イベントの成果は、参加者数と満足度のアンケートで測る」というものです。当社はワンキャリアの販売パートナーとして、イベントのKPIの相談を受けていますが、参加者数と満足度で測った会社は、「参加者は多く、満足度も高いのに、面談に来ない」で止まり、回の何を直せばよいか分からなくなっています。逆に、「来た人のうち近い人」「当日に次の場を申し込んだ人」「面談に進んだ人」を回ごとに持った会社は、「近い人は来ているが次の場を申し込まない→当日の案内を直す」「次の場は申し込むが面談に来ない→日程の出し方を直す」と、直す場所を指せています。満足度は「楽しかったか」で、「次に進むか」とは別の数です。当社がイベントのKPIの相談を受けるとき、最初にやるのは、満足度の列を外して、次の場と面談の列を足すことです。

## 四つの、KPI

| KPI | 何が分かるか | 見方 |
|---|---|---|
| 来た人のうち、近い人の数 | 告知と入口が、「こんな人」を集めているか | 回ごと。割合も |
| 当日に次の場を申し込んだ数 | 回の中身と当日の案内が効いているか | 回ごと。来た人に対する割合 |
| 参加後に面談へ進んだ数 | 回が母集団に効いたか | 回ごと。日数も |
| 体験談に「回のとおりだった」と書かれたか | 書いたとおりに運用できたか。翌年の集客 | 体験談が書かれたら読む |

四つで、「集めたか」「確かめられたか」「進んだか」「残ったか」が分かります。三つの数の考え方は[母集団形成のKPI](/media/kh-boshudan-kpi/)の三つを、イベントの段に置き換えたものです。

## ワンキャリアに独自の指標｜体験談に「回のとおりだった」と書かれたか

- **ワンキャリアでは、今年の回が翌年の体験談になる**：回の体験談を、翌年の学生が読む
- **「ページに書いてあったとおりだった」「少人数で聞けた」が、翌年の集客**
- **「ページと違った」「話せなかった」が、翌年の集客を減らす**
- **数で測れないが、最も長く効く指標**：体験談が書かれたら読み、次の回で直す。[ワンキャリアのイベント後のフォロー](/media/oc-event-follow/)の「回の体験談を、読む」
- **掲載のKPIと同じ考え方**：[ワンキャリアの掲載のKPI](/media/oc-keisai-kpi/)の「ワンキャリアに独自の指標」

## 入口で、分ける

- **体験談→企業ページ→イベントページの流れで来た人と、スカウトの締めで来た人を、分ける**
- **入口ごとに、近い人の割合と次の場への申込を見る**：どちらが近い人を連れてきているか
- **申込時に「どこで知ったか」を聞くか、スカウト経由を台帳で印を付ける**
- **入口ごとの表を、集客の見直しに**：[ワンキャリアのイベント集客の考え方](/media/oc-event-shuukyaku/)の「二つの、入口」
- **スカウト経由の数は、スカウトのKPIにも入る**：[ワンキャリアのスカウト運用のKPI](/media/oc-scout-kpi/)

## 回ごとに、変化で見る

- **目標値を、置かない**：置くと「未達」の表になる
- **回ごとに、前の回と並べる**：種類・出た人・時期が違う回を、同じ数で
- **変化があった段を、一つ指す**：近い人が減った、次の場の申込が減った、面談が減った
- **回の型を、一つ直す**：[ワンキャリアの説明会の構成の作り方](/media/oc-setsumeikai-sekkei/)の「回ごとの、直し方」
- **回をまとめて足さない**：足すと、どの回が効いたかが消える

## 細い段と、直す場所

| 細い段 | 直す場所 |
|---|---|
| 近い人が少ない | 告知（タイトル・「誰が出て何が確かめられるか」）、入口（スカウトの締めの相手）。[ワンキャリアのイベントに人が集まらないとき](/media/oc-event-atsumaranai/) |
| 次の場の申込が少ない | 回の中身（質問の時間・出る人）、当日の案内（申し込める形か）。[ワンキャリアのオフラインイベントの進め方](/media/oc-offline-event/) |
| 面談に進まない | 一通の速さ、次の場の日程の出し方。[ワンキャリアのイベント後のフォロー](/media/oc-event-follow/) |
| 面談以降で細い | 回で話したことと面談・選考が揃っているか。[ワンキャリアの掲載でやりがちな失敗](/media/oc-keisai-ng/) |
| 体験談に「違った」と書かれた | ページと当日の中身を揃える |

細い段は一つ指し、一つ直します。

## 台帳から、出す形

- **来た人を、回ごと・入口ごとに、台帳に**：入口「イベント」、回の名前、入口の種類、近さ、次の場の申込、面談の日付
- **月に一度、回ごとに四つを出す**：別の表を作らない
- **満足度のアンケートは、台帳に入れない**：入れるなら「出た質問」を
- **台帳の項目は[OfferBox運用のKPI設計](/media/ob-kpi-sekkei/)の手順5**

## 上司への報告

- **参加者数の一覧を、KPIの表にしない**：参考として欄外に
- **回ごとの「近い人・次の場・面談」を主に**
- **「どの回が、なぜ効いたか」を、種類・出た人・時期で**
- **体験談に書かれたことを、添える**：翌年の集客の根拠
- **報告の型は[ワンキャリアの掲載のKPI](/media/oc-keisai-kpi/)の「上司への報告の形」と[経営層にOfferBoxの成果を説明する方法](/media/ob-keiei-rikai/)**

### エージェントベストの見解

これは数字の読み方の話です。イベントのKPIの相談で、「次の場の申込は多いのに、面談に来ない」と言われることがあります。当社が確かめるのは、「次の場の申込」から「面談」までの日数と、その間の連絡です。当日に申し込んでも、日程の候補が数日後に来る、面談が数週間先、では温度が下がります。一通が当日か翌日に出て、日程の候補がその中にあり、面談が近い日に取れているかを見ます。数字の段で言えば「次の場の申込」と「面談」の間の日数で、それはイベントのKPIというより、フォローと面談の枠の話です。イベントのKPIが良いのに面談に来ないとき、回を直しても直りません。当社は、回のKPIの範囲を「次の場の申込」までと決め、その先はフォローと面談の枠で見ます。

## まとめ

- イベントのKPIは「参加者数」ではなく、回ごとの「来た人のうち近い人」「当日に次の場を申し込んだ数」「参加後に面談へ進んだ数」と「体験談に『回のとおりだった』と書かれたか」の四つ。申込数・参加者数・満足度は参考の数
- 見る段は、ページが読まれる→申込→参加→近い人→次の場の申込→面談→面談以降で、「近い人」から下がKPI
- 入口（体験談からの流れ・スカウトの締め）で分け、回ごとに前の回と並べて変化で見る。目標値を置かず、回をまとめて足さない
- 細い段を一つ指し、直す場所（告知と入口・回の中身と当日の案内・一通と日程・面談以降の揃え方）を一つ直す
- 台帳から回ごとに出し、上司には回ごとの表と体験談に書かれたことで報告する。回のKPIの範囲は「次の場の申込」までで、その先はフォローと面談の枠

## よくある質問

### 満足度のアンケートは、やめたほうがよいですか

やめなくてよいですが、KPIにしません。アンケートで聞くなら、「満足したか」より「聞きたいことが聞けたか」「次に何をしたいか」「ページと違ったことはあったか」で、直す材料になる質問にします。「楽しかった」の割合は、次の場に進む数と関係が薄く、それで回の良し悪しを決めると、楽しい回に寄って確かめられる回から離れます。

### 回ごとに来る人が少なく、割合を出しても意味がない気がします

少人数の回なら、割合より「数」と「誰が」で見ます。「来た人のうち近い人は〇人、そのうち次の場に申し込んだのは誰」の形で、人の名前で追えます。少人数の回の価値は、一人ずつ追えることで、割合を出すために人数を増やすと、追えなくなります。数が少ない回は、回を重ねて、回ごとの変化で見ます。数え方は[イベントからの母集団形成](/media/kh-boshudan-event/)で書きました。

### イベントのKPIの置き方は、御社に相談できますか

できます。当社は、四つのKPIの型、見る段の整理、入口の分け方、台帳の型、細い段と直す場所の対応、報告の型を支えられます。台帳を付けること、近さの判断、回を直すこと、体験談を読むこと、報告は、企業が行ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、3媒体の運用を支えています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
