会社ページを公開した。ここで運用が終わったと感じる会社は多いのですが、Wantedlyでは、公開した日が始まりです。**結論から言うと、会社ページを更新し続けるには、「書く仕組み」より先に「ネタを集める仕組み」が要ります。週に一度、「今週あったこと」を1つ拾う。これが溜まっていれば、書くことに困りません。溜まっていなければ、書く時間があっても書けません。** そのうえで、何を、どの頻度で、誰が、いつまでに更新するかを決めます。この記事では、更新する項目、頻度の目安、担当と締切、ネタを集める仕組み、更新が止まる原因と対処、記録、反応の見方、やりがちな失敗、分担を整理します。会社ページを最初に公開するまでは[会社ページで最初に書くこと](/media/wt-kaisha-page-kihon/)で書きました。

## この作業の目的｜「公開して止まる」を防ぐ

Wantedlyは、会社ページとストーリーに人が来て、そこから募集に入る媒体です。更新が止まると、会社ページに来る理由が無くなり、募集も動かなくなります。この止まり方は[WantedlyとGreenの違い](/media/hikaku-wantedly-green/)でも書きました。

更新が止まる原因は、書く時間が無いことより、書くことが無いことです。「何か書かないと」と思って管理画面を開いても、ネタが無ければ閉じます。ネタが手元にあれば、書く時間は短くて済みます。

この作業の目的は、「書く」を「集めたものを整える」に変えることです。集める仕組みがあれば、更新は続きます。

## 手順1｜何を更新するか

会社ページで、時間とともに古くなるものを並べます。それぞれ、更新の頻度の目安と一緒に。

| 項目 | 何が古くなるか | 頻度の目安 |
|---|---|---|
| ミッションの「いまの判断」 | 最近の判断が、数ヶ月前の話になる | 数ヶ月に一度、最近の場面に差し替え。[ミッションを伝える書き方](/media/wt-kaisha-page-mission/) |
| バリューの実例 | 実例が古くなる | 数ヶ月に一度、最近の場面に差し替え。[バリューを言葉にする方法](/media/wt-kaisha-page-value/) |
| メンバーの紹介 | 異動・退職、「いま何をしているか」の変化 | 異動と退職のたび。「いま何を」は数ヶ月に一度。[メンバーの選び方](/media/wt-kaisha-page-member/) |
| 写真 | いない人が写っている、場が変わった | 異動と退職のたび。移転のたび。[写真の選び方](/media/wt-kaisha-page-photo/) |
| 「なにをやっているのか」 | 事業の変化、力を入れていることの変化 | 事業が変わったとき。卒年や期の切り替わりに確認 |
| 「どうやっているのか」の場面 | 働き方の変化、決め方の変化 | 変わったとき。数ヶ月に一度確認 |
| 募集記事 | 募集している職種、仕事の中身 | 募集の開始と終了のたび |
| ストーリー | 新しい記事を足す | 月に数本 |

「ストーリーを月に数本」が、更新の中心です。会社ページの各項目は、変化があったときに直せば足ります。ストーリーは、変化が無くても、日常の一コマを書き足すものです。

## 手順2｜ネタを集める仕組みを、先に作る

書く前に、集めます。集める仕組みは、次の形にします。

1. **週に一度、「今週あったこと」を1つ拾う**：会議で決めたこと、顧客に言われたこと、うまくいったこと、失敗したこと、新しく始めたこと、入社した人、辞めた人。何でもよい。1つでよい
2. **拾う人を決める**：人事でも、代表でも、現場の誰かでも。「拾う」だけなら、書く力は要らない
3. **拾ったものを、1行で記録する**：日付、何があったか、誰が関わったか。長く書かない
4. **月に一度、記録を見て、書くものを選ぶ**：溜まった数個の中から、ストーリーにするもの、会社ページの項目に反映するものを選ぶ
5. **書くときは、記録を膨らませる**：ゼロから書くのではなく、1行を数段落にする

「1行で記録する」が要点です。書こうとすると止まりますが、1行なら続きます。1行が月に数個溜まれば、書くものは選べます。

集める人と書く人は、同じでなくて構いません。集めるのは現場に近い人、書くのは人事、という分け方が現実的です。

### エージェントベストの見解

これをやる前に、先に決めておかないと更新が続かないことがあります。「ネタを集める仕組み」を、書く担当を決めるより先に作ることです。当社がWantedlyの運用の相談で「更新が止まった」と聞くとき、書く担当は決まっていて、書く時間も月に一度は取っている。ところが、その時間に管理画面を開いて、何を書けばいいか分からず閉じる。当社は3媒体すべての販売パートナーとしてWantedlyの契約後の運用を見ていますが、更新が続いている会社は、書く時間より先に、週に一度1行を拾う習慣があります。1行が溜まっていれば、書く時間に「どれを書くか」を選ぶだけで済み、ゼロから考えません。書く担当を決めても、ネタが無ければ書けない。ネタがあれば、書く担当は誰でも書ける。先に決めるのは、拾う人と拾う曜日です。

## 手順3｜担当と締切

集める仕組みができたら、書く担当と締切を決めます。

| 作業 | 担当 | 締切 |
|---|---|---|
| 週に一度、1行を拾う | 現場に近い人（人事でも可） | 毎週決まった曜日 |
| 月に一度、書くものを選ぶ | 人事と代表 | 毎月決まった日 |
| ストーリーを書く | 人事、または1行を拾った本人 | 選んだ日から1週間以内 |
| 代表や本人が直す | 代表、本人 | 書いてから数日以内 |
| 会社ページの項目を直す | 人事 | 変化を知った週 |
| 異動・退職・移転の反映 | 人事 | 情報を受けた週 |
| 数ヶ月に一度の全体確認 | 人事 | 決めた月 |

「締切」を曜日と日で固定します。「時間があるときに」は、無いのと同じです。1人で回す場合の時間の固定は、OfferBoxの[人事1人でOfferBoxを回す運用設計](/media/ob-hitori-jinji/)と同じ考え方です。

代表の時間は、「月に一度、書くものを選ぶ」と「自分が関わる記事を直す」の2つに絞ります。書くのは人事です。

## 手順4｜更新が止まる原因と、対処

更新が止まる原因は、だいたい決まっています。

| 原因 | 何が起きるか | 対処 |
|---|---|---|
| ネタが無い | 管理画面を開いて閉じる | 週に一度1行を拾う仕組み |
| 書く人が忙しい | 締切を過ぎ、そのまま | 締切を固定し、過ぎたら翌週に繰り越す。溜めない |
| 代表の確認が遅い | 書いたものが公開されない | 確認の期限を決める。期限を過ぎたら人事の判断で公開してよいと合意する |
| 完璧を目指す | 何度も直して公開されない | 「更新の起点として出す」。公開してから直せる |
| 反応が見えず、意味を感じない | やる気が続かない | 話を聞きに来た人に「どこを読んだか」を聞き、書いた人に戻す（手順6） |
| 担当が変わった | 仕組みが引き継がれない | 拾う人・書く人・締切を1枚にして引き継ぐ |
| ストーリーの本数を多く設定しすぎ | 最初の月で息切れ | 月に数本から。続く数で |

「代表の確認が遅い」は、代表が書く記事で起きます。「期限を過ぎたら人事の判断で公開」と先に合意しておくと、止まりません。

## 手順5｜更新の記録

更新したことを記録しておきます。記録が無いと、何を更新したか、いつから更新していないかが分かりません。

- **更新した日と項目**：会社ページのどこを、ストーリーの何本目を
- **拾った1行のうち、使ったものと使っていないもの**：使っていないものは、次の月の候補
- **代表や本人が直した日**：確認の遅れが見える
- **異動・退職・移転の反映の日**：漏れが見える
- **数ヶ月に一度の全体確認の日**：次の確認の予定

記録は、集める仕組みの1行の記録と同じ場所に置くと、1つで済みます。

## 手順6｜反応の見方

更新の効果は、数字より、話を聞きに来た人の言葉で見ます。

1. **話を聞きに来た人に、「会社ページとストーリーのどこを読みましたか」と聞く**：面談の最初に。OfferBoxで「文面のどこに反応したか」を聞くのと同じ
2. **答えを記録する**：どの記事、どの項目が読まれたか
3. **書いた人に戻す**：「あなたが書いた〇〇の記事を読んで来た人がいます」。これが、書く動機になる
4. **読まれた記事の型を、次に活かす**：日常の一コマか、判断の話か、失敗の話か。読まれる型が見える
5. **読まれていない項目は、削るか直す**：長い会社説明、抽象的なバリューなど

「書いた人に戻す」が、更新を続ける最大の動機です。反応が無いと、書く意味が分からなくなります。反応が戻ると、次を書きたくなります。現場を巻き込むときの「反応を戻す」と同じ考え方で、OfferBoxの[現場社員を巻き込む方法](/media/ob-genba-makikomi/)で書きました。

## やりがちな失敗

| 失敗 | 何が起きるか | 直し方 |
|---|---|---|
| 書く担当を決めて、集める仕組みが無い | 書く時間にネタが無い | 週に一度1行を拾う仕組みを先に |
| 「時間があるときに更新」 | 更新されない | 曜日と日で締切を固定 |
| 代表の確認待ちで止まる | 公開されない | 期限を過ぎたら人事の判断で公開と合意 |
| 完璧を目指して直し続ける | 公開されない | 起点として出す |
| 反応を書いた人に戻さない | 書く動機が消える | 「どこを読んだか」を聞いて戻す |
| ストーリーの本数を高く設定 | 息切れ | 月に数本から |
| 異動と退職を反映しない | いない人が残る | 情報を受けた週に反映 |
| 更新の記録が無い | いつから止まっているか分からない | 1行の記録と同じ場所に |

最も多いのは、最初の「集める仕組みが無い」です。書く担当と時間を決めれば更新は続く、と思われがちですが、ネタが無ければ続きません。

## 社内の分担

| 作業 | 誰が |
|---|---|
| 週に一度1行を拾う | 現場に近い人（持ち回りでも可） |
| 月に一度、書くものを選ぶ | 人事と代表 |
| ストーリーを書く | 人事（1行を拾った本人が書いてもよい） |
| 自分が関わる記事を直す | 代表、本人 |
| 会社ページの項目を直す | 人事 |
| 反応を聞き、書いた人に戻す | 面談に出る人と人事 |
| 記録と全体確認 | 人事 |

現場の負担は、「週に一度1行」と「自分が関わる記事を直す」だけです。書くのは人事が持ちます。運用代行や代理店が支えられるのは、1行を記事に膨らませる下書き、更新の項目の整理、記録の型までで、拾うことと確認は企業が行います。代理店の代行の範囲は[代理店に運用まで頼めるか](/media/kh-dairiten-unyou/)で書きました。

### エージェントベストの見解

自社で持つべきなのは、どこまでか。当社がWantedlyの運用を支えるとき、企業から拾った1行を、ストーリーの下書きに膨らませることは当社が行えます。1行に「〇日、顧客の△△さんに□□と言われた。営業の〇〇が持ち帰って、翌週に◇◇を変えた」とあれば、数段落の下書きは書けます。ただし、「拾う」ことは当社にはできません。社内で何があったかは、社内の人にしか分からないからです。当社が支えられる更新は、「拾う人が社内にいて、1行が毎週来る」ことが条件です。1行が来なければ、当社も書けません。来れば、書くのは当社でも人事でも構いません。更新の仕組みで企業に残るのは、拾うことと、自分が関わる記事を確認することの2つだけです。この2つが回れば、Wantedlyの会社ページは止まりません。

## まとめ

- 会社ページは公開した日が始まり。更新が止まると、会社ページに来る理由が無くなる
- 書く仕組みより先に、ネタを集める仕組み。週に一度「今週あったこと」を1行で拾う
- 更新する項目と頻度を決め、担当と締切を曜日と日で固定する。代表の確認は期限を過ぎたら人事の判断で公開
- 更新が止まる原因（ネタが無い・忙しい・確認待ち・完璧主義・反応が無い）に、先に対処を用意する
- 話を聞きに来た人に「どこを読んだか」を聞き、書いた人に戻す。これが続ける動機になる

## よくある質問

### 書くネタが無くて、更新が止まっています

書く時間ではなく、拾う仕組みが無い状態です。週に一度、決まった曜日に「今週あったこと」を1つ、1行で記録します。会議で決めたこと、顧客の一言、失敗、入社した人。何でも構いません。1行が月に数個溜まれば、書くものは選べます。

### 代表に書いてもらいたいのですが、忙しくて進みません

代表に書いてもらう必要はありません。代表には、月に一度「書くものを選ぶ」ことと、自分が関わる記事を「直す」ことだけをお願いします。書くのは人事です。代表の確認が遅れて止まらないよう、「期限を過ぎたら人事の判断で公開」と先に合意しておきます。

### 更新の仕組みづくりは、御社に相談できますか

できます。当社は、拾った1行をストーリーの下書きに膨らませること、更新する項目と頻度の整理、記録の型の提供を支えられます。拾うことと、自分が関わる記事の確認は、企業が行ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、Wantedlyの運用を見ています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
