技術系・理系の学生を採るために、技術と研究の情報を根拠に送るスカウト型（TECH OFFER）を使っている、または使おうとしている。OfferBoxも使っている。同じ「企業から送る」型なので、「理系はこちら、それ以外はOfferBox」と分けたつもりでも、文面を書く現場の時間が両方に取られ、技術の文面が薄くなる、という形で崩れます。**結論から言うと、TECH OFFERは「技術系の学生に、技術と研究の情報を根拠に送る場」、OfferBoxは「幅広い学生に、志向と経験で送る場」です。使い分けるなら、職種で分け、送る前に現場が「研究とうちの仕事のつながり」を一行で書き、文面の型と書く人を分け、現場の時間を技術の文面だけに使い、同じ学生に両方から送らない台帳を持ちます。** この記事では、それぞれの役割、職種の分け方、送る前に書く一行、文面の型と書く人、現場の時間、台帳、承認率の読み方、やりがちな失敗、社内の分担を整理します。理系の学生への文面は[OfferBoxで理系学生にオファーを送るときの文面](/media/ob-rikei-gakusei/)、理系の母集団形成は[理系の母集団形成](/media/kh-boshudan-rikei/)で書きました。両サービスの仕様と数値は書きません。

## それぞれの役割｜「技術の情報で絞って送る」と「志向と経験で送る」

| | TECH OFFER | OfferBox |
|---|---|---|
| 対象 | 技術系・理系の学生。対象の範囲は公式で確認 | 幅広い学生。理系も文系も |
| 送る根拠 | 研究の内容、技術の分野、専攻。読める情報の項目は公式で確認 | 記述の経験と志向、適性、専攻 |
| 文面に要る情報 | 研究や技術と、自社の仕事のつながり | 最初の年に何をするか、誰と組むか、記述のどこを見たか |
| 書く人 | 現場の技術者が関わる。人事だけでは書けない | 人事で書ける。現場の名義を借りることはある |
| 向く職種 | 研究、開発、設計、生産技術など、専攻と直結する職種 | 技術営業、生産管理、品質管理、文系総合職など、専攻に直結しない職種 |
| 時期 | 研究の予定（学会、修論）に左右される | 就職活動の一般的な時期 |

技術の情報で絞って送る媒体は、「研究と自社の仕事のつながり」を文面で言えるかで承認が決まります。これは現場の技術者にしか書けません。OfferBoxは、「記述のどの経験を見たか」と「最初の年に何をするか」で承認が決まり、人事で書けます。書く人が違うので、両方を同じ人が抱えると、技術の文面から止まります。

## 職種で分ける｜専攻に直結する職種と、しない職種

- **研究・開発・設計・生産技術など、専攻と直結する職種は、技術の情報で絞る媒体で**：研究の内容と仕事のつながりを言える学生に送る
- **技術営業・生産管理・品質管理・文系総合職など、専攻に直結しない職種は、OfferBoxで**：理系の学生でも、志向と経験で送る
- **同じ職種を両方から追わない**：追うと、同じ学生に二つの文面が届く
- **理系の学生を「理系」で一括りにしない**：研究職志望と、研究を続けない理系は、別の層。[理系の母集団形成](/media/kh-boshudan-rikei/)
- **研究職の検索の考え方**：[OfferBoxで研究開発職志望の学生を見つける検索の考え方](/media/ob-kenkyu-target/)

### エージェントベストの見解

これをやる前に、先に現場の技術者が「その研究と、うちの仕事のつながり」を一行で書けるかを確かめておかないと、技術で絞る媒体を足しても効果が出ません。当社は3媒体すべての販売パートナーとして、理系採用の相談を受けますが、技術で絞る媒体を足した会社で起きるのは、検索で研究の内容は読めるのに、「その研究がうちの何に活きるか」を書ける人が社内におらず、人事が「研究内容を拝見しました」で止まる文面を送る、という形です。学生は、研究を読まれたことより、「読んだうえで、うちの仕事とどうつながるか」を書かれているかで承認します。順番は、採りたい職種ごとに、現場の技術者が「〇〇の研究をしている学生なら、うちの△△の仕事で□□ができる」を一行で書き、その一行がある職種だけを技術で絞る媒体で追うことです。書けない職種は、OfferBoxで志向と経験で送ります。

## 文面の型と、書く人を分ける

| 型 | 書くこと | 書く人 |
|---|---|---|
| 技術に触れる型（TECH OFFER） | 研究のどこを読んだか、自社の仕事とのつながり、最初の年に触る技術と設備、誰と組むか | 現場の技術者が下書き、人事が整える |
| 志向と経験に触れる型（OfferBox） | 記述のどの経験を見たか、最初の年に何をするか、誰と組むか | 人事が下書き、名義の社員が確認 |

- **技術の型で、研究の専門用語を並べない**：学生は「うちの仕事で何をするか」を知りたい。研究内容の書き方は[OfferBoxで研究開発職を採るオファー文面の書き方](/media/ob-kenkyu-offer-bunmen/)
- **志向の型で、理系の学生に「理系だから」と書かない**：専攻に直結しない職種に理系を採るなら、「なぜこの職種に理系か」を書く。[理系向けのスカウト文面](/media/kh-bunmen-rikei/)
- **どちらの型でも、「最初の年に何をするか」は書く**
- **文面と、採用サイトの仕事紹介をずらさない**：[OfferBoxと採用サイトの役割分担](/media/ob-heiyou-saiyo-hp/)

## 現場の時間を、技術の文面だけに使う

- **現場の技術者に頼むことを、三つに絞る**：技術の文面の下書き、名義、面談。OfferBoxの志向の型は頼まない
- **技術の文面は、一人あたりの時間が大きい**：研究を読んで、つながりを書く。送る数を、現場が書ける数から逆算する
- **OfferBoxの検索・文面下書き・送信・一次返信は、人事か代行で回す**：現場の時間を使わない
- **同じ現場の社員が、両方の名義を貸すのはよい**：名義は同じで、書く人が違う
- **現場が協力しないときは、頼む範囲が広すぎることが多い**：[OfferBoxの運用に現場社員を巻き込む方法](/media/ob-genba-makikomi/)

理系の学生の取り合いに負けるとき、原因は媒体ではなく、文面につながりが書けていないことが多いです。[理系学生の取り合いに負けるときのOfferBox運用](/media/ob-rikei-toriai/)

## 同じ学生に両方から送らない台帳

- **送る側の台帳を一つにし、媒体の列と職種の列を持つ**：理系の学生は、両方に登録していることがある
- **送る前に、もう一方の媒体で送った学生と名前を突き合わせる**
- **片方で承認した学生には、もう片方から送らない**
- **承認からあとは、来た学生の台帳で、職種ごとに同じ段と基準**：[OfferBoxと採用管理システム（ATS）の連携の考え方](/media/ob-heiyou-ats/)
- **面談で「どちらの文面のどこを見たか」を聞く**：技術のつながりが効いたか、志向の場面が効いたか

## 送る時期と、承認率の読み方

- **技術で絞る媒体の送る時期は、研究の予定に合わせる**：学会、修論、実験の繁忙で、学生が動けない時期がある。記述から読む
- **OfferBoxの送る時期は、就職活動の一般的な時期に**：[OfferBoxのオファーを送る時期と時間帯の考え方](/media/ob-soushin-timing/)
- **二つの送る時期を同じ週に重ねない**：承認への当日返信が集中する
- **承認率を並べない**：技術で絞って送った承認率と、幅広く送った承認率は、母集団も文面も違う。それぞれの媒体の中で先月と比べる
- **見るのは、職種ごとに、面談まで来た「近い」学生の数**：[OfferBoxを含む複数媒体の効果を並べて見る方法](/media/ob-heiyou-heiyou-kpi/)
- **費用は、各媒体の現在の条件を公式ページで確認する**：配分は[OfferBoxを含む複数媒体の予算配分の考え方](/media/ob-heiyou-heiyou-yosan/)

## やりがちな失敗

| 失敗 | 何が起きるか | 直し方 |
|---|---|---|
| 「つながり」を書ける人がいないまま技術で絞る媒体を足す | 「研究内容を拝見しました」で止まる文面になる | 一行を書ける職種だけ追う |
| 同じ職種を両方から追う | 同じ学生に二つの文面が届く | 職種で分け、突き合わせる |
| 現場にOfferBoxの文面まで頼む | 技術の文面から止まる | 現場は技術の文面だけ |
| 研究の予定を見ずに送る | 学生が動けない時期に届き、開封されない | 記述から時期を読む |
| 承認率を並べて片方を止める | 母集団の違う数で判断する | 職種ごとの近い学生の数で見る |

最も多いのは、一つ目です。技術で絞る媒体を足せば研究職が採れると考え、つながりを書ける人を決めないまま送り始めます。

## 社内の分担

| 作業 | 誰が |
|---|---|
| 採りたい職種を、専攻に直結するかで分ける | 人事と現場の責任者 |
| 「研究とうちの仕事のつながり」を職種ごとに一行で書く | 現場の技術者 |
| 技術の文面の下書き | 現場の技術者。人事が整える |
| OfferBoxの検索・文面下書き・送信・一次返信 | 人事、または代行 |
| 送る側の台帳を一つにし、突き合わせる | 人事（代行と） |
| 面談で「どちらの文面のどこを見たか」を聞く | 面談に出る人 |
| 現場の時間の配分 | 現場の責任者と人事 |

運用代行や代理店が支えられるのは、役割の整理、職種の分け方の型、文面の型、台帳と突き合わせの型、OfferBoxの検索・文面下書き・送信・一次返信、技術の文面を整える作業までで、職種の決定、「つながり」の一行、技術の文面の下書き、面談は企業の現場が行います。代理店の代行の範囲は[代理店に運用まで頼めるか](/media/kh-dairiten-unyou/)で書きました。

### エージェントベストの見解

技術で絞る媒体の承認率と、OfferBoxの承認率は、母集団も文面の型も違う数字なので、並べても優劣にはなりません。当社はOfferBoxの運用代行を受けているので、理系採用で両方を使う会社の数字を見ますが、「技術で絞る媒体のほうが承認率が高いので、OfferBoxは理系には効かない」という読み方をする会社があります。技術で絞る媒体は、研究の内容で絞った少数に、現場が書いた文面を送るので、承認の割合は高くなりやすく、OfferBoxは、幅広い学生に志向の型で送るので、割合は低くなりやすい。割合の差は、媒体の性能ではなく、絞り方と文面の型の差です。当社が見るのは、割合ではなく、職種ごとに面談まで来た「近い」学生の数で、研究職は技術で絞る媒体から、技術営業や生産管理はOfferBoxから、というように、職種ごとに効いている入口が違うのが普通です。割合で片方を止めると、その職種の入口を失います。

## まとめ

- TECH OFFERは「技術系の学生に、技術と研究の情報を根拠に送る場」、OfferBoxは「幅広い学生に、志向と経験で送る場」。書く人が違う
- 専攻に直結する職種は技術で絞る媒体で、直結しない職種はOfferBoxで。同じ職種を両方から追わない
- 送る前に、現場の技術者が「研究とうちの仕事のつながり」を職種ごとに一行で書く。書けない職種は技術で絞る媒体で追わない
- 現場に頼むのは技術の文面・名義・面談の三つ。OfferBoxの志向の型は人事か代行で回す
- 台帳を一つにして突き合わせ、送る時期を重ねず、承認率を並べない。職種ごとに面談まで来た近い学生の数で見る

## よくある質問

### 研究職の採用で、OfferBoxだけでは足りませんか

「研究とうちの仕事のつながり」を書ける現場の技術者がいて、OfferBoxの記述から研究の内容が読める範囲で足りているなら、OfferBoxだけでも回ります。研究の内容をより深く読んで絞りたい、専攻と直結する職種の母集団が足りない、というときに、技術で絞る媒体を足す意味があります。足す前に、つながりを書ける人がいるかを確かめます。

### 現場の技術者が、文面を書く時間を取れません

書いてもらうのではなく、「〇〇の研究をしている学生なら、うちの△△で□□ができる」の一行を、職種ごとに口頭で聞き、人事が文面に整える形にします。一行があれば、研究の内容ごとに文面を組めます。一行も取れないなら、その職種は技術で絞る媒体で追わず、OfferBoxで志向の型に絞ります。

### OfferBoxとTECH OFFERの使い分けは、御社に相談できますか

できます。当社は、役割の整理、職種の分け方の型、文面の型、台帳と突き合わせの型、OfferBoxの検索・文面下書き・送信・一次返信、技術の文面を整える作業を支えられます。職種の決定、「つながり」の一行、技術の文面の下書き、面談は、企業の現場が行ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、OfferBoxの運用代行も受けています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
