採用管理システムを入れるほどではないので、表計算で候補者を管理している。最初は一枚の表だったのに、媒体ごとにシートが増え、色分けが増え、集計のたびに手で数え直している。**結論から言うと、表計算で採用データを管理するなら、「候補者一人を一行にする」「入力を選択肢と日付にそろえる」「集計は別のシートで出す」の三つを守る型が崩れにくい形です。** この記事では、列の組み方、入力のルール、集計の分け方、複数人で使うときの決めごとを整理します。

## 表計算の管理が崩れる流れ

表計算の採用管理は、始めやすい反面、使ううちに崩れていきます。よくある流れは次のとおりです。

- 媒体ごとにシートを分け、同じ人が二つのシートに載る
- 選考の段を、色やセルの塗りで表す。集計できない
- 「一次通過」「1次OK」「一次○」のように、同じ意味の書き方が混ざる
- 面接の感想を一つのセルに長く書き、ほかの列が埋まらない
- 集計のための列を台帳の横に足していき、表が横に長くなる

どれも、その場では便利な工夫です。しかし、半年後に「媒体ごとに何人が一次を通ったか」を出そうとしたとき、手で数えるしかなくなります。

## 一人一行の台帳を作る

型の中心は、候補者一人を一行にした台帳です。媒体ごとにシートを分けず、入口は列で表します。

| 列 | 入れる内容 | 入力の形 |
|---|---|---|
| 番号 | 候補者ごとの通し番号 | 自動または連番 |
| 入口 | 媒体・紹介・紹介制度など | 選択肢 |
| 区分 | 新卒・中途 | 選択肢 |
| 職種 | 応募した職種 | 選択肢 |
| 起点の日 | 応募が届いた日、または返信をもらった日 | 日付 |
| いまの段 | 書類・一次・二次・最終・内定・承諾・入社 | 選択肢 |
| 一次の日 | 一次面接を行った日 | 日付 |
| 最終の日 | 最終面接を行った日 | 日付 |
| 内定の日 | 内定を伝えた日 | 日付 |
| 止まった理由 | 不合格・辞退・連絡なし | 選択肢 |
| 担当 | 社内の担当者 | 選択肢 |
| メモ | 一言だけ | 短い文 |

列は、最初は少なめに始めます。足りなくなったら足せばよく、使わない列があると入力が止まる原因になります。

候補者の氏名や連絡先を台帳に入れるかは、社内の個人情報の扱いに合わせて決めます。台帳には番号だけを置き、氏名は媒体の管理画面や別の場所で確かめる運用にすると、表を共有しやすくなります。個人情報の扱いは、法令で定められたことや社内の規程があるので、社内の担当部署や公式の案内で確かめてください。

## 入力のルールを三つ決める

台帳の列を決めたら、入力のルールを三つ決めます。

1. **選択肢の列は、選択肢以外を入れない**：表計算の入力規則の機能を使い、決めた言葉しか選べないようにします。「一次通過」と「1次OK」が混ざるのを防げます
2. **日付の列は、日付の形でだけ入れる**：「来週」「調整中」のような言葉を日付の列に入れません。決まっていなければ空欄にし、決まったら日付を入れます
3. **色で意味を持たせない**：色は見やすさのために使って構いませんが、色だけで段や結果を表しません。色は集計できないからです

三つ目は、とくに崩れやすい点です。「黄色は保留」のような決めごとは、担当者が替わると伝わりません。意味は列の値で持ち、色は値に合わせて自動で付く形にしておきます。

日付の列は、選考期間を出すときの材料になります。どの日付を記録すると期間を段ごとに分けられるかは[選考期間の測り方と縮め方](/media/kh-dt-kikan/)で整理しています。

## 集計は別のシートで出す

台帳の横に集計の列を足していくと、表が崩れます。集計は別のシートに分けます。

- **台帳のシート**：一人一行。入力だけをする
- **集計のシート**：台帳から数を数える式だけを置く。入口ごと、段ごと、月ごとの数
- **記録のシート**：選考の進め方や媒体の使い方を変えた日と、その内容

集計のシートは、台帳を数える式で作るので、台帳に入力すれば自動で更新されます。手で数え直す作業がなくなります。記録のシートは、数字が変わった理由をあとで確かめるためのものです。たとえば、スカウトの文面を変えた日を書いておくと、その前後で返信が変わったかを確かめられます。

シートの持ち方は[スプレッドシートで採用KPIを管理する方法](/media/kh-kpi-spreadsheet/)でも扱っています。集計した数をどう見せるかは[採用のダッシュボードの作り方](/media/kh-dt-dashboard/)にまとめています。

### エージェントベストの見解

表計算で採用データを管理している会社から、よく聞く相談に「媒体ごとにシートを分けたら、同じ学生が二つに載っていた」というものがあります。新卒採用では、OfferBoxでスカウトを受けた学生が、ワンキャリアの掲載を見て説明会に申し込むことがあります。媒体ごとのシートでは、同じ学生が二人として数えられ、母集団が実際より多く見えます。これを防ぐには、入口の列を「最初に接点を持った入口」と「応募が来た入口」の二つに分けておくのが有効です。シートを一枚にし、入口を二つの列で持てば、重複は台帳を並べ替えるだけで見つけられます。3媒体を並行して使う会社ほど、媒体を増やす前にこの二つの列を作っておくと、あとで媒体ごとの効果を比べるときに数が崩れません。

## 複数人で使うときの決めごと

人事担当が複数いたり、現場の面接官も入力したりする場合は、次のことを決めます。

- **誰がどの列を入力するか**：面接の日と結果は面接官、段の更新は人事、というように列ごとに担当を決めます
- **入力の期限**：面接の当日中、結果を返したら翌営業日まで、のように決めます。入力が遅れると、集計がその分だけ古くなります
- **触ってよい範囲**：集計のシートや選択肢の一覧は、決まった人だけが直せるようにします。誰でも直せると、式が壊れます
- **過去の版を残す**：表計算の版の履歴を使えるようにしておき、誤って消したときに戻せるようにします

決めごとは、台帳の一番上か、別のシートに短く書いておきます。新しく入力する人が増えたときに、それを読めば分かる状態にします。

### エージェントベストの見解

表計算から採用管理システムに移るかどうかを相談されたとき、当社が先に確かめるのは、表計算の台帳が「一人一行・選択肢・日付」の型で回っているかです。この型で回っていない会社がシステムを入れても、入力のルールが決まっていないまま画面だけが変わり、システムの中でも同じ崩れ方をします。逆に、型で回っている会社は、台帳の列をそのままシステムの項目に置き換えられるので、移るのが速くなります。移る目安としては、入力する人が増えて表の上書きが起きるようになった、候補者への連絡まで一つの画面でしたくなった、といった時点が考えられます。人数や件数だけで決めず、表計算の型が自社の運用に合っているかを先に確かめることを勧めます。システムの使い方は[採用管理システムのデータの使い方](/media/kh-dt-ats/)で整理しています。

## まとめ

- 表計算の台帳は、媒体ごとに分けず、候補者一人を一行にする
- 入口・段・結果は選択肢、期間に使う列は日付の形でだけ入れる
- 色で意味を持たせず、意味は列の値で持つ
- 台帳・集計・変えた記録の三つのシートに分け、集計は式で自動にする
- 複数人で使うときは、列ごとの担当、入力の期限、触ってよい範囲を決める

## よくある質問

### 面接の感想はどこに書けばよいですか

台帳のメモ列には一言だけ書き、詳しい感想は面接の評価シートに残します。台帳に長い文を書くと、ほかの列が見えにくくなり、入力も止まりやすくなります。評価シートの形は[面接の記録の残し方](/media/kh-ms-kiroku/)で整理しています。

### 新卒と中途は、別の台帳にしたほうがよいですか

一つの台帳で区分の列を持つほうが、全体の数を出しやすくなります。ただ、新卒と中途で選考の段が大きく違う場合は、段の選択肢が混ざって分かりにくくなるので、台帳を分けても構いません。分ける場合も、列の並びは同じにしておきます。

### 表計算とシステムのどちらがよいですか

会社の状況によって異なります。入力する人が少なく、型で回っているうちは表計算でも十分です。道具の選び方は[採用管理の道具の選び方](/media/kh-pl-tool/)にまとめています。
