エンジニアの採用で、技術の情報を根拠に候補者を絞って送るサービス（Findy）とWantedlyの両方を使っている、または使おうとしている。二つの違いは分かっていても、「文面に何を書き、記事に何を書くか」「エンジニアの時間を、文面と記事にどう分けるか」「送った候補者に、何を読んでもらうか」が決まっていないと、エンジニアの時間が文面に吸われ、記事が止まります。**結論から言うと、Findyは「技術の情報で絞って送る場」、Wantedlyは「開発の考え方を読んでもらう場」です。使い分けるなら、送る前に「作り方」のストーリーを一本出し、文面には技術の要件と「なぜあなたか」を、記事には技術選定の理由と失敗と改善を書き、エンジニアの時間を文面と記事で別の人に分け、面談の入口を一つにします。** この記事では、それぞれの役割、送る前に出すストーリー、文面と記事の線、エンジニアの時間の分け方、面談の入口と台帳、工数、やりがちな失敗、社内の分担を整理します。二つの違いそのものは[WantedlyとFindyの違い](/media/hikaku-wantedly-findy/)で書きました。この記事は、両方を持ったあとの運用の使い分けを扱います。両サービスの仕様と数値は書きません。

## それぞれの役割｜「技術で絞って送る」と「作り方を読む」

| | Findy | Wantedly |
|---|---|---|
| 送る根拠 | 候補者の技術の情報。公開されている活動や経歴 | 候補者の関心と、会社の考え方への反応 |
| 候補者の状態 | 送られた側。技術が合うかで開封し、会社は知らない | 読んだ側。開発の考え方を読んで「話を聞きに行きたい」と来る |
| 候補者が次にすること | 会社の技術と作り方を調べる | 面談に来る |
| 会社が用意するもの | 技術の要件、候補者ごとの文面、送る人の名義 | 開発の考え方のストーリー、募集記事、会社ページ |
| 書く人 | 技術が分かる人。エンジニアリングマネージャーなど | 作り方を語れる人。リードエンジニアや技術責任者 |
| 時期 | 送る時期に集中 | 通年。記事が残る |

技術で絞って送られた候補者は、「技術は合いそうだ」と思ったあと、「この人たちはどう作っているか」を調べます。技術選定の理由、失敗と改善、レビューの文化、意思決定の速さ。これは文面に書ききれず、公開されている技術情報からも分かりません。読む場所がWantedlyのストーリーです。

## 送る前に、「作り方」のストーリーを一本出す

- **技術責任者かリードエンジニアの名義で、「どう作っているか」を一本**：技術選定の理由、変えたこと、失敗と直したこと。製品名を並べない
- **文面に、そのストーリーへの導線を置く**：貼れる形は現在の仕様で確認。貼れないなら「〇〇という記事に書きました」
- **文面で触れた「作り方」を、記事で詳しく**：文面は「なぜあなたか」と要件に絞り、作り方は記事に
- **送る人と、記事の書き手が違ってよい**：文面はエンジニアリングマネージャー、記事は技術責任者。ただし、文面の「私たちの作り方」と記事の内容がずれない
- **募集記事に、最初の三か月で何を触るかを書く**：[Wantedlyでエンジニアを採る募集記事の書き方](/media/wt-engineer-boshu/)

「作り方」のストーリーは、技術の詳細ではなく、判断の場面です。「〇〇を選んだ理由は△△で、□□で困って、◇◇に変えた」。候補者は、技術の名前ではなく、判断の仕方で「合うか」を見ます。Wantedly側のスカウトの考え方は[Wantedlyでエンジニアにスカウトを送る文面の考え方](/media/wt-engineer-scout/)で書きました。

### エージェントベストの見解

これをやる前に、先に「作り方」のストーリーを一本出しておかないと、技術で絞って送っても効果が出ません。当社は3媒体すべての販売パートナーとして、エンジニア採用でFindyとWantedlyを併用する会社の相談を受けますが、文面は候補者ごとに丁寧に書いているのに、Wantedlyの会社ページを開くと、事業の説明と募集要項だけで、開発の考え方が一本もない、という状態が多くあります。技術で口説かれた候補者は、承認する前に「どう作っているか」を調べます。調べても出てこないと、「技術は合いそうだが、進め方が分からない」で止まり、返信が来ません。当社が併用の相談で最初に確かめるのは、技術責任者の名義で「なぜその技術を選び、何を変えたか」が読める記事があるかです。なければ、文面の改善より先に、その一本を出してもらいます。一本あると、文面は短くなり、返信の内容が「作り方」の話から始まります。

## 文面に書くことと、記事に書くことの線

| 文面（Findy） | 記事（Wantedly） |
|---|---|
| なぜあなたに送ったか。候補者の公開されている活動のどこを見たか | 会社の開発の考え方。技術選定の理由 |
| このポジションの技術の要件と、触るもの | 失敗と改善の場面。レビューと意思決定の文化 |
| 最初の三か月で何をするか、の一文 | 最初の三か月の詳しい中身と、誰と組むか |
| 「作り方は記事に書きました」の導線 | 技術責任者の「なぜ」と、これから変えたいこと |
| 書かない：技術の自慢、製品名の羅列、条件の詳細 | 書かない：技術の詳細だけ。判断の場面がないもの |

- **文面と記事の「作り方」をずらさない**：文面で「速い意思決定」、記事で「合議」だと、面談で「聞いていたのと違う」になる
- **条件は募集記事に**：文面に条件を並べない。書き方は[Wantedlyの募集記事に条件をどこまで書くか](/media/wt-boshu-joukenn/)
- **文面と記事を、最後に同じ人が見る**：書く人が違っても、見る人は一人

## エンジニアの時間を、文面と記事で分ける

- **文面はエンジニアリングマネージャー、記事は技術責任者かリードエンジニア**：同じ人が両方を抱えると、記事から止まる
- **文面の時間は、送る時期に集中する**：候補者ごとに書くので、一人あたりの時間が大きい。送る数を、書ける時間から逆算する
- **記事の時間は、月に一度、固定する**：話す時間を人事が取り、書くのは本人か、人事が整える
- **人事が持つのは、送る相手の一次の絞り込みと、返信の管理と、記事を整える部分**：技術の判断は持たない
- **文面の下書きを外に出すかは、技術の要件が言葉になっているかで決める**：言葉になっていれば、下書きは出せる。技術の判断は出せない

エンジニアの時間が足りないときの考え方は[Wantedlyの運用に工数が足りないとき](/media/wt-kousuu/)で書きました。エンジニア採用では、「エンジニアの時間」が予算そのものです。

## 面談の入口と台帳を一つにする

- **どちらから来ても、最初は「話を聞く面談」から**：技術の面接を最初に置かない。[Wantedlyのカジュアル面談の設計](/media/wt-scout-casual-mendan/)
- **Findy経由の候補者にも、面談の前に「作り方」のストーリーを読んでもらう**：文面で導線を置いていれば、読んで来る
- **面談に、記事の書き手が出る**：候補者は、読んだ記事の人と話したい
- **台帳は一つ**：入口の列に「Findy」と「Wantedly」。送信と開封と返信はそれぞれの中で、面談から先は共通の段
- **面談で「文面のどこ、記事のどこを見たか」を聞く**：技術の要件と作り方の、どちらが効いたかが分かる

台帳と段の揃え方は[Wantedlyを含む複数媒体の効果を並べて見る方法](/media/wt-heiyou-heiyou-kpi/)で書きました。

## 工数の配分

| 時間の種類 | Findy | Wantedly |
|---|---|---|
| エンジニアの時間 | 候補者ごとの文面、技術の要件の言語化、面談 | 「作り方」を話す時間、記事の確認、面談 |
| 人事の時間 | 一次の絞り込み、送信、返信の管理 | 記事を整える、募集記事、返信の管理 |
| 外に出せる部分 | 文面の下書き（要件が言葉になっていれば）、送信、一次の返信 | 整える部分。作り方を話す中身は出せない |
| 費用 | 各サービスの現在の条件を公式で確認。この記事では書かない | プランの費用。公式ページで確認 |

- **エンジニアの時間を、文面と記事で週に何時間ずつかを先に決める**：決めないと、文面に全部使われる
- **送る数を、書ける時間から逆算する**：送れる数ではなく、書ける数
- **記事は積み上がり、文面は残らない**：時間が足りないときは、記事を残す。配分の考え方は[Wantedlyを含む複数媒体の予算配分](/media/wt-heiyou-heiyou-yosan/)

## やりがちな失敗

| 失敗 | 何が起きるか | 直し方 |
|---|---|---|
| 「作り方」の記事がないまま送る | 候補者が調べても出てこず、返信が来ない | 技術責任者の一本を先に |
| 文面に技術の自慢と製品名を並べる | 候補者が「なぜ自分か」を読み取れない | 文面は「なぜあなたか」と要件に絞る |
| 同じエンジニアが文面と記事の両方を抱える | 記事から止まる | 別の人に分ける |
| 技術の面接を最初に置く | 転職を決めていない候補者が離れる | 話を聞く面談から |
| 送信数で効果を見る | 返信の内容と面談の言葉を見ない | 面談で「どこを見たか」を聞く |

最も多いのは、一つ目です。文面を丁寧に書くことに時間を使い、候補者が調べに来たときの記事がありません。

## 社内の分担

| 作業 | 誰が |
|---|---|
| 技術の要件を言葉にする | エンジニアリングマネージャーと技術責任者 |
| 「作り方」のストーリーを話す・書く | 技術責任者かリードエンジニア。人事が整える |
| 候補者ごとの文面を書く | エンジニアリングマネージャー（下書きは外に出せる） |
| 一次の絞り込み、送信、返信の管理 | 人事 |
| 文面と記事の「作り方」を揃えて見る | 人事（一人） |
| 面談に出る | 記事の書き手と、文面を送った人 |
| エンジニアの時間の配分 | 技術責任者と責任者 |

運用代行や代理店が支えられるのは、役割の整理、文面と記事の線の型、台帳の型、Wantedlyの整える部分、文面の下書き（要件が言葉になっていれば）までで、技術の要件の決定、作り方を話すこと、技術の判断、面談は企業のエンジニアが行います。代理店の代行の範囲は[代理店に運用まで頼めるか](/media/kh-dairiten-unyou/)で書きました。

### エージェントベストの見解

両方を使い始めたあと、最初の数か月で起きることに共通するのは、エンジニアの時間が文面に使われ、記事が止まることです。当社はWantedlyの運用を申込のあとまで見ていますが、技術で絞って送るサービスを始めた会社では、エンジニアリングマネージャーが候補者ごとの文面に週の時間を使い、「記事はあとで」になり、送られた候補者が調べに来たときに、半年前の会社ページが出ている、という形が多くあります。文面は送った相手にしか届かず、残りません。記事は、送った相手にも、Wantedlyから来た人にも届き、残ります。時間が足りないなら、先に減らすのは文面の数で、記事ではありません。当社が併用する会社に勧めているのは、送る数を「書ける時間」から逆算して減らし、その分の時間で、月に一本の「作り方」の記事を技術責任者に話してもらうことです。送る数が減っても、返信の内容が変わります。

## まとめ

- Findyは「技術の情報で絞って送る場」、Wantedlyは「開発の考え方を読んでもらう場」。送られた候補者は「どう作っているか」を調べる
- 送る前に、技術責任者かリードエンジニアの名義で「作り方」のストーリーを一本出し、文面から導線を置く
- 文面には「なぜあなたか」と技術の要件を、記事には技術選定の理由と失敗と改善を。「作り方」をずらさず、最後に同じ人が見る
- エンジニアの時間を、文面（エンジニアリングマネージャー）と記事（技術責任者）で分け、送る数を書ける時間から逆算する
- 面談の入口は「話を聞く面談」から。台帳は一つ。時間が足りないときは、文面の数を減らし、記事を残す

## よくある質問

### 技術責任者が忙しく、記事を書く時間がありません

書いてもらうのではなく、月に一度、話してもらう時間を取り、人事が整える形にします。「〇〇を選んだ理由と、困ったことと、変えたこと」を聞くだけなら、短い時間で済みます。文面に使っている時間の一部を、この時間に回します。文面は残らず、記事は残ります。

### Findyの文面に、Wantedlyの記事を貼ってよいですか

貼れる形と範囲は、現在の仕様で確認してください。貼れない場合も、「〇〇という記事に、私たちの作り方を書きました」と触れれば、候補者は会社名と書き手の名前で探します。大切なのは、貼れるかどうかより、調べたときに出てくる記事があることです。

### WantedlyとFindyの使い分けは、御社に相談できますか

できます。当社は、役割の整理、文面と記事の線の型、台帳の型、Wantedlyの整える部分、文面の下書きを支えられます。技術の要件の決定、作り方を話すこと、技術の判断、面談は、企業のエンジニアが行ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、Wantedlyの運用を支えています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
