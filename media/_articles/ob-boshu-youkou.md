募集要項は、書かなければならない項目を埋めるもの、と思われがちです。**結論から言うと、募集要項は学生が「自分に関係するか」を確かめる場で、学生は上から順に読まず、自分に関係する項目から読みます。読む順番に合わせて、仕事内容、勤務地、条件、選考の流れ、求める人物の順に、それぞれを具体的に書くと、承認したあとの「条件が合わない」という辞退が減ります。** この記事では、学生が読む順番、項目ごとの書き方、やりがちな失敗、人事と現場の分担を整理します。OfferBoxの募集要項の項目の仕様には触れず、考え方だけを書きます。企業ページとの役割の違いは[企業ページで伝えること・伝えないこと](/media/ob-kigyo-page/)で書きました。企業ページが「興味を運ぶ場」なら、募集要項は「条件を確かめる場」です。

## この作業の目的｜承認のあとの「条件が合わない」を無くす

文面で興味を持ち、企業ページで仕事の中身を読み、承認し、面談に来た学生が、面談のあとで「勤務地が合わない」「条件が想像と違った」と辞退する。これは、募集要項が読まれていないか、読んでも分からない書き方だったときに起きます。

募集要項の目的は、承認する前に、学生が自分で条件を確かめられる状態にすることです。確かめたうえで承認した学生は、条件で辞退しません。確かめずに承認した学生は、面談のあとで辞退します。

「条件を隠さず、正確に、学生が読む順番で書く」。それが募集要項の書き方です。

## 学生が読む順番

学生は、募集要項を上から順に読みません。自分に関係する項目から読みます。順番は、おおむね次のとおりです。

1. **仕事内容**：何をする仕事か。自分にできそうか、やりたいか
2. **勤務地**：通えるか、引っ越しが要るか
3. **条件**：給与、勤務時間、休日。生活が成り立つか
4. **選考の流れ**：承認したら何が起きるか。どのくらいかかるか
5. **求める人物**：自分が対象か
6. **会社の説明**：最後に、どんな会社かを確かめる

この順番は、学生が「自分」を起点に読むからです。会社の説明を最初に置いても、読まれるのは最後です。項目の並びを変えられない場合でも、それぞれの項目の中で「学生が知りたいこと」を先に書きます。

## 項目1｜仕事内容

最も読まれる項目です。抽象的な職種名だけでは、学生は自分にできるかを判断できません。

| 書くこと | 書き方 |
|---|---|
| 職種名 | 学生が知っている一般的な言葉で。社内用語や独自の職種名は避けるか、一言で説明する |
| 最初の仕事 | 入社して最初の数ヶ月で何をするか。研修の後に何を任されるか |
| 1日の流れ | 朝から夕方まで、どう過ごすか。会議、作業、外出、の配分 |
| 誰と一緒にやるか | チームの規模感、上司や先輩との関わり方 |
| 仕事の難しさ | 大変な部分。隠さない。面談で「聞いていない」とならないように |
| 数年後の姿 | この仕事を続けると、どうなるか。分かる範囲で |

「最初の仕事」と「1日の流れ」があると、学生は自分が働く姿を想像できます。「〇〇業務全般」のような書き方では、想像できません。仕事の中身は、文面のテンプレートと企業ページと同じ元から作ります。

### エージェントベストの見解

相談で最も多い思い込みは、「募集要項は決まった項目を埋めるもので、学生はあまり読まない」というものです。実際には、学生は文面で興味を持ったあと、承認する前に募集要項を読み、「自分に関係するか」を確かめています。当社は3媒体すべての販売パートナーとしてOfferBoxの契約後の運用を見ていますが、面談のあとに「勤務地が合わない」「条件が想像と違う」で辞退が出る会社の募集要項を見ると、勤務地が「本社および各拠点」、給与が「当社規定による」のように、確かめようがない書き方になっています。学生は確かめられないまま承認し、面談で初めて知り、辞退します。募集要項を具体的に書くと、承認の数は少し減るかもしれませんが、承認した学生の辞退が減ります。承認の数より、面談に進んだあとに残る数のほうが、採用には効きます。隠さず、正確に、学生が確かめられる形で書くことを勧めます。

## 項目2｜勤務地

勤務地は、学生が最初に確かめる条件の1つです。曖昧に書くと、承認のあとに辞退が出ます。

- **初任の勤務地を明記する**：「本社および各拠点」ではなく、最初に配属される可能性がある場所を列挙する
- **転勤の有無と時期の目安**：あるなら「入社後数年で転勤の可能性がある」と書く。無いなら「転勤なし」
- **在宅や出社の形**：出社が前提か、在宅が可能か。週の配分の目安
- **通勤の目安**：最寄りの駅や、車通勤の可否。地方の学生には特に

「配属は入社後に決まる」場合は、そう書いたうえで、候補地を列挙します。候補地が分かれば、学生は「通えるか」を判断できます。

## 項目3｜条件

給与、勤務時間、休日、手当。ここを曖昧にすると、面談のあとで辞退が出ます。

| 項目 | 書き方 |
|---|---|
| 給与 | 初任給を、学歴や職種ごとに正確に。「当社規定による」は避ける。固定残業代があるなら、その内訳 |
| 勤務時間 | 始業と終業、休憩、時間外の実態。「実態」を書かないと、面談で聞かれる |
| 休日 | 年間の休日の形、土日祝の扱い、繁忙期の状況 |
| 手当と福利厚生 | 学生に関係するものだけ。住宅手当、通勤手当、研修。一覧の羅列は不要 |
| 試用期間 | 有無と期間、その間の条件の違い |

条件は、社内で確認してから正確に書きます。間違えると、承諾のあとに問題になります。金額を含む条件は、人事が最終確認します。「隠さない」と「正確に」の両方が要ります。

## 項目4｜選考の流れ

承認したら何が起きるかを、段階と時期で書きます。

1. **承認のあと**：まず面談。選考ではないこと。誰が出るか
2. **選考の段階**：段階の数と、それぞれで何を見るか
3. **時期の目安**：承認から内定までのおおよその期間
4. **必要なもの**：エントリーシートの有無、適性検査の有無、提出物

選考の流れが分かると、学生は「承認したらいきなり選考か」と構えずに済みます。書き方は企業ページと揃えます。選考フローの設計は[選考フローを短くする考え方](/media/ob-senkou-sekkei/)で書きました。

## 項目5｜求める人物

「主体性のある方」「コミュニケーション力のある方」では、学生は自分が対象か判断できません。行動の型で書きます。

- **抽象語を行動に置き換える**：「主体性」→「分からないことを自分で調べて、それでも分からなければ人に聞ける」
- **ペルソナから引く**：ペルソナの「行動」の部分が、そのまま求める人物になる。作り方は[採りたい学生像を言葉にする](/media/ob-persona/)
- **必須と歓迎を分ける**：無いと選考に進めないもの（譲れない条件）と、あれば嬉しいものを分ける。分け方は[OfferBoxのターゲット設計](/media/ob-target-sekkei/)
- **学部や資格の条件は正確に**：必要なら書く。不要なら「学部不問」と明記する

「求める人物」を行動で書くと、学生は「自分はこういう行動をしてきたか」で判断できます。抽象語だと、誰もが「自分は当てはまる」と思うか、誰も判断できないかのどちらかです。

## やりがちな失敗

| 失敗 | 何が起きるか | 直し方 |
|---|---|---|
| 職種名が社内用語 | 学生が何の仕事か分からない | 一般的な言葉に直すか、一言で説明する |
| 仕事内容が「〇〇業務全般」 | 働く姿を想像できない | 最初の仕事と1日の流れを書く |
| 勤務地が「本社および各拠点」 | 通えるか判断できず、面談後に辞退 | 初任の候補地を列挙する |
| 給与が「当社規定による」 | 生活が成り立つか判断できない | 正確に書く。固定残業代の内訳も |
| 時間外の実態を書かない | 面談で聞かれ、答えに詰まる | 実態を書く |
| 求める人物が抽象語 | 自分が対象か判断できない | 行動の型で書く |
| 会社の説明を最初に置く | 読まれない | 仕事内容を先に |
| 文面や企業ページと矛盾する | 「どれが本当か」と迷う | 同じ元から作る |
| 良いことだけ書く | 面談で「聞いていない」となる | 難しさも書く |

最も多いのは、「勤務地」と「給与」の曖昧さです。書きにくい理由（配属が決まっていない、規定が複雑）はあっても、学生が確かめられる形まで具体化します。

## 社内の分担

| 項目 | 誰が |
|---|---|
| 仕事内容 | 人事が下書き、現場が直す（テンプレート・企業ページと同じ元） |
| 勤務地 | 人事（配属の候補は事業部門に確認） |
| 条件 | 人事（金額を含む条件は最終確認） |
| 選考の流れ | 人事（企業ページと揃える） |
| 求める人物 | 人事（ペルソナから引き、面接官と合意） |
| 学生の目線で読む | 入社して間もない社員 |
| 更新 | 人事（条件の変更時、卒年の切り替わり） |

条件の正確さは人事の責任で、仕事の中身の実態は現場の責任です。この2つを分けて確認します。運用代行に出している場合、募集要項の下書きは代行が行えますが、条件の最終確認と仕事の実態は企業が行います。代行の範囲は[代理店に運用まで頼めるか](/media/kh-dairiten-unyou/)で書きました。

### エージェントベストの見解

これをやる前に、先に決めておかないと募集要項が書けないことがあります。「初任の勤務地の候補」と「初任給の正確な金額」を、社内で確定することです。当社がOfferBoxの運用の相談で募集要項を見るとき、この2つが曖昧な会社は、社内で決まっていないことが多く、決まっていないから書けない、という状態です。書けないまま送り始めると、面談で学生に聞かれ、答えられず、辞退されます。募集要項を書く前に、この2つを人事と経営で確定する。確定に時間がかかるなら、送り始める時期をそれに合わせます。確定しないまま「当社規定による」で送るより、確定してから送るほうが、面談のあとに残る学生が増えます。募集要項は書く作業ではなく、社内で決める作業です。決まれば、書くのは短時間で済みます。

## まとめ

- 募集要項は「条件を確かめる場」。学生は上から順に読まず、仕事内容→勤務地→条件→選考の流れ→求める人物の順に読む
- 仕事内容は、最初の仕事と1日の流れと難しさを。職種名は一般的な言葉で
- 勤務地は初任の候補を列挙し、条件は隠さず正確に。「当社規定による」は避ける
- 求める人物は抽象語ではなく行動の型で。ペルソナから引く
- 文面、企業ページ、募集要項は同じ元から作り、矛盾させない

## よくある質問

### 配属が入社後に決まるので、勤務地を書けません

「配属は入社後に決まる」と書いたうえで、候補地を列挙します。候補地が分かれば、学生は「通えるか」を判断できます。候補地も決まっていないなら、送り始める前に事業部門と確定することを勧めます。

### 条件を正確に書くと、承認が減りませんか

減るかもしれませんが、減るのは「条件が合わない学生」の承認です。その学生は、面談のあとで辞退します。正確に書いて承認した学生は、条件で辞退しません。承認の数より、面談のあとに残る数で見ることを勧めます。

### 募集要項の作成は、御社に頼めますか

下書きと、学生が読む順番での整理は当社で行えます。条件の最終確認と、仕事の実態は企業に確認していただきます。当社がOfferBoxの運用代行を受けるときは、文面のテンプレート、企業ページ、募集要項を同じ元から一緒に作ります。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
