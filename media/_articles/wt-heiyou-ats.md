採用管理システムをすでに使っていて、Wantedlyの候補者もそこで管理したい。あるいは、複数の媒体を使い始めて、Wantedlyの「話を聞きに行きたい」を他の入口と同じ場で持ちたい。ところが、連携したあとに「Wantedlyの候補者だけ段がずれる」「メッセージがどちらにあるか分からない」「会社を読んで来た人が、ただの応募者として扱われる」という形で崩れることがあります。**結論から言うと、連携の前に段の定義を揃え、正をどちらに置くかを決めます。メッセージのやり取りはWantedlyの管理画面、候補者の状態（段・担当・次の連絡日）は採用管理システム、と分けて二重に持たず、Wantedlyから来た候補者には「会社を読んで来た」という入口の情報を残します。** この記事では、連携の形、段の定義の揃え方、正の置き方、入口の情報、通知と次の連絡日、個人情報、確認する項目、やりがちな失敗、社内の分担を整理します。連携の可否や取り込みの方法は、システムごとに違い、変わることもあるので、各システムとWantedlyの公式ページで現在の内容を確認してください。この記事では仕様と数値を書きません。Wantedly側の管理の基本は[Wantedlyの応募・スカウトの管理の仕方](/media/wt-scout-oubo-kanri/)で書きました。

## それぞれの役割｜Wantedlyは「来る場」、採用管理システムは「並べる場」

| | Wantedly | 採用管理システム |
|---|---|---|
| 役割 | 会社を読んだ候補者が来る。スカウトを送り、メッセージを交わす | 複数の入口から来た候補者を、同じ段で並べる |
| 持つもの | 会社ページ・記事・スカウト・メッセージ・プロフィール | 段・担当・次の連絡日・メモ・結果・入口 |
| 候補者の状態 | 「話を聞きに行きたい」と「返信」。会社を読んでいる | 入口を問わず、段で表す |
| 変わりやすいもの | 管理画面の機能 | 取り込みの方法、連携の可否 |

採用管理システムは、候補者を連れてくるものではありません。Wantedlyから来た候補者を、他の入口の候補者と同じ段で並べ、放置を防ぐ場所です。連携の目的は「楽になる」ではなく、「複数の入口の候補者を、一つの段の定義で持つ」ことです。

## 連携の形｜自動で取り込める場合と、手で写す場合

- **自動で取り込める場合**：Wantedlyの「話を聞きに行きたい」や返信が、システムに候補者として入る。入る段と、入るタイミングを確認する
- **手で写す場合**：管理画面の通知を受けて、人事がシステムに入れる。入れるまでの日数を決める。「その日のうち」か「翌営業日」か
- **どちらでも、入口を「Wantedly」として残す**：入口の列がないシステムなら、メモか区分で持つ
- **どちらでも、メッセージはシステムに写さない**：やり取りはWantedlyの管理画面に残る。写すのは状態だけ
- **取り込みの方法は変わる**：自動で入っていたものが入らなくなることがある。月に一度、管理画面とシステムの数を突き合わせる

自動か手かで、運用は大きくは変わりません。変わるのは「入れるまでの日数」と「突き合わせの頻度」です。

## 連携の前に、段の定義を揃える

1. **システム側の段を、自社の選考に合わせて決める**：新規・返信待ち・面談調整中・面談済み・選考中・内定・終了、のような五つから七つ
2. **Wantedlyの「話を聞きに行きたい」を、どの段に入れるかを決める**：「新規」に入れることが多い。「応募」と同じ段に入れるなら、入口の情報を残す
3. **Wantedlyの「スカウトへの返信」を、どの段に入れるかを決める**：「話を聞きに行きたい」と分けるか、同じ段にするか
4. **段ごとの担当を、名前で決める**：「人事」ではなく一人
5. **「次の連絡日」を、システムのどの項目で持つかを決める**：ない場合は、メモか期日の項目で代用する

段の定義が揃っていないまま連携すると、Wantedlyの候補者だけが「新規」に溜まり、他の入口の候補者は進む、という形になります。

### エージェントベストの見解

これをやる前に、先に段の定義を揃えておかないと、連携しても効果が出ません。当社は3媒体すべての販売パートナーとして、採用管理システムとの連携の相談を受けますが、「連携できるか」を先に聞く会社が多く、「連携したあと、Wantedlyの候補者はどの段に入るか」を決めている会社は少ないです。決めていないと、自動で入った候補者が「新規」のまま止まり、誰も担当になっておらず、Wantedlyの管理画面で返信を待つ候補者と、システムの上で放置される候補者が同じ人になります。連携の可否は、システムとWantedlyの公式ページで確認できますが、段の定義は自社にしか決められません。連携の前に、紙一枚で「Wantedlyから来た人は、この段に入り、この人が担当で、この日数で動く」を書いてから、取り込みの設定に進むのが順番です。

## 正をどちらに置くか｜メッセージは管理画面、状態はシステム

| 情報 | 正の場所 | 理由 |
|---|---|---|
| メッセージのやり取り | Wantedlyの管理画面 | 相手とのやり取りはWantedlyの上で行う。写すと古くなる |
| 相手のプロフィール | Wantedlyの管理画面 | 相手が更新する。写すとずれる |
| 段・担当・次の連絡日 | 採用管理システム | 複数の入口を並べる場所 |
| 面談の日程と結果 | 採用管理システム | 選考の記録 |
| 入口（Wantedly・どの記事・どのスカウト） | 採用管理システム | 並べて見るときに要る |
| 「何を見て来たか」の一行 | 採用管理システム | 面談で聞いて残す |

正を一つに決めると、「どちらが新しいか」で迷わなくなります。決めないと、両方を更新しようとして、片方が止まります。管理画面の機能は変わることがあるので、どこまでを管理画面で持てるかは現在の仕様を確認し、仕様がどうであれ、段と担当と次の連絡日はシステムで持ちます。

## 「会社を読んで来た」という入口の情報を落とさない

Wantedlyから来た候補者は、会社ページとストーリーを読んでから「話を聞きに行きたい」と来ています。採用管理システムに入ると、他の入口の候補者と同じ「応募者」に見え、この状態が落ちます。

- **入口の列に「Wantedly」を残す**：面談に出る人が、システムを見ただけで「会社を読んで来た人」と分かる
- **どの記事から来たかを、分かる範囲で残す**：管理画面で見えるなら写す。見えないなら、面談で聞く
- **面談で「記事のどこを見て来たか」を聞き、一行で残す**：入口の情報を、面談の言葉で補う
- **面談の話し方を、入口で変える**：会社を読んで来た人に、会社の説明から始めない。仕事の場面から
- **並べて見るときに、入口の列で分ける**：入口ごとの段の数と、近い人の数。[Wantedlyを含む複数媒体の効果を並べて見る方法](/media/wt-heiyou-heiyou-kpi/)

入口の情報が落ちると、Wantedlyから来た候補者が、ナビから来た候補者と同じ流れで扱われ、「読んだとおりの会社か」を確かめに来た温度が下がります。

## 通知と、次の連絡日

- **Wantedlyの通知を、誰が受けるかを決める**：管理画面の通知は、担当者に届く形にする
- **通知を受けてから、システムに入るまでの日数を決める**：自動なら確認だけ。手なら「その日のうち」
- **「次の連絡日」を空欄にしない**：システムに入った時点で、最初の返信の期日を入れる
- **過ぎた「次の連絡日」を、誰が見るかを決める**：週に一度、システムの一覧で
- **返信はWantedlyの管理画面で行い、返信したらシステムの段を進める**：二つの作業を一つの手順に

放置を防ぐ「次の連絡日」の考え方は、[Wantedlyの応募・スカウトの管理の仕方](/media/wt-scout-oubo-kanri/)の「放置を防ぐ『次の連絡日』」で書きました。連携しても、この項目が空欄なら放置は起きます。

## 個人情報の扱いと、確認する項目

| 項目 | 確認すること |
|---|---|
| 連携の可否と方法 | 自動か、手か。各システムとWantedlyの公式ページで現在の内容を確認 |
| 入る段とタイミング | 「話を聞きに行きたい」と「返信」がどの段に、いつ入るか |
| 入口の列 | 「Wantedly」と分かる形で持てるか |
| 次の連絡日 | 候補者ごとに期日を持ち、過ぎたときに気づけるか |
| 見られる人 | システムの上で、候補者の情報を誰が見られるか。採用に関わる人だけに |
| メモの範囲 | 採用の目的の範囲で。書かないことを決める |
| 消す時期 | 選考が終わった候補者の情報を、いつ、どちらの場で消すか |
| 突き合わせ | 管理画面とシステムの数を、月に一度、誰が合わせるか |

個人情報は、Wantedlyの管理画面とシステムの両方に存在します。消す時期と、消す場所を、両方について決めておきます。

## やりがちな失敗

| 失敗 | 何が起きるか | 直し方 |
|---|---|---|
| 「連携できるか」だけ確認して始める | 段が揃わず、Wantedlyの候補者だけ「新規」に溜まる | 段の定義を先に |
| メッセージをシステムにも写す | 二重管理になり、片方が古くなる | 正を一つに |
| 入口の列を持たない | 会社を読んで来た人が、ただの応募者として扱われる | 入口の列かメモで残す |
| 自動取り込みを信じて突き合わせない | 取り込みの方法が変わり、入っていない候補者が出る | 月に一度、数を合わせる |
| 次の連絡日を空欄のままにする | 連携しても放置が起きる | 入った時点で期日を入れる |

最も多いのは、一つ目です。連携の設定を終えたことで管理ができた気になり、段と担当が決まらないまま候補者が入ってきます。

## 社内の分担

| 作業 | 誰が |
|---|---|
| 段の定義と、Wantedlyの候補者が入る段を決める | 人事と面接官 |
| 連携の可否と方法を公式ページで確認し、設定する | 人事 |
| 正の場所を決め、手順を一枚にする | 人事 |
| 通知を受け、システムに入れ、次の連絡日を入れる | 担当者 |
| 面談で「記事のどこを見て来たか」を聞いて残す | 面談に出る人 |
| 月に一度、管理画面とシステムの数を突き合わせる | 人事 |
| 個人情報の見られる範囲と消す時期を決める | 人事と責任者 |

運用代行や代理店が支えられるのは、段の定義の型、正の置き方の整理、手順の一枚の型、確認項目の一覧、突き合わせの型までで、段の決定、連携の設定と契約、候補者との連絡、個人情報の判断は企業が行います。代理店の代行の範囲は[代理店に運用まで頼めるか](/media/kh-dairiten-unyou/)で書きました。

### エージェントベストの見解

連携したあと、最初の数か月で起きることに共通するのは、Wantedlyから来た候補者が、システムの上では「応募者」の一人になり、会社を読んで来たという状態が、面談に出る人に伝わらなくなることです。当社はWantedlyの運用を申込のあとまで見ていますが、連携の前は、人事が管理画面で候補者のプロフィールと記事の閲覧を見てから面談に臨んでいたのに、連携のあとは、システムの一覧だけを見て面談に入るようになり、「読んだとおりの会社か」を確かめに来た候補者に、会社の説明から始めてしまう会社があります。連携は、管理の手間を減らす代わりに、入口の状態を落とします。落とさないために、入口の列と「何を見て来たか」の一行を、システムの側に置きます。この二つがあれば、面談に出る人はシステムだけを見ても、会社を読んで来た人だと分かります。

## まとめ

- Wantedlyは「来る場」、採用管理システムは「複数の入口を同じ段で並べる場」。連携の目的は、一つの段の定義で持つこと
- 連携の前に、段の定義と、Wantedlyの候補者が入る段と、担当と、次の連絡日の持ち方を決める
- 正は一つに。メッセージとプロフィールはWantedlyの管理画面、段・担当・次の連絡日・入口・面談の言葉はシステム
- 入口の列と「記事のどこを見て来たか」の一行を残し、会社を読んで来たという状態を落とさない
- 取り込みの方法は変わる。月に一度、管理画面とシステムの数を突き合わせる。個人情報は両方の場で消す時期を決める

## よくある質問

### 自動で連携できないシステムを使っています。手で写すのは負担ですか

写すのは、状態だけです。メッセージは写しません。通知を受けて、候補者の名前と入口と段と担当と次の連絡日を入れるだけなので、一人あたりの手間は小さく、「その日のうち」のルールがあれば回ります。自動で入る場合も、突き合わせは要るので、手間の差は思うほど大きくありません。

### Wantedlyの候補者を、ナビの応募者と同じ段に入れてよいですか

段は同じでよいです。ただし、入口の列で「Wantedly」と分かる形にし、面談に出る人が、会社を読んで来た人だと分かるようにします。同じ段に入れて、入口の情報を落とすと、会社を読んで来た候補者に会社の説明から始めることになります。

### Wantedlyと採用管理システムの連携は、御社に相談できますか

できます。当社は、段の定義の型、正の置き方の整理、手順の一枚の型、確認項目の一覧、突き合わせの型を支えられます。段の決定、連携の設定と契約、候補者との連絡、個人情報の判断は、企業が行ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、Wantedlyの運用を支えています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
