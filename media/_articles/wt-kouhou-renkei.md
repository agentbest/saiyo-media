広報担当がいる会社では、「Wantedlyのストーリーは広報が書くのか、人事が書くのか」「広報の確認を通すと、記事がプレスリリースのようになる」という相談をよく受けます。どちらかに寄せると、片方の仕事が増えるか、記事の調子が変わるかのどちらかになりがちです。**結論から言うと、広報と人事では、読者と目的が違います。それを先に並べたうえで、広報は「出してよい情報の線」と「社内で起きていることのネタ」を持ち、人事は「候補者に見せる場面」と「書くこと」を持つ、と分けます。広報の確認は、出してはいけない情報に観点を絞ります。** ストーリーが何を書く場所かは[Wantedlyのストーリーの基本](/media/wt-story-kihon/)、事業の出来事の書き方は[事業の裏側を書く方法](/media/wt-story-jigyo/)で書きました。

## この作業の目的｜同じ出来事を、二つの読者に向けて使い分ける

広報が書く記事の読者は、顧客、取引先、報道関係者、投資家などです。目的は、会社の事業や発表を正しく知ってもらうことです。Wantedlyの記事の読者は、一緒に働くかもしれない候補者です。目的は、会社の日常と考えを知り、「話を聞きに行きたい」と思ってもらうことです。

同じ「新しいサービスを始めた」という出来事でも、広報は「何を始めたか」を書き、Wantedlyでは「始めるまでに誰が何に迷い、どう決めたか」を書きます。分担の目的は、一つの出来事を二つの読者に向けて使い分け、どちらの仕事も増やしすぎないことです。

## 手順1｜読者と目的の違いを並べる

| 項目 | 広報の発信 | Wantedlyの発信 |
|---|---|---|
| 読者 | 顧客、取引先、報道関係者、投資家 | 候補者 |
| 知ってほしいこと | 事業、発表、実績 | 日常、考え、一緒に働く人 |
| 書き方 | 事実を正確に、会社の言葉で | 場面を、本人の言葉で |
| うまくいかなかったこと | 原則として書かない | 書くと信用される |
| 成果の見方 | 掲載、問い合わせ | 「話を聞きに行きたい」、面談での言葉 |

この表を広報と人事で一度見て、「同じ会社の発信でも、書き方が違ってよい」と合意しておきます。この合意がないと、確認のたびに調子をそろえる議論が起きます。

## 手順2｜ネタの受け渡しを決める

1. **広報が持っているネタ帳を、人事も見られるようにする**：発表の予定、取材の予定、社内の出来事
2. **人事は、その中から「裏側に場面がありそうなもの」を選ぶ**：発表そのものではなく、その裏で誰が何をしたか
3. **広報が取材した社員の話のうち、記事に使わなかった部分をもらう**：迷ったこと、うまくいかなかったことは、Wantedlyの材料になる
4. **人事が拾ったネタも広報に渡す**：社員の日常の場面から、広報の発信に使えるものが出ることもある

広報の取材に人事が同席できると、聞き取りが一度で済みます。社員に何度も話してもらう負担を減らせます。社員への頼み方は[Wantedlyの記事づくりに社員の協力を得る方法](/media/wt-shain-kyouryoku/)で書きました。

### エージェントベストの見解

相談で多い思い込みは、「広報担当がいるなら、Wantedlyの発信も広報に任せるのがよい」というものです。当社は3媒体すべての販売パートナーとしてWantedlyの運用を見ていますが、広報がそのまま書いたストーリーは、文章は整っていても、実績と発表が中心になり、候補者が知りたい日常の場面が抜けやすくなります。広報の仕事は、会社が外に出してよいことを正確に出すことで、それ自体は採用にも欠かせません。ただ、候補者が読みたいのは、発表の裏で誰が何に迷ったか、です。当社が勧めるのは、広報に「書く人」ではなく「線を引く人」と「ネタを渡す人」になってもらうことです。書くのは、候補者の質問を面談で聞いている人事のほうが向いています。

## 手順3｜確認の観点を絞る

広報の確認は、次の観点に絞ります。

- **まだ発表していない情報が入っていないか**：事業の計画、数字、取引先の名前
- **取引先や顧客が特定できる書き方になっていないか**
- **会社として事実と違う表現がないか**
- **名称やロゴの使い方が、社内の決まりと合っているか**

文体や言い回し、うまくいかなかった話を入れるかどうかは、確認の観点に入れません。ここを直し始めると、記事が広報の調子に寄っていきます。確認を短く回す流れは[Wantedlyの記事を上司に確認してもらう流れ](/media/wt-joushi-check/)、出してよい情報の線引きは[Wantedlyで会社の素顔を出す範囲](/media/wt-kaisha-no-sugao/)で書きました。

## 手順4｜発表日と文体をそろえる

- **発表日より前に、Wantedlyで出さない**：広報の予定を人事が見られるようにしておく
- **発表のあとに、裏側のストーリーを出す**：発表の記事と並べて読めると、候補者に伝わりやすい
- **会社の基本の言葉はそろえる**：社名、サービス名、ミッションの言い回しは広報と同じにする
- **それ以外の文体は、Wantedlyの側で決める**：話すときの言葉に寄せる。考え方は[Wantedlyの文章のトーンの決め方](/media/wt-bunsho-tone/)

## やりがちな失敗

| 失敗 | 何が起きるか | 直し方 |
|---|---|---|
| 広報が全部を書き直す | プレスリリースの調子になる | 確認の観点を絞る |
| 発表前の情報を出す | 社内外の調整が必要になる | 広報の予定を共有する |
| お互いに相手が書くと思っている | どちらも書かない | 書くのは人事、と決める |
| 社員に二度同じ話を聞く | 社員の協力が減る | 取材に同席し、一度で聞く |
| 成果を同じ数字で見る | 広報と採用の判断がずれる | それぞれの成果の見方を分ける |

## 社内の分担

| 作業 | 誰が |
|---|---|
| 読者と目的の違いを合意する | 広報と人事 |
| ネタ帳と発表の予定を共有する | 広報 |
| 裏側に場面があるネタを選ぶ | 人事 |
| 社員に話してもらう・書く | 人事（取材に広報が同席してもよい） |
| 出してはいけない情報の確認 | 広報 |
| 本人の確認 | 話した社員 |
| 公開する | 人事 |

### エージェントベストの見解

広報と分担を始めた会社で、数か月後に起きやすいのは、確認が二重になって記事が止まることです。人事が書き、広報が確認し、さらに上司が確認する、という流れが重なり、一本を出すまでに時間がかかって、ストーリーの更新が途切れます。当社が運用の見直しでこの状態を見たときに勧めるのは、確認する人ごとに観点を一つに決めることです。広報は「出してはいけない情報」、話した本人は「自分の言葉として違和感がないか」、上司は必要な場合だけ「事実と違わないか」。観点が重ならなければ、確認は並行して進められます。広報の確認期限を決め、期限までに指摘がなければ出す、と合意しておくと、更新は止まりにくくなります。

## まとめ

- 広報とWantedlyの発信は、読者と目的が違う。同じ出来事でも、広報は「何を」、Wantedlyは「裏で誰がどう動いたか」を書く
- 広報は「出してよい情報の線」と「ネタ」を、人事は「場面」と「書くこと」を持つ
- ネタ帳と発表の予定を共有し、取材に同席して社員に一度で話してもらう
- 広報の確認は、未発表の情報・取引先の特定・事実との違い・名称の扱いに絞る。文体は確認の観点に入れない
- 確認する人ごとに観点を一つにし、期限を決めて、更新を止めない

## よくある質問

### 広報担当が一人で、Wantedlyまで手が回りません

広報に頼むのは、ネタ帳と発表の予定を共有することと、出してはいけない情報の確認だけにします。書くのは人事が受け持ちます。確認の観点が絞られていれば、広報の負担は短い時間で済みます。

### 広報の発表記事を、Wantedlyのストーリーにそのまま載せてもよいですか

載せること自体はできますが、候補者には読まれにくい傾向があります。発表の内容を短く引いたうえで、その裏で誰が何をしたかを一つの場面で書き足すと、Wantedlyの記事になります。発表記事への導線は、会社の採用サイトや広報のページに置く方法もあります。

### 広報と人事の分担は、御社に相談できますか

できます。当社は、読者と目的の整理、ネタの受け渡しの形、確認の観点と流れの設計、記事の構成を支えられます。社員に話してもらうこと、出してはいけない情報の確認、公開の判断は企業が行ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、Wantedlyのコンテンツづくりを支えています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
