社員インタビューは、ストーリーの中で最も書かれる型で、最も候補者に届く型です。同時に、最も「経歴の羅列と褒め言葉」になりやすい型でもあります。**結論から言うと、社員インタビューは、募集している職種の、候補者が自分を重ねられる人に、1つの場面に絞って聞き、本人の言葉を残して場面で書き、本人が直して同意する、という手順で作ります。「経歴」「やりがい」「メッセージ」の3段構成にすると、どの会社のインタビューも同じになります。** この記事では、誰に聞くか、聞く前の準備、聞き方、書き方、本人の確認と同意、写真、公開後、やりがちな失敗、分担を整理します。ストーリーの位置づけは[ストーリーの基本](/media/wt-story-kihon/)、テーマの決め方は[ストーリーのテーマの決め方](/media/wt-story-theme/)で書きました。

## この作業の目的｜候補者が「この人と働く自分」を想像できる記事にする

社員インタビューを候補者が読むのは、「一緒に働く人はどんな人か」「その人は毎日何をしているか」「入る前と後で何が違ったか」を知るためです。経歴や実績を知るためではありません。

インタビューの目的は、候補者が「この人と働く自分」を想像できる記事にすることです。想像できるのは、その人の1日、詰まった場面、決めた理由が、具体的に書かれているときです。「〇〇大学卒、△△社を経て入社」「やりがいは□□です」では、想像できません。

## 手順1｜誰に聞くか

聞く相手を選ぶ軸は、会社ページのメンバーの選び方と同じです。[会社ページに載せるメンバーの選び方](/media/wt-kaisha-page-member/)で書きました。

| 軸 | 確かめ方 |
|---|---|
| 募集している職種の人か | 候補者が募集記事から来る前提で、その職種の人 |
| 候補者が自分を重ねられるか | 年代、前職や学生時代、未経験か経験者か、が候補者に近い |
| 具体的に話せるか | 「昨日1日」「一番大変だった案件」を、具体的に語れる人。語れない人の記事は薄くなる |
| 本人が同意しているか | 名前、写真、話した内容を載せることに同意しているか。断られたら別の人 |

「経歴が立派な人」を選ばない理由も、メンバーの選び方と同じです。候補者は経歴を見ず、「自分と同じ道から来た人」を探しています。

最初は、募集記事の「誰と」で挙げた人か、入社して数年の若手が向いています。

## 手順2｜聞く前に、1つの場面に絞り、質問を用意する

聞く前の準備で、インタビューの質が決まります。

1. **テーマを1つの場面に絞る**：「〇〇さんの話」ではなく、「〇〇さんが初めて1人で提案に行った日」「〇〇さんが入社して最初の月に詰まったこと」。絞り方は[ストーリーのテーマの決め方](/media/wt-story-theme/)
2. **質問を5つ程度用意する**：場面を引き出す質問。次の手順で
3. **本人に、テーマと質問を先に伝える**：当日に思い出せるように。「先週の〇〇の案件について聞きます」
4. **録音の許可を取る**：書き起こしのため。録音があれば、聞くことに集中できる
5. **時間を短く決める**：長い時間は本人の負担。1つの場面なら短時間で足りる
6. **人事が聞く。本人に書かせない**：「書いて」と頼むと止まる。「話して」と頼む

「1つの場面に絞る」が、準備の中心です。絞らずに「あなたについて教えてください」と聞くと、経歴の話から始まり、場面にたどり着きません。

## 手順3｜聞き方

質問は、場面を引き出す形にします。

| 質問 | 引き出せること |
|---|---|
| 「昨日1日、何をしましたか。朝から順に」 | 1日の流れ。仕事の実態 |
| 「最近、一番大変だった案件は。そのとき、何が起きて、自分はどう動きましたか」 | 詰まった場面と、動き方 |
| 「なぜこの会社に来たのですか。決める前に、何を見て、何を迷いましたか」 | 入社の理由。候補者が重ねる部分 |
| 「入る前に想像していたことと、入ってから違ったことは」 | 実態とのずれ。正直さが伝わる |
| 「うまくいかなかったとき、誰に何を聞きましたか」 | チームの様子、頼り方 |
| 「この仕事を続けて、できるようになったことは」 | 成長の道筋。役職ではなく、できること |

聞き方の要点を並べます。

- **答えが抽象的なら、「たとえば」「そのとき具体的には」と場面に戻す**：「やりがいがあります」と言われたら、「最近、やりがいを感じた場面は」
- **雑談を許す**：雑談の中に、場面が出てくる
- **本人の言葉を、そのまま覚えておく**：書くときに、言い換えない
- **良い話だけを引き出そうとしない**：「大変だったこと」「違ったこと」を、遠慮なく聞く

### エージェントベストの見解

相談で最も多い思い込みは、「社員インタビューは、経歴、仕事内容、やりがい、候補者へのメッセージ、の順で聞けばよい」というものです。この構成で聞くと、どの会社のインタビューも同じ形になり、候補者は最初の数行で「またこの形か」と閉じます。当社は3媒体すべての販売パートナーとしてWantedlyの契約後の運用を見ていますが、話を聞きに来る候補者が「あのインタビューを読んで来た」と言う記事は、例外なく1つの場面から始まっています。「入社して2ヶ月目、初めて1人で顧客に行った日の話」のように。経歴は最後に一言、やりがいは書かず、メッセージも無い。場面だけで、候補者は「この人と働く自分」を想像します。インタビューの構成を決めるのは、聞く側です。「経歴から」ではなく「場面から」聞く。それだけで、記事は変わります。

## 手順4｜書き方｜場面で、本人の言葉で

聞いた内容を、記事にします。

1. **場面から書き始める**：「〇月、△△の案件で」。経歴や自己紹介から始めない
2. **誰が、何を見て、何を思い、どう動いたか、の順で**：本人が話した順ではなく、場面の順で組み直す
3. **本人の言葉を、そのまま残す**：言い換えると、本人の声が消える。書き言葉に整えすぎない
4. **抽象語を、本人が話した場面に置き換える**：「やりがい」と言った部分は、そのとき話した具体的な場面に。置き換えの考え方は[会社ページでバリューを言葉にする方法](/media/wt-kaisha-page-value/)
5. **大変だったこと、違ったことを、削らない**：正直さが記事の信頼になる
6. **経歴は、最後に一言**：「〇〇出身。△△を経て入社」。冒頭に置かない
7. **教訓やメッセージでまとめない**：場面を置いて終える。「候補者へのメッセージ」の欄は要らない
8. **募集記事か会社ページへ、一言で誘導する**：「〇〇さんのチームの募集はこちら」

Q&Aの形式にするか、地の文にするかは、どちらでも構いません。Q&Aでも、質問が「経歴を教えてください」ではなく「初めて1人で提案に行った日は」なら、場面になります。

## 手順5｜本人の確認と同意、写真

書いたら、本人に見せます。

- **記事の全文と、使う写真を見せて、直してもらう**：「載せてよいか」だけでなく「この内容でよいか」
- **本人の言葉を変えていないかを、本人に確かめてもらう**：言い換えた部分があれば、本人の言葉に戻す
- **本人が「ここは載せたくない」と言った部分は、削る**：大変だったことでも、本人が望まなければ載せない
- **名前と写真の扱いを確認する**：顔を出すか、名前を出すか。出さない形でも記事は成立する
- **写真は、その人が仕事をしている場面**：インタビュー中の写真より、普段の仕事の写真。撮り方は[会社ページの写真の選び方](/media/wt-kaisha-page-photo/)
- **公開の同意を取ってから出す**

本人の確認を省くと、本人が公開後に「こんなことは言っていない」と感じ、社内の空気が悪くなります。確認は省きません。

## 手順6｜公開後｜反応を本人に戻す

公開したあと、本人に反応を戻します。

1. **話を聞きに来た候補者に「どのストーリーを読みましたか」と聞く**：面談の最初に
2. **本人の記事が読まれていたら、本人に伝える**：「あなたの記事を読んで来た人がいます」
3. **候補者がその記事のどこに反応したかも伝える**：「初めて1人で行った日の話が、自分と重なったと言っていました」
4. **本人が面談に出られるなら、出てもらう**：記事の人と会える、が候補者に効く

反応が戻ると、本人は「話してよかった」と感じ、次のインタビューに協力しやすくなり、他の社員にも広がります。反応が戻らないと、「話したのに何も無かった」となり、次は断られます。この考え方は、OfferBoxの[現場社員を巻き込む方法](/media/ob-genba-makikomi/)で書いた「反応を戻す」と同じです。

## やりがちな失敗

| 失敗 | 何が起きるか | 直し方 |
|---|---|---|
| 経歴・仕事内容・やりがい・メッセージの3段構成 | どの会社も同じ | 1つの場面から |
| 経歴が立派な人を選ぶ | 候補者が重ねられない | 募集職種の、候補者に近い人 |
| テーマを絞らずに「あなたについて」と聞く | 経歴の話で終わる | 1つの場面に絞る |
| 本人に書いてもらう | 止まる、または謙遜 | 聞いて、人事が書く |
| 本人の言葉を言い換える | 声が消える | そのまま残す |
| 「やりがい」を抽象語のまま書く | 建前に読まれる | 話した場面に置き換える |
| 大変だったことを削る | 良いことだけの記事 | 残す。本人が望まない部分だけ削る |
| 本人の確認を省く | 「言っていない」となる | 全文と写真を見せる |
| 反応を本人に戻さない | 次は断られる | 面談で聞いて戻す |
| 長い | 読まれない | 1つの場面を書き切る長さ |

最も多いのは、最初の「3段構成」です。インタビューの型として染みついているので、意識して崩します。

## 社内の分担

| 作業 | 誰が |
|---|---|
| 聞く相手を選ぶ | 人事（募集記事のパターンから） |
| テーマを絞り、質問を用意する | 人事 |
| 話す | 本人 |
| 聞く、録音する | 人事 |
| 書く | 人事 |
| 直す、同意する | 本人 |
| 写真 | 人事が手配、本人が同意 |
| 反応を戻す | 人事（面談で聞いて） |

本人の負担は、「話す」「直す」「写られる」の3つです。運用代行や代理店が支えられるのは、質問の型、書き起こしから記事への整理、抽象語の置き換えまでで、聞くことと本人の確認は企業が行います。代理店の代行の範囲は[代理店に運用まで頼めるか](/media/kh-dairiten-unyou/)で書きました。

### エージェントベストの見解

自社で持つべきなのは、どこまでか。当社がWantedlyのストーリーを支えるとき、聞いた内容の書き起こしを記事に整えること、抽象語を場面に置き換える案、募集記事へのつなぎ方は当社が出せます。ただし、「聞く」ことは、企業の人事がやるほうがよいと考えています。外部の当社が社員に「一番大変だった案件は」と聞くと、社員は身構え、本音が出にくい。同じ会社の人事が、雑談の中で聞くほうが、場面が出てきます。当社の役割は、聞く前に「この質問で、この場面を引き出してください」と質問を渡し、聞いたあとに録音を記事に整えることです。聞くのは企業、整えるのは当社。この分担で、本人の負担は「話す」だけになり、記事は本人の言葉で書かれます。

## まとめ

- 社員インタビューは、募集している職種の、候補者が自分を重ねられる人に、1つの場面に絞って聞く
- 経歴・やりがい・メッセージの3段構成にせず、場面から始めて、行動と感じたことで書く
- 「昨日1日」「一番大変だった案件」「なぜこの会社に」「入る前と後で違ったこと」を聞き、抽象的な答えは「たとえば」で場面に戻す
- 本人の言葉をそのまま残し、大変だったことを削らず、経歴は最後に一言。教訓でまとめない
- 全文と写真を本人に見せて同意を取り、公開後は面談で聞いた反応を本人に戻す

## よくある質問

### 社員が「話すことが無い」と言います

「あなたについて」と聞くと、話すことが無いと感じます。「昨日1日、何をしましたか」「最近、一番大変だった案件は」と、場面を聞きます。誰でも昨日は何かをしていて、最近何かに詰まっています。それが記事になります。

### Q&A形式と、地の文と、どちらがよいですか

どちらでも構いません。要点は、質問が「経歴を教えてください」ではなく「初めて1人で提案に行った日は」のように場面を聞く形になっていることです。Q&Aなら本人の言葉が残しやすく、地の文なら場面の順に組み直しやすい。書きやすいほうで足ります。

### 社員インタビューの作成は、御社に相談できますか

できます。当社は、聞く相手の選び方、質問の型、録音から記事への整理、抽象語の置き換え、募集記事へのつなぎ方を支えられます。聞くことと、本人の確認と同意は、企業の人事にお願いしています。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、Wantedlyのストーリーの整備を支えています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
