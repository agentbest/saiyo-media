「ワンキャリアの掲載は、どのくらいの頻度で更新すればよいのか」と聞かれることが多くあります。ところが、頻度を先に決めると、「毎週触る」と決めて体験談とずれる更新を重ねるか、「年に一度」と決めて選考の変更が反映されないか、のどちらかになります。**結論から言うと、ワンキャリアの掲載の更新は、頻度ではなく「起点」で決めます。企業ページは、選考の変更・体験談の増加・新しい入社者・よく聞かれることの変化・年度の切れ目の5つの起点で。イベントの掲載は、開催前と終了後。インターンと本選考の掲載は、掲載前と選考後。学生に見えるのは「更新した」ことではなく「体験談と揃っている」ことなので、頻度より整合を保ちます。** この記事では、頻度を先に決めると起きること、掲載の種類ごとの起点、揃っていることが見える理由、作業を短くする仕組み、多すぎる・少なすぎるサイン、3媒体の違い、分担を整理します。企業ページの更新の詳細は[企業ページを更新し続ける方法](/media/oc-kigyo-page-koushin/)で書きました。この記事は、掲載の種類をまたいで「頻度」の問いに答えるものです。

## この作業の目的｜「いつ読んでも、体験談と揃っている」を、少ない作業で保つ

学生は、掲載の更新日を見て会社を判断しているわけではありません。見ているのは、体験談で読んだことと、掲載に書かれていることが揃っているかです。

更新の目的は、「いつ読んでも揃っている」状態を、少ない作業で保つことです。頻繁に触ることでも、放置することでもありません。

## 頻度を先に決めると、起きること

| 決め方 | 何が起きるか |
|---|---|
| 「毎週更新する」 | 触る理由が無いのに触り、言い回しが変わり、体験談とのずれが生まれる。続かない |
| 「毎月更新する」 | 月の中で選考の流れが変わっても、次の月まで古いまま |
| 「年に一度」 | 体験談が増えても、選考が変わっても、反映されない |
| 「気づいたときに」 | 誰も気づかず、担当が変わると止まる |
| 「他社に合わせて」 | 他社の起点は、他社の選考の予定 |

共通するのは、「何を直すか」ではなく「いつ直すか」から考えていることです。直すものが無い更新は、ずれを生むだけです。

## 掲載の種類ごとの、更新の起点

| 掲載の種類 | 起点 | 直すもの |
|---|---|---|
| 企業ページ | 選考の変更／体験談の増加／新しい入社者／よく聞かれることの変化／年度の切れ目 | それぞれの起点に対応する箇所。[企業ページを更新し続ける方法](/media/oc-kigyo-page-koushin/) |
| イベントの掲載 | 開催前（作る）／終了後（誘導を外す、出た質問を企業ページへ） | ページそのものは開催ごとに新しく。[イベントページの作り方](/media/oc-event-page-kihon/) |
| インターンの掲載 | 掲載前（体験談を読んで揃える）／選考後（体験談を読んで直す） | 何を任せるか、誰が見るか、選考との関係。[インターンを掲載するときの書き方](/media/oc-intern-keisai/) |
| 本選考の掲載 | 掲載前（体験談を読んで揃える）／選考後（体験談を読んで直す）／選考の変更（その場で） | 段階と何を見るか、連絡の目安。[本選考を掲載するときの書き方](/media/oc-honsenkou-keisai/) |
| 写真 | 年に一度、または大きく変わったとき | 普段の仕事中の写真に入れ替え |

起点が来ないときは、触りません。起点が来たら、対応する箇所だけを直します。これで、年に数回の短い作業になります。

### エージェントベストの見解

相談で最も多い思い込みは、「掲載を頻繁に更新すると、学生に『活発な会社』と見られる」というものです。当社は3媒体すべての販売パートナーとして、ワンキャリアの掲載を支えていますが、更新の頻度が学生の反応に結びついた例は見ていません。学生が見ているのは、体験談で読んだ選考の流れと、掲載の流れが同じかどうかで、更新日ではありません。逆に、頻繁に触った結果、言い回しが変わり、前の体験談と揃わなくなった掲載は見ています。当社が更新の相談を受けるとき、最初に伝えるのは「頻度は決めなくてよい。起点を決めてください」ということです。起点が決まれば、更新は年に数回で足り、その数回で体験談との整合が保てます。

## 「更新した」より「揃っている」が、学生に見える

学生が掲載を読むときに見えるのは、次のことです。

- **体験談の選考の流れと、掲載の流れが同じか**：同じなら「掲載は本当」。違えば「体験談が本当」
- **体験談で「分からなかった」と書かれたことに、掲載が答えているか**：答えていれば「読んで直した会社」
- **企業ページの「働く人」に、イベントで話す人が出ているか**：出ていれば「つながっている」
- **終わったイベントへの誘導が残っていないか**：残っていれば「放置されている」
- **事実（事業、拠点、代表）が古くないか**：古ければ「更新されていない」

「更新日が新しい」は、この一覧に入っていません。揃っていることと、放置されていないことが、学生に見える更新です。

## 更新の作業を、短くする仕組み

起点が来たときの作業を短くするために、普段から溜めておくものがあります。

| 溜めておくもの | 集め方 | 使う起点 |
|---|---|---|
| 面接でよく聞かれたことの一行 | 面接に出る人が、面接後に一行を人事に送る | よく聞かれることの変化 |
| 体験談の読んだ範囲 | 前回どこまで読んだかを記録 | 体験談の増加（増えた分だけ読む） |
| 選考の変更の記録 | 選考を変える会議に、掲載の担当が出る | 選考の変更（その場で） |
| 新しい入社者の話 | 入社してしばらく経った頃に、人事が聞く | 新しい入社者 |
| 更新の記録 | いつ、どの起点で、どこを直したか | すべて（前回の続きから） |

「面接の一行」と「読んだ範囲の記録」があれば、起点が来たときに全部を読み直さずに済みます。溜め方の考え方は[コンテンツを資産として貯める考え方](/media/wt-naiyou-shisan/)で書きました。

## 更新が多すぎるサイン、少なすぎるサイン

| 多すぎるサイン | 少なすぎるサイン |
|---|---|
| 起点が無いのに触っている | 選考の流れが変わったのに、掲載が前のまま |
| 言い回しの直しを繰り返している | 体験談が増えたのに、読んでいない |
| 直すたびに、体験談との整合を確かめていない | 終わったイベントへの誘導が残っている |
| 更新の記録が無く、何を変えたか分からない | 事実（事業、拠点、代表）が古い |
| 担当が「更新すること」を目標にしている | 担当が掲載の存在を知らない |

多すぎるサインが出たら、起点の一覧に戻り、「起点が無いときは触らない」を確かめます。少なすぎるサインが出たら、起点を人事の年間の予定に入れ、面接の一行を集める形を作ります。

## 3媒体で、更新の頻度が違う理由

OfferBox、Wantedly、ワンキャリアで、更新の頻度の考え方は違います。

| 媒体 | 更新の考え方 | 理由 |
|---|---|---|
| OfferBox | オファーは学生ごとに毎回。企業ページは年度の切れ目と、学生の反応で | 学生ごとに送るものが中心。企業ページは補い |
| Wantedly | 会社ページとストーリーは、毎週か毎月の小さな更新で「動いている会社」を見せる | 候補者が会社ページの更新の様子を見る。途切れないことが信用 |
| ワンキャリア | 起点で。頻度ではなく体験談との整合 | 学生が見るのは体験談との整合で、更新の様子ではない |

Wantedlyの「毎週の一行」をワンキャリアに持ち込むと、触りすぎになります。ワンキャリアの「起点で」をWantedlyに持ち込むと、途切れます。媒体で分けます。Wantedlyの更新は[会社ページを更新し続ける仕組み](/media/wt-kaisha-page-koushin/)で書きました。

## 更新の記録の残し方

| 残すこと | 使い方 |
|---|---|
| いつ、どの起点で、どこを直したか | 次の起点で、前回の続きから |
| 直す前の記述 | 戻せる |
| 読んだ体験談の範囲 | 次は増えた分だけ |
| 「直す」に回した選考の運用の変更 | 運用の改善の記録 |
| 最終更新日 | 担当が変わったときに古さが分かる |

記録は、掲載の本文とは別に、社内の置き場に持ちます。担当が変わったとき、この記録と起点の一覧を渡せば、更新は続きます。

## 社内の分担

| 作業 | 誰が |
|---|---|
| 掲載の種類ごとの起点を決める | 人事 |
| 起点を年間の予定に入れる | 人事 |
| 面接の一行を送る | 面接に出る人 |
| 選考の変更をその場で反映する | 人事（変更を決める会議に出る） |
| 体験談を増えた分だけ読む | 人事 |
| 起点が来たら、対応する箇所だけ直す | 人事 |
| 更新の記録を残す | 人事 |
| 起点が無いときは触らない | 人事 |

運用代行や代理店が支えられるのは、起点の一覧の型、溜めておくものの集め方の設計、多すぎる・少なすぎるサインの点検、更新の記録の型までで、起点そのもの（選考の変更、体験談を読むこと）と、直す判断は企業が行います。代理店の代行の範囲は[代理店に運用まで頼めるか](/media/kh-dairiten-unyou/)で書きました。

### エージェントベストの見解

これをやる前に、先に決めておかないと更新が「多すぎる」か「少なすぎる」かのどちらかになることがあります。「起点が無いときは触らない」と「起点が来たらその場で直す」の二つを、担当と上司で合意しておくことです。当社がワンキャリアの掲載の更新を支える中で、上司が「最近更新していないのでは」と言い、担当が起点の無い更新をして、体験談とずれる、という形を見ています。逆に、担当が「更新は年に一度」と思い込み、選考の変更が反映されない形も見ています。当社が最初にお願いするのは、起点の一覧を上司と共有し、「更新の頻度ではなく、起点に対応したかで見る」と合意してもらうことです。合意があれば、担当は起点だけを見て動け、上司は頻度で詰めなくなります。

## まとめ

- 更新は頻度ではなく起点で決める。企業ページは5つの起点、イベントは開催前と終了後、インターンと本選考は掲載前と選考後と選考の変更
- 頻度を先に決めると、触りすぎて体験談とずれるか、放置して選考の変更が反映されないかのどちらか
- 学生に見えるのは「更新した」ことではなく「体験談と揃っている」「放置されていない」こと
- 面接の一行、読んだ範囲の記録、選考の変更の記録、更新の記録を溜めておくと、起点が来たときの作業が短い
- 多すぎる・少なすぎるサインで見直し、3媒体で更新の考え方を分け、「起点が無いときは触らない」を上司と合意する

## よくある質問

### 上司に「もっと頻繁に更新すべきだ」と言われます

起点の一覧を見せ、「起点に対応したか」で見てもらうよう提案します。学生に見えるのは更新日ではなく体験談との整合で、起点の無い更新は言い回しを変えてずれを生むことを伝えます。「最近の起点はこれで、こう直した」という記録があれば、頻度で詰められません。

### 起点が来ているかどうか、どうやって気づけばよいですか

選考の変更は、変更を決める会議に出ることで気づきます。体験談の増加は、選考の山のあとに読む予定を入れることで気づきます。新しい入社者とよく聞かれることの変化は、面接の一行と入社者の話を集める形で気づきます。年度の切れ目は、予定に入れます。起点ごとに「気づく仕組み」を一つ持てば、見落としません。

### ワンキャリアの掲載の更新の設計は、御社に相談できますか

できます。当社は、起点の一覧の型、溜めておくものの集め方の設計、多すぎる・少なすぎるサインの点検、更新の記録の型を支えられます。起点そのものと、直す判断は、企業が行ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、ワンキャリアの掲載の整備を支えています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
