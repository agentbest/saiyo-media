インフラエンジニアを新卒で採る会社が媒体を選ぶとき、最初にぶつかるのは「志望職種で『インフラ』を選んでいる学生がほとんどおらず、基盤やサービスの名前で絞っても届かない。『安定稼働を支える』の掲載を出しても、学生には自分が何をするのか読めず、面談で『夜間の当番はありますか』『手作業はどのくらい残っていますか』に答えられず、入社後に当番と手作業を知って離れる」という問題です。**結論から言うと、「インフラ」を志望職種に選んでいる学生はほとんどおらず、基盤やサービスの名前で絞ると届きません。志望職種と基盤の名前をあればよい条件に置き、開発志望・研究志望の中から「動かし続けた・止まった原因を探して直した・手作業を仕組みに変えた・壊れる前に気付いた」の行動で探します。学生は「何を動かしている基盤で、何を自分たちで持ち、止まったとき誰がどう動き、夜間の当番はあるか、手作業はどのくらい残っているか」を確かめていて、送る型は行動で絞ってインフラの先輩の名義で、記事を置く型は止まった日の一日と手作業を減らした話を、比べられる場は「地味・夜間対応」の体験談に対して企業ページに当番の体制と自動化の範囲を先に書きます。当番は隠しません。** エンジニア全般の選び方は[エンジニアの採用媒体の選び方](/media/hikaku-engineer-erabikata/)、バックエンドは[バックエンドエンジニアの採用媒体の選び方](/media/hikaku-backend-erabikata/)で書きました。この記事はインフラに絞ります。

## インフラエンジニアの採用で、起きること

| 会社の状態 | 採用で起きること | 媒体との相性 |
|---|---|---|
| 志望職種「インフラ」で絞る | 選んでいる学生がほとんどいない。母集団が最初から無い | 志望を見ない条件に置き、行動で探す。[OfferBoxでエンジニア志望の学生を見つける検索の考え方](/media/ob-engineer-target/) |
| 基盤やサービスの名前で絞る | 学生は授業で触っておらず、名前では自分のことだと思わない | 名前をあればよい条件に置く |
| 「安定稼働を支える」で出す | 自分が何をするのか読めない。「地味」の像で読まれる | 何を動かし、止まったとき何をするかを先に書く。[Wantedlyでインフラエンジニアを採る募集記事の書き方](/media/wt-infra-boshu/) |
| 夜間の当番を面談で言わない | 入社後に知って離れる。「聞いていない」と体験談に書かれる | あるならある、体制と新卒が入る時期を書く |
| 手作業の残りを言わない | 自動化された像で来て、手順書どおりの手作業だと離れる | 残っている範囲と、減らす計画を実態で書く |

## 判断軸を、インフラエンジニアに当てる

| 軸 | インフラエンジニアでの見方 |
|---|---|
| 対象（誰に届くか） | 志望職種と基盤の名前を見ない。開発志望・研究志望・物理・数学系の中から「動かし続けた・止まった原因を探して直した・手作業を仕組みに変えた・壊れる前に気付いた」の行動で探す。研究室のサーバーやサークルの環境を一人で面倒を見ていた学生は、志望に「開発」「研究」を書いている |
| 型（送るか、来るか、比べられるか） | 送る型は、行動で絞ってインフラの先輩の名義で「あなたの止まった原因を探して直した経験を読んで」と一人に書ける。来る型は、止まった日の一日と、手作業を減らした話と、当番の実態を記事で通年で。比べられる型は、「地味」「夜間対応」の体験談に対して、企業ページに当番の体制と自動化の範囲を先に書けるかで |
| 課金（費用の性格） | 各媒体の公式ページで現在の条件を確認。この記事では書かない |
| 運用工数（誰の時間が要るか） | インフラの先輩が名義と面談と技術面接を持つ時間。当番と障害対応で予定が崩れるので、面談の枠を当番の外に先に固定し、崩れたときの代わりを決めないと運用が止まる |

軸の詳しい見方は[掲載型とスカウト型の違い](/media/hikaku-keisai-vs-scout/)、[共感型と条件型の媒体の違い](/media/hikaku-kyoukan-vs-jouken/)で書きました。インフラでは、「対象」を志望職種ではなく動かし続けた行動で探すことと、「運用工数」に当番で崩れたときの代わりを含めることが、他の職種と違います。

### エージェントベストの見解

相談で最も多い思い込みは、「インフラは志望職種でインフラを選んでいる学生に送ればよい。いないなら、この媒体にインフラの学生はいない」というものです。当社は3媒体すべての販売パートナーとして、エンジニアの採用の相談を受けますが、志望職種で絞って「いない」と判断した会社は、インフラに合う学生を開発志望と研究志望の中に見落としています。学生がインフラを選ばないのは、向いていないからではなく、授業でインフラという仕事を知る機会がないからです。「研究室のサーバーを一人で面倒を見ていた」「サークルの環境が止まって原因を探して直した」「毎回の手作業を仕組みに変えた」「ログを見て壊れる前に気付いた」学生は、志望に「開発」「研究」を書いています。当社が最初にお願いするのは、志望職種と基盤の名前を「あればよい条件」に下げ、この行動を「優先する条件」に上げることです。媒体を変える前に、絞り方を変えます。

## 学生が、確かめること

- **何を動かしている基盤か**：何のサービスの、どの規模の基盤か。「インフラ」の名前では分からない
- **何を自分たちで持っているか**：外部のサービスに乗せている範囲と、自分たちで設計し運用する範囲。設計の余地がどこにあるか
- **止まったとき、誰がどう動くか**：最初に気付く仕組み、誰が動くか、新卒はどこから加わるか
- **夜間の当番**：あるか。何人で回すか。新卒が入るのはいつからか。最も多く辞退の理由になる
- **手作業はどのくらい残っているか**：手順書どおりの作業の割合。減らす計画があるか。自動化でコードを書く範囲

## この条件なら、どれを先に検討するか

| 会社の条件 | 先に検討する型 | 理由 |
|---|---|---|
| 行動で絞り、インフラの先輩の名義で「あなたの止まった原因を探して直した経験を読んで」と一人に書ける | 企業から送る型（OfferBox） | 志望職種と基盤の名前を見ずに、開発志望・研究志望の中から探せる。[エンジニア向けのオファー文面](/media/ob-engineer-offer-bunmen/) |
| インフラの先輩が、止まった日の一日と手作業を減らした話を自分の言葉で書ける | 通年で記事を置く型（Wantedly） | エンジニアが読みに来る場で、「地味」の像を、止まった日と自動化の記事で置き換える。[Wantedlyでインフラエンジニアにスカウトを送る文面](/media/wt-infra-scout/) |
| 体験談があり、企業ページに当番の体制と自動化の範囲を先に書ける | 学生が並べて比べる場（ワンキャリア） | 「夜間対応」の体験談に対して、入る前に当番の体制が分かる会社として読まれる。[ワンキャリアでエンジニアを募集するときの掲載とスカウト](/media/oc-engineer-keisai/) |
| 当番の体制と、新卒が入る時期が決まっていない | どれも先ではない | インフラの責任者と決めてから。決めずに送ると内定後の辞退になる |
| 手作業の残りと減らす計画が、書けるほど整理されていない | どれも先ではない | 「自動化されている」と書いて手作業だと、体験談に書かれる |

どれか一つが正解ではなく、行動で絞れるか、先輩が書けるか、体験談があるかで、先に検討するものが変わります。

## 組み合わせ

- **送る型と記事を置く型を組み合わせる**：文面で原因を探した経験を読んだ一文を、記事で止まった日と自動化の話を。[OfferBoxとWantedlyの併用](/media/ob-heiyou-wantedly/)
- **バックエンドとの境目を、決めてから**：[バックエンドエンジニアの採用媒体の選び方](/media/hikaku-backend-erabikata/)。基盤をどこまでバックエンドが持つかで、募集を分けるか一つにするかが決まる
- **技術面接の聞き方の型を、揃える**：「何を使ったかより、止まったときどこから疑ったか、手作業を何に置き換えたか、壊れる前に何を見て気付いたか」。[エンジニア向けのスカウト文面](/media/kh-bunmen-engineer/)
- **内定前に、当番と障害の記録を見せる**：当番表と、止まった日の対応の記録と、自動化した手順の前後を。[内定辞退が続くときの見直し方](/media/ob-naitei-jitai/)
- **代行と組み合わせるなら、絞る作業と文面の下書きまで。読んで直すのはインフラの先輩、技術面接は社内**：[媒体と代行の違い](/media/hikaku-baitai-vs-daikou/)

## 見せ方｜「インフラエンジニア」ではなく、何を動かし、止まったとき何をし、当番はどうか

- **「インフラエンジニア」「安定稼働を支える」「縁の下の力持ち」と基盤の名前の一覧を消す**：自分が何をするのか読めず、「地味」の像で読まれる
- **何を動かしている基盤かを、職種名に**：「〇〇（サービス）を動かす基盤を設計し運用するエンジニア」。規模は自社の実態で。この記事では書かない
- **持っている範囲を、線で**：「△△は外部のサービス。自分たちで設計し運用するのは□□。設計の余地は〇〇にある」。乗せているだけなら、隠さない
- **止まったときの動きを、書く**：「最初に気付くのは〇〇の仕組み。動くのは△△。新卒は□か月目から一緒に動く」
- **夜間の当番を、最初に**：「当番は〇人で回す。新卒が入るのは△か月目から。当番の日は□□」。無いなら「無い。夜間は〇〇が見る」と。隠して入社後に知られると体験談に書かれる
- **手作業の残りと減らす計画を、実態で**：「手順書どおりの作業が〇〇に残っている。△△から自動化を進めていて、新卒も自動化のコードを書く」。減らす計画が無いなら、無いと

## 社内の分担

| 作業 | 誰が |
|---|---|
| 持っている範囲、止まったときの動き、当番の体制、手作業の残りと減らす計画、最初の年を決める | インフラの責任者 |
| 面談と技術面接の枠を当番の外に固定し、崩れたときの代わりを決める | インフラの責任者。書く前に |
| 行動で絞る条件 | インフラの先輩が作り、人事か代行が絞る |
| 文面と記事 | 先輩が話し、人事が書き、本人が確認 |
| 名義と、オファーの一文 | インフラの先輩 |
| 面談と技術面接 | 責任者と先輩。聞き方の型を揃えて |
| 辞退の理由の記録 | 人事。当番か、手作業か、仕事の中身か、他社かを分けて |

運用代行や代理店が支えられるのは、絞る条件の型、絞る作業、文面の下書き、記録の型までで、当番の体制の決定、面談の枠の固定、名義、技術面接は社内が担います。代理店の代行の範囲は[代理店に運用まで頼めるか](/media/kh-dairiten-unyou/)で書きました。

### エージェントベストの見解

インフラの採用で、申し込んだあとに運用が止まる会社に共通するのは、名義の先輩が当番と障害対応で面談の予定を崩し、承認から面談までの間に学生が他社で決まることです。人事が承認を集めても、面談の当日に障害が起きて先輩が出られず、次の候補日は一週間後になり、その間に学生は他社の内定を受けます。当社が案内するのは、送り始める前に、面談の枠を当番の外に固定するだけでなく、「崩れたとき、誰が代わりに出るか」を先に決めることです。代わりは、同じ部門の別の先輩か、責任者です。代わりが決まっていれば、障害の日でも面談が流れません。枠と代わりを決めてから、その枠の数で送る数を逆算します。

## まとめ

- 「インフラ」を志望職種に選んでいる学生はほとんどいない。志望職種と基盤の名前をあればよい条件に置き、開発志望・研究志望の中から「動かし続けた・止まった原因を探して直した・手作業を仕組みに変えた・壊れる前に気付いた」の行動で探す
- 「安定稼働を支える」ではなく「何を動かし、何を自分たちで持ち、止まったとき誰がどう動き、当番はどうで、手作業はどのくらい残っているか」を先に書く。当番は隠さない
- 送る型（OfferBox）は行動で絞って先輩の名義で、記事を置く型（Wantedly）は止まった日と自動化の話を、比べられる場（ワンキャリア）は「夜間対応」の体験談に対して企業ページに当番の体制と自動化の範囲を先に
- 面談と技術面接の枠を当番の外に固定し、崩れたときの代わりを先に決める
- 承認の数ではなく、内定後に当番と手作業で辞退した数で効果を見る

## よくある質問

### 志望職種で「インフラ」を選んでいる学生が本当にいません。媒体を変えるべきですか

媒体を変える前に、絞り方を変えます。志望職種と基盤の名前を「あればよい条件」に下げ、「開発」「研究」を志望している学生の中から、「研究室のサーバーを見ていた」「止まって原因を探して直した」「手作業を仕組みに変えた」の行動で探します。インフラに合う学生は、インフラという仕事を知らないだけで、媒体の中にいます。

### 手作業がまだ多く残っています。書くと学生が来なくなりませんか

「自動化されている」と書いて手作業だったほうが、体験談に書かれて次の年の学生が離れます。「手順書どおりの作業が〇〇に残っている。△△から自動化を進めていて、新卒も自動化のコードを書く」と、残りと減らす計画を書きます。減らす仕事そのものに惹かれる学生が来ます。計画が無いなら、無いと書きます。

### インフラエンジニアの媒体選びは、御社に相談できますか

できます。当社は、絞る条件の型、絞る作業、文面の下書き、記録の型を支えられます。当番の体制の決定、面談の枠の固定、名義、技術面接は、社内で担ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、エンジニアの媒体選びと運用を支えています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
