Wantedlyでは、募集記事から候補者が「話を聞きに行きたい」を押して来る流れと、会社からスカウトを送って返信が来る流れの、2つの入口があります。この2つを別々に管理していたり、管理画面だけで追っていたりすると、誰が担当で、いま何の段階で、次にいつ連絡するかが分からなくなり、放置が起きます。**結論から言うと、「話を聞きに行きたい」とスカウトの返信は、一つの台帳で管理します。台帳には、入口・相手・募集・段・担当・最終連絡日・次の連絡日・面談の日程・面談後の選択肢・メモを持ち、段の定義を決め、毎日見る人と毎週見る人を分け、「次の連絡日」で放置を防ぎます。管理画面はやり取りの場、台帳は状態を見る場、と役割を分けます。** この記事では、やりがちな失敗、台帳の項目、段の定義、見る人と頻度、更新のルール、放置の防ぎ方、個人情報の扱い、管理画面との役割分担、分担を整理します。返信後の進め方は[返信が来たあとの進め方](/media/wt-scout-henshin-go/)で書きました。

## この作業の目的｜誰も放置されず、誰が何をするかが見える状態にする

管理の目的は、「いま関わっている候補者の全員が、誰かの担当で、次の連絡日が決まっていて、放置されていない」状態を保つことです。

Wantedlyの候補者は、話を聞きに行きたいと押した時点、スカウトに返信した時点で、「この会社と話したい」と思っています。そこから対応が空くと、気持ちが薄れます。管理は、その空きを無くすためのものです。

## やりがちな失敗

| 失敗 | 何が起きるか |
|---|---|
| 管理画面だけで追う | 誰が対応中か、次にいつ連絡するかが見えない。未対応が埋もれる |
| 「話を聞きに行きたい」とスカウトの返信を別々に管理する | 同じ人が両方から来たときに重複する。全体の数が見えない |
| 担当が書かれていない | 「誰かがやっていると思った」で放置 |
| 次の連絡日が無い | 「返事待ち」のまま止まる |
| 段が更新されない | 面談したのに「返信あり」のまま。数字が出ない |
| メモが個人のノートにある | 担当が変わると分からない |
| 台帳が人事しか見られない | 面談に出る人が、相手の状況を知らずに出る |
| 個人情報を必要以上に残す | 採用の目的の範囲を超える |

最も多いのは、最初の「管理画面だけで追う」です。管理画面はやり取りを見るには便利ですが、「次に誰が何をするか」を持つ場所ではありません。

## 一つの台帳に持つ項目

| 項目 | 中身 |
|---|---|
| 入口 | 「話を聞きに行きたい」か、スカウトの返信か |
| 相手 | Wantedly上で識別できる情報。氏名は採用の目的の範囲で |
| 募集 | どの募集記事か |
| 段 | 下の定義のいずれか |
| 担当 | 返信対応の担当と、面談で話す人 |
| 最終連絡日 | こちらから最後に連絡した日 |
| 次の連絡日 | 次にこちらから動く日。空欄にしない |
| 面談の日程 | 決まっていれば |
| 面談後の選択肢 | 選考に進む・もう一度話す・いったん終わる・返事待ち |
| メモ | 相手が知りたがっていたこと、面談で話したこと、記事についての一言。採用に関係ないことは書かない |
| 入口の日 | 「話を聞きに行きたい」が押された日か、返信が来た日 |

「次の連絡日」を空欄にしない、が最も大切なルールです。返事待ちの相手にも、「〇日に一度だけ確認」と入れます。

## 段の定義

| 段 | 意味 |
|---|---|
| 新規 | 「話を聞きに行きたい」が来た、または返信が来た。まだこちらから返していない |
| 返信済み | こちらから返し、日程の候補を出した |
| 日程調整中 | 相手と日程をやり取り中 |
| 面談予定 | 日程が決まった |
| 面談済み | 面談が終わり、選択肢を伝えた |
| 選考へ | 選考に進むと決まった |
| もう一度話す | 別の人との面談を調整中 |
| 保留 | 相手が「いまは考えていない」。再連絡の日を入れる |
| 終了 | 辞退、または会社側から終えた。理由をメモに |

段は、この数で足ります。増やすと更新されなくなります。「保留」に再連絡の日を入れるのは、潜在層との関係を残すためです。考え方は[転職を考えていない人にスカウトを送る方法](/media/wt-scout-senzai/)で書きました。

### エージェントベストの見解

申し込んだあと、管理で半年後に起きやすいのは、「候補者が増えて、管理画面の中で未対応が埋もれ、気づいたときには数日経っている」ことです。当社は3媒体すべての販売パートナーとしてWantedlyの契約後の運用を見ていますが、最初の数か月は候補者が少なく、管理画面だけで回ります。募集記事とスカウトが整って候補者が増えると、管理画面の一覧は長くなり、「返事待ち」と「未対応」の区別がつかなくなります。当社が管理の相談を受けるとき、最初に作るのは、項目が少ない台帳と、「次の連絡日」の欄です。管理画面はやり取りの場で、台帳は状態の場。この分け方を最初から作っておくと、候補者が増えても放置は起きません。増えてから作ると、移す作業が重くなります。

## 見る人と、頻度

| 誰が | いつ | 何を見るか |
|---|---|---|
| 返信対応の担当（人事） | 毎日、決まった時間 | 「新規」を翌日までに「返信済み」に。「次の連絡日」が今日の相手に連絡 |
| 面談で話す人 | 面談の前 | 自分が出る相手の、入口・募集・メモ |
| 人事 | 毎週 | 段ごとの数、「次の連絡日」が過ぎているもの、「日程調整中」が長いもの |
| 人事と責任者 | 毎月 | 段ごとの数の変化。KPIの表へ。[スカウト運用のKPI設計](/media/wt-scout-kpi/) |

「毎日見る人が一人」と「次の連絡日が今日の相手を毎日確かめる」の2つで、放置はほぼ無くなります。毎週の見直しは[スカウトの返信率を毎週見直す方法](/media/wt-scout-review/)で書きました。

## 更新のルール

台帳は、更新されなければ意味がありません。ルールを少なくします。

1. **こちらから連絡したら、その場で「最終連絡日」と「次の連絡日」を更新する**：あとでまとめて、にしない
2. **段が変わったら、その場で更新する**：面談が終わったら「面談済み」に
3. **面談で話す人は、面談後に一行だけメモを足す**：相手についてのことと、記事についてのこと。長く書かない
4. **「終了」にするときは、理由を一言**：辞退・会社側・連絡が途絶えた
5. **更新するのは、担当と話す人だけ**：全員が触ると、ばらつく

「その場で更新」が原則です。まとめて更新すると、忘れ、台帳と実態がずれます。

## 放置を防ぐ「次の連絡日」

放置は、「返事待ち」で起きます。相手からの返事を待っている間、こちらは動かず、時間が過ぎます。

- **返事待ちにも、次の連絡日を入れる**：「〇日に一度だけ確認」
- **一度確認して返事が無ければ、「保留」か「終了」に**：追い続けない
- **「次の連絡日」が過ぎているものを、毎日の最初に見る**：担当の日課
- **面談予定の相手には、前日を「次の連絡日」に**：前日の一言を忘れない
- **「保留」の再連絡の日は、本人が言った時期か、新しい募集が出たとき**

「次の連絡日」が空欄の行が無い状態を保てば、放置は起きません。

## 個人情報の扱い

台帳には、候補者の情報が入ります。扱いを決めておきます。

- **採用の目的の範囲で、必要なものだけ残す**：面談に関係ないことは書かない
- **仕事に関係ない個人の事情は残さない**：家族、健康、出身、信条など。聞かないことは[カジュアル面談で聞くこと・聞かないこと](/media/wt-scout-mendan-shitsumon/)
- **見られる人を限る**：担当、話す人、人事、責任者
- **「終了」になった相手の情報は、自社の方針に沿って扱う**：残す期間、消す時期。管理部門と決める
- **社外（代理店など）に台帳を共有する場合は、範囲を決めて合意する**

この記事では、保存の期間や方法の具体は書きません。自社の方針と、管理部門の確認に沿ってください。

## 管理画面との役割分担

| 管理画面 | 台帳 |
|---|---|
| メッセージのやり取り | 状態（段・担当・次の連絡日） |
| 相手のプロフィール | メモ（採用の目的の範囲で） |
| 「話を聞きに行きたい」の通知、返信の通知 | 通知を受けたあとに「新規」として入れる |
| 送信の履歴 | 送った文面の一文（スカウトの台帳と共通） |

管理画面の機能は変わることがあるので、どこまでを管理画面で持てるかは、現在の仕様を確認してください。仕様がどうであれ、「次の連絡日」と「担当」は、台帳で持ちます。

スカウトを送る側の台帳（誰に送ったか、一文、返信の有無）と、この応募・返信の台帳は、同じファイルの別の表か、返信が来た時点でこちらに移す形にします。送る側の台帳は[スカウト対象の絞り方](/media/wt-scout-target/)で書きました。

## 社内の分担

| 作業 | 誰が |
|---|---|
| 台帳の項目と段を決める | 人事 |
| 毎日、「新規」と「次の連絡日が今日」を見る | 返信対応の担当（人事） |
| 連絡したら、その場で更新する | 担当 |
| 面談後に一行メモを足す | 話す人 |
| 毎週、過ぎているものと長いものを見る | 人事 |
| 個人情報の扱いを決める | 人事と管理部門 |
| 担当が変わるときに台帳を引き継ぐ | 人事 |

運用代行や代理店が支えられるのは、台帳の型、段の定義、更新のルールの整理、放置を防ぐ仕組みの設計、個人情報の扱いの項目の整理までで、毎日見ること、連絡すること、更新すること、個人情報の方針の決定は企業が行います。代理店の代行の範囲は[代理店に運用まで頼めるか](/media/kh-dairiten-unyou/)で書きました。

### エージェントベストの見解

自社で持つべきなのは、どこまでか。当社がWantedlyの応募とスカウトの管理を支えるとき、台帳の型、段の定義、更新のルール、放置を防ぐ仕組みは当社が出せます。ただし、「毎日、決まった時間に台帳を開いて、次の連絡日が今日の相手に連絡する」ことだけは、社内の一人が続けるしかありません。当社が台帳を代わりに見て「今日はこの人に連絡してください」と伝える形もできますが、連絡するのは社内の人で、その人が台帳を開く習慣が無ければ、当社からの連絡も埋もれます。当社が最初にお願いするのは、「毎日開く人を一人決め、その人の予定に時間を入れる」ことです。人が決まれば、台帳は当社が整えられます。決まらなければ、どれだけ整えても、開かれません。

## まとめ

- 「話を聞きに行きたい」とスカウトの返信は、一つの台帳で管理する。管理画面はやり取りの場、台帳は状態の場
- 項目は、入口・相手・募集・段・担当・最終連絡日・次の連絡日・面談の日程・面談後の選択肢・メモ。「次の連絡日」を空欄にしない
- 段は、新規・返信済み・日程調整中・面談予定・面談済み・選考へ・もう一度話す・保留・終了。増やさない
- 毎日見る人を一人決め、「新規」を翌日までに返し、「次の連絡日が今日」の相手に連絡する。連絡したらその場で更新
- 個人情報は採用の目的の範囲で、必要なものだけ、見られる人を限り、扱いは自社の方針と管理部門で決める

## よくある質問

### 候補者が少ないうちは、管理画面だけで足りませんか

少ないうちは回ります。ただし、増えてから台帳を作ると、移す作業が重くなります。少ないうちに、項目の少ない台帳と「次の連絡日」の欄だけ作っておくと、増えたときにそのまま使えます。

### 面談に出る人が、台帳を見てくれません

台帳の全体を見てもらう必要はありません。面談の前に、その相手の行（入口・募集・メモ）だけを人事から送ります。面談後は、一行メモを人事に送ってもらい、人事が台帳に入れます。話す人に頼むのは、その二つだけです。

### 応募とスカウトの管理は、御社に相談できますか

できます。当社は、台帳の型、段の定義、更新のルールの整理、放置を防ぐ仕組みの設計、個人情報の扱いの項目の整理を支えられます。毎日見ること、連絡すること、更新すること、個人情報の方針の決定は、企業が行ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、Wantedlyのスカウト運用を支えています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
