Wantedlyの募集記事を出したものの、話を聞きに来る人が少ない。そこでタイトルを変え、写真を変え、本文も少し足してみる。それでも変わらず、何が効いたのかも分からない。書き直しでよく起きる流れです。**結論から言うと、募集記事は「症状を確かめてから、何をやるか、冒頭、誰と・どうやって、タイトル、写真」の順に、中身から外側へ一か所ずつ直します。** 外側のタイトルや写真から直すと、開かれても本文で離れる状態が残ります。この記事では、書き直しの順番と理由、直したあとの見方、やりがちな失敗と分担を整理します。募集記事のよくある失敗の一覧は[Wantedlyの募集記事でやりがちな失敗](/media/wt-boshu-ng/)で書きました。

## この作業の目的｜どこが効いたか分かる直し方をする

書き直しの目的は、話を聞きに来る人を増やすことだけではありません。どこを直したら何が変わったかが分かる状態を作ることです。分かれば、次の募集記事にも同じ直し方を使えます。

一度にいくつも直すと、変わったとしても、どれが効いたのか分かりません。変わらなかったとしても、どれが足を引っ張ったのか分かりません。だから、書き直しは順番を決めて、一か所ずつ進めます。

## 手順1｜症状を確かめる

直す前に、どこで止まっているかを確かめます。

| 症状 | 疑う場所 |
|---|---|
| 一覧で開かれていない | タイトル、写真。ただし中身が固まってから直す |
| 開かれているが話を聞きに来ない | 本文の「何をやるか」、冒頭、誰と |
| 話を聞きに来るが、合わない人が多い | 来てほしい人の像、求める動き方 |
| 面談で「記事と違う」と言われる | 仕事の中身、写真、誰と |

閲覧や話を聞きに来た数は、管理画面の分析で見られます。ただ、数だけで判断しません。面談で候補者が何を言ったか、なぜ話を聞きに来たか、を合わせて見ます。来た人の言葉に、記事のどこが読まれたかが表れます。

開かれていない症状でも、先に本文の中身を確かめます。中身が薄いままタイトルを強くすると、開かれても離れるだけになるからです。

## 手順2｜中身を直す｜何をやるか、冒頭、誰と・どうやって

中身は、次の順で直します。

1. **この募集で何をやるか**：入って最初にやること、数か月後にやること、その仕事の難しさ。抽象的な言葉を、場面に置き換える
2. **冒頭**：この募集がなぜ今あるのかを一文で。会社の「なぜ」の繰り返しになっていないか
3. **誰と・どうやって**：一緒に働く人と、チームの仕事の進め方。いまの顔ぶれと合っているか

「何をやるか」を最初に直すのは、募集記事の中心だからです。ここが具体的になると、冒頭で何を言えばよいかも、誰を紹介すればよいかも決まります。逆に、冒頭や誰とを先に直しても、「何をやるか」が薄いままだと、候補者は自分がその仕事をする姿を想像できません。

直すときは、現場の責任者に「入って最初の一か月、この人は何をしているか」を聞き直します。最初に書いたときから、仕事が変わっていることもあります。

### エージェントベストの見解

相談で多い思い込みは、「話を聞きに来ないのは、タイトルが弱いから」というものです。たしかにタイトルは一覧で最初に読まれます。しかし、相談の場で募集記事を見ると、タイトルより先に「何をやるか」が薄いことが多くあります。「何をやるか」が薄いと、タイトルも職種名や抽象語になりがちです。タイトルは「何をやるか」を縮めたものなので、縮める元が薄ければ、どれだけ言い回しを工夫しても中身が伝わりません。書き直しで迷ったら、タイトルの候補を考える前に、「何をやるか」の段落だけを読み、そこから一行の要約を作ってみることを勧めます。その要約が、そのまま新しいタイトルの元になります。

## 手順3｜外側を直す｜タイトル、写真、締め

中身が固まったら、外側を直します。

- **タイトル**：直した「何をやるか」の要約になっているか。職種名だけ、抽象語だけになっていないか
- **カバー写真**：直した「何をやるか」の場面が写っているか。タイトルと同じ仕事を指しているか
- **締め**：応募ではなく、まず話を聞きに来てほしいという誘いになっているか

タイトルと写真は、同時に変えません。同時に変えると、一覧で開かれるようになっても、どちらが効いたか分かりません。タイトルを変えて様子を見てから、写真を変えます。写真の選び方は[募集記事のカバー写真の選び方](/media/wt-boshu-shashin/)、差し替えの時期は[Wantedlyの募集記事の写真を差し替えるタイミング](/media/wt-sd-boshu-shashin-koushin/)で書きました。

## 手順4｜直したあとの見方

直したら、次のように見ます。

1. **直した日と直した場所を記録する**：一か所ごとに残す
2. **しばらく様子を見る**：直してすぐの数日の動きで判断しない
3. **話を聞きに来た数と、来た人の言葉を見る**：閲覧が増えても、来た人が増えなければ中身の問題が残っている
4. **次の一か所に進む**：変わらなければ順番どおり次へ、変わったら記録して次の募集記事にも使う

閲覧だけを見ると、タイトルや写真の変更が効いたように見えやすくなります。見るのは、話を聞きに来た数と、面談で候補者が言ったことです。試し方の考え方は[募集記事の試し方](/media/wt-boshu-abtest/)も参考になります。

## やりがちな失敗と社内の分担

| 失敗 | 何が起きるか | 直し方 |
|---|---|---|
| タイトルと写真から直す | 開かれても本文で離れる | 中身から直す |
| 一度に全部直す | 何が効いたか分からない | 一か所ずつ、記録して |
| 閲覧だけで判断する | 来ない状態が残る | 来た数と来た人の言葉で見る |
| 人事だけで直す | 仕事の中身が古いまま | 現場に聞き直す |
| 直した記録を残さない | 次の募集記事に活かせない | 直した日と場所を残す |

| 作業 | 誰が |
|---|---|
| 症状を確かめる | 人事（分析と面談の記録から） |
| 「何をやるか」を聞き直す | 人事が聞き、現場の責任者が答える |
| 書き直す | 人事 |
| 仕事の中身を確かめる | 現場の責任者 |
| 記録する | 人事 |

現場の負担は、聞き直しに答えることと、直した中身を確かめることの二つです。面談に出た社員から「候補者が何を言っていたか」を集める仕組みがあると、症状の確認が楽になります。

### エージェントベストの見解

自社で持つべきなのは、「何をやるか」の中身です。書き直しの作業そのもの、つまり言い回しを整え、構成を組み替え、タイトルの候補を出すことは、人事でも外部の書き手でもできます。しかし、入って最初の一か月に何をするか、その仕事のどこが難しいか、といった中身は、現場にしか分かりません。外部に書き直しを頼むときも、この中身だけは社内で聞き取って渡すことを勧めます。中身を渡さずに書き直しを頼むと、文章は整っても、候補者が面談で「記事と違う」と感じる記事になりやすいからです。外部の書き手の使い方は[外部の書き手に頼むとき](/media/wt-gaibu-writer/)で書きました。

## まとめ

- 募集記事の書き直しは、症状を確かめてから、中身から外側へ一か所ずつ進める
- 中身は、何をやるか、冒頭、誰と・どうやっての順に直す
- 外側は、タイトル、写真、締めの順に直し、タイトルと写真は同時に変えない
- 直したら記録し、閲覧ではなく話を聞きに来た数と来た人の言葉で見る
- 「何をやるか」の中身は現場に聞き直し、社内で持つ

## よくある質問

### 書き直すより、新しい募集記事を出したほうが早くありませんか

中身が同じなら、新しく出しても同じ症状が出やすいです。まず「何をやるか」を直し、それでも変わらなければ、来てほしい人の像から見直します。職種や仕事が変わったときは、新しい募集記事として出すほうが分かりやすいこともあります。

### どこを直しても変わりません

来てほしい人の像と、媒体の相性を見直す時期かもしれません。来てほしい人がWantedlyの中でどう動いているかを、スカウトの反応などから確かめます。来ないときの切り分けは[Wantedlyの募集記事でやりがちな失敗](/media/wt-boshu-ng/)で整理しています。

### 直す間、募集記事を止めたほうがよいですか

止める必要はありません。直しながら出し続けるほうが、直したあとの変化を比べられます。直した日を記録しておけば、前後の違いが見られます。
