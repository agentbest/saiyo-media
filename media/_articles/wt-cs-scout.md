Wantedlyでカスタマーサクセスにスカウトを送るとき、最初にぶつかるのは「肩書で検索して『CSのご経験を活かして、顧客の成功を』と送っているのに、返信が来ない。来ても、面談で『成功とは何ですか』『製品側に声は戻せますか』と聞かれて止まる」という問題です。**結論から言うと、カスタマーサクセスへのスカウトは、肩書や業界の一致で相手を選ぶのではなく、先に自社の成功の定義と境界と製品への戻し方と最初に持ってもらう顧客を決め、「同じ種類と単価の顧客を持ち、使われなくなりかけた顧客を戻し、製品側に声を戻した経験を書いている人」を選び、その人の「何を続けさせたか」を読んだ一文から、自社の成功の定義と離れた顧客の実態で誘います。** この記事では、カスタマーサクセスがスカウトで見ているもの、送る前に決めること、誰に送るか、文面に書くこと、返信後の面談、社内の分担、やりがちな失敗を整理します。文面の3段の型は[ビジネス職向けスカウト文面の型](/media/wt-scout-bunmen-rei-biz/)、募集記事は[カスタマーサクセスを採る募集記事の書き方](/media/wt-cs-boshu/)で書きました。

## カスタマーサクセスがスカウトで見ているもの

| 見ているもの | 何を確かめているか |
|---|---|
| 誰から来たか | 事業の責任者か、いま顧客を見ている人か、人事か。送り主が顧客に会っている人か |
| 自分の仕事の何を読んだか | 肩書で検索しただけか、「何の顧客の、何を続けさせ、何を戻したか」を読んだか |
| 成功の定義 | 顧客の何が続いたら成功か。文面で分かるか。「顧客の成功を支援」だけなら、定義が無いと読む |
| 境界 | サポートを兼ねるか。売上の責任があるか。文面で分かるか |
| 製品側に声を戻せるか | 戻す場があるか。戻して変わった例があるか。「戻しても変わらない会社」ではないか |
| 離れた顧客の実態 | 会社説明ではなく、実態が書かれているか |

## 送る前に決めること｜成功の定義、境界、戻し方、最初に持ってもらう顧客

送る前に、社内で四つを決めます。決め方は[カスタマーサクセスを採る募集記事の書き方](/media/wt-cs-boshu/)で書きました。

- **成功の定義**：「顧客の〇〇が続いたら成功」を一文に。無いなら、無いと書き、一緒に作ると
- **境界**：サポートを兼ねるか、売上の責任があるか、給与に連動するか。隠さない前提で
- **製品への戻し方**：声を戻す場があるか。前に変わった例があるか。無いなら、無いと
- **最初に持ってもらう顧客**：「〇〇の業種の既存顧客△△社の引き継ぎから」「使われなくなりかけている□□の顧客の立て直しから」を一つ。これが文面の2段目になり、送る相手を「それができる人」に絞れる

## 誰に送るか｜肩書や業界ではなく、顧客の種類・続けさせた経験・戻した経験の重なり

肩書が「カスタマーサクセス」で一致していても、持っていた顧客の種類と単価が違えば、面談で「うちの顧客とは違う」になります。選ぶ基準は、「同じ種類と単価の顧客を持ち、使われなくなりかけた顧客を戻し、製品側に声を戻した経験を書いているか」です。

| 読む箇所 | 重なりの見方 |
|---|---|
| 顧客の種類と単価 | 企業か個人か。単価の高い少数か、低い多数か。自社の顧客と同じ種類か。ここが最も重なりが要る |
| 何を続けさせたか | 「使われなくなりかけた顧客の理由を見つけて、戻した」が書かれているか。自社の「最初に持ってもらう顧客」と重なるか |
| 製品側に何を戻したか | 「顧客の声を製品側に伝えて、〇〇が変わった」が書かれているか。戻す動き方を知っている人か |
| 境界の経験 | サポートを兼ねていたか、売上を持っていたか。自社の境界と合うか |
| 数字の見方 | 継続の数字を見ていたか、利用の深さを見ていたか、顧客の成果を見ていたか。自社の見る数字と近いか |

「何を続けさせたか」と「製品側に何を戻したか」が要点です。

### 肩書と業界の幅に配慮する

カスタマーサクセスの仕事は、「カスタマーサクセス」「アカウントマネージャー」「サポートで継続を見ていた人」「営業で契約後も顧客を見ていた人」「導入支援」など、違う肩書で書かれています。肩書で検索すると、顧客の種類が合う人を落とします。「何の顧客の、何を続けさせ、何を戻したか」で読み、肩書と業界は「あればよい条件」に置きます。絞り方の基本は[スカウト対象の絞り方](/media/wt-scout-target/)で書きました。

### エージェントベストの見解

相談で最も多い思い込みは、「カスタマーサクセスには、『顧客に寄り添える方』のような人柄で送れば返信が来る」というものです。当社は3媒体すべての販売パートナーとしてWantedlyのスカウトを見ていますが、カスタマーサクセスが返信した文面を並べると、「寄り添う」「ホスピタリティ」の言葉は、返信の有無とほとんど関係がありません。関係があるのは、「自分が何を続けさせ、製品側に何を戻したかを読んでくれたか」と、「成功の定義と、製品側に戻せるかが文面で分かるか」の二つです。人柄で送った文面は、「サポートか、解約を止める仕事か」を想像されて開かれません。定義が無くても、「成功が何かをまだ一文にできていない。離れた顧客と続いている顧客を並べて、違いを一緒に見つけたい」と書かれていれば、「定義を作る仕事」として返信が来ます。当社が対象を組み直すとき、最初にやるのは、検索条件から肩書と人柄を外し、「何を続けさせ、何を戻した人か」で並べ直し、成功の定義と戻し方を文面の最初のほうに入れることです。

## 文面に書くこと

文面の型（相手の一文→自社の場面→話す場の案内）は[ビジネス職向けスカウト文面の型](/media/wt-scout-bunmen-rei-biz/)に書いたので、ここではカスタマーサクセス特有の要点だけを書きます。

- **相手の一文は、続けさせたことと戻したことで**：「使われなくなりかけた顧客の理由を見つけて戻されたと書かれていたのを読んで」「顧客の声を製品側に伝えて〇〇が変わったと書かれていた点を読んで」。肩書や人柄ではなく、動き方
- **成功の定義を、最初のほうで**：「うちでは、顧客が〇〇を毎週使い続けていたら成功と考えています」。無いなら「まだ一文にできていない。一緒に作りたい」
- **離れた顧客の実態を、一文で**：「契約後に使われなくなる顧客が一定数いて、なぜかが分かっていない」。分かっているように書かない
- **境界を、一文で**：「問い合わせは〇〇の範囲まで受ける」「更新と追加の提案はこの仕事が持ち、給与には△△の形で連動する」。隠さない
- **製品への戻し方を、盛らずに**：「顧客の声は〇〇の場で製品側に戻す。前に△△が変わった」。場が無いなら「作るところから」
- **話す場は、事業の責任者と製品を作る側の人と**：「事業の責任者の〇〇と、製品を作る△△が、離れた顧客の実態と戻し方を隠さず話します。転職を決めていなくても構いません」

相手の前の会社の製品を評価しません。

## 返信後の面談｜離れた顧客の実態を話す

| 話すこと | 中身 |
|---|---|
| 成功の定義と、いまの状態 | 定義があるなら、それ。無いなら、無いと。事業の責任者本人が話す |
| 離れた顧客と、続いている顧客の実態 | 顧客が特定されない形で。なぜかが分かっていないなら、分かっていないと |
| 相手ならどう見つけるか | 離れる理由をどう見つけ、どう戻すか、相手の考えを聞く。ここが長い面談ほど次につながる |
| 境界の確認 | サポート、売上、給与への連動。文面と同じことを本人が話す。「聞いていない」を出さない |
| 製品を作る側の人が出て、話す | 声を戻す場と、前に変わった例と、変わらなかった例。作る側が出ると「戻せる」が実際に伝わる |
| 相手の仕事の話 | 何の顧客の、何を続けさせ、何を戻し、どうなったか。聞く時間を長く |

面談には、事業の責任者と、製品を作る側の人が出ます。面談の設計は[カジュアル面談の設計](/media/wt-scout-casual-mendan/)で書きました。

選考に進むとき、「離れた顧客の記録を見て、理由の仮説を立ててほしい」のような課題を出すなら、面談のときに「課題がある」「どのくらいの時間がかかるか」「記録はこちらで用意する」を先に伝えます。伝え方は[カジュアル面談から選考に進むときの伝え方](/media/wt-scout-senkou-ikou/)で書きました。

## 社内の分担

| 作業 | 誰が |
|---|---|
| 成功の定義、境界、戻し方、最初に持ってもらう顧客を決める | 経営者か事業の責任者 |
| 「顧客の種類、続けさせた経験、戻した経験」で対象を並べ直す | 人事（事業の責任者が基準を伝える） |
| 相手の動き方を読み、一文を書く | 事業の責任者かいま顧客を見ている人（または人事が下書きし、本人が確認） |
| 製品への戻し方と、前に変わった例の確認 | 製品を作る側の責任者 |
| 型、送信、返信対応、台帳 | 人事 |
| 面談 | 事業の責任者と、製品を作る側の人 |

一人目のカスタマーサクセスを採るスカウトでは、いま営業かサポートか経営者が兼務で顧客を見ていることが多くあります。その場合は、兼務の人が相手のプロフィールを読み、「一人目で、いまは営業が契約後も見ている。成功の定義は一緒に作る。最初は〇〇の顧客の引き継ぎから」と正直に文面に書きます。

運用代行や代理店が支えられるのは、対象の並べ直しの基準づくり、型、避ける言葉のチェック、募集記事との整合の確認までで、成功の定義、境界と戻し方の決定、相手の動き方を読んだ一文、面談は社内が担います。代理店の代行の範囲は[代理店に運用まで頼めるか](/media/kh-dairiten-unyou/)で書きました。

### エージェントベストの見解

カスタマーサクセスにスカウトを送る前に、先に決めておかないと効果が出ないのは、「製品側に声を戻せるかを、盛らずに一文にすること」です。当社がWantedlyのカスタマーサクセス向けスカウトを支えるとき、「顧客の声はプロダクトに反映されます」と書きたいが、実際に反映された例はまだ無い、という会社が多くあります。書けば返信は増えるかもしれませんが、入社後に「戻しても変わらない」と分かった人は、この仕事ごと離れます。逆に、「戻す場はまだ無い。月に一度、製品を作る〇〇と一緒に顧客の声を見る場を作るところから」と書いた会社は、返信の数は減っても、戻す仕組みを作りたい人が来て、その人が実際に場を作ります。当社が最初にお願いするのは、対象の絞り込みではなく、製品を作る側の責任者に「顧客の声で、いままでに実際に変えたものは何か」を、無ければ無いと、一文で言ってもらうことです。その一文が、文面の信用を決めます。

## やりがちな失敗

| 失敗 | 何が起きるか | 直し方 |
|---|---|---|
| 肩書や人柄で相手を選ぶ | 面談で「顧客の種類が違う」「境界が違う」 | 顧客の種類、続けさせた経験、戻した経験で選ぶ |
| 「顧客に寄り添える方」「CS経験を活かして」と送る | 開かれない | 相手の動き方を読んだ一文で |
| 成功の定義が無いのに、あるように書く | 面談で聞かれ、答えられない | 無いなら、一緒に作ると書く |
| 境界を文面で隠す | 面談で「聞いていない」で離れる | サポート、売上、給与への連動を書く |
| 製品への戻し方を盛る | 入社後に「変わらない」と分かり、離れる | 場の有無と、前に変わった例だけ |
| 面談に製品を作る側が出ない | 「戻せる」が伝わらない | 作る側の人が出る |

最も多いのは、最初の「肩書や人柄で選ぶ」と、製品への戻し方の盛りです。

## まとめ

- カスタマーサクセスは、誰から来たか・自分の仕事の何を読んだか・成功の定義・境界・製品側に声を戻せるか・離れた顧客の実態、を文面の段階で見ている
- 送る前に、成功の定義、境界、製品への戻し方、最初に持ってもらう顧客を、事業の責任者が決める。無いものは無いと書く前提で
- 誰に送るかは、肩書や業界ではなく、顧客の種類と単価、「使われない理由を見つけて戻した」「製品側に戻して変わった」の重なりで。肩書と人柄は「あればよい条件」に
- 文面には、相手の動き方を読んだ一文、成功の定義、離れた顧客の実態、境界、戻し方を盛らずに。「寄り添う」「CS経験を活かして」を書かない
- 面談は事業の責任者と製品を作る側の人が出て、離れた顧客の実態と、戻して変わった例・変わらなかった例を話す

## よくある質問

### 肩書が「カスタマーサクセス」の人が、検索でほとんど出ません

肩書で絞る必要はありません。この仕事は、「アカウントマネージャー」「サポートで継続を見ていた人」「営業で契約後も顧客を見ていた人」「導入支援」が担っていることが多くあります。「何の顧客の、何を続けさせ、何を戻したか」で読み、その人に「〇〇の顧客の使われない理由を見つけて戻されたと書かれていたのを読んで」と送ります。

### 製品側に声を戻す場がまだありません。文面にそう書くと開かれませんか

盛るほうが、入社後に分かって離れます。「戻す場は、いまは無い。月に一度、製品を作る〇〇と一緒に顧客の声を見る場を作るところから。前に変わった例はまだ無い」と、無いことと、これから作ることを分けて書きます。

### カスタマーサクセス向けのスカウトの対象の絞り込みは、御社に相談できますか

できます。当社は、対象の並べ直しの基準づくり、文面の型、避ける言葉のチェック、募集記事との整合の確認を支えられます。成功の定義、境界と戻し方の決定、相手の動き方を読んだ一文、面談は、社内の事業の責任者が担ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、Wantedlyのスカウト運用を支えています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
