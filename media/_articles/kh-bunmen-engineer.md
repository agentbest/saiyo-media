エンジニアにスカウトを送る。「〇〇、△△、□□のご経験をお持ちの方を探しています」と技術名を並べ、「最新技術」「モダンな開発環境」と書く。人事の名義で送る。返信が来ない。**結論から言うと、エンジニア向けの文面は、技術名の羅列ではなく「何を、どう作ったか」を読み、自社の開発の「進め方と決め方」と重ね、送り主はエンジニアにします。技術の言葉は、相手が使った言葉だけを使い、分からないことは分からないと書きます。四段の型は、作ったものを読んだ一文、自社の開発の進め方と決め方との重なり、選考で何を見るか（コードか設計か話か）、エンジニアと話す場、です。新卒エンジニアには、読む場所を変えます。** この記事では、エンジニアが開かない文面、読む箇所、四段の型、技術の言葉の扱い、送り主、新卒エンジニア、分担を整理します。文面全体の骨組みは[スカウト文面の基本構成](/media/kh-bunmen-kihon/)、Wantedlyでのエンジニア向けは[Wantedlyのエンジニア向けスカウト文面の型](/media/wt-scout-bunmen-rei-eng/)で書きました。この記事は、三つの媒体に共通するエンジニア向けの型です。

## この作業の目的｜「技術を分かっている人からの、開発の話」にする

エンジニアは、技術を分かっていない人からの技術の話を、すぐに見抜きます。技術名を並べただけの文面、「最新技術」で埋めた文面、人事が技術を語る文面は、開かれるか、開かれてすぐ閉じられます。

目的は、文面を「技術を分かっている人（自社のエンジニア）からの、開発の進め方の話」にすることです。技術の深さで競うのではなく、「何をどう作っているか」を正直に書きます。

## エンジニアが、開かない文面

| 文面 | エンジニアが受け取ること |
|---|---|
| 「〇〇、△△、□□のご経験をお持ちの方を探しています」 | 技術名の検索で送った。求人票の要件 |
| 「最新技術」「モダンな開発環境」「最先端の」 | 中身がない。技術を分かっていない |
| 人事の名義で、技術を語る | 誰が書いたか分かる。開発の話にならない |
| 「エンジニア募集」「〇〇エンジニアの方へ」の件名 | 全部の会社が同じ件名 |
| 「技術力の高い方に」「優秀なエンジニアを」 | 持ち上げ。慣れている |
| 事業の説明が長く、開発の話がない | 何を作っているかが分からない |
| 「裁量が大きい」「自由な環境」の抽象語 | 具体がない。何を決められるかが分からない |

共通するのは、「技術名」と「抽象語」で埋まっていて、「何を、どう作っているか」がないことです。開かない文面の詳しくは[Wantedlyのエンジニア向けスカウト文面の型](/media/wt-scout-bunmen-rei-eng/)の「エンジニアが開かない文面」で書きました。

## プロフィール・ストーリー・成果物で、読む箇所

- **何を作ったか**：「〇〇のサービスの△△機能を、設計から実装まで」。技術名ではなく、作ったもの
- **どう作ったか**：「□□で詰まって、✕✕の方法に変えた」「一人で設計した」「チームで分担した」
- **なぜその技術を選んだか**：「〇〇を選んだ理由は△△」。ストーリーや自由記述に書かれていることがある
- **公開されている成果物**：コード、記事、登壇。相手が公開しているものは、読んでよい。公開していないものは、推測しない
- **読まない箇所**：技術名の一覧、資格、所属の社名。これは見出し
- **拾うのは、「作ったもの」と「その進め方」を一つ**

読む箇所の詳しくは[Wantedlyのエンジニア向けスカウト文面の型](/media/wt-scout-bunmen-rei-eng/)の「プロフィールで、読む箇所」で書きました。

### エージェントベストの見解

相談で最も多い思い込みは、「エンジニアには技術の話をしなければならないので、人事では書けない」というものです。当社は3媒体すべての販売パートナーとして、三つの媒体のエンジニア向けの文面を見ていますが、返信が来ている文面の多くは、技術の深い話をしていません。「〇〇の機能を設計から実装まで担当されたと書かれていて」「うちの△△は、一人が設計から持ちます」のように、「何を作ったか」と「どう進めているか」を、平易な言葉で書いています。技術の深さで書くのではなく、開発の進め方で書く、なら、人事が現場のエンジニアから一文を聞いて書けます。ただし、送り主の名義はエンジニアで、エンジニアが文面を確認します。当社がエンジニア向けの文面の相談を受けるとき、最初にやるのは、技術名を全部抜いて、「何を作っているか」と「どう進めているか」の二つを、現場のエンジニアに聞くことです。

## 四段の型

| 段 | 書くこと | 例 |
|---|---|---|
| 1. 作ったものを読んだ一文 | 相手が作ったものと、その進め方を一つ、相手の言葉のまま | 「〇〇の△△機能を、設計から実装まで一人で担当されたと書かれているのを拝見しました」 |
| 2. 自社の開発の進め方と決め方との重なり | 何を作っていて、どう進めていて、誰が何を決めるか。1と重ねる | 「うちでは□□を作っていて、機能ごとに一人が設計から持ちます。技術の選定は、その担当が決めます。近いと思いました」 |
| 3. 選考で何を見るか | コードか、設計か、話か。相手が準備できる形で | 「選考では、これまでに作ったものについて、どう設計したかの話を聞きます。コーディングテストはありません」（有無は自社の実態で） |
| 4. エンジニアと話す場 | 誰（エンジニア）と、どんな形で、選考ではないこと | 「選考ではなく、この文面を書いた私（エンジニア）と、オンラインで短い時間、開発の話をする場です。一言だけご返信ください」 |

「2」で書くのは、「技術スタック」ではなく、「進め方と決め方」です。何を使っているかより、誰がどう決めるかを、エンジニアは読みます。四段の詳しくは[Wantedlyのエンジニア向けスカウト文面の型](/media/wt-scout-bunmen-rei-eng/)の「文面の3段の型」に、この記事の「3」を足したものです。

## 技術の言葉の、扱い

- **相手が使った言葉だけを使う**：相手が「〇〇」と書いていれば「〇〇」。言い換えない
- **自社が使っている技術は、事実として一言**：「うちは〇〇と△△を使っています」。「最新の」「モダンな」を付けない
- **分からないことは、分からないと書く**：人事が書く場合、「私は技術の詳細は分かりませんが、□□（エンジニア）から、あなたの✕✕の進め方が近いと聞きました」
- **技術の優劣を書かない**：「〇〇より△△のほうが」は、相手の判断の領域
- **技術の詳しい話は、話す場で**：文面では「進め方」まで。技術の話はエンジニア同士で

扱いの詳しくは[Wantedlyのエンジニア向けスカウト文面の型](/media/wt-scout-bunmen-rei-eng/)の「技術の言葉の扱い」で書きました。

## 送り主は、エンジニア

- **名義は、自社のエンジニア**：人事の名義で技術の話をしない
- **エンジニアが書けないなら、人事が「進め方」を聞いて書き、エンジニアが確認して、エンジニアの名義で**：名前だけ貸さない。確認は要る
- **話す場に、そのエンジニアが出る**：文面に書いた人と、出る人を揃える
- **エンジニアの時間は、「一文を話す」「確認する」「話す場に出る」の三つだけ**：文面の作成と送信は人事
- **エンジニアの巻き込み方は[OfferBoxの現場の巻き込み方](/media/ob-genba-makikomi/)と同じ**

送り主の考え方は[Wantedlyのエンジニア向けスカウト文面の型](/media/wt-scout-bunmen-rei-eng/)の「送り主は、エンジニア」で書きました。

## 新卒エンジニアで、変える点

| 変える点 | 中途エンジニア | 新卒エンジニア |
|---|---|---|
| 1で読むもの | 仕事で作ったものと進め方 | 研究・授業・個人で作ったものと、その進め方。「研究で条件を変えて比べた」「個人で〇〇を作って公開した」 |
| 2の重なり | 開発の進め方と決め方 | 「最初の一年」で何を作るか、誰と、どう。「入社した年に、△△の機能を先輩と二人で」 |
| 3の何を見るか | 作ったものの設計 | 作ったものと、なぜそう作ったか。研究の進め方 |
| 4の場 | エンジニアと開発の話 | エンジニアと、最初の一年の話 |

新卒エンジニアの読み方は、理系学生の読み方と同じで、「研究テーマ」ではなく「研究の進め方」です。[OfferBoxで理系学生にオファーを送るときの文面](/media/ob-rikei-gakusei/)、[ワンキャリアで理系学生にスカウトを送る](/media/oc-scout-rikei/)で書きました。新卒向けの型は[新卒向けスカウト文面の型](/media/kh-bunmen-shinsotsu/)で書きました。

## 社内の分担

| 作業 | 誰が |
|---|---|
| 技術名と抽象語を文面から抜く | 人事 |
| 相手の「作ったもの」と「進め方」を一つ拾う | 送る人（エンジニアか、エンジニアに確認した人事） |
| 自社の開発の「進め方と決め方」を一文で話す | 現場のエンジニア |
| 「選考で何を見るか」（コードか設計か話か）を決める | エンジニアの責任者と人事 |
| 四段の型を作り、1と2を相手ごとに埋める | 人事。エンジニアが確認 |
| エンジニアの名義で送り、話す場に出る | エンジニア |

運用代行や代理店が支えられるのは、四段の型、読む箇所の型、技術の言葉の扱いの整理、エンジニアへの聞き方の型までで、作ったものを拾うこと、進め方を話すこと、名義、話す場に出ることは企業が行います。代理店の代行の範囲は[代理店に運用まで頼めるか](/media/kh-dairiten-unyou/)で書きました。

### エージェントベストの見解

これはどこまでやるかの線引きの話です。当社がエンジニア向けの文面の相談を受けるとき、当社が持てるのは、四段の型と、読む箇所の型と、技術の言葉の扱いの整理と、現場のエンジニアへの聞き方の型までです。「何を作っているか」「どう進めているか」「誰が何を決めるか」は、会社の中のエンジニアにしか言えず、当社が推測して書くと、エンジニアの相手に「技術を分かっていない人が書いた」と読まれます。当社が線を引くのは、「技術のことは分からないので、代理店で技術的な文面を書いてほしい」という依頼です。当社も技術の中身は書けず、書くべきでもありません。当社が勧めるのは、現場のエンジニアに三つ（何を、どう、誰が決める）を聞いて、その言葉のまま型に入れ、エンジニアの名義で送ることです。

## まとめ

- エンジニアは、技術名の羅列・「最新技術」の抽象語・人事が技術を語る文面・「エンジニア募集」の件名を開かない。「何を、どう作っているか」がないから
- 読むのは、相手が「何を作ったか」「どう作ったか」「なぜその技術を選んだか」「詰まったときどうしたか」。技術名の一覧は見出しで拾わない
- 四段の型は、作ったものを読んだ一文→自社の開発の「進め方と決め方」との重なり→選考で何を見るか（コードか設計か話か）→エンジニアと話す場。「2」は技術スタックではなく、誰がどう決めるか
- 技術の言葉は相手が使った言葉だけ。「最新の」を付けず、優劣を書かず、分からないことは分からないと書く。送り主はエンジニアで、名前だけ貸さない
- 新卒エンジニアは、研究・授業・個人で作ったものと進め方を読み、「最初の一年」で何を作るかと重ねる

## よくある質問

### 社内にエンジニアが少なく、名義になれる人がいません

一人でもいれば、その一人の名義で、人事が「進め方」を聞いて書き、その人が確認します。エンジニアの時間は「一文を話す」「確認する」「話す場に出る」の三つだけです。一人もいなければ、エンジニアの一人目を採る文面になるので、「一人目のエンジニアを探しています。技術の決定は、入った方に任せます」と正直に書き、名義は代表にします。隠さないことが、エンジニアには届きます。

### コーディングテストがある場合、文面に書くべきですか

書きます。「選考では〇〇のコーディングテストがあります」と、事実で。隠して選考で初めて出すと、「聞いていなかった」が残ります。テストの有無と形は自社の実態で、文面の「3」に一文で書きます。エンジニアは、選考で何を見られるかが分かれば準備でき、分からなければ返信しません。

### エンジニア向けスカウト文面の型は、御社に相談できますか

できます。当社は、四段の型、読む箇所の型、技術の言葉の扱いの整理、エンジニアへの聞き方の型を支えられます。作ったものを拾うこと、進め方を話すこと、名義、話す場に出ることは、企業が行ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、3媒体の運用を支えています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
