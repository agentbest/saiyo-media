ワンキャリアで新卒エンジニアを募集したとき、最初にぶつかるのは「『エンジニア職』と使っている技術の一覧を掲載したのに、エントリーが少ない。来ても、技術面接で『何を作るのですか』『誰が教えてくれますか』と聞かれ、答えた内容が体験談で『面接官によって聞かれることが違った』『技術の話が出なかった』と書かれる」という問題です。**結論から言うと、ワンキャリアのエンジニアの掲載は、技術名の一覧ではなく「何を作っていて、最初の年に誰と何を作り、自社開発か受託か、技術面接で何を見るか」を、学生が体験談で読む前に企業ページと募集に書き、技術面接の型を揃えて、スカウトと面接でも同じ言葉で話します。** この記事では、エンジニア志望の学生が体験談で読んでいること、掲載に書くこと、学生の見つけ方、スカウトの文面、選考への接続、社内の分担、やりがちな失敗を整理します。理系学生向けの掲載の全体は[ワンキャリアで理系学生向けに掲載するとき](/media/oc-rikei-keisai/)、理系学生へのスカウトは[ワンキャリアで理系学生にスカウトを送る文面](/media/oc-scout-rikei/)で書きました。この記事は、エンジニアに絞って、掲載とスカウトと技術面接をつなげて書きます。

## エンジニア志望の学生が、体験談で読んでいること

ワンキャリアの学生は、企業ページを読む前に、技術面接の体験談と、その会社のエンジニアで入った先輩の話を読んでいます。

| 読んでいること | 掲載への意味 |
|---|---|
| 何を作っている会社か | 技術名ではなく、何を作っていて、誰が使うものか。「エンジニア職」の名前では分からない |
| 自社開発か、受託か | 自社のものを作るのか、顧客のものを作るのか。常駐の有無。体験談で最も聞かれる |
| 最初の年に何を作るか | 研修の期間、最初に触るもの、誰がレビューするか。「研修充実」の一語では分からない |
| 誰が教えるか | 同じ職種の先輩が付くか。一人目の新卒エンジニアか |
| 技術面接で何を聞かれたか | 作ったものを見せたか、その場で書かされたか、面接官によって違ったか |

「技術面接で何を聞かれたか」が、エンジニアの体験談で最も読まれ、企業ページで最も書かれない項目です。面接官によって聞かれることが違うと、体験談に「型が無い」と書かれ、学生は「技術を見ていない会社」と読みます。

## 掲載に書くこと｜作っているもの、最初の年、教える人、技術面接の型

| 書くこと | 書き方 |
|---|---|
| 職種名 | 「エンジニア職」ではなく「〇〇（作っているもの）を作るエンジニア」。配属が決まっているなら、そう書く |
| 何を作っているか | 「〇〇の業種の担当者が毎日使う△△を作っている。自社のもの」「顧客の□□を受託で作っている。常駐は無い」 |
| 自社開発か受託か | 隠さない。受託なら、案件の種類と常駐の有無と期間 |
| 最初の年 | 「最初の〇か月は研修で△△を作る。その後、□□の一部を先輩のレビュー付きで。一年目の終わりに◇◇を一人で」 |
| 教える人 | 「同じ職種の先輩が付く。週に一度、書いたものを一緒に見る」「新卒エンジニアは一人目。責任者が付く」 |
| 技術構成 | 技術名の一覧ではなく、何のためにどれを使っていて、なぜか。古いものが残っているなら、残っていると |
| 技術面接の型 | 「作ったものを見せてもらい、なぜそう作ったかを聞く。その場で書いてもらうことはしない」。面接官が変わっても同じ |

技術構成の書き方は[Wantedlyでエンジニアを採る募集記事の書き方](/media/wt-engineer-boshu/)と共通で、「名前の一覧にせず、何のために、なぜ」を文で書きます。企業ページには作っているものと技術面接の型を、募集には最初の年と教える人を、と分担します。

### エージェントベストの見解

相談で最も多い思い込みは、「エンジニア志望の学生には、使っている技術を一覧で見せれば専門性が伝わる」というものです。当社は3媒体すべての販売パートナーとして、ワンキャリアのエンジニアの掲載と選考を見ていますが、技術名の一覧を掲載した会社の体験談には、技術名はほとんど出てきません。出てくるのは、「何を作っている会社か分からなかった」「技術面接で作ったものを見てもらえなかった」「面接官によって聞かれることが違った」です。逆に、「〇〇を作っている。技術面接では作ったものを見せてもらい、なぜそう作ったかを聞く」と企業ページに書き、実際にその型で面接した会社は、体験談に「作ったものを丁寧に見てくれた」と書かれ、次の年の学生がそれを読んで来ます。当社が最初にお願いするのは、技術名の一覧を消し、「何を作っているか」を一文と、技術面接の型を一つ決めることです。

## エンジニア志望の学生の見つけ方

ワンキャリアでエンジニアに合う学生は、情報系の専攻だけでは見つかりません。

| 見る箇所 | 何が書かれているか | 読み方 |
|---|---|---|
| 専攻 | 情報系は多いが、情報系以外でプログラミングをしている学生も多い | あればよい条件。情報系だけで絞らない |
| 作ったもの | 「〇〇を作った」「△△のアプリを公開した」。授業の課題か、自分で作ったか | 自分で作って、動かなかったときに直した記述を優先 |
| 動かなかったときの記述 | 「エラーが出て、原因を調べて直した」「設計を変えた」 | 技術面接で聞く「なぜそう作ったか」と重なる |
| 研究の進め方 | 情報系以外なら、研究で「詰まった場面と、そのとき何をしたか」 | 開発の「詰まったときの動き方」と同じ型 |
| 公開しているもの | コードや記事を公開していれば、何に関心があるか | あれば読む。無くても外さない |

「動かなかったときに、何をしたか」を書いている学生が、エンジニアと重なります。研究の進め方の読み方は[ワンキャリアで理系学生にスカウトを送る文面](/media/oc-scout-rikei/)で書きました。

## スカウトの文面｜掲載と同じ言葉で

スカウト文面の型（学生時代を読んだ一文→最初の1年との重なり→選考で何を見るか→話す場か選考か）は[ワンキャリアのスカウト文面の書き方](/media/oc-scout-bunmen/)で書きました。エンジニアでは、次の点を足します。

- **相手の一文は、作ったものと直したことで**：「〇〇を作って、△△で動かなくなって設計を変えたと書かれていたのを読んで」。技術名を並べない
- **何を作っているかを、一文で**：「うちは、〇〇の担当者が毎日使う△△を作っています。自社のものです」。受託なら受託と
- **最初の年を、一文で**：「最初の〇か月は研修で△△を作り、その後、先輩のレビュー付きで□□の一部を」
- **技術面接の型を、一文で**：「面接では、作ったものを見せてもらい、なぜそう作ったかを聞きます。その場で書いてもらうことはしません」
- **送り主は、同じ職種の先輩エンジニア**：人事の名前で「技術力を活かして」と送らない

技術の言葉は、送り主が確認して正確に。スカウトと掲載の言葉が違うと、学生は体験談で確かめます。つなげ方は[スカウトと掲載のつなげ方](/media/oc-scout-keisai-renkei/)で書きました。

## 選考への接続｜技術面接の型を揃え、聞かれる前に話す

- **技術面接の型を、一つに決める**：「作ったものを見せてもらい、なぜそう作ったかを聞く」か、「課題を事前に渡して、面接で説明してもらう」か。面接官が変わっても同じにする。型の揃え方は[ワンキャリアで理系学生向けに掲載するとき](/media/oc-rikei-keisai/)
- **面接には、エンジニアが出る**：人事だけの面接は、体験談に「技術の話が出なかった」と書かれる。同じ職種の先輩が出て、作ったものを見る
- **自社開発か受託か、常駐の有無を、聞かれる前に話す**：面接の最初のほうで。聞かれてから答えると「隠していた」と書かれる
- **学生の「動かなかったとき」を聞く**：結果ではなく、動かなかったとき何を調べ、何を変えたか
- **内定後に、開発の場を見せる**：内定の後、実際の開発の一日やレビューの場を見せると、辞退が減る。[ワンキャリア経由の内定辞退が続くとき](/media/oc-naitei-jitai/)
- **面接で話したことは、体験談に書かれる前提で**：掲載と面接で同じことを言う

## 社内の分担

| 作業 | 誰が |
|---|---|
| 何を作っているか、自社開発か受託か、最初の年、教える人、技術面接の型を決める | エンジニアの責任者 |
| 企業ページのエンジニアの記述 | 人事が、責任者と先輩エンジニアに聞いて書く |
| 技術構成と、技術の言葉の確認 | エンジニア |
| 先輩エンジニアの話 | 先輩本人が話し、人事が書き、本人が確認 |
| 体験談との整合の確認 | 人事（技術面接の体験談を読み、型と食い違う箇所を直す） |
| スカウトの一文 | 先輩エンジニア |
| 技術面接 | エンジニアの責任者と、先輩エンジニア。型を揃えて |

一人目の新卒エンジニアを採る会社では、「先輩エンジニア」が中途の人になります。その場合は、「新卒エンジニアは一人目。中途で入った〇〇が付く。最初の年は△△」のように、一人目であることと、付く人を書きます。

運用代行や代理店が支えられるのは、掲載の型、技術構成を文で書く直し方、技術面接の型の整理、体験談との整合の確認、スカウトの型、学生の見つけ方の基準づくりまでで、技術の言葉の確認、技術面接、先輩の話は社内のエンジニアが担います。代理店の代行の範囲は[代理店に運用まで頼めるか](/media/kh-dairiten-unyou/)で書きました。

### エージェントベストの見解

エンジニアの内定辞退が続く会社に共通するのは、「技術面接の型が面接官ごとに違い、体験談に『何を見られたか分からなかった』と書かれている」ことです。当社がワンキャリアのエンジニアの選考を見ていると、一次の面接官は作ったものを見て、二次の面接官はその場で書かせ、三次は人事が志望動機を聞く、という形が多くあります。学生は、面接官ごとに違う型を「技術を見る基準が無い会社」と読み、体験談にそう書き、次の年の学生がそれを読みます。辞退の理由は「技術面接が難しいから」ではなく、「何を見られたか分からないから」です。逆に、「作ったものを見せてもらい、なぜそう作ったかを聞く」と型を一つに決め、企業ページに書き、全員の面接官がその型で聞いた会社は、体験談に「一貫していた」と書かれ、辞退が減ります。当社が案内するのは、技術面接の型を一つに決めて企業ページに書き、面接官の全員に同じ型で聞いてもらい、体験談に「一貫していた」と書かれる形にすることです。面接の難しさで学生は離れません。型が無いことで離れます。

## やりがちな失敗

| 失敗 | 何が起きるか | 直し方 |
|---|---|---|
| 技術名の一覧で掲載する | 「どの会社にもある」と読み飛ばされる | 何を作っているかを一文。技術は何のために、なぜ、で |
| 自社開発か受託かを書かない | 面接で「常駐がある」と出て、体験談に書かれる | 隠さず書く。受託なら常駐の有無と期間 |
| 技術面接の型が面接官ごとに違う | 体験談に「何を見られたか分からない」と書かれる | 型を一つに決め、企業ページに書き、全員で揃える |
| 人事だけで技術面接をする | 体験談に「技術の話が出なかった」と書かれる | エンジニアが出る |
| 情報系だけで学生を絞る | 情報系以外で作っている学生を落とす | 作ったものと、動かなかったときの記述で読む |

最も多いのは、技術名の一覧と、技術面接の型の不揃いです。

## まとめ

- エンジニア志望の学生は、体験談で「何を作っている会社か・自社開発か受託か・最初の年に何を作るか・誰が教えるか・技術面接で何を聞かれたか・先輩の実態」を、企業ページより先に読む
- 掲載には、何を作っているかを一文、自社開発か受託か、最初の年、教える人、技術構成は何のためになぜ、技術面接の型を書く。体験談と食い違わないように
- エンジニア志望の学生は、専攻だけでなく、「作ったもの」と「動かなかったときに何をしたか」の記述で見つける
- スカウトは、先輩エンジニアの名前で、掲載と同じ言葉で。技術名を並べず、作ったものと直したことを読んだ一文で
- 技術面接の型を一つに決め、エンジニアが出て、自社開発か受託かを聞かれる前に話す。面接で話したことは体験談に書かれる前提で

## よくある質問

### 受託が中心で、常駐もあります。企業ページに書くと、エントリーが減りませんか

減りますが、面接後の辞退と、入社後の離職が減ります。「受託で、〇〇の種類の案件が中心。常駐は△△の期間で、週に□□日は自社」と事実で書けば、それを前提にエントリーする学生が来ます。書かずに面接で出ると、体験談に「面接で初めて常駐と聞いた」と書かれ、次の年の学生がそれを読みます。

### 技術面接の型を、社内で揃えられません

揃わないなら、型を一つに減らします。「作ったものを見せてもらい、なぜそう作ったかを聞く」だけにし、その場で書かせる面接官がいるなら、やめてもらいます。

### エンジニアの掲載とスカウトは、御社に相談できますか

できます。当社は、掲載の型、技術構成を文で書く直し方、技術面接の型の整理、体験談との整合の確認、スカウトの型、学生の見つけ方の基準づくりを支えられます。技術の言葉の確認、技術面接、先輩の話は、社内のエンジニアが担ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、ワンキャリアの掲載とスカウトの運用を支えています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
