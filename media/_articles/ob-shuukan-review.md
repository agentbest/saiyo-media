OfferBoxの運用は、送り続ける限り動き、止まると止まります。止まったことに気づくのが遅いほど、取り戻すのに時間がかかります。**結論から言うと、週に一度、短く固定した場で、「止まっている段階はどこか」を確認し、「翌週に直すことを1つ」決める。これが週次レビューです。数字の解釈や、報告のための会議にしないことが要点です。** この記事では、週次レビューの目的、時間と参加者、見る順番、記録の型、変更を1つに絞る理由、月次レビューとの違い、やりがちな失敗、人事と現場と代行の分担を整理します。見る数字の決め方は[KPI設計](/media/ob-kpi-sekkei/)で書きました。この記事は、その数字を「どう見る場を持つか」です。

## この作業の目的｜止まりを、その週のうちに直す

OfferBoxの運用で最も多い失敗は、止まったことに気づかないまま時期が過ぎることです。送る人の時間が取れなくなった、承認への返信が溜まった、面談枠が埋まった。どれも、起きた週に気づけば直せます。月末に気づくと、その月は無駄になります。

週次レビューの目的は、止まりを「その週のうちに」見つけて、翌週に直すことです。成果を報告する場でも、数字を解釈する場でもありません。「止まっているか」「どこで」「翌週に何を変えるか」の3つを決める場です。

## 手順1｜時間と参加者を固定する

週次レビューは、短く、決まった曜日と時間に固定します。

| 項目 | 決め方 |
|---|---|
| 時間 | 短く。段階ごとの数と日数を確認し、直すことを1つ決めるだけなら、長い時間は要らない |
| 曜日 | 週の初めか終わり。週の初めなら「今週何をするか」、終わりなら「来週何を変えるか」 |
| 参加者 | 人事（運用の担当）と、名義の人（面談枠の話があるため）。運用代行に出しているなら代行の担当 |
| 場所 | オンラインで足りる。管理画面と記録を画面で共有する |
| 固定 | 「忙しいから今週は飛ばす」を許さない。飛ばした週に止まりが起きる |

「名義の人が出る」のは、承認から面談までの日数が延びたときに、面談枠の話がその場でできるからです。人事だけで見ると、「面談枠が足りない」と分かっても、現場に頼みに行く1週間が挟まります。

## 手順2｜見る順番を決める

見る順番を固定すると、レビューが短くなります。

1. **止まりの確認**：今週、送ったか。承認に当日返信したか。面談が翌週に入っているか。この3つを最初に「はい・いいえ」で確認する
2. **段階ごとの数と日数**：送信数、承認数、返信までの日数、面談数、面談までの日数、選考の各段階、内定と承諾。目標値との差を見る。数字の読み方はKPI設計の記事で
3. **原因の切り分け**：差が出た段階について、原因を1つに絞る。送信が少ないなら「送る時間が取れなかったか、読む対象が尽きたか」。承認が少ないなら「検索条件か、文面か、見に来た先か、時期か」。面談が少ないなら「返信が遅いか、面談枠が無いか、日程が合わないか」
4. **翌週に直すことを1つ決める**：原因に対して、翌週に変えることを1つ。誰が、いつまでに
5. **先週決めたことの結果を見る**：先週の変更が、今週の数字にどう出たか

1の「止まりの確認」だけで終わる週も多くあります。3つとも「はい」なら、止まっていません。数字を細かく見なくても、レビューは終わりです。

### エージェントベストの見解

申し込んだあと、週次レビューを始めた会社で数ヶ月後に起きやすいのは、「レビューが報告会になる」ことです。人事が数字を読み上げ、上司が聞き、「引き続き頑張ろう」で終わる。止まっている段階も、翌週に直すことも決まらず、数字を眺めるだけの場になります。当社は3媒体すべての販売パートナーとしてOfferBoxの契約後の運用を見ていますが、レビューが機能している会社は、「翌週に直すことを1つ決めて終わる」を型にしています。数字の読み上げは記録を見れば済むので省き、「止まっている段階はどこか」「何を変えるか」「誰がやるか」の3つだけを話す。当社がOfferBoxの運用代行で週次の打ち合わせを持つときも、この3つで終えます。報告は事前に記録で共有し、打ち合わせでは決めることだけをやる。この分け方で、レビューは短くなり、続きます。

## 手順3｜変更は1つずつ

翌週に直すことは、1つに絞ります。複数を同時に変えると、翌週の数字がどの変更の結果か分かりません。

- **1つだけ変える**：検索条件を広げる、文面の冒頭を深くする、返信の担当を増やす、面談枠を足す、のどれか1つ
- **変えたことを記録する**：何を、いつ、どう変えたか
- **翌週のレビューで、結果を見る**：変えた段階の数字が動いたか
- **動かなければ、別の原因を疑う**：同じ段階の別の原因か、別の段階か
- **動いたら、定着させてから次へ**：数週間続けて、安定したら次の変更に

「1つずつ」は遅く感じますが、複数を同時に変えて何が効いたか分からない状態より、結果として速く進みます。文面の変更は特に、テンプレートの一部を変えると全員に影響するので、1つずつにします。テンプレートの更新は[オファー文面テンプレートを作るときの注意](/media/ob-offer-template/)で書きました。

## 手順4｜記録の型

週次レビューの記録は、KPI設計の記事で書いた「週ごとに1行」に、レビューの決定を足したものです。

| 項目 | 書くこと |
|---|---|
| 週 | いつの週か |
| 止まりの確認 | 送ったか、当日返信したか、面談が翌週に入っているか。はい・いいえ |
| 段階ごとの数と日数 | 送信、承認、返信日数、面談、面談日数、選考、内定、承諾 |
| 目標との差 | 差が出た段階 |
| 原因 | 1つに絞った原因 |
| 翌週に直すこと | 何を、誰が、いつまでに |
| 先週の変更の結果 | 効いたか、効かなかったか |

記録は、レビューの場でそのまま書きます。あとで書こうとすると、書かれません。記録が残っていれば、担当が変わっても、どの変更が効いてどの変更が効かなかったかが引き継げます。引き継ぎは[運用を担当者間で引き継ぐ方法](/media/ob-tantousha-hikitsugi/)で書きます。

## 手順5｜月次レビューとの違い

週次と月次は、見るものが違います。

| 観点 | 週次 | 月次 |
|---|---|---|
| 目的 | 止まりを見つけて翌週に直す | 率を置き直し、計画を見直す |
| 見るもの | 段階ごとの数と日数 | 月の合計と率 |
| 決めること | 翌週に直すこと1つ | 残りの期間の送信数、時期の配分、体制の追加 |
| 参加者 | 人事と名義の人 | 人事と面接官と経営（見込みの共有） |
| 時間 | 短く | 週次より長くてよい |

月次レビューでは、「採る人数に対して、いまの見込みは何人か」を経営に伝えます。見込みが足りないなら、送信数を増やすか、体制を足すか、人数を見直すかを、この場で決めます。率の置き直しと計画の見直しは[採用人数から逆算する送信計画](/media/ob-ninzu-keikaku/)で書きました。

週次で率を議論し始めたら、それは月次の話です。「それは月末に」と切って、週次を短く保ちます。

## やりがちな失敗

| 失敗 | 何が起きるか | 直し方 |
|---|---|---|
| 報告会になる | 決めることが無く、止まりが直らない | 「止まっている段階」「直すこと」「誰が」の3つだけ |
| 忙しい週に飛ばす | その週に止まりが起きる | 固定し、飛ばさない |
| 名義の人が出ない | 面談枠の話がその場でできない | 面談枠に関わるので出てもらう |
| 複数を同時に変える | 何が効いたか分からない | 1つずつ |
| 週次で率を議論する | 長くなり、結論が出ない | 率は月次 |
| 記録をあとで書く | 書かれない | その場で書く |
| 先週の変更の結果を見ない | 変更の効果が分からず、変え続ける | レビューの最後に見る |
| 数字を担当の評価に使う | 担当が身構え、止まりを隠す | 直す場所を決めるためと合意する |

最も多いのは、最初の「報告会になる」です。数字を読み上げる時間を省き、決めることだけをやると防げます。

## 社内の分担

| 作業 | 誰が |
|---|---|
| 週次レビューを設定し、固定する | 人事 |
| 記録を事前に埋めておく | 人事（または運用代行） |
| 止まりの確認と、段階ごとの数と日数 | 人事 |
| 面談枠に関わる判断 | 名義の人 |
| 原因の切り分け | 人事（代行と一緒に） |
| 翌週に直すことを決める | 人事（現場の協力が要るなら名義の人と） |
| 変更を実行する | 決めた人 |
| 月次で率を置き直し、経営に見込みを伝える | 人事 |

運用代行に出している場合、記録の事前作成と、段階ごとの数と日数の整理は代行が行います。止まりの確認と原因の切り分けは、代行と社内で一緒に。翌週に直すことのうち、文面と検索条件は代行が、面談枠と返信の体制は社内が担います。代行の範囲は[代理店に運用まで頼めるか](/media/kh-dairiten-unyou/)で書きました。

### エージェントベストの見解

自社で持つべきなのは、どこまでか。当社がOfferBoxの運用代行で週次レビューを持つとき、数字の整理、止まっている段階の特定、文面と検索条件の変更は当社が担いますが、「面談枠を足す」「返信の担当を決める」「面接官に頼む」は社内にしか決められません。週次レビューで止まりの原因が面談枠にあると分かっても、名義の人がその場にいなければ、枠の話は翌週に持ち越されます。当社が週次の打ち合わせに名義の人の同席をお願いするのは、このためです。代行に出しても、週次レビューの「決める」部分の半分は社内にあります。レビューを代行に任せきりにすると、代行が直せる範囲（文面と条件）だけが直り、社内でしか直せない範囲（枠と体制）が止まったままになります。週次レビューは、代行と社内が一緒に持つ場です。

## まとめ

- 週次レビューの目的は、止まりをその週のうちに見つけ、翌週に直すことを1つ決めること。報告会にしない
- 時間と曜日と参加者を固定し、忙しい週も飛ばさない。名義の人が出る
- 見る順番は、止まりの確認→段階ごとの数と日数→原因の切り分け→翌週に直すこと1つ→先週の結果
- 変更は1つずつ。記録はその場で書く
- 率と計画の見直しは月次。週次で率を議論し始めたら「月末に」と切る

## よくある質問

### 週次レビューに、上司や経営は出るべきですか

週次には出なくて構いません。週次は止まりを見つけて翌週に直す場で、人事と名義の人で足ります。経営には月次で「採る人数に対する見込み」を伝えます。週次に経営が出ると、報告会になりやすいです。

### 止まっていない週も、レビューは必要ですか

必要です。「送ったか、当日返信したか、面談が翌週に入っているか」の3つを確認するだけなら、数分で終わります。止まっていないことを確認して終わる週があってよく、飛ばすと、その週に止まりが起きたときに気づけません。

### 週次レビューは、御社に頼めますか

頼めます。当社がOfferBoxの運用代行を受けるときは、記録を事前に整理し、週次の打ち合わせで止まっている段階と翌週に直すことを一緒に決めます。面談枠と返信の体制は企業に決めていただくので、名義の人の同席をお願いしています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
