OfferBoxの担当者が、急に交代した。異動、退職、休職。引き継ぎは短いか、ないままで、管理画面の権限だけが渡された。承認が来ているが、誰が誰にどこまで対応していたか分からない。**結論から言うと、引き継ぎがないまま交代したときは、「承認待ちの学生」を最初に拾って返します。台帳と型と「こんな人」は、作り直すのではなく、前任の記録と管理画面から復元します。名義の人が変わったことを、進行中の学生に伝えます。前任に聞けることと聞けないことを分け、代理店に聞けることは聞き、交代後の最初の月は送る数を減らして、復元に時間を使います。** この記事では、交代直後に起きること、最初の一週間、復元の順番、名義の変更の伝え方、前任と代理店に聞けること、最初の月、分担を整理します。計画的な引き継ぎは[OfferBoxの運用を担当者間で引き継ぐ方法](/media/ob-tantousha-hikitsugi/)で書きました。この記事は、引き継ぎが十分でなかったときの立て直しです。

## この作業の目的｜「止めない」と「復元する」を、同時に進める

担当者の交代で最も重いのは、承認した学生が放置されることです。学生の側から見ると、担当が変わったことは分からず、「返事が来ない会社」になります。

目的は、進行中の学生を止めないことと、前任の運用（台帳・型・「こんな人」）を復元することを、同時に進めることです。復元を待ってから対応すると、学生が離れます。

## 交代直後に、起きること

| 起きること | 何が起きるか |
|---|---|
| 承認待ちの学生が放置される | 承認が来ていたが、誰も返していない。日数が経つほど、他社の面談が先に入る |
| 台帳がどこにあるか分からない | 前任の個人のファイルにあった。共有されていない |
| 「こんな人」と型が、前任の頭の中にあった | 文面の型はあるが、なぜその型かが分からない |
| 名義の人が変わり、学生が戸惑う | 「〇〇さんとやりとりしていたのに、別の人から連絡が来た」 |
| 数字の意味が分からない | 管理画面の数字は見えるが、何が良くて何が悪いかが分からない |
| 面談に出る人が、交代を知らない | 現場は前任と話していて、新任からの依頼に戸惑う |
| 代理店との窓口が途切れる | 代理店は前任と連絡していて、新任を知らない |

「承認待ちの学生が放置される」だけは、今日中に対処します。他は、一週間から一か月で復元します。

## 最初の一週間で、やること

### 1. 承認待ちの学生を、拾って返す

- **管理画面で、承認済みで未対応の学生を全部拾う**：日付の古い順に
- **当日、全員に一言返す**：「担当が変わりました。〇〇と申します。お待たせしました」。面談の日程を添える
- **日数が経っている学生には、遅れたことを一言添える**：隠さない
- **返した記録を、新しい台帳の最初の行にする**

承認への対応の型は[OfferBoxで承認が来たあとの対応](/media/ob-shounin-go/)で書きました。

### 2. 進行中の学生の状況を、管理画面から復元する

- **承認済みの学生を、段ごとに並べる**：承認のみ、面談済み、選考中、内定
- **管理画面のやりとりを読み、各学生の「次に何をするか」を一行で**
- **面談済みの学生は、誰が面談に出たかを、やりとりと現場に聞いて確かめる**
- **選考中の学生は、次の段の面接官と日程を確かめる**
- **内定者は、次の連絡日と話す相手を確かめる**：[OfferBoxで内定を出したあとのフォロー](/media/ob-naitei-follow/)

### 3. 面談に出る人と代理店に、交代を伝える

- **面談に出ていた現場の人に、交代と、進行中の学生の状況を伝える**：「前任から聞いていない」を先に言う
- **代理店に、新任の連絡先を伝え、前任とのやりとりの記録を聞く**
- **上司に、「承認待ちを返した。台帳と型は一か月で復元する」と伝える**

### エージェントベストの見解

相談で最も多い思い込みは、「担当が変わったので、運用を一から作り直したほうが早い」というものです。当社は3媒体すべての販売パートナーとして、OfferBoxの運用を見ていますが、一から作り直した新任は、前任が一年かけて作った型と「こんな人」を捨て、初年度と同じ時間をかけて、同じ失敗をしています。前任の記録は、個人のファイルになくても、管理画面のやりとり、送った文面、承認した学生のプロフィール、面談に出た現場の人の記憶、代理店の記録、に残っています。当社が担当交代の相談を受けるとき、最初にやるのは、新しい型を渡すことではなく、前任が送った文面を管理画面から数通読んで、型と「こんな人」を復元することです。復元は、作り直すより早く、前任の一年が残ります。

## 台帳・型・「こんな人」を、復元する順番

| 復元するもの | どこから | どう復元するか |
|---|---|---|
| 1. 進行中の学生の台帳 | 管理画面のやりとり | 承認済みの学生を段ごとに並べ、次の一手を一行で（最初の一週間） |
| 2. 文面の型 | 管理画面の送信済みの文面 | 承認が来た文面を数通読み、共通の構造（学生の一文・現場の一文・何を見るか・話す場）を抜き出す |
| 3. 「こんな人」 | 承認した学生のプロフィールと、面談に出た現場の人 | 承認して面談まで進んだ学生の自由記述に共通する行動を書き出し、現場に「こういう人でよいか」と確かめる |
| 4. 検索条件 | 管理画面の保存された条件、なければ承認した学生の共通点 | 「こんな人」から組み直す |
| 5. 面談の型と、出る人 | 面談に出た現場の人 | 「前任のときは、どう進めていたか」を聞く |
| 6. 数字の意味 | 管理画面の数字と、復元した台帳 | 段ごとに並べ、どこで止まっているかを見る。前任との比較はしない |
| 7. 企業ページ | 管理画面 | 年度表記・選考の流れ・条件が現在のものかを確かめる |

「2」と「3」は、管理画面の送信済みの文面と承認した学生のプロフィールから復元できます。前任がいなくても、記録は管理画面にあります。「こんな人」の作り方は[OfferBoxで採りたい学生像を言葉にする](/media/ob-persona/)、型の作り方は[OfferBoxのオファー文面テンプレートを作るときの注意](/media/ob-offer-template/)で書きました。

## 名義の変更を、学生に伝える

- **前任の名義で送ったオファーに承認した学生には、「担当が変わりました」を最初の連絡で**：隠さない
- **前任の名義の文面を、そのまま新任の名義で送らない**：「送っている私は〜」の一文が、新任のものに変わる
- **前任が面談に出ていた学生には、面談に出た現場の人が同じなら、その人を「変わらない人」として伝える**
- **内定者には、名義の変更と、話す相手が変わらないことを伝える**：内定者は、担当の交代に敏感
- **名義の変更の伝え方は、[OfferBoxの運用を担当者間で引き継ぐ方法](/media/ob-tantousha-hikitsugi/)の手順4**

## 前任に聞けることと、聞けないこと、代理店に聞けること

| 相手 | 聞けること | 聞けないこと |
|---|---|---|
| 前任（連絡が取れるなら） | 台帳の場所、「こんな人」の元、型を作った理由、面談に出ていた人、内定者の状況 | 退職・休職の事情。短い時間で、一度だけ |
| 面談に出ていた現場の人 | 面談の進め方、学生の反応、前任との分担 | 台帳や文面の詳細 |
| 代理店 | 前任とのやりとりの記録、申込時の「こんな人」、契約と更新時期、管理画面の使い方 | 学生とのやりとりの中身（代理店は持っていない） |
| 上司 | 導入時の目的、判断の基準、やめる条件 | 運用の詳細 |
| 管理画面 | 送信済みの文面、承認した学生、やりとり、数字 | 「なぜそうしたか」 |

前任に聞けない場合でも、この五つで、ほぼ復元できます。代理店を交えた引き継ぎの場は[OfferBoxの運用を担当者間で引き継ぐ方法](/media/ob-tantousha-hikitsugi/)の手順5で書きました。

## 交代後の最初の月は、送る数を減らす

- **新しく送るより、進行中の学生を止めないことと、復元を優先する**
- **送るなら、復元した型で少数**：型を復元する前に送ると、前任の型と違う文面になり、学生に「会社の言うことが変わった」と読まれる
- **承認への当日返しだけは、最初から守る**
- **一か月で復元を終え、翌月から読める数に戻す**
- **上司に「最初の月は復元に使う」と先に伝える**：「動いていない」と見られないように

送る数の戻し方は[OfferBoxの運用が止まってしまったときの再開手順](/media/ob-unyou-teitai/)と同じです。

### エージェントベストの見解

これは契約後に起きることの話です。当社が販売パートナーとして契約後に最も多く関わるのが、担当者の交代です。契約の途中で担当が変わり、新任から「何をしていたか分からない」と連絡が来ます。当社は、前任とのやりとりの記録と、申込時に決めた「こんな人」と、送った文面の型を持っているので、それを新任に渡し、管理画面の送信済みの文面と合わせて、一週間から一か月で復元します。逆に、代理店を通していない場合、前任の記録は管理画面にしかなく、「なぜそうしたか」が残りません。当社が契約時にお願いしているのは、台帳を個人のファイルではなく共有の場所に置くことと、「こんな人」と型を当社にも共有しておくことです。交代は、いつ起きるか分かりません。

## まとめ

- 引き継ぎがないまま交代したら、「承認待ちの学生」を当日に拾って返すことを最初に。放置が最も重い
- 最初の一週間で、進行中の学生の状況を管理画面から復元し、面談に出る人と代理店に交代を伝える
- 台帳・型・「こんな人」は作り直さず、管理画面の送信済み文面と承認した学生のプロフィールと現場の記憶から復元する。前任がいなくても復元できる
- 名義の変更を、承認した学生と内定者に隠さず伝える。前任の名義の文面をそのまま送らない
- 最初の月は送る数を減らして復元に使い、承認への当日返しだけは守る。台帳を共有の場所に置いて次の交代に備える

## よくある質問

### 前任が退職していて、連絡が取れません

管理画面の送信済みの文面と、承認した学生のプロフィールと、やりとりの記録と、面談に出ていた現場の人と、代理店の記録で、ほぼ復元できます。「なぜそうしたか」は分からないことがありますが、「何をしたか」は残っています。承認が来た文面を数通読めば、型と「こんな人」の元は見えます。

### 復元している間に、新しいオファーを送らなくてよいのでしょうか

最初の月は、進行中の学生を止めないことと復元を優先し、送るなら復元した型で少数です。型を復元する前に送ると、前任の型と違う文面になり、学生に「変わった」と読まれます。上司には「最初の月は復元に使う」と先に伝え、「動いていない」と見られないようにします。

### 担当者交代の立て直しは、御社に相談できますか

できます。当社は、復元の順番、前任とのやりとりの記録、申込時の「こんな人」、型の復元の手伝い、管理画面の使い方、契約と更新時期を支えられます。承認待ちへの対応、学生への連絡、面談、名義の決定は、企業が行ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、OfferBoxの運用を支えています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
