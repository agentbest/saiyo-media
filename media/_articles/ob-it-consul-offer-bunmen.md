OfferBoxでITコンサルタントを採るとき、文面で最も多い失敗は「ITコンサルタント募集」と書けば、コンサル志望とIT志望の両方から来ると考えることです。**結論から言うと、ITコンサルタント志望の学生に届く文面は、「ITコンサル」の一語で書いた文面ではなく、ITコンサルを一言で書き、SEとの違いと戦略コンサルとの違いを一文ずつ書き、案件を一つ抽象化して書き、最初の年の仕事と客先常駐の有無を正直に書いた文面です。** 「ITコンサル」の一語は、戦略コンサルを志望する学生には「ITの実装をさせられる」と読まれ、SEを志望する学生には「コードを書かせてもらえない」と読まれます。この記事では、ITコンサルタント志望の学生がOfferBoxで何を見ているか、文面に書くこと、違いの書き方、面談への接続を整理します。文面全体の基本は[OfferBoxのオファー文面の基本](/media/ob-offer-bunmen-kihon/)で書いたので、ここではITコンサルタントに固有の部分だけを扱います。OfferBoxの仕様や数値には触れず、運用の考え方だけを書きます。

## ITコンサルタント志望の学生がOfferBoxで見ているもの

ITコンサルタントを志望する学生は、オファーを開いたときに、次のことを見ています。

| 学生が見分けたいこと | 文面で見ている箇所 |
|---|---|
| ITコンサルが何をする仕事か | 業務を決める側か、システムを作る側か。一言で書いてあるか |
| SEとの違い | コードを書くのか。書かないなら、何をするのか |
| 戦略コンサルとの違い | 経営の課題から入るのか、システムの導入から入るのか |
| 案件の中身 | 誰の、何の業務を、どう変える案件か |
| 最初の年に何をするか | 議事録、テスト、資料作成から、なのか。要件のヒアリングに同席できるのか |
| 客先常駐の有無 | 顧客先に常駐するのか、自社で働くのか。常駐なら期間と範囲 |

二つ目と三つ目が、ITコンサルタントの文面で特に重要です。学生は、ITコンサルを「コンサルとSEの間」と理解していますが、その「間」がどこにあるかは会社によって違います。要件を決める側に近い会社もあれば、実装の管理に近い会社もあります。SEとの違いと戦略コンサルとの違いを一文ずつ書くと、学生は自社の「間」の位置を読めます。

もう一つ、学生が見ているのは、客先常駐の有無です。常駐がある会社は、それを書かないと、面談で分かった学生が離れます。

## 文面に書くこと｜一言、二つの違い、案件を一つ、最初の年と常駐

ITコンサルタント向けの文面は、次の順で組みます。

1. **書き出し**：学生の「業務を分解した」「人の間に立って合意させた」「仕組みで手間を減らした」経験に触れる。「読んだ」「こう思った」「だから送った」の三つ
2. **ITコンサルを一言で**：「顧客の業務をITでどう変えるかを決めて、業務の側と作る側の間に立つ仕事」のように
3. **SEとの違いと、戦略コンサルとの違いを一文ずつ**
4. **案件を一つ、抽象化して**：顧客が特定できない形で、誰の何の業務を、どう変えたか
5. **最初の年の仕事と、客先常駐の有無を正直に**
6. **次の行動を一つ**：現場のコンサルタントとの面談の案内だけ

三つ目の「二つの違い」が、ITコンサルタントの文面の中心です。「SEはシステムを作りますが、うちは何を作るかを業務の側と決めて、作る側に渡します。戦略コンサルは経営の課題から入りますが、うちは決まった業務をITでどう回すかから入ります」のように、両側との違いを書きます。ここまで書くと、学生は自社の「間」の位置を読み、自分の志望と合うかを判断できます。

書き出しで学生の経験に触れるとき、ITコンサルタントの場合は「論理的」「ITに強い」の言葉ではなく、「業務を分解した」「人の間に立って合意させた」「仕組みで手間を減らした」の行動で触れます。「サークルの会計の作業を、集める・記録する・報告するに分けて、表計算で回るようにしたのを読みました」「アルバイト先で、店長と現場の間に立って、シフトの決め方を変えたのを読みました」のような形です。評価はしません。コンサルタントの文面で案件を抽象化する考え方は[OfferBoxでコンサルタントを採るオファー文面の書き方](/media/ob-consultant-offer-bunmen/)、エンジニア寄りの会社は[OfferBoxでエンジニアを採るオファー文面の書き方](/media/ob-engineer-offer-bunmen/)も合わせて読んでください。

### エージェントベストの見解

ITコンサルタントの文面で、発注側が最も誤解しているのは「ITコンサルと書けば、コンサル志望とIT志望の両方を取り込める」という考え方です。両方から承認は付きます。ただ、戦略コンサルを志望する学生は面談で「システム導入が中心」と知って離れ、SEを志望する学生は「コードを書かない」と知って離れます。当社は3媒体すべての販売パートナーとしてOfferBoxの契約後の運用を見ていますが、ITコンサルタントで面談後に進んでいる会社は、両方を取り込もうとせず、自社の「間」の位置を、SEとの違いと戦略コンサルとの違いの二文で書き、その位置を望む学生だけを呼んでいます。承認は減りますが、面談に来る学生が「業務を決める側で、コードは書かず、経営の課題からではなく業務から入る」を知った上で来るので、残ります。「間」の位置を曖昧にするほど、承認は増えて、面談後に残る学生は減ります。ITコンサルタントの文面は、両側から取り込むためではなく、自社の位置を望む学生に絞るために書きます。

## 案件を一つ、抽象化して書く

ITコンサルタントの文面で案件を書くとき、守ることが三つあります。

- **顧客が特定できる情報を書かない**：社名、業界と地域と規模の組み合わせで絞れる書き方をしない
- **業務の変え方を書き、システムの名前を盛らない**：「受注から出荷までの記録が紙で分かれていたのを、一つの流れに揃えた」のように。製品名や技術名は中心に置かない
- **自社が担った部分と、新卒が入る部分を書く**：案件全体ではなく、コンサルタントが手を動かした部分。新卒が入ったら、その部分のどこを担うか

案件を一つに絞ると、その案件に近い経験を持つ学生に送ることになります。「業務を分解した」経験を持つ学生には要件を決める工程が中心の案件を、「人の間に立った」経験を持つ学生には業務の側と作る側の調整が中心の案件を書きます。文面の失敗の型は[OfferBoxのオファー文面でやりがちな失敗](/media/ob-offer-bunmen-ng/)で書きました。

## 最初の年と客先常駐を正直に書く

ITコンサルタントの文面で、学生が入社後に最も差を感じるのが、最初の年の仕事と、客先常駐です。

- **最初の年は議事録とテストと資料が中心なら、そう書く**：「最初の年は先輩の案件で議事録とテストを担い、要件のヒアリングに同席します」のように、同席できるものも書く
- **客先常駐があるなら、そう書く**：期間、範囲、自社に戻る頻度。常駐先が変わる頻度
- **常駐がないなら、ないと書く**：それだけで見比べた学生に残る
- **「上流工程から」「若手から裁量」を書かない**：書くなら、何の工程に、いつから入るかを具体的に

最初の年と常駐を隠して送ると、面談で分かった学生が離れます。正直に書くと、その条件で来られる学生だけが面談に進みます。

## 検索・ターゲットの考え方との関係

ITコンサルタントの文面は、コンサル志望の学生とSE志望の学生で、書き出しが変わります。前者にはSEとの違いと業務の側の話を先に、後者には戦略コンサルとの違いと作る側との接点を先に書きます。情報系でない学生には、専攻ではなく「業務を分解した」経験と、ITを入社後に学ぶ仕組みを書きます。検索の考え方は、次の記事で書きます。

## 選考への接続｜現場のコンサルタントが面談に出る

ITコンサルタント向けの文面は、面談で現場のコンサルタントが案件の話をすることを前提に書きます。

- **面談の担当は、名義になったコンサルタントか、文面に書いた案件を担った人**：人事だけで面談をしない
- **文面で書いた案件を、面談で一段細かく話す**：業務の側と作る側の間で、何を決め、どこで詰まったか
- **最初の年と常駐は、面談でも同じことを言う**：文面と面談で違うと、学生はそこで離れる
- **常駐先の働き方を、面談で話す**：常駐がある会社は、常駐中の一日と、自社との関わり方を

文面と面談で話すことが揃っていると、承認から面談、面談から選考への流れが読めます。面談の組み方は[OfferBoxの面談設計](/media/ob-mendan-sekkei/)、現場の社員を面談に出す整え方は[OfferBoxの面談に現場の面接官を出す](/media/ob-genba-mensetsukan/)で書きました。

### エージェントベストの見解

ITコンサルタントで申し込んだ会社が、最初の数週間で共通してつまずくのは、客先常駐を文面に書かず、「上流工程」「コンサルティング」の言葉で送り、承認は付くのに、面談で常駐の話になったところで学生が離れる、という流れです。当社が運用を見ている会社でも、この流れに入った会社は、承認は付くので運用が回っているように見え、面談後に残らない理由を「学生の志望が弱い」と読んでしまいます。抜け方は、常駐の有無と期間と範囲を文面に書き、常駐中の働き方と自社との関わり方まで書くことです。常駐がある会社は、常駐を隠すのではなく、常駐先で何を担うか、自社に戻る頻度、常駐先が変わる頻度を書きます。承認は減りますが、面談に来る学生が常駐を知った上で来るので、面談後に残ります。ITコンサルタントの文面で最初に書くのは、上流工程の言葉ではなく、常駐の実態の一文です。

## 社内の分担

| 作業 | 担当 | 決めておくこと |
|---|---|---|
| ITコンサルの一言と、SE・戦略コンサルとの違いの二文 | 現場の責任者 | 自社の「間」の位置を |
| 案件の一つ（誰の何の業務を、どう変えたか） | 名義になるコンサルタント | 顧客が特定できない形で。製品名を盛らない |
| 最初の年の仕事と、客先常駐の有無・期間・範囲 | 責任者と人事 | 正直に。「上流工程から」を書かない |
| 学生の行動を読み、文面を組む | 人事（または運用代行） | 「論理的」ではなく分解した・間に立った・仕組みで減らした行動で触れる |
| 名義の確認 | 名義のコンサルタント | 送る前に一度目を通す。顧客が特定できないかも確認 |
| 面談で案件と常駐を話す | 名義のコンサルタント | 文面に書いたことを同じ言葉で |

コンサルタントに頼むのは、案件の一言と、確認と、面談の三つです。二つの違いと常駐の一文は、責任者と人事が決めます。

## やりがちな失敗

| 失敗 | 何が起きるか | 直し方 |
|---|---|---|
| 「ITコンサル募集」の一語で書く | コンサル志望とSE志望の両方が承認し、両方が面談で離れる | SEとの違いと戦略コンサルとの違いを一文ずつ |
| 客先常駐を書かない | 面談で分かった学生が離れる | 有無・期間・範囲を書く |
| 「上流工程から」「若手から裁量」と書く | 最初の年の実態とずれる | 議事録・テスト・同席を正直に |
| システムや製品の名前を盛る | 業務を変える仕事の中身が消える | 業務の変え方で案件を書く |
| 「論理的」「ITに強い」で学生に触れる | どの文面にも同じ言葉が並ぶ | 分解した・間に立った・仕組みで減らした行動で触れる |

## まとめ

- 「ITコンサル」の一語は、コンサル志望にもSE志望にも届き、両方が面談で離れる。自社の「間」の位置を書く
- ITコンサルを一言で、SEとの違いと戦略コンサルとの違いを一文ずつ書く
- 案件は顧客が特定できない形で、業務の変え方を一つ。製品名を盛らない
- 最初の年の仕事と客先常駐は正直に。「上流工程から」を書かない
- 学生には「論理的」ではなく「業務を分解した・人の間に立って合意させた・仕組みで手間を減らした」で触れ、名義は現場のコンサルタント

## よくある質問

### 客先常駐が中心で、正直に書くと学生が来ない気がします

正直に書いた上で、常駐先で何を担うか、自社との関わり方を書きます。「最初の年は顧客先に常駐して、業務の側の担当者と毎日話しながら要件を整理します。週に一度は自社に戻ります」のように、常駐の中身と自社との接点を書けば、学生は判断できます。隠して送ると、承認は付いても、面談で分かった学生が離れ、掛けた時間が戻りません。

### 情報系でない学生にも送るべきですか

送ります。ITコンサルタントで求める「業務を分解する」「人の間に立って合意させる」は、専攻に関係なく見つかり、情報系でない学生のほうがこの行動を書いていることもあります。文面では、専攻に触れず、その行動を読んだことと、ITの知識を入社後に誰からどう学ぶかを書きます。「未経験歓迎」の一言で済ませず、学ぶ仕組みを書きます。

### ITコンサルタントの文面は、運用代行に頼めますか

頼めますが、「ITコンサルの一言」「二つの違い」「案件の一つ」「最初の年と常駐」と、名義になるコンサルタントは社内で決めておきます。代行に任せられるのは、学生の行動を読み、決まった案件とつなげて書き、名義のコンサルタントに確認を回す作業です。二つの違いと常駐が決まっていないと、代行は「ITコンサル募集」と書くしかなく、両側から承認が付いて面談で離れる文面になります。範囲の決め方は[運用代行に任せる範囲](/media/ob-unyou-daikou-hanni/)で書きました。
