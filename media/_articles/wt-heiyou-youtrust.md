社員のつながりを軸にしたキャリアSNS（YOUTRUST）を使い始めた、または検討している。Wantedlyも使っている。二つの違いは分かっていても、「社員に何をどこまで頼むか」「つながりの先から来た人を、どう受けるか」「副業から関わりたいという人を、どの流れに入れるか」が決まっていないと、社員に登録を頼んだところで止まります。**結論から言うと、YOUTRUSTは「社員のつながりの先に、本人の名義で届く場」、Wantedlyは「届いた人が、会社を読んで来る場」です。使い分けるなら、社員に頼むのは登録ではなく「この記事を、この人に」であり、副業から始まる関わりの受け皿をWantedlyの募集記事に用意し、面談の入口を一つにし、登録した社員の数やつながりの数を母集団と読まないことです。** この記事では、それぞれの役割、社員に頼むことの範囲と型、副業から始まる関わりの受け皿、面談の入口、数字の読み方、工数と名義、やりがちな失敗、社内の分担を整理します。二つの違いそのものは[WantedlyとYOUTRUSTの違い](/media/hikaku-wantedly-youtrust/)、リファラル全般は[Wantedlyとリファラル採用の併用](/media/wt-heiyou-referral/)で書きました。両サービスの仕様と数値は書きません。

## それぞれの役割｜「つながりの先に届く」と「会社を読む」

| | YOUTRUST | Wantedly |
|---|---|---|
| 誰の名義で届くか | 社員本人。本人のつながりの先に | 会社。社員が会社の名義で話す |
| 相手の状態 | 社員を知っている、または社員の知人を知っている。会社は知らないことが多い | 会社を読んでいる。会社で選んでいる |
| 相手の温度 | 転職を決めていない人が多い。副業や情報交換から始まることがある | 「話を聞きに行きたい」と来る。会社に関心がある |
| 会社が用意するもの | 社員が渡せる記事と、頼み方の型 | 会社ページ、ストーリー、募集記事 |
| 残るもの | 社員のつながりと、声をかけた経験 | 記事、会社ページ、面談の言葉 |
| 時期 | 通年。社員の発信に合わせて | 通年。記事が残る |

YOUTRUSTで届く相手は、社員を信頼していますが、会社を知りません。「知っている人がいる安心」で興味を持ち、「この会社で働くとどうなるか」を読んで判断します。読む場所がWantedlyです。逆に、Wantedlyから来た人は会社を読んでいますが、社内に知っている人はいません。二つは、相手が持っているものが逆です。

## 社員に頼むことの範囲と型｜登録ではなく「この記事を、この人に」

- **「登録してほしい」で終わらせない**：登録は入口で、その先に何かが届くのは、社員が何かを渡したときだけ
- **頼むときは、渡すものと相手を具体的に**：「〇〇さんが出ているこのストーリーを、△△のような経験のある知人に送ってほしい」。渡すものは、社員自身が出ている記事が最も渡しやすい
- **「こんな人」の一行を、社員に渡す**：「営業経験のある人」ではなく、「自分で始めた経験のある人」。社員が「誰に」を思い浮かべられる
- **頼む頻度を決める**：記事が出たときに一度。毎週は頼まない。頼まれ続けると、社員は動かなくなる
- **社員が声をかけた相手のことを、社員に聞かない**：本人の判断で伝えてもらう。会社が把握しようとすると、社員は声をかけなくなる
- **結果を社員に返す**：「面談しました」「ご縁がありませんでした」。返す範囲は、本人の同意と個人情報の扱いの範囲で

社員に渡す記事は、募集記事より、その社員自身のストーリーです。書いてもらう形は[Wantedlyのストーリーで入社エントリーを書いてもらう方法](/media/wt-story-nyusha/)で書きました。

### エージェントベストの見解

相談で最も多い思い込みは、「社員の数とつながりの数を掛けた分が、母集団になる」というものです。当社は3媒体すべての販売パートナーとして、つながりを軸にした媒体とWantedlyを併せて使いたいという相談を受けますが、社員全員に登録を頼んで、つながりの数を集計したところで止まっている会社が多くあります。つながりの先の人は、社員を知っていても、会社を知りません。社員が何かを渡さなければ、会社の存在は届かず、渡すものがなければ、社員は渡せません。母集団になるのは、社員の数でも、つながりの数でもなく、「渡せる記事を持っている社員の数」です。当社が最初に確かめるのは、登録した社員のうち、自分の出ているストーリーをWantedlyに持っている人が何人いるかです。いなければ、登録を広げる前に、声をかけてほしい社員のストーリーを一本ずつ出すことから始めてもらいます。

## 副業から始まる関わりの受け皿

- **副業や業務委託から関わりたい人を、断らない受け皿を用意する**：Wantedlyの募集記事に、副業・業務委託の募集を一つ置く。書き方は[Wantedlyの副業・業務委託の募集記事の書き方](/media/wt-fukugyo-boshu/)
- **副業からの関わりを、「まず副業で、合えば」の流れとして設計する**：[Wantedlyで副業から入ってもらうスカウト設計](/media/wt-scout-fukugyo/)
- **副業の条件（何を、いつ、どのくらい、報酬の考え方）は、自社の方針と契約の確認のうえで**：数値と契約の形は、この記事では書かない
- **副業で関わった人にも、ストーリーを書いてもらえる形を**：本人が特定されない範囲で。次のつながりに渡せる記事になる
- **正社員への転換を前提にしない**：前提にすると、副業で関わる人が来ない。「合えば話しましょう」の温度で

つながりの先から来る人は、転職を決めていないことが多いので、「いきなり選考」では来ません。副業や情報交換から関われる入口があると、温度が上がる前に関わりが始まります。

## 面談の入口を一つにし、台帳を一つにする

- **どちらから来ても、最初は「話を聞く面談」から**：選考に進む意思を確認してから、選考の流れに乗せる。[Wantedlyのカジュアル面談の設計](/media/wt-scout-casual-mendan/)
- **つながりの先から来た人にも、面談の前にWantedlyの記事を読んでもらう**：声をかけた社員から渡してもらう
- **台帳は一つ**：入口の列に「YOUTRUST（誰のつながり）」と「Wantedly」。段は共通
- **面談で「誰から、何を読んで来たか」を聞く**：社員の声かけと記事のどちらが効いたかが分かる
- **副業から始まった人は、段を分けて持つ**：「副業で関わり中」の段を一つ。選考の段と混ぜない

台帳と段の揃え方は[Wantedlyを含む複数媒体の効果を並べて見る方法](/media/wt-heiyou-heiyou-kpi/)で書きました。

## 工数と名義

| 項目 | YOUTRUST | Wantedly |
|---|---|---|
| 動く人 | 社員本人。人事は頼み方と結果の返しだけ | 人事と、話す社員 |
| 時間の性格 | 社員の時間。頼む頻度で決まる | 月に数本の記事。返信と面談 |
| 外に出せる部分 | 出せない。社員のつながりは本人のもの | 整える部分。話す中身は出せない |
| 費用 | 会社の有料の仕組みを使うなら、条件は公式で確認。この記事では書かない | プランの費用。公式ページで確認 |

- **社員の発信を、業務として認めるかを決める**：認めないなら、求めない
- **Wantedlyの記事の時間を、先に固定する**：渡す記事がなければ、社員は動けない
- **人事の時間は、「頼む」より「返す」に要る**：声をかけた社員に、結果を返す時間

## やりがちな失敗

| 失敗 | 何が起きるか | 直し方 |
|---|---|---|
| 登録を頼んで終わる | つながりの先に何も届かない | 「この記事を、この人に」まで頼む |
| 渡せる記事がない | 社員が何を渡せばいいか分からない | 社員のストーリーを先に一本 |
| つながりの先の人を、いきなり選考に入れる | 転職を決めていない人が離れる | 話を聞く面談から。副業の受け皿も |
| 社員に、声をかけた相手を報告させる | 社員が声をかけなくなる | 本人の判断に任せ、結果だけ返す |
| 登録数やつながりの数で効果を見る | 母集団と別の数字で判断する | 面談で「誰から来たか」を聞く |

最も多いのは、一つ目です。登録を全員に頼み、つながりの数を集計し、「反応がない」で止まります。

## 社内の分担

| 作業 | 誰が |
|---|---|
| 「こんな人」の一行を決める | 人事と現場の責任者 |
| 声をかけてほしい社員のストーリーを出す | 人事と、その社員 |
| 頼み方の型と頻度を決める | 人事 |
| 声をかける、記事を渡す | 社員（本人の判断で） |
| 副業・業務委託の募集記事を置く | 人事と現場 |
| 面談で「誰から、何を読んで来たか」を聞く | 面談に出る人 |
| 声をかけた社員に結果を返す | 人事 |
| 社員の発信を業務と認めるか、有料の仕組みを使うかの判断 | 責任者 |

運用代行や代理店が支えられるのは、役割の整理、頼み方の型、渡せる記事の型、副業の募集記事の型、台帳の型までで、「こんな人」の決定、声をかけること、面談、結果を返すこと、業務と認めるかの判断は企業と本人が行います。代理店の代行の範囲は[代理店に運用まで頼めるか](/media/kh-dairiten-unyou/)で書きました。

### エージェントベストの見解

登録した社員の数と、その社員のつながりの数は、「会社の存在が届き得る範囲」を示す数字で、「会社に関心を持った人の数」ではありません。当社はWantedlyの運用を申込のあとまで見ていますが、つながりを軸にした媒体を併用している会社で、「登録者は多いのに、面談が増えない」という相談を受けると、登録した社員の多くが、自分の出ている記事を持っておらず、何も渡していません。届き得る範囲が広くても、届けるものがなければ届きません。当社が数字を見るとき、登録数とつながりの数は参考に置き、見るのは「記事を渡した社員の数」と「面談で『〇〇さんから記事をもらって』と言った人の数」です。前者が増えれば後者が増え、前者が増えなければ、登録を増やしても後者は変わりません。数字の読み方を変えるだけで、社員に頼むことが「登録」から「記事を渡す」に変わります。

## まとめ

- YOUTRUSTは「社員のつながりの先に、本人の名義で届く場」、Wantedlyは「届いた人が会社を読む場」。相手が持っているものが逆
- 社員に頼むのは登録ではなく、「この記事を、この人に」。渡すものは社員自身のストーリー。頼む頻度は記事が出たときに一度
- 副業・業務委託から関われる受け皿をWantedlyの募集記事に置く。転職を決めていない人が、温度が上がる前に関われる
- 面談の入口は一つ。台帳は一つで、副業から始まった人は段を分けて持つ
- 登録数とつながりの数を母集団と読まない。見るのは「記事を渡した社員の数」と、面談で「誰から来たか」

## よくある質問

### 社員全員に登録を頼むべきですか

全員に頼む前に、声をかけてほしい社員のストーリーを一本出し、その社員に「この記事を、こんな人に」と頼む形から始めることを勧めます。渡せる記事を持つ社員が増えるごとに、頼む社員を増やします。登録だけを全員に広げても、渡すものがなければ届きません。

### つながりの先から「副業なら」と言われました。断るべきですか

副業・業務委託の受け皿があれば、断らずに関わりを始められます。「まず副業で、合えば話しましょう」の温度で、条件は自社の方針と契約の確認のうえで決めます。受け皿がないなら、この機会にWantedlyに副業の募集記事を一つ置くことを勧めます。

### WantedlyとYOUTRUSTの使い分けは、御社に相談できますか

できます。当社は、役割の整理、頼み方の型、渡せる記事の型、副業の募集記事の型、台帳の型を支えられます。「こんな人」の決定、声をかけること、面談、結果を返すこと、業務と認めるかの判断は、企業と本人が行ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、Wantedlyの運用を支えています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
