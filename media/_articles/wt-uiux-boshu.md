WantedlyでUI/UXデザイナーの募集記事を出したとき、最初にぶつかるのは「『UI/UXデザイナー募集』『ユーザー体験を向上』と書いたのに、話を聞きに来る人が少ない。来ても、面談で『使う人に会えますか』『何を根拠に決めるのですか』『企画のどの段階から入れますか』を聞かれて答えられない」という問題です。**結論から言うと、UI/UXデザイナーの募集記事は、「UI/UX」の一語ではなく「UIとUXのどちらを主に求めていて、使う人に会えるか、何を根拠にデザインを決めるか、企画のどの段階から入れるか」を書き、募集記事を書く前に社内でUIとUXの線引きと根拠の取り方を決めておきます。** この記事では、UI/UXデザイナーが募集記事で見ているもの、書く前に決めること、「なにを・なぜ・どうやって」の書き方、「こんな人」の書き方、スカウトと面談への接続、社内の分担、やりがちな失敗を整理します。デザイナー全般の募集記事は[デザイナーを採る募集記事の書き方](/media/wt-designer-boshu/)で書きました。この記事は、そのうちUI/UXに特有の点を書きます。

## UI/UXデザイナーが募集記事で見ているもの

| 見ているもの | 何を確かめているか |
|---|---|
| UIとUXのどちらを主に求めているか | 画面の設計と仕上げ（UI）か、使う人の課題を見つけて流れを設計する（UX）か、両方か。「UI/UX」の一語は、どちらも中途半端に読まれる |
| 使う人に会えるか | 利用者に直接話を聞けるか。営業や支援の部署を通すか。まったく会えないか |
| 何を根拠に決めるか | 利用者の観察や聞き取りか、数字か、経営者の判断か、デザイナーの経験か。根拠を取る時間が認められているか |
| 企画のどの段階から入れるか | 何を作るかを決める段階から入れるか。決まったものを画面にする段階からか |
| エンジニアとの距離 | 実装まで一緒か、渡して終わりか。実装で変わったとき、戻せるか |
| 作ったものの反応が見られるか | 出した後の数字や声が届くか。作って終わりか |

「使う人に会えるか」と「何を根拠に決めるか」が、UI/UXに特有の点です。

## 書く前に決めること｜UIとUXの線引き、根拠の取り方、企画との関係

| 決めること | 選択肢 |
|---|---|
| UIとUXのどちらが主か | 画面の設計と仕上げが主／使う人の課題を見つけて流れを設計するのが主／両方（その場合、最初はどちらから） |
| 使う人に会えるか | 直接会える／営業や支援を通して聞ける／会えない（会えないなら、代わりに何があるか） |
| 根拠の取り方 | 観察や聞き取りの時間を認めるか。数字を見られるか。取る時間が無いなら、無いと |
| 企画との関係 | 何を作るかを決める段階から入る／決まったものを画面にする段階から |
| 意見が分かれたとき | 根拠で決めるか、経営者が決めるか。根拠が取れないときは誰が決めるか |
| エンジニアとの関係 | 実装まで一緒／渡して終わり。実装で変わったとき戻せるか |
| 最初の月に任せること | 一つの画面の見直しか、一つの流れの調査か。誰と組むか |

「使う人には会えない」「決まったものを画面にする段階から」でも構いません。隠さずに書けば、それを前提に読む人が来ます。使う人に会えず根拠も取れないなら、UIデザイナーの募集として書くほうが、合う人が来ます。

## 「なにを」｜どの画面の、誰の、何の困りごとか

「なにをやっているのか」は、会社の事業ではなく、このデザイナーが手を入れる画面と、使う人の困りごとに絞ります。

- **画面と使う人を書く**：「〇〇（利用者）が△△するための画面」「□□の担当者が毎日使う管理画面」
- **使う人の困りごとを、分かっている範囲で書く**：「初めて使う人が、申込の途中で離れている。どこで離れているかは数字で分かるが、なぜかは分かっていない」。分かっていないことは、分かっていないと
- **UIとUXのどちらが主かを書く**：「まず、離れている箇所の画面を直してほしい（UI）」「なぜ離れるかを、使う人に聞くところから（UX）」

「なにを」の書き方の基本は[「なにをやっているのか」の書き方](/media/wt-boshu-nani-wo/)で書きました。

### エージェントベストの見解

UI/UXデザイナーの募集記事を出す前に、先に決めておかないと効果が出ないのは、「使う人に会えるか」と「根拠を取る時間を認めるか」です。当社がWantedlyのUI/UXデザイナーの募集を支えるとき、「ユーザー体験を向上」と書かれているのに、経営者に聞くと「利用者に会う機会は無く、画面は自分の判断で決めている」という会社が多くあります。それ自体は問題ではありません。問題は、「UX」と書いていることです。UXを主にしたい人が面談で最初に聞くのは、「使う人に会えますか」「聞き取りや観察の時間はありますか」で、ここに答えがないと離れます。使う人に会えず、根拠を取る時間も無いなら、「UIデザイナー」として「決まった流れを、使いやすい画面にしてほしい」と書くほうが、合う人が来ます。逆に、会えるなら、「〇〇の担当者に週に一度話を聞ける」と具体に書くと、UXを主にしたい人が「本当に会える会社」として読みます。当社が最初にお願いするのは、道具の確認ではなく、「使う人に会えるか、根拠を取る時間を認めるか」を経営者本人に決めてもらうことです。

## 「どうやって」｜根拠の取り方と、決め方の書き方

| 書くこと | 書き方 |
|---|---|
| 根拠の取り方 | 利用者に会う頻度と形。数字をどこで見られるか。取る時間をどう確保するか |
| デザインの決め方 | 根拠で決めるか、経営者が決めるか。根拠が取れないときは誰が決めるか |
| 企画との関係 | 何を作るかを決める場に入るか。その場は誰がいて、どのくらいの頻度か |
| エンジニアとの関係 | 実装まで一緒か。実装で変わったとき、どう戻すか |
| 前に直した例 | 「前に〇〇の画面を、△△の根拠で直して、□□が変わった」。無ければ書かない |

「ユーザー中心」と書くより、「〇〇の担当者に週に一度話を聞き、その記録をもとに画面を決める」と書くほうが、根拠の取り方が伝わります。書き方の基本は[「どうやっているのか」の書き方](/media/wt-boshu-dou/)で書きました。

## 「こんな人」｜経歴ではなく、行動で書く

| 経歴で書く（避ける） | 行動で書く |
|---|---|
| UI/UX経験3年以上 | 使う人に会って、思い込んでいた困りごとと違ったことがある |
| ユーザー視点のある方 | 使う人が離れている箇所を、観察や数字で見つけて直したことがある |
| 論理的に説明できる方 | なぜその画面にしたかを、根拠とともにデザインを知らない人に説明したことがある |
| 〇〇（道具）の経験 | 作った画面が実装で変わったとき、エンジニアと一緒に戻したことがある |
| 即戦力 | 最初の月は〇〇の画面で離れている箇所の調査を任せる予定です。△△と組みます |

「使う人に会って、思い込みと違った」が、UI/UXで最も読まれる行動です。「最初の月に何を任せ、誰と組むか」を書くと、経験年数の条件がいらなくなります。作品は「あれば見せてほしい」にとどめ、見るときは「何を根拠に、どう決めたか」を聞きます。書き方の基本は[「こんなことやります」の書き方](/media/wt-boshu-konna/)で書きました。

## スカウトと面談への接続

- **スカウトの文面は、募集記事の「使う人に会えるか、何を根拠に決めるか」と同じ言葉で**：相手の作品の「何を根拠に、どう決めたか」を読み、自社のいま困っている画面と重ねる。[デザイナー向けスカウト文面の型](/media/wt-scout-bunmen-rei-design/)
- **面談には、デザインを決める人と、企画の人が出る**：企画の人が出ると、「企画のどの段階から入れるか」が言葉でなく実際に伝わる
- **面談で話すのは、いま困っている画面と、分かっていないことの話**：離れている箇所の数字を見せる、なぜかは分かっていないと話す、相手ならどう調べるかを聞く
- **使う人に会えるなら、その形を具体に**：「〇〇の担当者に、来週会う予定がある。一緒に来てもらってもいい」

つなげ方は[スカウトと募集記事のつなげ方](/media/wt-scout-boshu-renkei/)で書きました。

## 社内の分担

| 作業 | 誰が |
|---|---|
| UIとUXの線引き、根拠の取り方、企画との関係を決める | 経営者と企画の責任者 |
| 「なにを」（画面、使う人、困りごと、分かっていないこと）の下書き | 人事が、企画と支援の部署に聞いて書く |
| 「どうやって」（根拠の取り方、決め方、エンジニアとの関係） | 企画とエンジニアが話し、人事が書き、本人が確認 |
| 数字と、前に直した例の確認 | 企画の責任者 |
| 「こんな人」を行動で書く、最初の月の予定 | 決める人と人事 |
| 面談 | 決める人と、企画の人と、エンジニア |

一人目のUI/UXデザイナーを採る募集では、いま企画かエンジニアか経営者が画面を決めていることが多くあります。その場合は、「いまは〇〇が画面を決めていて、使う人の声は△△から届いている。最初の月は□□の画面の調査から」と正直に書きます。

運用代行や代理店が支えられるのは、募集記事の型、根拠の取り方を文で書く直し方、「こんな人」を行動に直す作業、スカウト文面との整合の確認までで、UIとUXの線引き、使う人に会えるかの決定、面談は社内が担います。代理店の代行の範囲は[代理店に運用まで頼めるか](/media/kh-dairiten-unyou/)で書きました。

### エージェントベストの見解

相談で最も多い思い込みは、「UIとUXを両方書いたほうが、幅広い人が来る」というものです。当社は3媒体すべての販売パートナーとして、Wantedlyのデザイナーの募集と面談を見ていますが、「UI/UXデザイナー」と並べて書いた募集記事より、「まず〇〇の画面を直してほしい。使う人には△△の形で会える」とどちらが主かを書いた募集記事のほうが、話を聞きに来る人の経験が合う傾向があります。UIを主にしたい人は「UX」を読んで「調査ばかりで画面を作れない」を想像し、UXを主にしたい人は「UI」を読んで「決まったものを仕上げるだけ」を想像して、どちらも離れます。両方を任せたいなら、「最初はUIから。使う人に会う仕組みは△△で、慣れたらUXも」のように順番を書けば、隠したことになりません。当社が案内するのは、「UI/UX」の並記を消し、どちらが主かと、使う人に会える形を書くことです。幅で人は来ません。どちらが主かが自分と合うことで来ます。

## やりがちな失敗

| 失敗 | 何が起きるか | 直し方 |
|---|---|---|
| 「UI/UX」「ユーザー体験を向上」で書く | どちらの人にも「自分の話が無い」と読まれる | どちらが主か、使う人に会えるかを書く |
| 使う人に会えないのに「UX」と書く | 面談で「会えない」と出て離れる | 会えないなら、UIの募集として書く |
| 根拠の取り方を書かない | 「好みで決まる会社」と読まれる | 会う頻度、数字、時間の確保を書く |
| 企画のどの段階から入れるかを書かない | 「決まったものを仕上げるだけ」を想像される | 段階を書く。後からなら、後からと |
| 分かっていないことを、分かっているように書く | 面談で聞かれ、答えられない | 「なぜかは分かっていない」と書く |
| 面談に企画の人が出ない | 「企画との関係」が伝わらない | 企画の人が出る |

最も多いのは、最初の「UI/UX」の並記です。

## まとめ

- UI/UXデザイナーが見ているのは、UIとUXのどちらが主か・使う人に会えるか・何を根拠に決めるか・企画のどの段階から入れるか・エンジニアとの距離・反応が見られるか
- 書く前に、UIとUXの線引き、使う人に会えるか、根拠を取る時間を認めるか、企画との関係を、経営者本人が決める。会えないなら、UIの募集として書く
- 「なにを」は画面と使う人の困りごと、分かっていないことは分かっていないと。「どうやって」は根拠の取り方と決め方を、頻度と形で。前に直した例を一つ
- 「こんな人」は経歴ではなく、「使う人に会って思い込みと違った」「離れている箇所を見つけて直した」の行動で
- 面談には決める人と企画の人が出て、いま困っている画面と分かっていないことを話す

## よくある質問

### 使う人に会う機会がありません。それでもUXの募集はできますか

会えないまま「UX」と書くと、面談で「会えない」と出て離れます。会えないなら、「UIデザイナー」として「決まった流れを、使いやすい画面にしてほしい。使う人の声は〇〇から届く」と書くほうが、合う人が来ます。会える仕組みをこれから作るなら、「いまは会えない。△△の形で会える仕組みを、一緒に作るところから」と、無いことと、作る意思を一緒に書きます。

### 離れている箇所は分かっていますが、なぜかは分かっていません

そのまま書きます。「〇〇の画面の△△で離れている。数字で分かっている。なぜかは分かっていない。最初の月は、なぜかを調べるところから任せたい」のように、分かっていることと分かっていないことを分けて書きます。

### UI/UXデザイナーの募集記事は、御社に相談できますか

できます。当社は、募集記事の型、根拠の取り方を文で書く直し方、「こんな人」を行動に直す作業、スカウト文面との整合の確認を支えられます。UIとUXの線引き、使う人に会えるかの決定、面談は、社内で担ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、Wantedlyの募集記事とスカウトの運用を支えています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
