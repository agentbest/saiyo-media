新卒を毎年五十名以上採る。採用チームがあり、ナビサイトで母集団は集まっている。OfferBoxを足したが、「人数が多いので、OfferBoxでも多く送る」と考えて送る総量を増やし、承認への返信が追いつかず、面談枠が足りず、承認した学生を失う。学生の側は、大量採用の会社に「使い捨て」「配属ガチャ」「埋もれる」の不安を持っていて、文面が答えていません。**結論から言うと、五十名以上をOfferBoxだけで採ろうとせず、ナビを受け皿にして、OfferBoxはナビで来ない層に絞ります。送る総量は返信と面談の体制から逆算し、名義を職種と地域で複数にし、承認への返信を一本化し、大量採用への学生の不安に、育成と配属の決まり方で答えます。** この記事では、この人数を採る会社が割ける時間と人、OfferBoxの位置づけ、送る総量の決め方、最初に決めること、文面の書き方、内定辞退の見込み、分担、やりがちな失敗を整理します。三十名規模の採用は[新卒三十名を採る会社のOfferBox運用](/media/ob-shinsotsu-30-unyou/)、チームの分担は[OfferBoxをチームで運用するときの役割分担](/media/ob-team-unyou/)で書きました。数値は書きません。

## この規模で割ける時間と人

| 状況 | 起きること |
|---|---|
| 採用チームがあり、人手はある | 「人数分だけ送る」と考えて、送る総量が返信の体制を超える |
| ナビで母集団は集まっている | OfferBoxの目的が曖昧で、ナビと同じ学生像を追う |
| 面接官が多く、部門と地域にまたがる | 基準がばらつき、オファー経由の学生の扱いが違う |
| 内定辞退が一定数ある前提で採用計画を組んでいる | 辞退の理由を追わず、「多めに内定を出す」だけになる |
| 学生が大量採用の会社に不安を持っている | 「使い捨て」「配属ガチャ」「埋もれる」に文面が答えていない |

この人数を採る会社がOfferBoxに割ける時間は、採用チームの人数ではなく、「承認に当日返せる数」と「名義の社員が面談に出られる数」で決まります。送る総量は、ここから逆算します。

## OfferBoxの位置づけ｜全体の一部、ナビで来ない層

- **五十名以上の全部をOfferBoxで採らない**：ナビと自社応募が受け皿。OfferBoxは、ナビで来ない層（特定の職種、地域、記述の行動で選びたい層）に絞る。[OfferBoxとマイナビの併用](/media/ob-heiyou-mynavi/)
- **OfferBoxで採る人数を、全体の中で決める**：「全体の一部を、ナビで来ない層から」。この人数が、送る総量の元
- **ナビのエントリー者と突き合わせ、重ねない**：大量採用の会社ほど、ナビと重なる

### エージェントベストの見解

相談で最も多い思い込みは、「採る人数が多いので、OfferBoxでも人数に見合った数を送る」というものです。当社は3媒体すべての販売パートナーとしてOfferBoxの運用代行も受けていますが、人数に合わせて送る総量を増やした会社は、承認は増えても、返信が翌日以降にずれ、面談枠が埋まり、承認した学生の多くを失っています。OfferBoxは、送った相手の中から承認が返る入口で、承認のあとに人が動く必要があり、その人の数は採る人数に比例して増えません。当社が大量採用の会社に最初に決めてもらうのは、OfferBoxで採る人数を「全体の一部」に置くことと、その人数から逆算した送る総量を「返せる数と会える数」の中に収めることです。五十名を採る会社のOfferBoxの役割は、五十名を採ることではなく、ナビでは会えない層の数名に、取りこぼさずに会うことです。

## 送る総量を、返信と面談の体制から逆算する

1. **承認への当日返信を、毎日、何通まで返せるかを出す**：返信の担当の人数と時間。外に出す分も含めて
2. **名義の社員が、月に何人と面談できるかを出す**：職種と地域ごとに。面談枠の合計
3. **承認の割合を、昨年の台帳で置く**：ない場合は小さく送って様子を見る。この記事では数値を書かない
4. **返せる数と会える数の小さいほうから、送る総量の上限を出す**：上限を超えるなら、返信の担当と面談枠を増やしてから
5. **上限を、職種と地域に配分する**：ナビで来ない職種・地域に厚く
6. **送る時期を、返信と面談が回る山に分ける**：[OfferBoxのオファーを送る時期と時間帯の考え方](/media/ob-soushin-timing/)

## 最初に決めること

1. **承認への返信を、一本化する**：部門や地域ごとに返さない。採用チーム（または代行）が型で当日に返し、面談の日程だけ名義の社員に渡す。[OfferBoxでオファーが承認されたあとの連絡手順](/media/ob-shounin-go/)
2. **名義を、職種と地域で複数にする**：採用チームの名義は「会社が送った」になる。職種ごと、拠点ごとに現場の若手。頼むことは名義・一文・面談の三つ。[OfferBoxの運用に現場社員を巻き込む方法](/media/ob-genba-makikomi/)
3. **文面の共通原稿を一つで版管理し、個別の一文だけ名義の社員が書く**：総量が多いほど、型どおりになりやすい。一文で「なぜあなたに」を残す
4. **面接官の基準を、オファー経由の学生について統一する**：部門と地域をまたいで。「なぜうちか」を聞かない。[OfferBox経由の学生を面接する現場社員への説明](/media/ob-genba-mensetsukan/)
5. **台帳を一つにし、職種・地域・名義の列を持つ**：送る側と来た学生の台帳を分け、承認した学生だけ来た学生の台帳に。[OfferBoxと採用管理システム（ATS）の連携の考え方](/media/ob-heiyou-ats/)
6. **大量採用への学生の不安に、文面で答える**：後述
7. **内定辞退の見込みを、「多めに出す」だけにしない**：辞退の理由を台帳で追い、翌年の送る相手と文面に。[OfferBox経由の内定辞退が続くときに見直すこと](/media/ob-naitei-jitai/)

## 文面の書き方｜大量採用への不安に、育成と配属の決まり方で答える

| 学生の不安 | 書かない | 書く |
|---|---|---|
| 使い捨てではないか | 「大量採用」「積極採用」 | 最初の年に、誰が、何を、隣で教えるか。育成の実態 |
| 配属はどう決まるか | 配属に触れない | 「配属は、いつ、誰が、何を見て決めます」 |
| 同期が多くて埋もれないか | 「同期が多くて心強い」 | 同期の中で、一人ひとりに担当が付くか。名義の若手が、同期の多い中でどう育ったか |
| 会社が送っただけではないか | 型どおりの文面 | 記述のどの行動を見たか、の一文 |

- **名義の若手が「同期が多い中で、最初の年に誰に教わって何をしたか」を一場面**：大量採用の会社の育成の実態は、この場面にある
- **文面の基本**：[OfferBoxのオファー文面の基本](/media/ob-offer-bunmen-kihon/)。上場していれば開示のルールに触れる数値を書かない。[上場企業のOfferBox運用](/media/ob-joujou-unyou/)

## 内定辞退の見込みを、「多めに出す」だけにしない

- **辞退の理由を、「他社に決めた」で終わらせない**：「何が決め手だったか」まで聞く。多くは「配属の決まり方が明確だった」「連絡が速かった」「担当が付いた」
- **内定者に、名義の若手と配属を決める人に会ってもらう**：同期が多い会社ほど、「自分を見てくれる人」が要る。[OfferBoxで内定を出したあとのフォロー](/media/ob-naitei-follow/)
- **並べて見るときは、承認数ではなく、面談まで来た「近い」学生の数**：[OfferBoxを含む複数媒体の効果を並べて見る方法](/media/ob-heiyou-heiyou-kpi/)

## 運用の分担

| 作業 | 誰が |
|---|---|
| OfferBoxで採る人数を全体の中で置く | 採用の責任者 |
| 送る総量を、返せる数と会える数から逆算する | 採用チーム |
| 承認への返信の一本化 | 採用チーム、または代行 |
| 名義の社員の選定（職種と地域で複数） | 採用チームと部門・拠点の責任者 |
| 共通原稿の版管理、台帳、面接官の基準 | 採用チーム |
| 検索、共通部分の下書き、送信、突き合わせ | 採用チーム、または代行 |
| 個別の一文、文面の最終確認、名義、面談 | 現場の若手 |
| 辞退の理由を「決め手」まで聞く | 採用チーム |

- **採用チームは、型・台帳・返信・基準に絞る**：名義と面談まで持つと「会社が送った」になる。[大企業のOfferBox運用](/media/ob-daikigyo-unyou/)の線と同じ
- **送る総量が多いほど、検索・下書き・送信・一次返信を外に出す意味がある**：[OfferBoxの運用代行に任せられる範囲と自社で持つ判断](/media/ob-unyou-daikou-hanni/)

運用代行や代理店が支えられるのは、位置づけの整理の型、送る総量の逆算の型、共通原稿と返信の型、台帳の型、検索・下書き・送信・一次返信・突き合わせまでで、OfferBoxで採る人数の決定、名義の選定、個別の一文、面談、基準の統一、辞退の理由を聞くことは企業が行います。代理店の代行の範囲は[代理店に運用まで頼めるか](/media/kh-dairiten-unyou/)で書きました。

### エージェントベストの見解

これをやる前に、先に「承認に当日返せる数」と「名義の社員が面談に出られる数」を出しておかないと、送る総量が決まらず、人数に引きずられて送りすぎます。当社はOfferBoxの運用代行で大量採用の会社の送る総量を企業と一緒に決めますが、「今年は〇〇名採る」から始まる相談に、「毎日、何通まで返せますか」「名義の社員は月に何人と会えますか」と聞くと、答えが出てこない会社が多くあります。答えが出ないまま送ると、承認のあとの人の動きが追いつかず、承認した学生を失って「OfferBoxは大量採用に向かない」で終わります。順番は、返せる数と会える数を先に出し、その小さいほうから送る総量の上限を置き、上限を職種と地域に配分し、山を分けて送ることです。上限が決まれば、採用チームの人手は、送ることではなく、返すことと会うことに使えます。

## やりがちな失敗

| 失敗 | 何が起きるか | 直し方 |
|---|---|---|
| 採る人数に合わせて送る総量を増やす | 返信と面談が追いつかず、承認した学生を失う | 返せる数と会える数から逆算 |
| 五十名以上をOfferBoxだけで採ろうとする | ナビと同じ学生像を追い、二重になる | ナビを受け皿に、OfferBoxはナビで来ない層に |
| 採用チームの名義で送る | 「会社が送った」に読まれる | 職種と地域で現場の若手を名義に |
| 大量採用への不安に文面が答えない | 「使い捨て」「配属ガチャ」で離れる | 育成と配属の決まり方を書く |
| 辞退を「多めに出す」だけで対応する | 理由を追わず、翌年も同じ | 「決め手」まで聞いて翌年に |

最も多いのは、一つ目です。人数が多いことを、送る総量を増やす理由にしています。

## まとめ

- 五十名以上をOfferBoxだけで採らない。ナビと自社応募を受け皿にし、OfferBoxはナビで来ない層（職種・地域・記述の行動）に絞り、採る人数を全体の一部に置く
- 送る総量は、「承認に当日返せる数」と「名義の社員が面談に出られる数」の小さいほうから逆算し、職種と地域に配分し、山を分けて送る
- 承認への返信を一本化し、名義を職種と地域で複数にし、共通原稿を版管理して個別の一文だけ名義の社員が書く。面接官の基準を統一する
- 大量採用への学生の不安（使い捨て・配属ガチャ・埋もれる）に、育成の実態と配属の決まり方と「同期の多い中でどう育ったか」の一場面で答える
- 内定辞退を「多めに出す」だけにせず、理由を「決め手」まで聞き、内定者に名義の若手と配属を決める人に会ってもらう

## よくある質問

### OfferBoxで採る人数を、全体のどのくらいに置けばよいですか

数値では決めません。「ナビで近い学生が来ていない職種・地域」を昨年の台帳で見て、そこで会いたい人数を置きます。それが全体の一部になります。「全体の〇割」から決めると、ナビで来ている層にも送ることになり、二重になります。

### 送る総量の上限を守ると、採用計画に届きません

届かない分は、OfferBoxではなく、ナビと自社応募と他の入口で採ります。OfferBoxの総量を上限を超えて増やしても、承認した学生を失うだけで、採用計画には届きません。届かせるには、返信の担当と面談枠を増やしてから、上限を上げます。上限を先に上げると、崩れます。

### 新卒五十名以上を採る会社のOfferBox運用は、御社に相談できますか

できます。当社は、位置づけの整理の型、送る総量の逆算の型、共通原稿と返信の型、台帳の型、検索・下書き・送信・一次返信・突き合わせを支えられます。OfferBoxで採る人数の決定、名義の選定、個別の一文、面談、基準の統一、辞退の理由を聞くことは、企業が行ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、OfferBoxの運用代行も受けています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
