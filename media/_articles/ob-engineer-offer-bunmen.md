OfferBoxでエンジニアを採るとき、文面で最も多い失敗は「技術の言葉を並べれば届く」と考えることです。**結論から言うと、エンジニア志望の学生に届く文面は、技術の言葉が多い文面ではなく、学生が作ったものや研究に触れ、自社が「何を、どう作っているか」を一つだけ正直に書き、名義がエンジニアになっている文面です。** 学生は、文面の技術用語より、「この会社は自分の作ったものを見たか」「入ったら誰と何を作るのか」を見ています。この記事では、エンジニア志望の学生がOfferBoxで何を見ているか、文面に書くこと、情報系以外の学生への送り方、面談への接続を整理します。文面全体の基本は[OfferBoxのオファー文面の基本](/media/ob-offer-bunmen-kihon/)で書いたので、ここではエンジニアに固有の部分だけを扱います。OfferBoxの仕様や数値には触れず、運用の考え方だけを書きます。

## エンジニア志望の学生がOfferBoxで見ているもの

エンジニアを志望する学生は、オファーを開いたときに、会社の規模や事業より先に、次のことを見ています。

| 学生が見分けたいこと | 文面で見ている箇所 |
|---|---|
| 自分の作ったものを見たか | 書き出しに、制作物・研究・使った技術への言及があるか |
| 何を作っているか | 自社の製品か、受託か。誰が使うものか |
| どう作っているか | チームの大きさ、進め方、設計から関われるか |
| 誰が見てくれるか | 入社後に誰の下で、どう育つか。相談相手がいるか |
| 技術の言葉が正直か | 使っている技術が、実態と合っているように読めるか |

最後の一つが、エンジニアの文面で特に重要です。学生は技術の言葉に敏感で、「最新技術」「先進的な開発環境」のように中身のない言葉を見ると、実態を隠していると受け取ります。逆に、古い技術でも「ここは古い仕組みが残っていて、置き換えを進めている」と書いてあれば、正直な会社として読まれます。

もう一つ、学生が見ているのは名義です。人事名義の文面と、エンジニア名義の文面では、学生の受け取り方が違います。エンジニア名義であれば「自分の作ったものを分かる人が読んだ」と受け取ります。

## 文面に書くこと｜学生の作ったものに触れ、自社の開発を一つ書く

エンジニア向けの文面は、次の順で組みます。

1. **書き出し**：学生の制作物・研究・使った技術に触れる。「読んだ」「こう思った」「だから送った」の三つ
2. **自社の開発を一つ**：何を作っているか、どう作っているか、誰が見るか、のうち一つを具体に
3. **学生の経験とのつながり**：その制作物や研究が、自社の開発のどこに近いか
4. **技術の実態に一言**：使っている技術と、変えたいところを正直に
5. **次の行動を一つ**：エンジニアとの面談の案内だけ

書き出しで学生の制作物に触れるとき、評価はしません。「素晴らしい作品ですね」「高い技術力をお持ちですね」と書くと、学生は「見ていない人が褒めている」と受け取ります。書くのは、何を作っていたかを読んだ事実と、それが自社のどこに近いかです。「〇〇を作られていたのを読みました。うちでも同じような仕組みで△△を作っていて、その部分を担ってもらえると思い、お送りしました」のような形です。

自社の開発は、一つに絞ります。製品も、チームも、技術も、育て方も全部書くと、会社紹介になります。自社の開発を一言で言うと何か、現場のエンジニアに聞いて決めます。

### エージェントベストの見解

エンジニア向けの文面で、発注側が最も誤解しているのは「文面はエンジニアに書いてもらえないから、人事が技術の言葉を調べて書く」という考え方です。人事が調べて書いた技術の言葉は、学生に見抜かれます。使い方が少しずれていたり、実態より盛られていたりするからです。当社は3媒体すべての販売パートナーとしてOfferBoxの契約後の運用を見ていますが、エンジニア採用で承認が続いている会社は、文面の中心の一文だけをエンジニアに書いてもらい、残りを人事が組み立てています。エンジニアに文面全体を書いてもらう必要はありません。「うちの開発を一言で言うと」と「この学生の制作物のどこがうちに近いか」の二つだけをエンジニアに聞き、あとは人事が型に入れる。この分担なら、エンジニアの負担は一通あたり数分で済み、文面の技術の言葉は正直なものになります。文面に技術の言葉を増やすことより、技術の言葉を書く人を変えることが先です。

## 情報系以外の学生に送るとき

エンジニア志望の学生を情報系の専攻だけで探すと、送る相手が足りなくなります。情報系以外の学生の中にも、自分で作ったもの、研究で書いたプログラム、独学で学んだ技術を書いている学生がいます。

- **専攻ではなく、作ったものと学んだことに触れる**。「情報系ではないですが」とは書かない。学生の側は専攻を弱みと思っていないことが多い
- **未経験の扱いを正直に書く**。入社後にどう学ぶか、誰が見るか。「未経験歓迎」の一言で済ませない
- **作ったものがない学生には、学んだ動機に触れる**。なぜ独学で始めたか、何を作りたいかが書いてあれば、そこに触れる

情報系以外の学生に届く文面は、専攻に配慮する文面ではなく、その学生が「作ったもの」「学んだこと」を読んだと伝わる文面です。理系全般の考え方は[OfferBoxで理系学生を採る](/media/ob-rikei-gakusei/)、理系学生の取り合いになる場面は[OfferBoxで理系学生の取り合いになるとき](/media/ob-rikei-toriai/)で書きました。

## 検索・ターゲットの考え方との関係

エンジニアの文面は、検索で「情報系・制作物あり」に絞った相手と、「専攻を問わず、学んだことがある」まで広げた相手で、書き出しが変わります。前者には自社の開発との近さを先に書き、後者には学んだ動機への言及を先に書きます。検索条件は文面の前提なので、検索を組んだ段階で「この検索の相手には、書き出しに何を置くか」を決めておきます。検索の考え方は、次の記事で書きます。

## 選考への接続｜面談にエンジニアが出る

エンジニア向けの文面は、面談でエンジニアが話すことを前提に書きます。文面にエンジニアの名義があるのに、面談に人事しか出ないと、学生は「名義だけだった」と受け取ります。

- **面談の担当は、名義になったエンジニアか、同じチームのエンジニア**。技術の話ができる人が出る
- **文面で触れた制作物を、面談で聞く**。何を作り、どこで詰まり、どう解いたか
- **技術の実態を、面談でも正直に話す**。文面で「置き換えを進めている」と書いたなら、面談で進み具合を話す
- **コードや制作物を見せてもらう場合は、文面か面談前に伝える**。当日に求めると、学生は準備がなく、会社への印象が下がる

文面と面談で話すことが揃っていると、承認から面談、面談から選考への流れが読めます。面談の組み方は[OfferBoxの面談設計](/media/ob-mendan-sekkei/)、現場の社員を面談に出す整え方は[OfferBoxの面談に現場の面接官を出す](/media/ob-genba-mensetsukan/)で書きました。

### エージェントベストの見解

エンジニア向けの文面を書く順番として、当社が勧めているのは「文面を書く前に、エンジニアの面談担当を決める」ことです。多くの会社では、文面を書いてから、面談の担当を探します。この順番だと、文面の名義と面談の担当が別になり、文面で書いた開発の話を面談で確かめられません。順番を変えて、最初に「面談に出るエンジニア」を決め、その人に「うちの開発を一言で言うと」を聞き、その人の名義で文面を送ると、文面と面談が揃います。当社が運用を見ている会社でも、面談担当のエンジニアが先に決まっている会社は、文面の技術の言葉が正直で、面談後の離脱が少ない傾向があります。エンジニア採用で最初に決めるのは、文面の書き出しでも技術の言葉でもなく、「誰が面談に出るか」です。その人が決まれば、文面に書くことは自然に決まります。

## 社内の分担

| 作業 | 担当 | 決めておくこと |
|---|---|---|
| 「うちの開発を一言で言うと」 | 面談に出るエンジニア | 何を、どう作っているかの一つ |
| 学生の制作物・研究を読み、近さを一言 | エンジニア（一通あたり数分） | 評価ではなく、自社のどこに近いか |
| 文面を型に入れて組み立てる | 人事（または運用代行） | 書き出し・開発の一文・実態・次の行動 |
| 名義の確認 | 名義のエンジニア | 送る前に一度目を通す |
| 面談で制作物と技術の実態を話す | 名義のエンジニア | 文面に書いたことを同じ言葉で |

エンジニアに頼むのは、一言と近さの判断と、面談の三つです。文面の組み立てと送る作業は人事が持ちます。この分担にしておくと、エンジニアの負担が読めるようになり、協力を続けてもらえます。

## やりがちな失敗

| 失敗 | 何が起きるか | 直し方 |
|---|---|---|
| 技術の言葉を並べる | 実態とずれ、学生に見抜かれる | 自社の開発を一つ、正直に書く |
| 学生の制作物を褒める | 「見ていない人が褒めている」と受け取られる | 何を作ったかを読んだ事実と、自社との近さを書く |
| 人事名義で送る | 作ったものを分かる人が読んだと思われない | エンジニア名義にし、面談もエンジニアが出る |
| 「未経験歓迎」で済ませる | 入社後の育ち方が見えない | 誰が見て、どう学ぶかを書く |
| 情報系以外に「専攻は問いません」と書く | 専攻を弱みと扱う形になる | 作ったもの・学んだことに触れる |

## まとめ

- エンジニア志望の学生は、技術の言葉より「自分の作ったものを見たか」「何を、どう作っているか」を見ている
- 書き出しは制作物・研究に触れ、評価はしない。読んだ事実と、自社との近さを書く
- 自社の開発を一つに絞り、技術の実態は正直に。変えたいところも書く
- 中心の一文だけをエンジニアに書いてもらい、名義もエンジニアにする
- 面談に出るエンジニアを先に決め、その人の名義で送り、文面に書いたことを面談で話す

## よくある質問

### エンジニアが忙しく、文面に関われません

文面全体に関わってもらう必要はありません。「うちの開発を一言で言うと」を一度決めてもらい、送る学生ごとに「この制作物のどこがうちに近いか」を一言もらうだけです。一通あたり数分で済む形にすれば、関わってもらえることが多いです。それも難しい場合は、面談に出る一人だけを決め、その人の一言を文面の中心にします。

### 使っている技術が古く、正直に書くと学生が来ないのではないですか

古い技術を隠して送ると、面談で分かった学生が離れます。書き方は「古い仕組みが残っていて、ここを置き換えたい」です。置き換えに関わりたい学生は、それを理由に来ます。隠すより、変えたいところを書くほうが、来る学生の種類が絞れ、面談後の離脱も減ります。書けることがない場合は、育て方や見てくれる人の話に軸を移します。

### エンジニア向けの文面は、運用代行に頼めますか

頼めますが、「うちの開発を一言で言うと」と、面談に出るエンジニアは社内で決めておきます。代行に任せられるのは、学生の制作物や研究を読み、決まった一言とつなげて書き、名義のエンジニアに確認を回す作業です。一言と担当が決まっていないと、代行は技術の言葉を調べて書くしかなく、盛った文面になります。範囲の決め方は[運用代行に任せる範囲](/media/ob-unyou-daikou-hanni/)で書きました。
