WantedlyでUI/UXデザイナーにスカウトを送るとき、最初にぶつかるのは「作品の画面を見て『使いやすそうな画面ですね』と送っているのに、返信が来ない。来ても、面談で『使う人に会えますか』『何を根拠に決めるのですか』と聞かれて止まる」という問題です。**結論から言うと、UI/UXデザイナーへのスカウトは、作品の画面の見た目で相手を選ぶのではなく、先にUIとUXの線引きと使う人に会える形と最初に調べたい・直したい画面を決め、「近い根拠の取り方で、同じような使う人のために、企画と近い距離で作ってきた人」を選び、その人の作品の「何を根拠に、どう決めたか」を読んだ一文から、使う人に会える形と、いま分かっていないことで誘います。** この記事では、UI/UXデザイナーがスカウトで見ているもの、送る前に決めること、誰に送るか、文面に書くこと、返信後の面談、社内の分担、やりがちな失敗を整理します。デザイナー全般のスカウトの考え方は[デザイナーにスカウトを送る文面の考え方](/media/wt-designer-scout/)、文面の3段の型は[デザイナー向けスカウト文面の型](/media/wt-scout-bunmen-rei-design/)、募集記事は[UI/UXデザイナーを採る募集記事の書き方](/media/wt-uiux-boshu/)で書きました。

## UI/UXデザイナーがスカウトで見ているもの

| 見ているもの | 何を確かめているか |
|---|---|
| 誰から来たか | デザインを決める人か、企画の人か、人事か。送り主が使う人に会っている人か |
| 作品の、根拠の部分を読んだか | 画面の見た目を褒めただけか、「何を根拠に、どう決めたか」を読んだか |
| UIとUXのどちらを求めているか | 画面の設計と仕上げか、使う人の課題を見つけて流れを設計するのか。「UI/UX」の並記は、どちらも中途半端と読む |
| 使う人に会える形 | 直接会えるか、営業や支援を通すか、会えないか。文面で分かるか |
| 根拠の取り方 | 観察や聞き取りの時間があるか、数字が見られるか、経営者の判断か。文面で分かるか |
| 分かっていないこと | 会社説明ではなく、調べたいことが書かれているか |

「使う人に会える形」と「根拠の取り方」は、書かれていなければ面談で最初に聞かれます。

## 送る前に決めること｜線引き、会える形、最初に調べたい・直したい画面

送る前に、社内で三つを決めます。

- **UIとUXの線引き**：画面の設計と仕上げが主か、使う人の課題を見つけて流れを設計するのが主か。両方なら、最初はどちらから。決め方は[UI/UXデザイナーを採る募集記事の書き方](/media/wt-uiux-boshu/)で書きました
- **使う人に会える形**：直接会えるか、誰を通すか、会えないか。会えないなら、UIの募集として送る
- **最初に調べたい・直したい画面**：「〇〇の画面の△△で離れている。数字で分かっているが、なぜかは分かっていない。ここを最初に調べてほしい」を一つ。これが文面の2段目になり、送る相手を「それを調べられる人」に絞れる

## 誰に送るか｜見た目や道具ではなく、根拠の取り方と使う人、企画との距離の重なり

作品の画面が使いやすそうに見える人、自社と同じ道具を使う人で選ぶと、面談で「根拠の取り方が違う」「企画との距離が違う」になります。選ぶ基準は、「近い根拠の取り方で、同じような使う人のために、企画と近い距離で作ってきたか」です。

| 読む箇所 | 重なりの見方 |
|---|---|
| 何を根拠に決めたか | 作品の説明に「使う人に聞いて」「観察して」「数字を見て」「経営者の判断で」のどれが書かれているか。自社の根拠の取り方と近いか |
| 誰のために作ったか | 社外の利用者か、社内の部署か。初めて使う人か、毎日使う人か。自社の使う人と近いか |
| 企画との距離 | 何を作るかを決める段階から入ったか、決まったものを画面にしたか。自社の関係と合うか |
| UIとUXのどちらが主か | 画面の設計と仕上げの話が多いか、課題を見つけて流れを設計した話が多いか。自社が主にしたいほうと合うか |
| 思い込みと違った経験 | 「使う人に会ったら、想定と違った」が書かれているか。根拠を取る人の証拠 |

「思い込みと違った経験」が要点です。作品の読み方は[デザイナー向けスカウト文面の型](/media/wt-scout-bunmen-rei-design/)で書きました。

### 肩書の幅に配慮する

UI/UXの仕事は、「UIデザイナー」「UXデザイナー」「プロダクトデザイナー」「Webデザイナー」「UXリサーチャー」「企画で画面も見ている人」など、違う肩書で書かれています。肩書で検索すると、自社が主にしたいほうの人を落とします。「何を根拠に、どう決めたか」で読み、肩書と道具は「あればよい条件」に置きます。絞り方の基本は[スカウト対象の絞り方](/media/wt-scout-target/)で書きました。

### エージェントベストの見解

相談で最も多い思い込みは、「UI/UXデザイナーには、自社の画面がきれいに整っていることを見せないと返信が来ない」というものです。当社は3媒体すべての販売パートナーとしてWantedlyのスカウトを見ていますが、UI/UXデザイナーが返信した文面を並べると、自社の画面の見た目は、返信の有無とほとんど関係がありません。関係があるのは、「作品の根拠の部分を読んでくれたか」と、「使う人に会える形と、いま分かっていないことが文面で分かるか」の二つです。画面が整っていても「使う人に会える形」が書かれていない文面は、「好みで決まる会社」と読まれて開かれません。逆に、画面が古くても「〇〇の画面の△△で離れている。なぜかは分かっていない。□□の担当者に週に一度会える」と書かれていれば、「調べることがあり、会える会社」として返信が来ます。当社が対象を組み直すとき、最初にやるのは、検索条件から道具と肩書を外し、「何を根拠に決めた人か」で並べ直し、褒め言葉を消して、会える形と分かっていないことを文面の最初のほうに入れることです。

## 文面に書くこと

文面の型（相手の一文→自社の場面→話す場の案内）は[デザイナー向けスカウト文面の型](/media/wt-scout-bunmen-rei-design/)に書いたので、ここではUI/UX特有の要点だけを書きます。

- **相手の一文は、根拠で**：「〇〇の画面で、使う人に聞いたら想定と違ったと書かれていたのを読んで」「△△の数字を見て□□を直された点を読んで」。画面の見た目を褒めない
- **UIとUXのどちらが主かを、最初のほうで**：「まず〇〇の画面を直してほしい（UI）」「なぜ離れるかを調べるところから（UX）」。並記しない
- **使う人に会える形を、一文で**：「〇〇の担当者に、週に一度話を聞ける」「直接は会えない。△△の部署を通して聞ける」。隠さない
- **分かっていないことを、一文で**：「〇〇の画面の△△で離れている。数字で分かっているが、なぜかは分かっていない」。分かっているように書かない
- **根拠の取り方を、一文で**：「聞き取りや観察の時間は、業務の中で取れる」「数字は〇〇で見られる」
- **話す場は、決める人と企画の人と**：「デザインを決める〇〇と企画の△△が、離れている画面の数字を見せながら話します。転職を決めていなくても構いません」

相手の作品を評価しません。

## 返信後の面談｜分かっていないことを話す

| 話すこと | 中身 |
|---|---|
| 離れている画面と数字を見せる | 実際の画面と、どこで離れているかの数字。隠さない |
| なぜかは分かっていない、と話す | 分かっているように盛らない。相手ならどう調べるかを聞く。ここが長い面談ほど次につながる |
| 使う人に会える形の確認 | 誰に、どのくらいの頻度で会えるか。文面と同じことを、決める人が話す。「聞いていない」を出さない |
| 企画の人が出て、話す | 何を作るかを決める場に、どの段階から入れるか。企画の人が出ると実際に伝わる |
| 相手の作品の話 | 見た目ではなく、「何を根拠に、どう決めたか」「想定と違ったこと」を聞く。聞く時間を長く |

面談には、デザインを決める人と、企画の人が出ます。会える形は、具体の予定で示します。面談の設計は[カジュアル面談の設計](/media/wt-scout-casual-mendan/)で書きました。

選考に進むとき、調査や設計の課題を出すなら、面談のときに「課題がある」「どのくらいの時間がかかるか」「対価の有無」を先に伝えます。伝え方は[カジュアル面談から選考に進むときの伝え方](/media/wt-scout-senkou-ikou/)で書きました。

## 社内の分担

| 作業 | 誰が |
|---|---|
| UIとUXの線引き、会える形、最初に調べたい画面を決める | 経営者と企画の責任者 |
| 「根拠の取り方と使う人、企画との距離」で対象を並べ直す | 人事（デザインを見られる人が基準を伝える） |
| 相手の作品の根拠の部分を読み、一文を書く | 社内のデザイナーか企画の人（または人事が下書きし、本人が確認） |
| 離れている画面の数字の確認 | 企画の責任者 |
| 型、送信、返信対応、台帳 | 人事 |
| 面談 | 決める人と、企画の人 |

社内にデザイナーがいない一人目の募集では、企画の人が「使う人の立場で、根拠が分かるか」の観点で作品を読みます。

運用代行や代理店が支えられるのは、対象の並べ直しの基準づくり、型、避ける言葉のチェック、募集記事との整合の確認までで、線引きと会える形の決定、相手の作品を読んだ一文、面談は社内が担います。代理店の代行の範囲は[代理店に運用まで頼めるか](/media/kh-dairiten-unyou/)で書きました。

### エージェントベストの見解

UI/UXデザイナーにスカウトを送る前に、先に決めておかないと効果が出ないのは、「使う人に会える形を、具体の相手と頻度で一文にすること」です。当社がWantedlyのUI/UX向けスカウトを支えるとき、「ユーザーの声は大事にしている」までは決まっていても、「誰に、どのくらいの頻度で、どうやって会えるか」が決まっていない会社が多くあります。決まっていないと、文面は「ユーザー体験を向上」に戻り、相手には「会えない会社」と読まれて開かれません。逆に、「〇〇の担当者に週に一度話を聞ける。来週も予定がある」と一文で書けた会社は、返信の数は減っても、面談で「会えないと聞いていない」になる人がいなくなります。当社が最初にお願いするのは、対象の絞り込みではなく、経営者か企画の責任者に「使う人に、誰が、いつ、どう会えるか」を一文で言ってもらうことです。その一文が、UIかUXかも、送る相手も、文面の2段目も決めます。

## やりがちな失敗

| 失敗 | 何が起きるか | 直し方 |
|---|---|---|
| 作品の画面の見た目で相手を選ぶ | 面談で「根拠の取り方が違う」 | 根拠の取り方と使う人、企画との距離で選ぶ |
| 「使いやすそうな画面ですね」と送る | 「見ただけ」と読まれ、開かれない | 根拠の部分を読んだ一文で |
| 「UI/UX」を並記する | どちらの人にも「自分の話が無い」と読まれる | どちらが主かを書く |
| 会えないのに「ユーザーの声を大事に」と書く | 面談で「会えない」と出て離れる | 会えないなら、UIの募集として送る |
| 分かっていないことを、分かっているように書く | 面談で聞かれ、答えられない | 「なぜかは分かっていない」と書く |
| 面談に企画の人が出ない | 「企画との距離」が伝わらない | 企画の人が出る |

最も多いのは、最初の「見た目で選ぶ」です。

## まとめ

- UI/UXデザイナーは、誰から来たか・作品の根拠の部分を読んだか・UIとUXのどちらか・使う人に会える形・根拠の取り方・分かっていないこと、を文面の段階で見ている
- 送る前に、UIとUXの線引き、使う人に会える形（誰に、どのくらいの頻度で）、最初に調べたい・直したい画面を決める。会えないなら、UIの募集として送る
- 誰に送るかは、見た目や道具ではなく、根拠の取り方と使う人、企画との距離の重なりで。「会ったら想定と違った」を書いている人を優先し、肩書と道具は「あればよい条件」に
- 文面には、相手の根拠を読んだ一文、どちらが主か、会える形、分かっていないこと、根拠の取り方を。褒め言葉と「ユーザー体験を向上」を書かない
- 面談は分かっていないことを話し、相手ならどう調べるかを聞く。企画の人が出て、会える形を具体の予定で示す

## よくある質問

### 使う人に会える仕組みが無く、これから作るところです

そのまま書きます。「いまは直接会えない。〇〇の部署を通して声は届く。会える仕組みを、一緒に作るところから始めたい」と、無いことと、作る意思を一緒に書きます。仕組みづくりから関わりたい人が返信します。

### 作品の説明に、根拠や判断の理由が書かれていない人が多いです

書かれていない人を外さず、面談で聞きます。文面では、作品の中で「なぜこの形か」が推測できる箇所を一つ挙げ、「〇〇の画面で△△にされた理由を、面談で聞かせてほしい」と書きます。根拠を持って作った人は、聞かれると話せます。

### UI/UXデザイナー向けのスカウトの対象の絞り込みは、御社に相談できますか

できます。当社は、対象の並べ直しの基準づくり、文面の型、避ける言葉のチェック、募集記事との整合の確認を支えられます。線引きと会える形の決定、相手の作品を読んだ一文、面談は、社内で担ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、Wantedlyのスカウト運用を支えています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
