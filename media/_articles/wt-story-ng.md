ストーリーの各型の書き方は、これまでの記事で書いてきました。この記事は、その基本を知っていても起きる失敗を、5つに分けて集めたものです。**結論から言うと、ストーリーの失敗は「題材」「書き方」「写真」「運用」「確認」の5つに分けると直しやすく、読まれないときは、失敗を探す前に「一覧で開かれていないのか、開いて離れているのか、読まれても話を聞きに来ないのか」を切り分けます。** 切り分けずに書き方だけを直しても、原因が運用（途切れている）や誘導（募集記事につながっていない）にあれば、直りません。この記事では、5つの失敗と直し方、公開前のセルフチェック、読まれない原因の切り分け、放置と燃え尽きの失敗、分担を整理します。ストーリーの位置づけは[ストーリーの基本](/media/wt-story-kihon/)で書きました。

## この作業の目的｜失敗に「気づける」状態を作る

ストーリーの失敗は、書いた本人には見えにくいものです。書いているときは「会社の良さが伝わる記事」のつもりで、候補者から読むと「会社の宣伝」に映ります。

気づける状態を作るには、公開前に5つの観点でチェックすることと、公開後に面談で「どのストーリーを読みましたか」と聞くことの2つです。後者は、面談の最初に一言聞くだけで、どの記事が届いていて、どの記事が読まれていないかが分かります。

## 失敗1｜題材

| 失敗 | 候補者からどう見えるか | 直し方 |
|---|---|---|
| 広報や宣伝、受賞や発表 | 会社の言葉。読まない | 裏で誰が何をしたか |
| 書きやすい題材（イベント、制度）から選ぶ | 候補者の知りたいことでない | 読ませたい候補者から決める。[テーマの決め方](/media/wt-story-theme/) |
| 1本に全部を詰める | 会社紹介になる | 1本に1つの場面 |
| 同じ型ばかり | 会社の一面しか見えない | 6つの型をローテーション |
| イベントの様子だけ | 楽しさの報告。来ない | 裏の動き。[社内イベントを書くときの注意](/media/wt-story-event/) |
| 募集している職種と関係が無い | 募集記事を補わない | 募集記事のどこを補うかで決める |

## 失敗2｜書き方

| 失敗 | 候補者からどう見えるか | 直し方 |
|---|---|---|
| 会社の説明から始める | 読まれない | 場面から始める |
| 抽象語（成長・挑戦・アットホーム） | どの会社も同じ | 場面に置き換える。[カルチャーを伝える書き方](/media/wt-story-culture/) |
| 良いことだけ | 建前 | うまくいかなかったこと、違ったこと、詰まったこと |
| 教訓や決意でまとめる | 説教、ポエム | 場面を置いて終える |
| 経歴・やりがい・メッセージの3段構成 | どの会社のインタビューも同じ | 1つの場面から。[社員インタビューを書く手順](/media/wt-story-interview/) |
| 理念をもう一度書く | 会社ページと重なる | 最近の1つの判断。[代表の考えを書く方法](/media/wt-story-daihyo/) |
| 成功事例にする | 実績の紹介 | 詰まりと判断。[事業の裏側を書く方法](/media/wt-story-jigyo/) |
| 本人の言葉を言い換える | 声が消える | そのまま残す |
| 長い | 読み切れない | 1つの場面を書き切る長さ |
| 募集記事や会社ページへ誘導しない | 読んで終わる | 一言で誘導 |

### エージェントベストの見解

申し込んだあと、ストーリーで半年後に起きやすいのは、「出しては放置し、人事が1人で疲れて止まる」ことです。書いた記事の反応を見ず、読まれたかどうかを聞かず、次を書く。材料は人事の目に入る範囲で尽き、書く時間は他の業務に食われ、本人の熱が下がる。当社は3媒体すべての販売パートナーとしてWantedlyの契約後の運用を見ていますが、ストーリーが1年以上続いている会社に共通するのは、「面談で読まれた記事を聞き、書いた人と話した人に戻している」ことと、「人事が書く人ではなく整える人になっている」ことです。反応が戻ると、社内の協力が続きます。整える人になると、人事の負担が減ります。この2つが無いと、どれだけ書き方が良くても、半年で止まります。ストーリーの失敗で最も重いのは、書き方ではなく、止まることです。

## 失敗3｜写真

| 失敗 | 候補者からどう見えるか | 直し方 |
|---|---|---|
| 記事と関係の無い写真 | 場面が伝わらない | 書いた場面の写真。[ストーリーの写真の撮り方](/media/wt-story-shashin/) |
| 写真を先に撮って記事を合わせる | 題材が写真に偏る | 記事を書いてから撮る |
| 集合写真、外観、乾杯 | 人と動きが見えない | 仕事中、会議中、準備の場面 |
| フリー素材 | 記事が疑われる | 無いほうがまし |
| 写真を待って公開しない | 途切れる | 無いまま出し、あとで足す |
| 顧客や機密の写り込み | 問題になる | 撮ったあとに確認 |
| 同意を取らない | 後で問題になる | 写真を見せて同意 |

## 失敗4｜運用

| 失敗 | 何が起きるか | 直し方 |
|---|---|---|
| 本数の目標を先に決める | 届かない月に止まる | 途切れないことを基準に。[更新頻度の決め方](/media/wt-story-hindo/) |
| 最初の月に多く書いて息切れ | 翌月から止まる | 最初は少なく |
| 募集が無い時期に止める | 次の募集の前に人が来ない | 減らしても止めない |
| ネタを集める仕組みが無い | 書く時間にネタが無い | 週に一度1行を拾う。[会社ページを更新し続ける仕組み](/media/wt-kaisha-page-koushin/) |
| 人事1人で書き続ける | 疲れて止まる | 話す人・拾う人・直す人を増やす。[書き手を社内で増やす方法](/media/wt-story-kakite/) |
| 出して放置 | 反応が分からず、次に活きない | 面談で「どのストーリーを読んだか」を聞く |
| 閲覧で判断する | イベントの記事が増える | 来た人の言葉で |
| タイトルが分類や連番 | 開かれない | 誰の、何が起きた。[ストーリーのタイトルの付け方](/media/wt-story-title/) |
| 古い記事を直さない | 良い記事が埋もれる | タイトルと誘導を直す |

## 失敗5｜確認

| 失敗 | 何が起きるか | 直し方 |
|---|---|---|
| 本人の確認を省く | 「言っていない」となる | 全文と写真を見せる |
| 代表の確認待ちで止まる | 公開されない | 期限と、過ぎたら人事判断の合意 |
| 人事が直しすぎる | 本人の言葉が消え、書き手が減る | 抽象語・事実・特定の3つだけ |
| 特定される情報を見落とす | 顧客や社員の問題 | 責任者と管理部門の確認 |
| 業務外に書かせる | 負担になり、次から断られる | 業務時間内 |
| 反応を本人に戻さない | 「話した意味が無かった」 | 面談で聞いて戻す |

## 公開前のセルフチェック

公開前に、次の順で見ます。数分で済みます。

1. **1本に1つの場面か**：2つ以上を詰めていないか
2. **場面から始まっているか**：会社の説明から始まっていないか
3. **抽象語が残っていないか**：成長、挑戦、アットホーム、風通し、想い
4. **うまくいかなかったこと、違ったこと、詰まったことが1つあるか**
5. **本人の言葉が残っているか**：言い換えていないか
6. **タイトルに「誰の、何が起きた」があるか**：分類や連番になっていないか
7. **写真が記事の場面か**：関係の無い写真、写り込みが無いか
8. **募集記事か会社ページへ誘導しているか**
9. **本人と、必要なら責任者・管理部門の確認を取ったか**
10. **別の1人に読んでもらったか**：候補者の目線で「この会社で働く自分が想像できるか」

1と3と6で止まることが多いので、この3つだけでも毎回見ます。

## 読まれないときの、原因の切り分け

「ストーリーが読まれない」「話を聞きに来ない」という症状は、原因が3つに分かれます。書き方を直す前に、どこで止まっているかを見ます。

| 止まっている場所 | 見えるサイン | 直す場所 |
|---|---|---|
| 一覧で開かれていない | 閲覧が見えるなら少ない。タイトルが分類や連番 | タイトルと最初の写真 |
| 開いたが、途中で離れている | 開かれているが、面談で挙がらない。会社の説明から始まる、抽象語が多い | 書き方 |
| 読まれているが、話を聞きに来ない | 面談で「読んだ」と言われるが、募集記事に進んでいない。誘導が無い、会社ページが古い | 募集記事への誘導、会社ページ |
| そもそも新しい記事が無い | 途切れている | 運用。頻度と書き手 |

「そもそも新しい記事が無い」は、失敗を探す前に確かめることです。途切れている状態で書き方を直しても、直した記事が出なければ意味がありません。

「読まれているが来ない」は、ストーリーの失敗ではなく、募集記事か会社ページの失敗です。ストーリーから募集記事へ誘導し、募集記事が「この募集で何をやるか」を具体的に書いていて、会社ページが古くなければ、読んだ候補者は話を聞きに来ます。募集記事の失敗は[募集記事でやりがちな失敗](/media/wt-boshu-ng/)で書きました。

## 社内の分担

| 作業 | 誰が |
|---|---|
| 公開前のセルフチェック | 書いた人と、別の1人 |
| 面談で「どのストーリーを読んだか」を聞く | 面談に出る人 |
| 読まれない原因を切り分ける | 人事 |
| 5つの失敗を直す | 人事（本人の言葉に関わる部分は本人と） |
| 途切れていないかを見る | 人事 |
| 古い記事のタイトルと誘導を直す | 人事 |

運用代行や代理店が支えられるのは、セルフチェックの型、原因の切り分け、5つの失敗の直し方の案、古い記事の直し案までで、本人の確認、特定の判断、面談で聞くことは企業が行います。代理店の代行の範囲は[代理店に運用まで頼めるか](/media/kh-dairiten-unyou/)で書きました。

### エージェントベストの見解

自社で持つべきなのは、どこまでか。当社がWantedlyのストーリーの見直しを支えるとき、5つの観点のチェック、読まれない原因の切り分け、直し方の案、古い記事のタイトルと誘導の直し案は当社が出せます。ただし、「面談で候補者に『どのストーリーを読みましたか』と聞く」ことだけは、企業にしかできません。この一言が無いと、当社も企業も、どの記事が届いているかを推測するしかなく、閲覧の数で判断することになり、イベントの記事が増えます。当社が見直しを支えるとき、最初に「面談の型に、この一言を入れてください」とお願いするのは、この理由です。一言があれば、失敗は見つかり、直せます。無ければ、失敗は見えないまま続きます。ストーリーの見直しは、書き方の技術より、聞く一言から始まります。

## まとめ

- ストーリーの失敗は、題材・書き方・写真・運用・確認の5つに分けると直しやすい
- 公開前に、1本1場面か・場面から始まるか・抽象語が無いか・タイトルに場面があるか、を最低限チェックし、別の1人に読んでもらう
- 読まれないときは、一覧で開かれないのか・開いて離れるのか・読まれても来ないのか・そもそも新しい記事が無いのか、を切り分けてから直す
- 最も重い失敗は、書き方ではなく「止まること」。出して放置と、人事1人の燃え尽きを防ぐ
- 面談で「どのストーリーを読んだか」を聞く一言が、失敗に気づく唯一の手段

## よくある質問

### ストーリーを直したのに、話を聞きに来る人が増えません

原因がストーリー以外にある可能性があります。読まれているのに来ないなら、募集記事への誘導が無いか、募集記事が具体的でないか、会社ページが古いかです。そもそも新しい記事が出ていないなら、運用の問題です。面談で「どのストーリーを読んだか」を聞き、どこで止まっているかを切り分けてから直します。

### 記事の質より、続けることを優先してよいのですか

続けることが先です。質の高い記事が半年止まるより、月に1本の短い記事が途切れないほうが、会社ページに人が来続けます。質は、続けながら、面談で聞いた反応を戻して上げていきます。止まった時点で、質を上げる機会も無くなります。

### ストーリーの見直しは、御社に相談できますか

できます。当社は、5つの観点のチェック、読まれない原因の切り分け、直し方の案、古い記事の直し案を支えられます。本人の確認と、面談で聞くことは、企業が行ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、Wantedlyのストーリーの整備を支えています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
