エンジニアを新卒で採りたい会社が媒体を選ぶとき、最初にぶつかるのは「情報系の学科で絞って技術名の一覧を並べた文面を人事の名義で送り、承認されず、承認しても人事だけの面談で『何を作っているのですか』『レビューは誰がするのですか』に答えられず、技術面接で何を聞かれるかが体験談に無く、『エンジニアは取り合いで無理だ』で終わる」という問題です。**結論から言うと、エンジニア志望の学生は情報系だけでなく独学と他学科にもいて、技術名の一覧ではなく「何を作っていて、どう進めていて、最初の年に誰と何を作り、レビューは誰が、技術面接で何を聞かれるか」を読みます。記事を置く型は「作っているものと進め方」を通年で読ませる場として最も向き、送る型は技術名ではなく「作ったことがあるか」で絞って技術の人の名義で、比べられる場は体験談が総合職中心でエンジニアの実態が書かれにくい前提で使います。どの入口も技術の人の時間が要ります。** 理系学生全般は[理系学生を採りたい会社の採用媒体の選び方](/media/hikaku-rikei-erabikata/)で書きました。この記事はエンジニアに絞ります。

## エンジニアの採用で、起きること

| 会社の状態 | 採用で起きること | 媒体との相性 |
|---|---|---|
| 情報系の学科で絞る | 独学と他学科でものを作っている学生を落とす | 「作ったことがあるか」で絞る。[OfferBoxでエンジニア志望の学生を見つける検索の考え方](/media/ob-engineer-target/) |
| 技術名の一覧を並べる | 学生は「何を作っているか」「どう進めているか」を読んでいて、一覧では分からない | 作っているものと進め方を書く。[Wantedlyでエンジニアを採る募集記事の書き方](/media/wt-engineer-boshu/) |
| 人事の名義で送り、人事だけで面談する | 「レビューは誰が」「技術選定は誰が」に答えられない | 技術の人の名義と面談 |
| 体験談が総合職中心 | エンジニアの技術面接の実態が体験談に無く、学生は確かめられない | 企業ページに技術面接で聞くことを先に。[ワンキャリアでエンジニアを募集するときの掲載とスカウト](/media/oc-engineer-keisai/) |
| 技術の人が面談に出ない | 「エンジニアは人事の仕事ではない」で止まる | 技術の人の時間を先に確保 |
| 大手と取り合い | 「取り合いで無理」で諦める | 作っているものと進め方で絞れば、大手と並べられない届け方になる |

## 判断軸を、エンジニアに当てる

| 軸 | エンジニアでの見方 |
|---|---|
| 対象（誰に届くか） | 「どのエンジニアか」（自社製品か受託か、Webか組み込みか、設計から関わるか）を一言で決め、求める行動（作り切る・動かないときに原因を探す・人と分担して作る）で絞る。専攻と技術名はあればよい条件 |
| 型（送るか、来るか、比べられるか） | 来る型は、作っているものと進め方と「いま何を決めようとしているか」を通年で読ませる場で、エンジニアに最も向く。送る型は、作ったものの記述で絞って技術の人の名義で一人に。比べられる型は、体験談が総合職中心でエンジニアの実態が書かれにくく、企業ページで技術面接と最初の年を分けて書けるかで |
| 課金（費用の性格） | 各媒体の公式ページで現在の条件を確認。この記事では書かない。エンジニア向けの媒体を併用するなら役割で。[WantedlyとFindyの違い](/media/hikaku-wantedly-findy/) |
| 運用工数（誰の時間が要るか） | 技術の人が、読む・書く・面談に出るの三つに週に何時間出せるかで、入口と送る数を絞る。人事は絞る作業と日程 |

軸の詳しい見方は[掲載型とスカウト型の違い](/media/hikaku-keisai-vs-scout/)、[共感型と条件型の媒体の違い](/media/hikaku-kyoukan-vs-jouken/)で書きました。エンジニアでは、「型」で記事を置く型が最も向くことと、「運用工数」を技術の人の時間で決めることが、他の職種と違います。

### エージェントベストの見解

エンジニアの採用に、向いている媒体と向いていない媒体があります。当社は3媒体すべての販売パートナーとして、エンジニアの新卒採用の相談を受けますが、エンジニア志望の学生は、知名度より「何を作っていて、どう進めているか」で会社を読みます。記事を置く型（Wantedly）は、作っているものと進め方と「いま何を決めようとしているか」を技術の人が通年で書ける場で、エンジニアには最も向きます。送る型（OfferBox）は、作ったものの記述で絞って技術の人の名義で一人に書けるときに効き、技術名で絞って人事の名義で送ると効きません。比べられる場（ワンキャリア）は、体験談が総合職の選考に偏っていて、エンジニアの技術面接の実態が書かれにくく、企業ページで技術面接と最初の年を分けて書けないなら、エンジニアには届きにくい場です。当社が最初に確かめるのは、技術の人が書けるか、面談に出られるかです。書けて出られるなら、記事を置く型から始めます。書けないなら、媒体より先に、技術の人の時間を作ることです。

## 学生が、確かめること

- **何を作っているか**：自社製品か受託か。Webか組み込みか。何のために誰が使うものか
- **どう進めているか**：レビューは誰が、どのくらいの頻度で。技術選定は誰が決めるか。テストとリリースの流れ
- **最初の年に、誰と何を作るか**：先輩の下で一部を作るのか、小さな機能を一人で持つのか。誰が見るか
- **技術面接で何を聞かれるか**：作ったものを見せるか、その場で書くか、設計を聞かれるか。体験談に無いなら企業ページで
- **技術の人と話せるか**：人事だけの面談か。技術の人が出るか
- **技術の学び方と、最新の技術への向き合い方**：社内で何をどう学ぶか。古い技術のまま止まっていないか

## この条件なら、どれを先に検討するか

| 会社の条件 | 先に検討する型 | 理由 |
|---|---|---|
| 技術の人が、作っているものと進め方と「いま決めようとしていること」を自分の言葉で通年で書ける | 通年で記事を置く型（Wantedly） | エンジニアに最も向く場。読んだ学生が話を聞きに来る。[Wantedlyでエンジニアにスカウトを送る文面](/media/wt-engineer-scout/) |
| 「作ったことがあるか」で絞り、技術の人の名義で「あなたの〇〇を読んで」と一人に書ける | 企業から送る型（OfferBox） | 独学と他学科の学生にも届く。[エンジニア向けスカウト文面の型](/media/kh-bunmen-engineer/) |
| 知名度があり、企業ページで技術面接と最初の年をエンジニア向けに分けて書ける | 学生が並べて比べる場（ワンキャリア） | 体験談が総合職中心の前提で、エンジニア向けの部分を分けて。分けて書けないなら先ではない |
| 技術名の一覧を並べた文面のまま | どれも先ではない | 作っているものと進め方に置き換えてから |
| 技術の人が読む・書く・面談に出る時間が決まっていない | どれも先ではない | 決めてから |

どれか一つが正解ではなく、技術の人が書けるか、絞って送りたいか、知名度で、先に検討するものが変わります。

## 組み合わせ

- **記事を置く型を主に、送る型で「作ったことがある」学生に届ける**：記事で作っているものと進め方を、文面で「あなたの〇〇を読んで」を。[OfferBoxとWantedlyの併用](/media/ob-heiyou-wantedly/)
- **エンジニア向けの媒体と組み合わせるなら、役割で**：技術で絞って送る場と、会社の考えで集める場。[WantedlyとFindyの違い](/media/hikaku-wantedly-findy/)
- **インターンで、作っているものを実際に触ってもらう**：技術の人が受け入れる。[インターンからの母集団形成](/media/kh-boshudan-intern/)
- **技術面接の型を、揃える**：作ったものの「なぜそうしたか」「動かなかったとき何をしたか」を聞く。面接官が変わっても同じ
- **技術の人の時間で、入口を絞る**：全入口を開けない。[理系学生を採りたい会社の採用媒体の選び方](/media/hikaku-rikei-erabikata/)
- **代行と組み合わせるなら、絞る作業と文面の下書きまで。読んで直すのは技術の人**：[媒体と代行の違い](/media/hikaku-baitai-vs-daikou/)

## 見せ方｜技術名の一覧ではなく、作っているものと進め方

- **技術名の一覧を、消す**：「使用技術：〇〇、△△、□□」は、学生には「何を作っているか」が分からない。技術名は進め方の中で一つずつ
- **何を作っているかを、誰が使うもので**：「〇〇の業種の△△が毎日使う□□を作っている」
- **どう進めているかを、レビューと技術選定で**：「レビューは〇〇が週に△回。技術選定は□□が提案し、◇◇で決める」
- **最初の年に誰と何を作るかを、具体で**：「最初の〇か月は△△の下で□□の一部。◇か月目に小さな機能を一人で。見るのは△△」
- **技術面接で何を聞くかを、先に**：「作ったものを見せてもらい、なぜそうしたか、動かなかったとき何をしたかを聞く。その場で書く試験は無い」
- **いま何を決めようとしているかを、書く**：「〇〇を△△に置き換えるかを、いま決めようとしている」。決まっていないことが、学生には実態に見える
- **技術の人が出ることを、書く**：「面談は技術の〇〇が出る」。数値は自社の実態で。この記事では書かない

## 社内の分担

| 作業 | 誰が |
|---|---|
| 「どのエンジニアか」の一言、求める行動、技術の人の時間、入口の絞り方を決める | 技術の責任者と採用の責任者 |
| 記事（作っているもの、進め方、いま決めようとしていること） | 技術の人本人。人事は清書と公開 |
| 「作ったことがあるか」で絞る条件 | 技術の人が作り、人事か代行が絞る |
| 文面の一文 | 技術の人が読んで書く。人事が下書き |
| 面談と技術面接 | 技術の人。型を揃えて |
| 日程と返信 | 人事 |

運用代行や代理店が支えられるのは、「どのエンジニアか」の型、絞る条件の型、文面の下書き、記事の清書と公開、日程と返信までで、技術の人の時間の決定、記事の中身、読んで直す、面談と技術面接は社内が担います。代理店の代行の範囲は[代理店に運用まで頼めるか](/media/kh-dairiten-unyou/)で書きました。

### エージェントベストの見解

エンジニアの採用で、当社が順番として最初にお願いするのは、媒体を選ぶことではなく、「技術の人が、作っているものと進め方を、一本、自分の言葉で書く」ことです。技術名の一覧を人事が並べた文面は、どの媒体に出しても、エンジニア志望の学生には「何を作っているか分からない会社」と読まれます。逆に、技術の人が作っているものと進め方を一本書けば、その文章は記事にも企業ページにも文面にも使え、どの媒体でも「作っているものが分かる会社」になります。一本が書けたら、技術の人の時間で入口を絞り、そのうえで媒体を選びます。当社が媒体の運用を引き受けるときも、「技術の人の一本→時間で入口を絞る→媒体」の順番でお願いしています。順番が逆だと、媒体を契約した後に、技術の人が書く時間も面談に出る時間も無く、人事の名義で技術名の一覧を送ることになります。

## まとめ

- エンジニア志望の学生は情報系だけでなく独学と他学科にもいる。「作ったことがあるか」で絞り、専攻と技術名はあればよい条件
- 学生が読むのは技術名の一覧ではなく「何を作っていて、どう進めていて、最初の年に誰と何を作り、レビューは誰が、技術面接で何を聞かれるか」
- 記事を置く型（Wantedly）が最も向く。送る型（OfferBox）は作ったものの記述で絞って技術の人の名義で。比べられる場（ワンキャリア）は体験談が総合職中心の前提で、企業ページにエンジニア向けの部分を分けて書けるかで
- どの入口も技術の人の時間が要る。読む・書く・面談に出るの三つに週に何時間出せるかで、入口と送る数を絞る
- 順番は「技術の人が作っているものと進め方を一本書く→時間で入口を絞る→媒体」

## よくある質問

### 技術の人が「文章は苦手」と言って、記事を書いてくれません

書くのは「作っているものと進め方」で、文章の上手さは要りません。技術の人に話してもらい、人事が書き起こして、技術の人が直す形にします。「何を作っているか、誰が使うか、レビューは誰が、いま何を決めようとしているか」の四つを話してもらえば、一本になります。話す時間は一時間で足ります。

### 情報系の学生が来ないので、諦めています

情報系だけで絞っているなら、対象を自分で減らしています。独学でものを作っている学生、他学科でサークルや研究でプログラムを書いている学生は、情報系の学科にはいません。「作ったことがあるか」（何を作ったか、動かなかったとき何をしたか、人と分担して作ったか）で絞ると、対象が広がります。技術面接で「作ったものの、なぜそうしたか」を聞けば、学科は関係ありません。

### エンジニアの媒体選びは、御社に相談できますか

できます。当社は、「どのエンジニアか」の型、絞る条件の型、文面の下書き、記事の清書と公開、日程と返信を支えられます。技術の人の時間の決定、記事の中身、読んで直す、面談と技術面接は、社内で担ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、エンジニアの媒体選びと運用を支えています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
