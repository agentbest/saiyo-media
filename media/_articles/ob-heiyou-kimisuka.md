OfferBoxと、同じスカウト型のもう一つの媒体（キミスカ）を、一つに集中せず併用すると決めた。決めたあとに起きるのは、「文面は使い回せるので手間は増えない」と考えていたのに、承認への返信と面談が増えて回らなくなる、同じ学生に両方から届いて学生から指摘される、文面の原稿が二つに分かれて片方が古くなる、という形の崩れです。**結論から言うと、併用を始めたあとの運用は、送る総量の上限を「承認に当日返せる数」と「面談に出られる数」で決め、同じ学生に両方から届いたときの対応を先に決め、文面の共通原稿を一つで版管理し、月に一度「配分が薄まっていないか」を見て、片方をやめる判断は契約の切れ目で行います。** この記事では、送る総量の上限、重なりへの対応、文面の版管理、月に一度の見直し、やめる判断、台帳、やりがちな失敗、社内の分担を整理します。一つに集中するか併用するかの判断そのものは[OfferBoxとキミスカの違い](/media/hikaku-offerbox-kimisuka/)、学生像の分け方は[OfferBoxとirootsの使い分け](/media/ob-heiyou-iroots/)、時期の分け方と管理画面の見方は[OfferBoxとdodaキャンパスの違いと使い分け](/media/ob-heiyou-doda-campus/)で書きました。この記事は、併用を続けるための日々の運用を扱います。両サービスの仕様と数値は書きません。

## 送る総量の上限を、「返せる数」と「会える数」で決める

- **上限は、送れる数ではなく、承認に当日返せる数と、面談に出られる数**：送る数を増やしても、返せる数と会える数は増えない
- **承認の割合を仮に置いて、返せる数から送る数を逆算する**：割合は自社の昨年の台帳から。ない場合は小さく送って様子を見る。この記事では数値を書かない
- **二つの媒体の送る数の合計を、上限の中に収める**：媒体ごとに上限を置くのではなく、合計で
- **送る社員が文面を確認できる数も、上限に入れる**：名義の社員が読まずに送る文面は、承認されない
- **時間が足りないときは、送る数を減らす**：文面を薄くして数を保つより、数を減らして文面と返信を保つ。[OfferBoxの運用に工数が足りないときの対処](/media/ob-kousuu-tarinai/)

併用で増えるのは、送れる数です。増えないのは、返す時間と会う時間です。上限を「返せる数と会える数」で置くと、二つ持っても送る合計は変わらず、変わるのは「どの層に、どの媒体から届けるか」の幅だけになります。

## 同じ学生に両方から届いたときの対応を、先に決める

- **送る前に突き合わせて、両方から送らない**：これが基本。送る側の台帳を一つにし、媒体の列で持つ
- **それでも届いてしまったときの対応を、先に決めておく**：登録の名前が違う、突き合わせの前に送ってしまった、などで起きる
- **学生から「両方から来た」と言われたら、隠さない**：「二つの媒体で探しており、重なってしまいました。お話は一本で進めます」と、承認した側の媒体で連絡を続ける
- **二通の文面が違う型（会社側の型と学生側の型）だった場合は、学生側の型の続きで話す**：会社側の型は「型に名前を入れただけ」と読まれやすい
- **重なった学生を、台帳に印を付けて数える**：月に一度、重なりの数を見る。増えていれば、突き合わせの手順が崩れている

重なりは、併用で最も学生の印象を下げる失敗です。「同じ会社から、違う文面で二通」は、「この会社は誰に送っているか分かっていない」と読まれます。

### エージェントベストの見解

相談で最も多い思い込みは、「文面は使い回せるので、二つ目を足しても手間は増えない」というものです。当社は3媒体すべての販売パートナーとして、OfferBoxの運用代行を受けているので、送る数と承認後の作業の関係を毎週見ていますが、併用で増える手間は、文面ではなく、承認への返信と面談です。文面は一つの原稿から流せますが、承認は媒体ごとに別の管理画面に来て、返信はその日のうちに要り、面談は送る社員か面接官が出ます。送る数を二つの媒体で倍にすれば、承認も返信も面談も倍になり、返信が翌日にずれて、面談が埋まらず、承認した学生を失います。当社が併用する会社に最初に決めてもらうのは、二つの媒体の送る数の合計の上限で、その上限は「承認に当日返せる数」と「面談に出られる数」から逆算します。上限が決まれば、二つ持つ意味は、送る数を増やすことではなく、届く層を広げることに変わります。

## 文面の共通原稿を、一つで版管理する

- **共通部分の原稿を一つのファイルで持つ**：最初の年に何をするか、誰と組むか、名義、会社紹介の短い一文。両方の媒体のテンプレートは、この原稿から作る
- **媒体ごとの部分は、プロフィールから拾う一文だけ**：読める項目が媒体で違うので、拾う場所だけを媒体ごとに書く
- **共通部分を直したら、版を上げて、両方のテンプレートを同じ日に直す**：「第〇版」と日付を原稿に書く。片方だけ古くなると、同じ会社が違うことを言う
- **名義の社員が変わったら、両方を同じ日に**：辞めた社員の名義で片方だけ送り続ける失敗を防ぐ
- **文面がマンネリ化したら、共通原稿の側を直す**：[OfferBoxのオファー文面がマンネリ化したとき](/media/ob-bunmen-mannerika/)

文面の基本は[OfferBoxのオファー文面の基本](/media/ob-offer-bunmen-kihon/)で書きました。二つの媒体で、共通部分がずれるのは、原稿が二つあるからです。原稿を一つにすれば、ずれません。

## 月に一度、「薄まっていないか」を見る

| 見る項目 | 何を見るか | 薄まっているサイン |
|---|---|---|
| 送る数の合計 | 上限の中に収まっているか | 上限を超えている。文面の確認が追いついていない |
| 媒体ごとの送る数 | 片方に偏っていないか | 片方がほとんど送られていない。契約だけ残っている |
| 承認から返信までの日数 | 当日に返せているか | 翌日以降が増えている |
| 面談の設定 | 承認した学生の面談が入っているか | 承認から面談まで日数が伸びている |
| 重なりの数 | 両方から届いた学生 | 増えている |
| 近い学生の数 | 面談まで来た「近い」学生が、媒体ごとに何人か | 片方からゼロが続く |

- **月に一度の見直しは、優劣をつけるためではなく、配分が薄まっていないかを見るため**：数字は[OfferBoxを含む複数媒体の効果を並べて見る方法](/media/ob-heiyou-heiyou-kpi/)の見方で
- **薄まっていたら、送る数を減らすか、片方の送る時期をずらす**：足すのではなく、減らす
- **開封率と承認率を媒体の間で比べない**：それぞれの中で先月と。[OfferBox運用のKPI設計](/media/ob-kpi-sekkei/)

## 片方をやめる判断は、契約の切れ目で

- **途中の月に「効かない」でやめない**：時期の偏りで結論が逆になる。切れ目までは、止まっている段を直す
- **やめる判断の材料は、一年の台帳**：媒体ごとに、面談まで来た「近い」学生の数と、送る側の時間。[媒体をやめる判断基準](/media/hikaku-baitai-tettai/)
- **やめる前に、「送っていなかっただけ」を疑う**：片方がほとんど送られていないなら、効かなかったのではなく、使っていなかった
- **やめるなら、残す側に送る数を戻す**：上限は変わらないので、合計は同じ。残す側の層を広げる
- **やめた媒体の台帳は残す**：翌年に戻す判断の材料

## 台帳

- **送る側の台帳を一つにし、媒体の列と、重なりの印を持つ**：誰に、どの媒体から、どの版の文面で、誰の名義で、いつ送ったか
- **承認した学生だけを、来た学生の台帳に移す**：[OfferBoxと採用管理システム（ATS）の連携の考え方](/media/ob-heiyou-ats/)
- **月に一度、両方の管理画面の承認数と台帳を突き合わせる**
- **費用は、各媒体の現在の条件を公式ページで確認する**：配分は[OfferBoxを含む複数媒体の予算配分の考え方](/media/ob-heiyou-heiyou-yosan/)

## やりがちな失敗

| 失敗 | 何が起きるか | 直し方 |
|---|---|---|
| 送る総量を媒体ごとに置く | 合計が返せる数を超え、返信が遅れる | 合計で上限を置く |
| 重なりの対応を決めていない | 学生に指摘されて慌て、印象が下がる | 対応を先に決め、隠さない |
| 文面の原稿が二つある | 片方が古くなり、同じ会社が違うことを言う | 一つの原稿で版管理 |
| 月に一度の見直しをしない | 片方がほとんど送られず、契約だけ残る | 薄まっていないかを月に一度 |
| 途中の月に片方をやめる | 時期の偏りで結論が逆になる | 契約の切れ目で、一年の台帳で |

最も多いのは、一つ目です。媒体ごとに「これくらい送れる」で上限を置き、合計が返せる数を超えます。

| 作業 | 誰が |

| 送る総量の上限を、返せる数と会える数から決める | 人事と責任者 |
| 重なりへの対応の文面を決める | 人事 |
| 文面の共通原稿を持ち、版を管理する | 人事と送る社員 |
| 送る側の台帳を一つにし、突き合わせる | 人事、または代行 |

### エージェントベストの見解

これをやる前に、先に一つ目の媒体で「送る→当日に返す→会う」の週の型が回っている状態を作っておかないと、二つ目を足しても薄まるだけです。当社はOfferBoxの運用代行を受けているので、二つ目のスカウト型を足したいという相談を受けますが、一つ目の承認への返信が翌日にずれている会社に二つ目を足すと、ずれが二つになります。当社が足す前に確かめるのは、直近の送る時期で、承認への返信が当日に行えていたか、面談が承認から数日で設定できていたか、の二つです。できていれば、上限の中で二つ目に層を分けられます。できていなければ、二つ目の前に、一つ目の返信と面談の型を直します。併用は、一つ目が回っている会社の「層を広げる手段」であって、一つ目が回っていない会社の「数を増やす手段」ではありません。

## まとめ

- 送る総量の上限は、送れる数ではなく「承認に当日返せる数」と「面談に出られる数」で、二つの媒体の合計で置く
- 同じ学生に両方から届いたときの対応を先に決める。送る前に突き合わせ、届いてしまったら隠さず一本で進める
- 文面の共通原稿を一つのファイルで持ち、版と日付を書き、直したら両方を同じ日に直す
- 月に一度、薄まっていないか（上限、偏り、返信の日数、面談の設定、重なり、近い学生の数）を見る。優劣をつけるためではない
- 片方をやめる判断は契約の切れ目で、一年の台帳で。「送っていなかっただけ」を先に疑う

## よくある質問

### 併用を始めたら、承認への返信が遅れ始めました

送る総量が、返せる数を超えています。送る数を減らすか、通知を見て一次の返信を行う作業を外に出します。文面を薄くして数を保つ方向には行かないでください。当社の運用代行は、二つの媒体の通知を見て、承認の古い順に当日に返す作業を受けています。

### 二つの媒体で、文面を完全に変えたほうが承認は上がりますか

共通部分（最初の年、誰と組むか、名義）を変える理由はありません。変えるのは、プロフィールから拾う一文だけで、そこが媒体ごとに違えば、学生には「自分に来た」と読まれます。全部を変えると、原稿が二つになり、片方が古くなります。承認を上げるのは、文面の違いではなく、拾う一文の具体さと、返信の速さです。

### OfferBoxとキミスカの使い分けは、御社に相談できますか

できます。当社は、役割の整理、上限の逆算の型、重なりの対応の型、原稿の版管理の型、台帳と突き合わせの型、検索・文面下書き・送信・一次返信、月に一度の数字の整理を支えられます。「こんな人」の決定、共通原稿の中身、面談、やめるかの判断は、企業が行ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、OfferBoxの運用代行も受けています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
