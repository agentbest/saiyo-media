OfferBoxで新卒を採っていて、Wantedlyも契約している。ところが、Wantedlyは中途採用のためのもの、または「共感採用」の別の取り組みとして置かれていて、OfferBoxの運用とつながっていない。承認した学生が面談の前に離れる、面談で「思っていたのと違う」と言われる、という悩みがあるのに、Wantedlyの記事はその学生に届いていない。**結論から言うと、OfferBoxは「企業が選んで送り、承認をもらう入口」、Wantedlyは「承認した学生が、面談の前に会社を読む場所」です。OfferBoxの側から見た併用は、承認後の連絡の型に記事を入れ、文面の会社紹介を短くして記事に置き、承認後の辞退を記事で減らし、内定者にストーリーを書いてもらって翌年の文面と記事の元にすることです。** この記事では、それぞれの役割、承認後の連絡の型、文面と記事の分担、辞退の減らし方、内定者のストーリー、時間の配分、台帳、やりがちな失敗、社内の分担を整理します。二つの違いそのものは[OfferBoxとWantedlyの違い](/media/hikaku-offerbox-wantedly/)、Wantedlyの側から見た併用は[WantedlyとOfferBoxの併用](/media/wt-heiyou-offerbox/)で書きました。この記事は、OfferBoxの運用の中でWantedlyをどう使うかを扱います。数値は書きません。

## それぞれの役割｜「承認をもらう入口」と「承認した学生が読む場所」

| | OfferBox | Wantedly |
|---|---|---|
| 役割 | 企業が学生を選んで送り、承認をもらう | 承認した学生が、面談の前に会社を読む |
| 学生の状態 | 文面と送ってきた人で興味を持ち、承認した。会社の中身は文面の範囲 | 会社ページとストーリーを読んだ。「読んだとおりか」を確かめに面談に来る |
| 時期 | 送る時期に集中 | 通年。記事が残る |
| 会社が出すもの | 検索条件、文面、送る社員の名義 | 会社ページ、送る社員のストーリー、募集記事 |
| 数の性格 | 送信・開封・承認 | 閲覧、「話を聞きに行きたい」。OfferBoxの学生が読んだ数は直接には見えない |
| 外に出せる時間 | 検索、文面の下書き、送信、一次の返信。出せる | 整える部分は出せる。社員が話す中身は出せない |

承認した学生は、面談までの間に会社を調べます。調べた先に送ってきた社員のストーリーと会社ページがあると、文面で持った興味が「この会社で働く自分」の想像に変わり、ないと面談の前に他社に決まります。OfferBoxの運用から見ると、Wantedlyは「承認から面談までの間を埋める場所」です。

## 承認後の連絡の型に、記事を入れる

- **承認への当日の返信に、送った社員のストーリーの場所を添える**：「面談の前に、私が書いたこちらを読んでいただけると、話が早いです」。返信の手順は[OfferBoxでオファーが承認されたあとの連絡手順](/media/ob-shounin-go/)
- **面談前の連絡（確定・前日・当日）のどこかに、会社ページの場所を**：[OfferBoxの面談前の連絡で辞退を減らす方法](/media/ob-mendan-mae-renraku/)
- **面談の冒頭で、「読んでいただけたか、どこが気になったか」を聞く**：読んでいれば記事の場面から、読んでいなければ文面の続きから
- **記事の場所を、返信の型に固定する**：毎回手で書かない。型に入っていれば、代行が返信しても記事が届く

### エージェントベストの見解

相談で最も多い思い込みは、「OfferBoxで採れているので、Wantedlyは中途採用用に置いておけばよい」というものです。当社は3媒体すべての販売パートナーとして、OfferBoxの運用代行を受けているので、承認から面談までの間に学生が離れるのを毎年見ていますが、離れる学生の多くは、承認のあとに会社を調べて、調べた先に文面の続きがなかった学生です。Wantedlyを契約していても、送った社員のストーリーがなく、会社ページが中途向けの募集要項だけ、という会社があります。OfferBoxの運用から見ると、Wantedlyは「共感採用」の別の取り組みではなく、承認から面談までの間を埋める道具です。当社が承認後の辞退の相談を受けたとき、最初に確かめるのは、承認への返信の型に、送った社員の記事の場所が入っているかです。入っていなければ、文面より先に、その一行を型に足してもらいます。

## 文面の会社紹介を短くして、記事に置く

| 文面（OfferBox） | 記事（Wantedly） |
|---|---|
| なぜあなたに送ったか。記述のどこを見たか | 送った社員のストーリー。何をどう変えた場面 |
| 最初の年に何をするか、の一文 | 最初の年の詳しい中身と、誰と組むか |
| 会社紹介は短く。「詳しくは記事に」 | 会社ページの「なぜ」。代表の言葉の場面 |
| 条件の概要（詳細は採用サイトに） | 募集記事。条件は採用サイトと同じ |
| 書かない：会社の沿革、事業の羅列、社風の抽象語 | 書かない：文面の貼り直し、募集要項だけ |

- **文面の会社紹介が長いなら、記事に逃がす**：文面は学生の側の話に使い、会社の中身は記事に。[スカウトでの会社紹介の書き方](/media/kh-bunmen-kigyo-shoukai/)
- **送る社員の名義とストーリーの書き手を同じ人に**：学生が文面、記事、面談で同じ人に三度会う
- **文面の「最初の年」と記事の「最初の年」をずらさない**：最後に同じ人が見る
- **文面の基本**：[OfferBoxのオファー文面の基本](/media/ob-offer-bunmen-kihon/)

## 承認後の辞退を、記事で減らす

- **承認から面談までの間に離れる学生は、「文面の続き」を見つけられなかった学生**：記事があれば、続きが読める
- **面談で「思っていたのと違う」と言われる学生は、面談の前に会社を読んでいない学生**：読んでから来ると、面談が「読んだとおりか」の確認になる
- **内定のあとに離れる学生には、内定者が書いたストーリーを**：「入る前に不安だったこと」を先に入った人が書いている
- **選考離脱の全体の直し方**：[OfferBoxの選考離脱を減らす方法](/media/ob-senkou-ridatsu/)

## 内定者にストーリーを書いてもらい、翌年の元にする

- **内定者に、Wantedlyのストーリーを書いてもらう**：「オファーを受け取ったとき、何を見て承認したか」「面談の前に何を調べたか」「入る前に不安だったこと」。[Wantedlyのストーリーで入社エントリーを書いてもらう方法](/media/wt-story-nyusha/)
- **その記事を、翌年の承認後の返信の型に入れる**：承認した学生が、一年前に同じ立場だった人の言葉を読める
- **内定者の言葉を、翌年の文面の元にする**：[OfferBoxで内定者にオファー文面を手伝ってもらう方法](/media/ob-naiteisha-katsuyou/)

## 時間の配分と、台帳

- **OfferBoxの出せる時間を外に出し、Wantedlyの出せない時間を自社に残す**：検索・文面下書き・送信・一次返信は代行に、送る社員が話す時間は社内に。[OfferBoxの運用代行に任せられる範囲と自社で持つ判断](/media/ob-unyou-daikou-hanni/)
- **送る時期の前に、送る社員のストーリーを一本出す**：送る時期に入ると、記事の時間は消える
- **送る時期に、Wantedlyの更新を止めない**：承認した学生が読みに来る時期
- **台帳は一つ**：入口の列に「OfferBox」と「Wantedly」。OfferBoxで承認した学生がWantedlyで「話を聞きに行きたい」と来たら、最初の入口をOfferBoxにし、連絡は一本に。[OfferBoxと採用管理システム（ATS）の連携の考え方](/media/ob-heiyou-ats/)
- **「記事を読んだか」の列を、来た学生の台帳に足す**
- **費用は、各媒体の現在の条件を公式ページで確認する**：配分は[OfferBoxを含む複数媒体の予算配分の考え方](/media/ob-heiyou-heiyou-yosan/)、並べ方は[OfferBoxを含む複数媒体の効果を並べて見る方法](/media/ob-heiyou-heiyou-kpi/)

## やりがちな失敗

| 失敗 | 何が起きるか | 直し方 |
|---|---|---|
| Wantedlyを中途用に置いておく | 承認した学生が読みに来て、文面の続きがない | 送る社員のストーリーを一本 |
| 承認後の返信に記事を入れない | 学生が会社を調べても、記事にたどり着かない | 返信の型に固定する |
| 文面で会社を全部説明する | 文面が長く、記事が読まれない | 会社紹介は短く、中身は記事に |
| 送る時期にWantedlyが止まる | 読みに来た学生が古い会社ページを見る | 送る時期の前に記事を出す |
| 「読んだか」を台帳に残さない | 記事が辞退を減らしているかが分からない | 列を一つ足す |

最も多いのは、一つ目です。Wantedlyを契約していても、OfferBoxの運用とつながっておらず、承認した学生の行き先になっていません。

| 作業 | 誰が |
|---|---|
| 送る社員を決め、その社員のストーリーを出す | 人事と、送る社員 |
| 承認後の返信の型に記事の場所を入れる | 人事 |
| 検索・文面下書き・送信・一次返信 | 人事、または代行 |
| 文面と記事の「最初の年」を揃えて見る | 人事（一人） |
| 面談で「読んだか、どこが気になったか」を聞く | 面談に出る人 |
| 内定者にストーリーを頼む | 人事 |
| 「記事を読んだか」の列を台帳に足し、辞退の差を見る | 人事 |
| 時間の配分と、外に出す範囲 | 責任者 |

運用代行や代理店が支えられるのは、役割の整理、返信の型、文面と記事の分担の型、台帳の型、OfferBoxの検索・文面下書き・送信・一次返信、Wantedlyの記事を整える部分までで、送る社員の選定、話す中身、面談、内定者への依頼、配分の判断は企業が行います。代理店の代行の範囲は[代理店に運用まで頼めるか](/media/kh-dairiten-unyou/)で書きました。

### エージェントベストの見解

両方を契約したあと、最初の年で、承認後の辞退が減る会社と減らない会社の違いは、承認への返信の型に、送った社員の記事が入っているかです。当社はOfferBoxの運用代行を受けているので、承認への返信を当社が行う会社も多くありますが、返信の型に記事の場所が入っている会社では、面談の冒頭で「記事の〇〇を読みました」と学生が言い、面談が文面と記事の続きから始まります。入っていない会社では、面談の冒頭が会社の説明になり、学生は「文面で読んだこと」しか知らずに来ています。文面も記事も同じ社員の名義なら、学生は三度同じ人に会うことになり、面談の前に離れる理由が減ります。当社が代行で返信の型を作るときは、送る社員のストーリーがあるかを先に確かめ、なければ、送る前に一本出してもらってから、型に入れています。

## まとめ

- OfferBoxは「選んで送り、承認をもらう入口」、Wantedlyは「承認した学生が面談の前に会社を読む場所」。承認から面談までの間を埋める道具
- 承認への当日の返信と面談前の連絡の型に、送った社員のストーリーと会社ページの場所を固定で入れる。面談の冒頭で「読んだか」を聞く
- 文面の会社紹介は短くして記事に逃がす。送る社員の名義とストーリーの書き手を同じ人にし、「最初の年」をずらさない
- 内定者にストーリーを書いてもらい、翌年の返信の型と文面の元にする
- OfferBoxの出せる時間は外に、Wantedlyの話す時間は自社に。送る時期の前に記事を出し、台帳に「記事を読んだか」の列を足す

## よくある質問

### Wantedlyは中途採用で使っています。新卒のOfferBoxとつなげてよいですか

つなげてよいです。会社ページの「なぜ」は新卒にも中途にも同じで、送る社員のストーリーを一本足せば、承認した学生の行き先になります。新卒と中途の募集記事は分けます。分け方は[Wantedlyで新卒と中途を同時に採るときの整理](/media/wt-shinsotsu-chuuto/)で書きました。

### オファーの文面に、Wantedlyの記事を貼ってよいですか

文面と承認後のメッセージで、記事の場所をどう伝えられるかは、OfferBoxの現在の仕様で確認してください。どちらで伝えるにしても、承認後の返信のほうが、学生が読む確率は高いです。文面では「詳しくは私が書いた記事に」と触れ、承認後の返信で「会社名と私の名前で検索すると出てきます」と伝える形が、仕様に左右されにくい形です。

### OfferBoxとWantedlyの併用は、御社に相談できますか

できます。当社は、役割の整理、返信の型、文面と記事の分担の型、台帳の型、OfferBoxの検索・文面下書き・送信・一次返信、Wantedlyの記事を整える部分を支えられます。送る社員の選定、話す中身、面談、内定者への依頼、配分の判断は、企業が行ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、両方の運用を一つの窓口で支えています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
