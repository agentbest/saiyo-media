Wantedlyを使っていると、同じウォンテッドリー株式会社が提供する採用管理の仕組み（Wantedly Hire）の案内を目にすることがあります。「Wantedlyと何が違うのか」「入れたほうがいいのか」「入れると管理が楽になるのか」と聞かれます。**結論から言うと、Wantedlyは「候補者が来る場」、採用管理の仕組みは「候補者の段と担当と次の連絡日を持つ場」で、役割が違います。同じ会社の提供なので候補者の受け渡しは想定しやすい一方、段の定義と担当は仕組みが決めてくれるものではなく、自社で決めてから入れるものです。** この記事では、募集の場と管理の場の役割、同じ会社の提供であることの意味、入口が一つの会社と複数の会社での位置づけ、導入の前に決めること、確認する項目、やりがちな失敗、社内の分担を整理します。機能の範囲・提供の条件・料金は変わることがあるので、公式ページで現在の内容を確認してください。この記事では仕様と数値を書きません。Wantedlyの応募とスカウトの管理の基本は[Wantedlyの応募・スカウトの管理の仕方](/media/wt-scout-oubo-kanri/)で書きました。

## それぞれの役割｜「来る場」と「持つ場」

Wantedlyは、会社ページとストーリーと募集記事を出し、読んだ候補者が「話を聞きに行きたい」と来る場です。スカウトを送り、返信が来るのもここです。メッセージのやり取りと、相手のプロフィールは、Wantedlyの管理画面にあります。

採用管理の仕組みは、来た候補者が「いまどの段にいるか」「誰が担当か」「次にいつ連絡するか」を持つ場です。Wantedlyから来た人も、他の媒体から来た人も、紹介で来た人も、同じ段の定義で並びます。

| | Wantedly | 採用管理の仕組み |
|---|---|---|
| 役割 | 候補者が来る。メッセージを交わす | 候補者の状態を持つ。放置を防ぐ |
| 持つもの | 会社ページ・記事・スカウト・メッセージ・プロフィール | 段・担当・次の連絡日・メモ・結果 |
| 入口 | Wantedlyだけ | 複数の入口をまとめる |
| 決めるのは誰か | 記事の中身は自社 | 段の定義と担当は自社。仕組みは写す場所 |

Wantedlyは募集情報等提供事業者として運営される場で、候補者を紹介する仕組みではありません。採用管理の仕組みも、候補者を連れてくるものではなく、来た候補者を整理する場所です。「入れると候補者が増える」という期待は、役割の取り違えです。

## 同じ会社の提供であることの意味

- **候補者の受け渡しが想定されている**：Wantedlyから来た候補者を、管理の場に入れる手間が小さいことが期待できる。どこまで自動かは、現在の仕様を確認する
- **契約やプランの関係を確認する**：Wantedlyのプランと、採用管理の仕組みの提供条件が、どう結びついているかは変わることがある。公式ページで確認
- **同じ会社だから、段の定義も揃うわけではない**：段の名前や進め方は、自社の選考に合わせて決める。仕組み側の初期の形をそのまま使うと、自社の選考と合わない
- **Wantedly以外の入口をどう入れられるかは、別に確認する**：他の媒体、紹介、リファラルの候補者を、同じ場で持てるか。持てる形なら、複数の入口を一つの台帳にまとめる目的で使える
- **やめたときにデータをどう持ち出せるかを、入れる前に確認する**：台帳は、仕組みをやめても残る形で持つ

同じ会社の提供であることは、受け渡しの手間の面では利点になり得ますが、段の定義と担当を決める作業は減りません。

### エージェントベストの見解

相談で最も多い思い込みは、「採用管理の仕組みを入れれば、候補者の放置がなくなる」というものです。当社は3媒体すべての販売パートナーとして、Wantedlyの運用を申込のあとまで見ていますが、放置が起きる原因は、仕組みがないことではなく、「この候補者は、いまどの段で、誰が、いつまでに動くか」が決まっていないことです。決まっていない状態で仕組みを入れると、仕組みの中で放置されます。入れる前に、段を五つか六つで定義し、段ごとに担当を一人にし、「次の連絡日」を空欄にしないルールを決めます。ここまでが紙や表計算でできていれば、仕組みに写すだけで済み、できていなければ、仕組みを入れても同じ放置が起きます。当社が管理の仕組みの相談を受けたとき、最初に見せてもらうのは、仕組みの画面ではなく、いまの台帳です。

## 入口がWantedlyだけの会社と、複数の会社

| 会社の状態 | 位置づけ |
|---|---|
| 入口がWantedlyだけで、候補者の数が少ない | 管理画面と、自社の台帳（表計算）で足りることが多い。段・担当・次の連絡日を台帳で持つ |
| 入口がWantedlyだけで、候補者が増えて台帳が追いつかない | 管理の仕組みを検討する。Wantedlyからの受け渡しの手間が小さいことが利点になる |
| 入口が複数（OfferBox・ワンキャリア・ナビ・紹介など） | 複数の入口を一つの場で持てるかが判断の軸。持てるなら検討、持てないなら別の仕組みか台帳 |
| すでに別の採用管理システムがある | 二つの管理の場を持たない。既存の仕組みにWantedlyの候補者を入れる形を先に検討する。[Wantedlyと採用管理システムの連携の考え方](/media/wt-heiyou-ats/) |

判断の軸は、「候補者の数が台帳で持てるか」と「入口が複数か」の二つです。Wantedlyだけで、数が少ないうちは、仕組みより先に台帳の型を作ります。

## 導入の前に決めること

1. **段の定義**：新規・返信待ち・面談調整中・面談済み・選考中・内定・終了、のような五つから七つ。自社の選考に合わせる
2. **段ごとの担当**：一つの段に一人。「人事」ではなく名前で
3. **「次の連絡日」のルール**：空欄にしない。過ぎたら誰が気づくか
4. **メモに書く範囲**：採用の目的の範囲で。書かないことを決める
5. **月に一度、誰が見るか**：段ごとの数と、止まっている候補者を、誰が指すか

この五つは、[Wantedlyの応募・スカウトの管理の仕方](/media/wt-scout-oubo-kanri/)で書いた台帳の項目と同じです。仕組みは、この台帳を写す場所です。

## 確認する項目

| 項目 | 確認すること |
|---|---|
| 取り込める入口 | Wantedly以外の媒体・紹介・リファラルの候補者を、同じ場で持てるか |
| 段の自由度 | 段の名前と数を、自社の選考に合わせて変えられるか |
| 担当と次の連絡日 | 候補者ごとに担当と期日を持て、過ぎたときに気づける形か |
| メッセージの扱い | Wantedlyのメッセージは管理画面で、状態は仕組みで、と分けたときに二重にならないか |
| 個人情報 | 誰が見られるか、選考が終わった候補者の情報をいつ消すか |
| 契約とプラン | Wantedlyのプランとの関係、提供の条件。公式ページで現在の内容を確認 |
| やめたとき | 台帳を持ち出せる形か。持ち出せないなら、台帳を別に持つ |

確認できない項目があれば、その部分は台帳で持ちます。仕組みの機能に合わせて自社の選考を変えるのではなく、自社の選考に合う範囲で仕組みを使います。

## やりがちな失敗

| 失敗 | 何が起きるか | 直し方 |
|---|---|---|
| 「入れれば候補者が増える」と期待する | 来る場と持つ場を取り違え、記事の側が止まる | 役割を分けて考える |
| 段の定義を決めずに入れる | 仕組みの初期の段のまま、自社の選考と合わず放置が起きる | 段・担当・次の連絡日を先に決める |
| 既存の管理システムと二つ持つ | どちらが正か分からず、更新が止まる | 一つに決める |
| Wantedlyのメッセージを、仕組みにも写す | 二重管理になり、片方が古くなる | メッセージは管理画面、状態は仕組み |
| やめたときのデータを確認していない | 台帳が持ち出せず、履歴が消える | 入れる前に確認。持ち出せないなら台帳を別に |

最も多いのは、二つ目です。仕組みを入れたことで管理ができた気になり、段の定義を決めないまま運用が始まります。

## 社内の分担

| 作業 | 誰が |
|---|---|
| 段の定義・担当・次の連絡日のルールを決める | 人事と面接官 |
| 公式ページで機能・条件を確認し、確認項目を埋める | 人事 |
| 既存の管理システムの有無を確認し、一つに決める | 人事と責任者 |
| 台帳から仕組みへ写す | 人事 |
| 月に一度、段ごとの数と止まっている候補者を見る | 人事と責任者 |
| 入れるかどうか、やめるかどうかの判断 | 責任者 |

運用代行や代理店が支えられるのは、役割の整理、台帳の型、段の定義の型、確認項目の一覧までで、段と担当の決定、仕組みの契約、候補者との連絡、入れるかの判断は企業が行います。代理店の代行の範囲は[代理店に運用まで頼めるか](/media/kh-dairiten-unyou/)で書きました。

### エージェントベストの見解

これは切り分けの話です。自社で持つべきなのは、段の定義、段ごとの担当、「次の連絡日」を空欄にしないルール、月に一度止まっている候補者を指すこと、までです。ここから先の、台帳の型、仕組みに写すときの段の置き方、確認項目の一覧は、外に出せます。逆に、段の定義と担当まで外に出すと、外の人が決めた段で自社の選考が回ることになり、面接官が「この段は何を意味するのか」と迷って更新が止まります。当社はWantedlyの運用を支えるとき、管理の仕組みを入れるかどうかの前に、いまの台帳に段と担当と次の連絡日があるかを見ます。あれば、仕組みは写す場所なので、入れても入れなくても回ります。なければ、仕組みの話を止めて、台帳から始めてもらいます。

## まとめ

- Wantedlyは「候補者が来る場」、採用管理の仕組みは「段と担当と次の連絡日を持つ場」。入れても候補者は増えない
- 同じ会社の提供なので受け渡しの手間は小さいことが期待できるが、段の定義と担当を決める作業は減らない。仕様・条件は公式ページで確認
- 入口がWantedlyだけで数が少ないうちは、台帳で足りる。数が増えるか、入口が複数になったら検討する
- 入れる前に、段・担当・次の連絡日・メモの範囲・月に一度見る人、の五つを決める
- 既存の管理システムがあるなら、二つ持たない。やめたときにデータを持ち出せるかを、入れる前に確認する

## よくある質問

### Wantedlyを使うなら、Wantedly Hireも入れるべきですか

役割が違うので、「使うなら入れる」ではありません。入口がWantedlyだけで候補者の数が台帳で持てるうちは、管理画面と台帳で足ります。数が増えて台帳が追いつかない、入口が複数になった、というときに検討します。提供の条件と機能の範囲は、公式ページで現在の内容を確認してください。

### 段の定義は、仕組みの初期の形をそのまま使ってはいけませんか

自社の選考と合っていれば、使えます。合っているかは、面接官が「この段は何をする段か」を迷わず言えるかで見ます。言えない段があれば、名前を変えるか、減らします。段は五つから七つで足ります。

### 採用管理の仕組みを入れるかどうかは、御社に相談できますか

できます。当社は、役割の整理、台帳の型、段の定義の型、確認項目の一覧を支えられます。段と担当の決定、仕組みの契約、候補者との連絡、入れるかの判断は、企業が行ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、Wantedlyの運用を支えています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
