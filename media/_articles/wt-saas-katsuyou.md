業務ソフトを月額で提供する会社、業種特化のSaaS、水平型のSaaS、大手のSaaS事業部、SaaSのスタートアップが、Wantedlyで採用する。SaaSは、Wantedlyに最も多く並ぶ区分の一つで、候補者はSaaSの会社ページを何社も並べて読んでいる。並ぶ中で、多くの会社ページが「急成長」「シリーズ〇〇の資金調達」「事業を作る」「顧客の課題を解決」で書かれ、どのSaaSも同じ言葉で、区別されない。加えて、SaaSの採用は、最初の役割がインサイドセールス（IS）・フィールドセールス（FS）・カスタマーサクセス（CS）に分業されていて、「事業を作る」で押した候補者は、面談でISの架電の一日、CSの契約更新と解約の対応、FSの数字を聞いて離れる。**結論から言うと、SaaSのWantedlyは、並ぶSaaSと同じ言葉を使わず、「なにを」を顧客の業種と課題で書き、分業の中で「この役割で何を決められて、何は決められないか」を役割ごとに書きます。「事業を作る」ではなく、ISの一日（架電、商談の設定、数字）、CSの一日（オンボーディング、更新、解約の対応）、FSの一日（商談、数字）を隠さず、役割の間の移り方を実例で書きます。「話を聞きに行きたい」の数は、並ぶSaaSの中で多くて当たり前で、成果と見ず、面談で役割の実態を伝えた後に残った数で運用を見ます。** この記事では、SaaSの採用構造とWantedlyとの相性、同じ言葉を使わない見せ方、分業と役割の書き方、数の読み方、ストーリーとカジュアル面談とスカウトの運用設計、社内の分担を整理します。IT・Web全体の設計は[IT・Web業界の会社がWantedlyで採用するときの設計](/media/wt-it-katsuyou/)、スタートアップの設計は[スタートアップの会社がWantedlyで採用するときの設計](/media/wt-startup-katsuyou/)、媒体の選び方は[SaaS業界の採用媒体の選び方](/media/hikaku-saas-erabikata/)で書きました。数値と料金は書きません。

## SaaSの採用構造と、Wantedlyとの相性

| 区分 | 採用の形 | Wantedlyとの相性 |
|---|---|---|
| 業種特化のSaaS | 顧客の業種が決まっている。IS・FS・CSとエンジニア | 向く。顧客の業種と課題で並ぶSaaSと区別される |
| 水平型のSaaS | 業種を問わない。分業が細かい | 向く。「どの業務の、何を変えるか」で。分業の役割ごとに |
| SaaSのスタートアップ | 少人数。資金の段階で変わる | 向く。段階と決まっていないことを素顔として |

| 業界の特徴 | Wantedlyで起きること | 設計 |
|---|---|---|
| SaaSが最も多く並ぶ | 「急成長」「事業を作る」で区別されない | 顧客の業種と課題と役割で |
| 最初の役割が分業されている | 「事業を作る」で来て架電と更新で離れる | 役割ごとの一日を先に |
| 押される数が多い | 数を成果と見て、面談で離れる | 残った数で見る |
| 他のSaaSからの転職者が多い | 同じ言葉では動かない | 役割で何が違うかを |

## 同じ言葉を使わない｜顧客の業種と課題と、役割で何を決められるかで

- **「急成長」「シリーズ〇〇」「事業を作る」「顧客の課題を解決」を、一度だけ**：「なぜ」に事実として。並ぶSaaSが全部使っている言葉で、区別されない
- **「なにを」は、顧客の業種と、どの業務の何を変えるかで一言**：「〇〇業界の△△の業務の、□□を変えるソフトを、〇〇の顧客に提供している会社」。「業務を効率化するSaaS」で済ませない
- **分業の役割ごとに、募集を分ける**：IS、FS、CS、PdM、エンジニア、マーケ。「ビジネス職」でまとめない
- **役割ごとに、何を決められて何は決められないかを書く**：「ISは〇〇の架電先の優先順位を決める。商談の内容は△△が決める。CSは□□の対応を決めて、〇〇は決められない」。[Wantedlyの募集記事「こんなことやります」の書き方](/media/wt-boshu-konna/)
- **役割の間の移り方を、実例で**：「ISからFSに移った人は〇〇の条件で、△△の期間。CSからPdMに移った人は□□」。「キャリアパスあり」の一語で済ませない
- **「こんな人」は、「数字を持って改善した・断られた後も続けた・顧客の業務を理解して提案した・解約の理由を聞いて直した」の記述で**：「事業を作りたい」「成長したい」で絞らない

### エージェントベストの見解

これは発注側の誤解の話です。SaaSの会社から、「Wantedlyでは急成長と資金調達の段階を前面に出せば、事業を作りたい人が来る」と相談されることがあります。当社は3媒体すべての販売パートナーとして、Wantedlyの運用を見ていますが、「急成長」「シリーズ〇〇」「事業を作る」は、並ぶSaaSのほとんどが使っている言葉で、候補者はそれを何社分も読んでいて、区別しません。他のSaaSから転職する候補者は役割の実態を知っていて、「この会社のこの役割で、前の会社と何が違うか」で押します。当社がお願いしているのは、並ぶSaaSと同じ言葉を一度だけにし、「なにを」を顧客の業種と課題で書き、役割ごとに「何を決められて、何は決められないか」と役割の間の移り方の実例を書くことです。書くと、「事業を作りたい」候補者ではなく、「この業種の、この役割で、これを決めたい」候補者が押します。

## 分業の一日を隠さず｜IS・CS・FSの実態を先に

- **ISの一日を、先週の一日で**：「〇〇件の架電と、△△件の商談の設定。数字は□□」。「事業の入口を担う」で済ませない
- **CSの一日を、先週の一日で**：「〇〇社のオンボーディング、△△社の更新の対応、□□社の解約の理由の聞き取り」。「顧客の成功を支える」で済ませない
- **数字の責任を、誰が持つかを書く**：「ISの数字は担当が持つ。CSの更新率は△△で持つ」
- **役割の間の移り方の条件と期間を、隠さず**：移れない場合は「決まっていない」と書く
- **待遇と、数字と収入の関係を、隠さず**：[Wantedlyの募集記事で待遇をどう扱うか](/media/wt-boshu-kyuuyo/)
- **スタートアップは、段階と決まっていないことを素顔として**：「〇〇の段階で、△△は決まっていて、□□は決まっていない」。[Wantedlyで会社の素顔を出す範囲](/media/wt-kaisha-no-sugao/)

会社ページの書き方は[Wantedlyの会社ページで最初に書くこと](/media/wt-kaisha-page-kihon/)で書きました。

## 数の読み方｜並ぶSaaSの中で多くて当たり前

- **「話を聞きに行きたい」の数は、SaaSが並ぶ場の量を映している**：多いことを成果と見ない
- **役割ごとに、「押した数」「面談に来た数」「面談で役割の一日を伝えた後に残った数」を分けて見る**：ISの募集で押した数が多く残った数が少ないなら、記事が「事業を作る」で書かれている
- **実態を先に書くと、押した数は減り、残った数が増える**：減った数を「悪くなった」と読まない
- **他のSaaSからの転職者が押した数を、別に見る**：役割の実態を知っている候補者が押しているなら、記事が役割で書けている

## ストーリーとカジュアル面談の設計

- **ISの人のストーリーで、「架電が取れなかった週」「商談が決まった日」を本人の言葉で**：[Wantedlyのストーリーで事業の中身を書く方法](/media/wt-story-jigyo/)
- **役割を移った人のストーリーで、「どう移ったか」と「移る前と後で何が違ったか」を本人の言葉で**：[Wantedlyの入社後ストーリーの書き方](/media/wt-story-nyusha/)
- **カジュアル面談で、役割の一日と数字と移り方を、聞かれる前に伝える**：「事業を作る」の話で面談を終えない。[Wantedlyのカジュアル面談の設計](/media/wt-scout-casual-mendan/)
- **面談に、その役割の責任者が出る**：役割の実態は、人事だけでは伝えられない

## スカウトの設計

- **絞るのは、「数字を持って改善した・断られた後も続けた・顧客の業務を理解して提案した・解約の理由を聞いて直した」の記述**：「SaaS」「事業を作りたい」の言葉で絞らない。[Wantedlyのスカウトで対象を絞る方法](/media/wt-scout-target/)
- **文面は、顧客の業種と課題と、役割で決められることを最初に**：「〇〇業界の△△を変えるソフトで、ISとして□□を決められる役割で、あなたの〇〇を読んで」。「急成長」で始めない。[Wantedlyのスカウト文面の書き方](/media/wt-scout-bunmen/)

## 社内の分担

| 作業 | 誰が |
|---|---|
| 並ぶSaaSと同じ言葉を一度にし、顧客の業種と課題で「なにを」を書く | 責任者と人事 |
| 役割ごとに、決められることと一日と数字を書き出す | IS・FS・CSの責任者 |
| 役割の間の移り方を、実例で書けるか確かめる | 人事 |
| ISとCSの人が「取れなかった週」「更新が決まった日」を話す | IS・CS |
| 「話を聞きに行きたい」を役割ごとに、残った数で読む | 人事 |
| カジュアル面談に役割の責任者が出て、一日と数字を先に伝える | 責任者と人事 |
| スカウトを業種と課題と役割で決められることを最初に、役割ごとの文面で送る | 人事（絞る作業は外に出せる） |

運用代行や代理店が支えられるのは、同じ言葉を外す型、募集を分ける型、募集記事の型、聞き方の型、数の見方の型、面談の型、スカウトの絞る作業までで、役割の一日と数字の開示、移り方の実例、責任者が話すこと、ISとCSが話すこと、面談、残った数の判断は会社が行います。代理店の代行の範囲は[代理店に運用まで頼めるか](/media/kh-dairiten-unyou/)で書きました。

### エージェントベストの見解

これは数字の読み方の話です。SaaSの会社が、Wantedlyの「話を聞きに行きたい」が多いことを成果と見て、面談を重ねても採れず、「候補者の質が下がった」と判断する形を、当社は見ています。SaaSはWantedlyに最も多く並ぶ区分の一つで、「話を聞きに行きたい」の数は、その場の量を映していて、記事の良し悪しを映していません。見るべきは、役割ごとに「押した数」「面談に来た数」「面談で役割の一日と数字を伝えた後に残った数」を分けたときの、残った数です。ISの募集で押した数が多く残った数が少ないなら、記事が「事業を作る」で書かれています。当社がお願いしているのは、押した数が減ることを「記事が悪くなった」と読まず、残った数と、他のSaaSからの転職者が押した数で運用を見ることです。役割の実態を知っている候補者が押しているなら、記事が役割で書けています。

## まとめ

- SaaSはWantedlyに最も多く並ぶ区分の一つで、「急成長」「シリーズ〇〇」「事業を作る」はどのSaaSも使っていて区別されない。一度だけにし、「なにを」を顧客の業種と、どの業務の何を変えるかで書く
- 最初の役割はIS・FS・CSに分業されている。役割ごとに募集を分け、「何を決められて、何は決められないか」と一日（架電、更新、解約の対応、数字）を隠さず、役割の間の移り方を実例で。移れないなら「決まっていない」と書く
- 他のSaaSからの転職者は役割の実態を知っていて、「事業を作る」では動かない。「この役割で、前の会社と何が違うか」を書く
- 「話を聞きに行きたい」の数は場の量。役割ごとに実態を伝えた後に残った数と、他のSaaSからの転職者が押した数で読む
- ISの人が「架電が取れなかった週」を、役割を移った人が「移り方」を本人の言葉で。面談に役割の責任者が出て、一日と数字を先に伝える

## よくある質問

### 「急成長」「資金調達」を書かないと、他のSaaSに負けませんか

並ぶSaaSのほとんどがその言葉で書いていて、書いても区別されません。「なぜ」に一度、事実として書いてください。区別されるのは、顧客の業種と課題、役割ごとに何を決められるか、役割の間の移り方の実例です。他のSaaSから転職する候補者は、その三つで押します。

### ISの一日を書くと、来なくなりませんか

書かずに「事業の入口を担う」で来た人は、架電の一日で離れます。「〇〇件の架電と△△件の商談の設定。数字は□□。ISからFSに移った人は〇〇の条件で△△の期間」と、一日と数字と移り方を先に書いてください。押した数は減りますが、架電を知った上で来る候補者が残ります。

### SaaSのWantedlyの設計は、御社に相談できますか

できます。当社は、同じ言葉を外す型、募集を分ける型、募集記事の型、聞き方の型、数の見方の型、面談の型、スカウトの絞る作業を支えられます。役割の一日と数字の開示、移り方の実例、責任者が話すこと、ISとCSが話すこと、面談、残った数の判断は、会社が行ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、Wantedlyの運用を支えています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
