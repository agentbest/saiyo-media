Wantedlyでプロジェクトマネージャーの募集記事を出したとき、最初にぶつかるのは「『案件を推進』『顧客とエンジニアの橋渡し』と書いたのに、話を聞きに来る人が少ない。来ても、面談で『何本持つのですか』『遅れたとき誰が決めるのですか』『常駐はありますか』を聞かれて答えられない」という問題です。**結論から言うと、プロジェクトマネージャーの募集記事は、「推進」「橋渡し」ではなく「どんな案件を何本、誰と、人と予算と期限をどこまでの権限で進め、遅れたとき誰がどう動くか」を書き、募集記事を書く前に社内で案件の種類と遅れたときの決め方を決めておきます。** この記事では、プロジェクトマネージャーが募集記事で見ているもの、書く前に決めること、「なにを・なぜ・どうやって」の書き方、「こんな人」の書き方、スカウトと面談への接続、社内の分担、やりがちな失敗を整理します。募集記事の基本構成は[Wantedlyの募集記事の基本構成](/media/wt-boshu-kihon/)、プロダクトマネージャーとの違いは[プロダクトマネージャーを採る募集記事の書き方](/media/wt-pdm-boshu/)で書きました。

## プロジェクトマネージャーが募集記事で見ているもの

| 見ているもの | 何を確かめているか |
|---|---|
| どんな案件を、何本持つか | 社内の開発か、顧客の案件か。一本を深くか、複数を並行か。期間の長さ |
| 誰と進めるか | 社内のエンジニアか、外部の会社か、顧客の担当者か。チームの人数と、自分で選べるか |
| 人と予算と期限を、誰が決めるか | 人を増やせるか、予算を動かせるか、期限を交渉できるか。どこまで任されるか |
| 遅れたとき、どうなるか | 遅れが見えたとき誰に上げ、誰が決めるか。一人で抱える形か、会社で受け止める形か |
| 常駐の有無 | 顧客の案件なら、常駐があるか。期間と、自社に戻る頻度 |
| 一人目か | 一人目なら、いま誰が案件を見ていて、何が回っていないか |
| 前の案件がどうなったか | 前の案件で、遅れや揉め事があったか。隠さず書いてあるか |

「遅れたとき、どうなるか」と「人と予算と期限を誰が決めるか」が、プロジェクトマネージャーに特有の点です。「推進」の一語では、ここが分かりません。

## 書く前に決めること｜案件の種類と、遅れたときの決め方

| 決めること | 選択肢 |
|---|---|
| 案件の種類 | 社内の開発／顧客の案件（受託）／両方。最初に持つ案件を一つ |
| 何本を並行か | 一本／複数。複数なら、目安の本数を書けるか |
| 人と予算と期限の権限 | 人を増やす判断／予算の増減／期限の交渉。どこまで任せて、どこから上に上げるか |
| 遅れたときの決め方 | 誰に上げ、誰が決めるか。顧客への説明は誰がするか |
| 常駐の有無 | 無い／ある。あるなら期間と、自社に戻る頻度 |
| 一人目か | 一人目なら、いま誰が見ていて、何が回っていないか |
| 最初の月に任せること | 一つの案件の引き継ぎか、遅れている案件の立て直しか。誰と組むか |

「複数を並行」「常駐がある」「遅れたら経営者が決める」でも構いません。隠さずに書けば、それを前提に読む人が来ます。「案件を推進」とだけ書き、面談で「実は常駐が」「実は遅れている案件を引き継いでほしい」と出るのが、最も離れる形です。

## 「なにを」｜どんな案件を、誰と

「なにをやっているのか」は、会社の事業ではなく、このプロジェクトマネージャーが持つ案件に絞ります。

- **最初に持つ案件を、一つ書く**：「〇〇（顧客の業種）の△△を作る案件。期間は□□の段階」。顧客が特定されない形で
- **誰と進めるかを書く**：「社内のエンジニア〇人と、顧客の担当者」「外部の会社に一部を出していて、その管理も含む」
- **いまの状態を書く**：順調か、遅れているか、これから始まるか。「遅れている案件の立て直しから」なら、そう書く
- **顧客の案件なら、常駐の有無と期間を書く**：「常駐は無い」「〇〇の期間だけ顧客先で、それ以外は自社」

「なにを」の書き方の基本は[「なにをやっているのか」の書き方](/media/wt-boshu-nani-wo/)で書きました。

### エージェントベストの見解

プロジェクトマネージャーの募集記事を出す前に、先に決めておかないと効果が出ないのは、「遅れたとき、誰に上げて、誰が決めるか」です。当社がWantedlyのプロジェクトマネージャーの募集を支えるとき、案件の内容と「推進力のある方」は書かれているのに、遅れたときの決め方が書かれていない募集記事が多くあります。プロジェクトマネージャーが面談で最初に聞くのは、案件の内容ではなく、「遅れが見えたとき、どうなりますか」「顧客への説明は誰がしますか」です。ここに答えがないと、「遅れたら一人で抱えて、顧客にも一人で謝る仕事」を想像して離れます。遅れは起きます。「遅れが見えたら〇〇に上げ、人を足すか期限を交渉するかは△△が決める。顧客への説明は□□が一緒に行く」と書けば、「会社で受け止める形」として読まれます。当社が最初にお願いするのは、案件の説明ではなく、「遅れたとき誰がどう動くか」の一文です。

## 「どうやって」｜進め方と、権限の書き方

| 書くこと | 書き方 |
|---|---|
| 案件の進め方 | 計画をどう立て、進み具合をどう見て、誰に報告するか。道具の名前より、流れで |
| 人と予算と期限の権限 | 「人を足す判断は〇〇まで自分で。予算は△△に相談。期限の交渉は□□と一緒に」 |
| 遅れたときの動き方 | 誰に上げ、誰が決め、顧客に誰が説明するか |
| エンジニアとの関係 | 見積もりを一緒に作るか、受け取るか。技術の判断は誰がするか |
| 顧客との関係 | 窓口は自分か、営業か。要件の変更をどう受けるか |
| 前の案件の例 | 「前に〇〇で遅れて、△△の形で立て直した」。無ければ書かない |

「裁量が大きい」と書くより、「人を足す判断は自分で、予算は相談」と書くほうが、権限の範囲が伝わります。書き方の基本は[「どうやっているのか」の書き方](/media/wt-boshu-dou/)で書きました。

## 「こんな人」｜経歴ではなく、行動で書く

| 経歴で書く（避ける） | 行動で書く |
|---|---|
| PM経験3年以上 | 遅れが見えた案件を、早めに上げて、立て直したことがある |
| 推進力のある方 | 決まっていないことを、決める人に聞いて、決めてもらったことがある |
| 調整力 | 顧客とエンジニアの言い分が違う状態から、両方が納得する形を作ったことがある |
| 責任感 | 自分の見積もりが外れたとき、隠さずに報告して直したことがある |
| コミュニケーション能力 | 悪い知らせを、早く、正確に伝えたことがある |
| 即戦力 | 最初の月は〇〇の案件の引き継ぎを任せる予定です。△△と組みます |

「悪い知らせを早く伝えた」が、プロジェクトマネージャーで最も読まれる行動です。「最初の月に何を任せ、誰と組むか」を書くと、経験年数の条件がいらなくなります。書き方の基本は[「こんなことやります」の書き方](/media/wt-boshu-konna/)で書きました。

## スカウトと面談への接続

- **スカウトの文面は、募集記事の「どんな案件を、誰と、どこまでの権限で」と同じ言葉で**：相手が立て直した案件や、早く上げた経験を読み、自社の案件と重ねる。[スカウト文面の書き方](/media/wt-scout-bunmen/)
- **面談には、いま案件を見ている人と、遅れたとき決める人が出る**：「遅れたときどうなるか」を、決める本人が話す。人事だけの面談は、ここに答えられない
- **面談で話すのは、案件の話**：最初に持つ案件の状態を隠さず話す、遅れている案件があるならその状況を話す、相手ならどう立て直すかを聞く
- **前の案件で起きたことを話す**：「前に〇〇で遅れて、△△の形で立て直した」。良かったことだけにしない

つなげ方は[スカウトと募集記事のつなげ方](/media/wt-scout-boshu-renkei/)で書きました。

## 社内の分担

| 作業 | 誰が |
|---|---|
| 案件の種類、権限の範囲、遅れたときの決め方を決める | 経営者か事業の責任者 |
| 「なにを」（最初に持つ案件、誰と、いまの状態）の下書き | 人事が、いま案件を見ている人に聞いて書く |
| 「どうやって」（進め方、権限、遅れたときの動き方） | いま案件を見ている人が話し、人事が書き、本人が確認 |
| 常駐の有無と期間、前の案件の例 | 事業の責任者 |
| 「こんな人」を行動で書く、最初の月の予定 | 事業の責任者と人事 |
| 面談 | いま案件を見ている人と、遅れたとき決める人 |

一人目のプロジェクトマネージャーを採る募集では、いま経営者か営業かエンジニアの責任者が兼務で案件を見ていることが多くあります。その場合は、「いまは〇〇が兼務で見ていて、△△が回っていない。最初の月は□□の案件から引き継ぐ」と正直に書きます。

運用代行や代理店が支えられるのは、募集記事の型、権限と遅れたときの動き方を文で書く直し方、「こんな人」を行動に直す作業、スカウト文面との整合の確認までで、権限の決定、案件の実態、面談は社内が担います。代理店の代行の範囲は[代理店に運用まで頼めるか](/media/kh-dairiten-unyou/)で書きました。

### エージェントベストの見解

相談で最も多い思い込みは、「プロジェクトマネージャーには、案件が順調で体制が整っていることを見せないと来ない」というものです。当社は3媒体すべての販売パートナーとして、Wantedlyのプロジェクトマネージャーの募集と面談を見ていますが、「順調に成長中」と書いた募集記事より、「〇〇の案件が遅れていて、立て直しから任せたい。遅れたら△△が決め、顧客には□□が一緒に行く」と書いた募集記事のほうが、話を聞きに来る人の経験が合う傾向があります。プロジェクトマネージャーは、順調な案件だけを持ってきた人のほうが少なく、遅れた案件を立て直した経験が自分の仕事の中心だと思っている人が多くいます。「遅れている」を隠さず、「会社で受け止める形」を一緒に書くと、「自分の経験が活きる会社」として読まれます。逆に、順調とだけ書いて入社後に遅れた案件を渡すと、「聞いていない」で離れます。当社が案内するのは、案件の状態を隠さず書き、そのすぐ後に「遅れたとき誰がどう動くか」を書くことです。順調さで人は来ません。受け止める形があることで来ます。

## やりがちな失敗

| 失敗 | 何が起きるか | 直し方 |
|---|---|---|
| 「推進」「橋渡し」「調整」で書く | どの募集記事にもあり、読まれない | 何を、誰と、どこまでの権限で、を文で |
| 遅れたときの決め方を書かない | 「一人で抱える仕事」を想像される | 誰に上げ、誰が決め、顧客に誰が行くかを書く |
| 常駐の有無を書かない | 面談で「聞いていない」で離れる | 有無と期間、自社に戻る頻度を書く |
| 遅れている案件を隠して「順調」と書く | 入社後に分かり、離れる | 状態を書き、立て直しから任せると書く |
| 何本並行かを書かない | 「際限なく持たされる」を想像される | 目安を書く。書けないなら「一本から」 |
| 面談に、遅れたとき決める人が出ない | 「遅れたらどうなるか」に答えられない | 決める本人が出る |

最も多いのは、最初の「推進・橋渡し・調整」です。権限と、遅れたときの動き方が分からない言葉は、読まれません。

## まとめ

- プロジェクトマネージャーが見ているのは、どんな案件を何本か・誰と進めるか・人と予算と期限を誰が決めるか・遅れたときどうなるか・常駐の有無・一人目か
- 書く前に、案件の種類、権限の範囲、遅れたときの決め方（誰に上げ、誰が決め、顧客に誰が行くか）、常駐の有無を決める。遅れている案件があるなら、隠さない
- 「なにを」は最初に持つ案件を一つ、誰と、いまの状態。「どうやって」は進め方と権限と遅れたときの動き方を、流れで。前の案件の例を一つ
- 「こんな人」は経歴ではなく、「悪い知らせを早く伝えた」「遅れた案件を立て直した」の行動で
- 面談には、いま案件を見ている人と、遅れたとき決める人が出て、案件の状態と前に起きたことを隠さず話す

## よくある質問

### 遅れている案件を引き継いでほしいのですが、正直に書くと来ませんか

隠すほうが、入社後に分かって離れます。「〇〇の案件が遅れていて、立て直しから任せたい。遅れの原因は△△で、人を足すか期限を交渉するかは□□が決める。顧客には一緒に行く」のように、状態と、会社で受け止める形を一緒に書きます。立て直しの経験を自分の強みと思っている人には、「自分の経験が活きる」として読まれます。

### 何本並行で持つか、案件によって変わります

目安で構いません。「〇本前後を並行。時期によって増減する。増えるときは△△と相談して決める」のように、目安と、増えるときの決め方を書きます。書かないと「際限なく持たされる」を想像されます。数字を書けないなら、「最初は一本から。慣れたら増やす」でも構いません。

### プロジェクトマネージャーの募集記事は、御社に相談できますか

できます。当社は、募集記事の型、権限と遅れたときの動き方を文で書く直し方、「こんな人」を行動に直す作業、スカウト文面との整合の確認を支えられます。権限の決定、案件の実態、面談は、社内で担ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、Wantedlyの募集記事とスカウトの運用を支えています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
