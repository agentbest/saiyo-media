Wantedlyの記事が止まる場所で最も多いのは、書く段階ではなく、確認の段階です。上司や代表に見てもらうと、返ってこない、本音が削られる、全文を直される。**結論から言うと、上司の確認は「観点を絞り、確認者を記事の種類ごとに決め、期限を決め、返らなければ人事判断で出す」と先に合意しておくことで、止まらずに通ります。確認の観点は「出してはいけない情報が無いか」と「事実に誤りが無いか」の2つで、文章の好みや本音の濃さは観点に入れません。** この記事では、確認で起きる失敗、観点を絞る理由、確認者の決め方、期限の合意、頼む文面、直しの受け方、確認者が記事を読んでおく意味、分担を整理します。出してよい範囲の考え方は[会社の素顔を出す範囲](/media/wt-kaisha-no-sugao/)で書きました。この記事は、その範囲を確認の流れにどう組み込むかの話です。

## この作業の目的｜確認で止まらず、本音を薄めずに出す

確認の目的は、「出してはいけない情報が無いことを、責任のある人が見る」ことです。記事を良くすることでも、会社の見え方を整えることでもありません。

この目的を共有していないと、確認する人は「自分が見た以上、良い記事にしなければ」と考え、文章を直し、本音を削り、時間をかけます。結果、記事は止まり、出ても建前になります。

確認の流れを作るとは、「確認する人が、何を見て、何を見ないか」を先に決めることです。

## やりがちな失敗

| 失敗 | 何が起きるか |
|---|---|
| 確認の依頼が返ってこない | 記事が出ない。ストーリーが途切れる |
| 「念のため」で本音が削られる | 良いことだけの記事になる。書いた人が次から書かない |
| 文章の好みで全文が直される | 本人の言葉が消える。書き手が減る |
| 確認者が毎回違う | 基準が揃わず、通ったり通らなかったりする |
| 全記事を代表が見る | 代表がボトルネックになる |
| 確認の観点が無い | 確認者が「何を見ればいいか分からず」時間をかける |
| 確認者が会社ページや他の記事を読んでいない | 記事単体で判断され、全体とずれる |

最も多いのは、最初の「返ってこない」です。確認を頼む側も、期限と「返らなければどうするか」を決めていないので、待つしかなくなります。

## 手順1｜確認の観点を2つに絞る

確認者に見てもらうのは、次の2つだけです。

| 観点 | 見ること |
|---|---|
| 出してはいけない情報が無いか | 顧客名、機密、個人の情報、未公表の数字、他社への言及、私生活 |
| 事実に誤りが無いか | 事業の内容、時期、役職、出来事の順序 |

観点に入れないものを、先に合意しておきます。

- **文章の好み**：言い回し、語尾、構成。トーンは人事が見本で揃える。考え方は[文章のトーンの決め方](/media/wt-bunsho-tone/)
- **本音の濃さ**：失敗、迷い、まだ無いものは、出す方針。「会社の見え方が心配」は観点に入れない
- **本人の言葉**：インタビューや入社エントリーの本人の発言は、直さない。直すのは抽象語・事実・特定の3つだけ

「観点に入れないもの」を合意しておくことが、確認で本音が薄まらないための条件です。確認者に「見なくていいこと」を伝えるのは失礼ではなく、確認者の時間を減らすことでもあります。

### エージェントベストの見解

申し込んだあと、確認の流れで半年後に起きやすいのは、「代表の確認待ちで、ストーリーが月に1本も出ない」ことです。契約直後は代表も見る余裕があり、記事は出ます。ところが数か月で代表の手が回らなくなり、確認待ちの記事が溜まり、書いた人は「出ないなら書かない」と止まります。当社は3媒体すべての販売パートナーとしてWantedlyの契約後の運用を見ていますが、記事が出続けている会社は、代表が見る記事を「代表の考え」と「会社ページのミッション」に限り、他は責任者と人事で出しています。代表が全記事を見る会社は、代表の忙しさがそのまま記事の頻度になります。当社が確認の流れを設計するとき、最初に決めるのは「代表が見る記事はどれか」で、答えは「代表が出る記事だけ」です。

## 手順2｜記事の種類ごとに、確認者を決める

全記事を同じ人が見るのではなく、記事の種類で分けます。

| 記事 | 確認者 | 見ること |
|---|---|---|
| 会社ページ（ミッション、なにを・なぜ） | 代表 | 事実と、会社の「なぜ」の言葉が揃っているか |
| 会社ページ（メンバー、写真、価値観の場面） | 人事と、写っている本人 | 本人の同意、特定できる情報 |
| 募集記事 | その職種の責任者 | 仕事内容の事実、条件の事実 |
| ストーリー（社員の話、入社の話） | 本人と、人事 | 本人の同意、特定できる情報 |
| ストーリー（事業の裏側） | その事業の責任者 | 顧客・機密の有無、事実 |
| ストーリー（代表の考え） | 代表本人 | 本人の発言として正しいか |
| 顧客名・契約・数字に触れる記事 | 上記に加えて管理部門 | 契約と公表の判断 |

代表が見るのは、代表が出る記事と会社ページの中心部分だけです。それ以外は、責任者と本人と人事で出します。

## 手順3｜期限と、「返らなければ人事判断で出す」の合意

確認を頼むときに、期限を付けます。期限を過ぎたときの扱いも、先に合意しておきます。

1. **期限は短く**：数日。長いと、後回しにされる
2. **期限を過ぎたら、人事の判断で出す**：これを、確認者全員と先に合意する。「見なかったら出る」が分かっていれば、確認者は見る
3. **出したあとに問題が見つかれば、直す**：Wantedlyの記事は公開後に直せる。「出す前に完璧」を求めない
4. **本人の同意だけは、期限で省略しない**：本人が出ている記事は、本人の同意が無ければ出さない。ただし、本人にも期限を伝える

「返らなければ出す」は、確認者に対する圧力ではなく、「確認者の忙しさで記事が止まらない」ための仕組みです。合意を取るときは、この目的を伝えます。

## 手順4｜確認を頼む文面の型

頼み方で、返る速さと直しの量が変わります。

- **何を見てほしいかを、最初に書く**：「顧客名と機密が無いか、事実に誤りが無いかだけ見てください。文章と構成は人事で整えています」
- **期限を書く**：「〇日までに返らなければ、公開します」
- **直す場合の頼み方を書く**：「直す箇所と理由を教えてください。人事で反映します」。確認者が直接書き換えないように
- **短く**：長い依頼文は読まれない

確認者が直接書き換えると、本人の言葉やトーンが変わります。「直す箇所と理由を教えてもらい、人事が反映する」形にすると、直しが観点の中に収まります。

## 手順5｜直しの受け方

確認者から直しが返ってきたときの扱いを決めておきます。

| 直しの種類 | 扱い |
|---|---|
| 出してはいけない情報の指摘 | そのまま反映する |
| 事実の誤り | そのまま反映する |
| 文章の好み | 人事の判断。トーンの見本に沿っていれば反映しない |
| 本音を薄める方向 | 反映しない。「出す方針」を伝えて相談する |
| 本人の言葉の書き換え | 反映しない。本人に確認する |

「反映しない」直しがあることを、確認者と先に合意しておきます。合意が無いと、人事が確認者の直しを断れず、本音が薄まります。断るときは、「観点の外なので、人事で判断します」と伝えます。

## 確認者が、会社ページと他の記事を読んでおく

確認者が記事単体を見ると、「この記事だけ本音が強い」と感じて削りたくなります。会社ページと他のストーリーを読んでいれば、「会社全体でこの本音の濃さで書いている」と分かり、削りません。

- **確認者に、会社ページと最近のストーリーを一度読んでもらう**：確認の流れを作るときに
- **記事が増えたら、月に一度、出た記事の一覧を確認者に送る**：読まなくても、流れは分かる
- **面談に出る人は、記事を読んでおく**：書いたことと話すことを揃えるため

確認者が全体を知っていることは、確認の質を上げるだけでなく、確認者自身が面談で話す言葉と記事を揃えることにもつながります。

## 社内の分担

| 作業 | 誰が |
|---|---|
| 確認の観点と、観点に入れないものを決める | 人事（代表と責任者に合意を取る） |
| 記事の種類ごとの確認者を決める | 人事 |
| 期限と「返らなければ出す」の合意 | 人事が確認者全員と |
| 確認を頼む | 人事（文面の型で） |
| 直しを反映する・反映しないを判断する | 人事 |
| 本人の同意 | 人事が本人に |
| 出してはいけない情報と事実の確認 | 責任者、代表、管理部門（それぞれの記事だけ） |

運用代行や代理店が支えられるのは、観点の整理、確認者の割り当ての設計、期限の型、頼む文面の型、直しの扱いの整理までで、確認そのものと、社内の合意は企業が行います。代理店の代行の範囲は[代理店に運用まで頼めるか](/media/kh-dairiten-unyou/)で書きました。

### エージェントベストの見解

自社で持つべきなのは、どこまでか。当社がWantedlyの記事の確認の流れを設計するとき、観点の整理、確認者の割り当て、期限の型、頼む文面、直しの扱いの整理は当社が出せます。ただし、「返らなければ人事判断で出す」の合意だけは、社内でしか取れません。当社が「そうしましょう」と言っても、確認者が合意していなければ、人事は出せません。当社が最初にお願いするのは、人事が代表と責任者に「確認の観点は2つ、期限は数日、過ぎたら人事判断で出す」を口頭で合意してもらうことです。この合意があれば、当社が設計した流れは動きます。無ければ、流れは紙の上だけで、記事は確認待ちで止まります。確認の流れは、仕組みより先に、合意が要ります。

## まとめ

- 確認の目的は「出してはいけない情報が無いことを責任のある人が見る」こと。記事を良くすることではない
- 観点は「出してはいけない情報」と「事実の誤り」の2つ。文章の好み、本音の濃さ、本人の言葉は観点に入れない
- 記事の種類ごとに確認者を分け、代表が見るのは代表が出る記事と会社ページの中心だけ
- 期限を短く付け、「返らなければ人事判断で出す」を先に合意する。本人の同意だけは省略しない
- 頼む文面は観点と期限と「直す箇所と理由を教えてください」の3つ。直しは観点の中だけ反映する

## よくある質問

### 代表が全部の記事を見たいと言っています

代表が見る記事を「代表が出る記事」と「会社ページのミッション」に限ることを、頻度の話として相談します。全記事を代表が見ると、代表の忙しさが記事の頻度になり、ストーリーが途切れます。「見たい記事は、出た記事の一覧を月に一度送るので、そこから読んでください」という形にすると、代表も全体を把握できます。

### 確認者が文章を直してしまい、本人の言葉が消えます

確認を頼む文面に「直す箇所と理由を教えてください。人事で反映します」と書き、確認者が直接書き換えない形にします。返ってきた直しは、観点の中のものだけ反映し、本人の言葉の書き換えは本人に確認します。この扱いを、先に合意しておきます。

### 確認の流れの設計は、御社に相談できますか

できます。当社は、観点の整理、確認者の割り当て、期限の型、頼む文面の型、直しの扱いの整理を支えられます。確認そのものと社内の合意は、企業が行ってください。当社はOfferBox・Wantedly・ワンキャリアの販売パートナーとして、Wantedlyの記事の整備を支えています。3媒体の全体像は[3媒体の違いと選び方](/media/hikaku-3baitai/)にまとめています。
