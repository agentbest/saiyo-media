OfferBoxの企業ページは、契約したときに一度整えて、そのまま開かなくなりがちです。オファーの文面は毎週直しているのに、学生が見に来る先は数か月前のまま、という状態は珍しくありません。**結論から言うと、企業ページの更新は「時期で決める定期の見直し」と「出来事を起点にした見直し」の二本立てにすると止まりません。** 定期だけだと異動や仕事の変化に追いつかず、出来事だけだと誰も気づかないまま古くなるからです。この記事では、更新のきっかけの一覧、見る項目の順番、やりがちな失敗と社内の分担を整理します。企業ページに何を書くかは[OfferBoxの企業ページで伝えること・伝えないこと](/media/ob-kigyo-page/)で書きました。

## この作業の目的｜文面と企業ページのずれを、ためない

学生は、オファーの文面を読んで興味を持ったあと、承認するかどうかを決める前に企業ページを見に来ます。ここで文面と企業ページの中身がずれていると、学生は「どちらが本当か」と迷い、承認を見送ります。

ずれは、一度に大きく生まれるわけではありません。紹介していた若手の異動、配属先の仕事の変化、文面のテンプレートの書き直し、選考の段階の変更。小さな変化が少しずつたまり、気づいたときには企業ページが別の会社の説明のようになっています。

更新のタイミングを決める目的は、このずれを小さいうちに直すことです。きれいに作り直すことではありません。古くなった部分を、その都度、文面と同じ中身に戻す。これが企業ページの更新です。

## 手順1｜時期で決める定期の見直し

まず、カレンダーに入れておく定期の見直しを決めます。

1. **契約時・運用の立ち上げ時**：文面のテンプレートと同じ打ち合わせで、企業ページも整える
2. **卒年の切り替わり**：対象の学年が変わると、選考の時期や流れ、学生に伝える会社の一言が変わることがある
3. **送る山の前**：送信を増やす時期の前に、見に来る学生が増える前提で開いてみる
4. **月次の振り返りのついで**：振り返りの議題の最後に「企業ページを開いたか」を一行入れておく

月次の振り返りの進め方は[OfferBox運用の月次の振り返り](/media/ob-sd-tsukiji-review/)で書きました。毎月すべてを直す必要はありません。開いて、古い部分がないかを見るだけで十分です。

定期の見直しを年間の予定に組み込む考え方は[OfferBoxの年間スケジュール](/media/ob-nenkan-schedule/)とあわせて見ると、送る山との前後関係が整理しやすくなります。

## 手順2｜出来事を起点にした見直し

定期の見直しの間に起きる変化は、出来事を起点に拾います。次のことが起きたら、その週のうちに企業ページを開きます。

| 出来事 | 企業ページで見る場所 |
|---|---|
| 紹介している社員の異動・退職 | 人の紹介、写真 |
| オファーの名義の人が変わる | 名義の人の紹介、文面との対応 |
| 配属先や仕事の中身が変わる | 職種ごとの仕事の説明、一日の流れ |
| 文面のテンプレートを書き直した | 文面で触れた仕事の説明と、企業ページの説明が同じか |
| 選考の段階や時期が変わる | 選考の流れ、承認したあとに何が起きるか |
| 面談で「ページと違う」と言われた | 学生が違うと感じた箇所 |
| 承認が落ちてきた | 文面より先に、見に来た先が古くないか |

いちばん見落とされやすいのは、文面のテンプレートを書き直したときです。文面を直した人は文面のことだけを考えていて、企業ページとの対応まで目が届きません。テンプレートを直すときの手順に「企業ページの対応する箇所を確かめる」を一行足しておくと、ずれが生まれにくくなります。テンプレートの作り方は[OfferBoxのオファーテンプレート](/media/ob-offer-template/)で書きました。

### エージェントベストの見解

申し込んだあとの運用で、承認が落ちてきた会社から相談を受けたとき、先に確かめるのは文面ではなく企業ページの「最後にいつ開いたか」です。文面は毎週誰かが見ているので、古くなりにくい。企業ページは、誰の担当にもなっていないことが多く、半年ほど誰も開いていないこともあります。承認が落ちたら文面を直したくなりますが、文面を直しても見に来た先が古ければ、承認は戻りません。順番は、企業ページを学生の目線で開く、古い部分を直す、それでも戻らなければ文面を見直す、です。この順番で進めると、直す場所を取り違えずに済みます。企業ページの更新は手間が小さいわりに、文面の書き直しより先に効くことがある作業です。

## 手順3｜開いたときに見る順番

更新のために企業ページを開いたら、次の順で見ます。上から順に、学生の判断に響きやすいものです。

1. **人**：紹介している人がいまも在籍し、同じ仕事をしているか。写真の人が変わっていないか
2. **仕事の中身**：文面で触れている仕事と、企業ページの説明が一致しているか
3. **選考の流れ**：承認したあとに何が起きるか、段階と時期が今の運用と同じか
4. **会社の一言**：事業の説明が今の会社を表しているか
5. **言葉**：抽象語が増えていないか。前回の更新で足した文が浮いていないか

人と仕事の中身を先に見るのは、ここが古いと面談で「ページと違う」と言われるからです。会社の一言や言葉の古さは、学生の判断に響くまでに時間がかかります。時間が取れない週は、上の二つだけでも見ます。

## やりがちな失敗

| 失敗 | 何が起きるか | 直し方 |
|---|---|---|
| 更新の担当を決めていない | 誰も開かず、気づいたら古い | 主担当を一人決め、月次の議題に入れる |
| 定期の見直しだけ | 異動や仕事の変化に追いつかない | 出来事の一覧を手元に置く |
| 更新のたびに全面的に作り直す | 時間がかかり、次の更新が遠のく | 古い部分だけを直す |
| 文面を直しても企業ページを見ない | 文面と企業ページがずれる | テンプレートの修正手順に一行足す |
| 書いた本人だけが確認する | 見慣れていて古さに気づかない | 入社して間もない社員にも見てもらう |
| 承認が落ちると文面から直す | 見に来た先の古さが残る | 先に企業ページを開く |

最も多いのは、最初の「担当を決めていない」です。企業ページは送信の作業のように毎日触るものではないので、担当が決まっていないと、誰の仕事でもなくなります。

## 社内の分担

| 作業 | 誰が |
|---|---|
| 定期の見直しを予定に入れる | 人事（主担当） |
| 異動・退職・仕事の変化を伝える | 現場の責任者 |
| 古い部分を直す | 人事が下書き、現場が中身を確かめる |
| 学生の目線で開く | 入社して間もない社員 |
| 文面との対応を確かめる | 文面を書く人 |

現場の負担は「変化を伝える」と「中身を確かめる」の二つに絞ります。異動の情報は人事に届くことが多いので、異動の連絡を受けたら企業ページを開く、と決めておくだけでも漏れが減ります。運用代行に出している場合は、代行に下書きの更新を頼めますが、変化を伝えるのは企業の側です。

### エージェントベストの見解

自社で持つべきなのは、企業ページの「変化に気づくこと」です。直す作業は、人事でも運用代行でもできます。しかし、紹介していた若手が異動した、配属先の仕事が変わった、といった変化は、社内にいる人にしか分かりません。運用代行に出している会社で企業ページが古くなるのは、代行が直さないからではなく、変化が代行に届いていないからであることが多いです。代行に出すかどうかにかかわらず、「異動・退職・配属の変化があったら、企業ページの担当に一言伝える」を社内の決まりにしておくことを勧めます。気づく仕組みが社内にあれば、直す手は外にあっても企業ページは古くなりません。

## まとめ

- 企業ページの更新は、時期で決める定期の見直しと、出来事を起点にした見直しの二本立てにする
- 定期は、契約時、卒年の切り替わり、送る山の前、月次の振り返りのついで
- 出来事は、人の異動、名義の変更、仕事の変化、テンプレートの書き直し、選考の変更、面談での指摘、承認の低下
- 開いたら、人、仕事の中身、選考の流れ、会社の一言、言葉の順に見る
- 直す手は外に出せても、変化に気づく仕組みは社内に持つ

## よくある質問

### 企業ページは、どのくらいの頻度で開けばよいですか

決まった頻度はありません。月次の振り返りのついでに開き、出来事があればその週に開く形を勧めます。毎回すべてを直す必要はなく、古い部分がないかを確かめるだけで構いません。

### 更新するたびに、写真も撮り直すべきですか

写っている人が在籍していて、仕事の場面がいまと変わらないなら、撮り直す必要はありません。写っている人が異動・退職したとき、仕事の中身が変わったときに差し替えます。写真の選び方は[OfferBoxの企業ページの写真の選び方](/media/ob-sd-shashin-sentei/)で書きました。

### 企業ページの更新を、運用代行に任せられますか

下書きの更新は任せられることが多いです。ただし、仕事の中身や人の変化は企業の側から伝える必要があります。代行に任せる範囲の考え方は[OfferBoxの運用代行に任せられる範囲](/media/ob-unyou-daikou-hanni/)で整理しています。
