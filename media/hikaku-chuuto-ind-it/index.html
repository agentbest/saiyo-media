IT・Web業界の中途採用で媒体をどう選ぶか

自社のWebサービスを運営する会社、受託で開発を担う会社、Web制作の会社、SaaSを提供する会社、システムの開発や運用を請け負う会社。IT・Web業界とひとことで言っても、事業の形はさまざまです。中途採用の相談では「IT業界に強い媒体はどれか」と聞かれますが、同じ業界の中でも、事業の形と職種によって候補者のいる場所が変わります。結論から言うと、IT・Web業界の中途採用では、業界でまとめて媒体を選ぶのではなく、「自社サービスか受託か」と「どの職種か」の二つで募集を分け、募集ごとに媒体の役割を決めるのが基本です。 この記事では、媒体の料金や数値には触れず、判断の順番を整理します。

IT・Web業界の採用構造と、媒体との相性

IT・Web業界の中途採用には、ほかの業界と違う特徴がいくつかあります。

  • 業界の中での移動が多い：候補者の多くが、同じ業界の別の会社から移ってきます。比べられる相手は同業です
  • 職種が細かい：エンジニアだけでも、開発の領域や工程で分かれます。ビジネス職も、営業、マーケティング、カスタマーサクセス、企画と分かれます
  • 候補者が技術や事業の中身を見る：使っている技術、開発の進め方、事業の段階を、求人から読み取ろうとします
  • 働き方への関心が高い：在宅の可否、働く時間の柔軟さが、会社選びの条件になりやすい

媒体の型との相性は、次のように整理できます。

型IT・Web業界での使いどころ
業界に強い求人型（Greenなど）IT・Web業界の求人を中心に扱う。事業と職種をあわせて見せたいとき
共感型（Wantedlyなど）会社の考え方や事業の想いで集めたいとき。会社ページで日常を見せられる
総合型（doda、typeなど）業界の外も含めて幅広く集めたいとき。掲載・スカウト・紹介の窓口を持つ
スカウト型の中途向け媒体会社から候補者に声をかけたいとき
紹介責任者や、市場に少ない経験を持つ人を採りたいとき

判断軸｜対象・型・課金・運用工数

IT・Web業界で媒体を比べるときも、四つの軸で見ます。

  • 対象：同業の経験者か、他業界から移る人か。エンジニアかビジネス職か
  • 型：待つか、声をかけるか、共感で集めるか、紹介を使うか
  • 課金：掲載の期間で払うか、採用が決まったときに払うか。募集の数と期間で向き不向きが変わる
  • 運用工数：スカウトを書く人、技術の面談に出る人の時間があるか

この業界でとくに効くのは、運用工数のうち「技術の話ができる人の時間」です。エンジニアの候補者は、最初の面談から技術の話をしたがります。人事だけで面談すると、そこで関心が離れることがあります。

自社サービスか受託か、どの職種を採るか。募集の分け方から媒体の組み方まで一緒に整理します。

媒体選びを相談する

エージェントベストの見解

同じIT・Web業界でも、自社サービスの会社と受託の会社では、当社が先に勧める媒体の型が変わることが多いです。自社サービスの会社は、事業の想いやプロダクトの話で候補者を動かせるので、会社ページで日常と考え方を見せる共感型や、事業と職種をあわせて見せられる業界に強い求人型を先に検討します。受託の会社は、事業の想いより「どんな顧客の、どんな案件を、どの工程から担うか」が判断材料になるので、案件の具体を求人票に書き込める求人型や、職務経歴を見て声をかけられるスカウト型を先に検討します。媒体の性能ではなく、自社が候補者に何で選ばれるかで選ぶと、運用が始まってから文面に迷いません。

候補者に見せること｜業界イメージの扱い

IT・Web業界の候補者は、業界のことをよく知っています。だからこそ、業界の一般的なイメージで語る求人は、読み飛ばされやすくなります。

見せるときに意識したいことを挙げます。

  1. 技術と開発の進め方：使っている言語や基盤、開発の進め方、コードを見る仕組み。エンジニア向けには欠かせない
  2. 事業の段階：立ち上げ期か、伸ばす時期か、安定して改善する時期か。段階によって求める人が変わる
  3. 職種の分担：エンジニアとビジネス職がどう関わるか。企画を誰が決めるか
  4. 働き方の実際：在宅の可否を書くなら、実際にどう運用しているかまで
  5. 評価の仕組み：技術の力と事業への貢献をどう評価するか

「最新の技術」「成長できる環境」といった言葉は、具体が伴わないと、同業の求人と見分けがつきません。実際に使っている技術の名前や、最近取り組んだ改善の例を書くほうが伝わります。

この条件なら、どの型を先に検討するか

優劣ではなく、条件ごとに先に検討する形として置きます。

  • 自社サービスの会社で、エンジニアを採る → 業界に強い求人型（Greenなど）や共感型を先に。技術と事業をあわせて見せる
  • 受託の会社で、エンジニアを採る → 案件の具体を書ける求人型やスカウト型を先に。工程と顧客の業界を書く
  • ビジネス職を、業界の外からも採る → 総合型（doda、typeなど）を先に。業界の外の経験がどう活きるかを書く
  • 責任者や、経験の少ない領域の人を採る → 紹介を先に。並行してスカウトで声をかける

業界の中でも事業の形ごとに考え方は変わります。SaaS業界の中途採用で媒体をどう選ぶか、SIer業界の中途採用で媒体をどう選ぶか、SES業界の中途採用で媒体をどう選ぶか、ゲーム業界の中途採用で媒体をどう選ぶかに分けて書いています。

運用の組み方

IT・Web業界では、募集が複数同時に走ることがよくあります。エンジニアとビジネス職、経験者と若手。募集ごとに媒体を分けるなら、誰がどの媒体の運用を持つかを先に決めます。

  • 募集ごとの担当：媒体ごとに担当を分けるより、募集ごとに担当を決めるほうが、候補者への説明がそろう
  • 技術の面談の枠：エンジニアの面談に出る人の時間を、週の予定に先に入れておく
  • スカウトの材料：職種ごとに、仕事の具体を書いた短い説明を現場に一度書いてもらい、文面に使い回す
  • 応募への返信：同業の候補者は複数の会社を並行して見ている。返信の速さは会社の印象に直結する

募集が重なる時期のスカウトや返信を、外に出す形もあります。いま使っている媒体の運用の相談だけでも構いません。

運用の相談をする

エージェントベストの見解

IT・Web業界の会社から多い相談に、「エンジニアの取り合いなので、媒体を増やして露出を増やしたい」というものがあります。実際に申し込んだあとを見ていると、媒体を増やした会社ほど、スカウトの送信と返信の対応が回らなくなり、どの媒体でも中途半端な運用になることが少なくありません。媒体を増やす前に確かめたいのは、いまの媒体で、狙った候補者に文面が届き、返信が来て、面談まで進んでいるかです。届いていないなら文面か対象の問題で、媒体を増やしても同じことが起きます。返信が来ているのに面談に進まないなら、日程の調整か面談の中身の問題です。一つの媒体を回し切って、どこで止まるかが見えてから、次の媒体を足すかを決める順番を勧めています。

まとめ

  • IT・Web業界は業界の中での移動が多く、職種が細かく、候補者が技術と事業の中身を見る
  • 業界でまとめず、「自社サービスか受託か」と「職種」で募集を分けて媒体の役割を決める
  • 自社サービスは共感型や業界に強い求人型、受託は案件の具体を書ける求人型やスカウト型を先に検討する
  • 業界の一般的なイメージではなく、使っている技術や事業の段階を具体的に見せる
  • 媒体を増やす前に、いまの媒体でどこで止まっているかを確かめる

よくある質問

エンジニアとビジネス職は同じ媒体で採れますか

採れることもありますが、候補者が見ているものが違うので、文面と選考は分けます。エンジニアには技術と開発の進め方を、ビジネス職には事業と役割を中心に書きます。媒体を分けるかどうかは、それぞれの候補者がどの型の媒体にいるかで決めます。

業界の外から採ることはできますか

ビジネス職では、業界の外の経験が活きる場面が多くあります。その場合は、前職のどんな経験が、入社後のどの仕事に活きるかを求人に書きます。エンジニアでも、ほかの業界のシステムに関わってきた人を対象にできることがあります。

新卒の採用でも同じ考え方ですか

新卒は業界の中での移動がないので、業界のイメージをどう扱うかの比重が上がります。新卒向けの考え方はIT業界の採用媒体の選び方にまとめています。
