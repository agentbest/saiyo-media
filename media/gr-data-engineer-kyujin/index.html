Greenでデータエンジニアを採る求人票｜仕事内容と条件の書き方

データエンジニアの求人票では、「データ基盤の構築・運用」と書いて、使っている道具の名前を並べる形がよく見られます。けれど候補者にとっては、その基盤がこれから作る段階なのか、すでにあって広げる段階なのか、作り直す段階なのかで、仕事の中身がまったく違います。誰がそのデータを使うのかによっても、求められる動き方が変わります。結論から言うと、Greenでデータエンジニアを採る求人票は、「基盤の段階」「使う人」「入社した人に任せること」の三つを先に書くと、自社の段階に合う経験を持つ人が応募しやすくなります。 Greenは株式会社アトラエが運営する、IT・Web業界を中心とした中途採用の求人サイトです。この記事では、データエンジニアの求人票を項目ごとに型と例文で整理します。入力欄の名前や表示のされ方は、管理画面と媒体の案内で確認してください。

データエンジニアの候補者が求人票で確かめること

データエンジニアの候補者は、求人票を読みながら、次の点を確かめています。

  • 基盤の段階：これから作るのか、作り始めたところか、広げるのか、作り直すのか
  • 扱うデータの性質：サービスの利用の記録、業務のシステム、外部から受け取るデータなど、どこから来るデータか
  • 使う人：分析の担当者、事業部、経営、機械学習のエンジニアなど、誰のための基盤か
  • チームの構成：データエンジニアは何人か、分析の担当者と同じチームか
  • 判断の権限：基盤の構成や道具の選定を、チームで決められるか
  • データの品質と管理：データの定義がそろっているか、品質に誰が責任を持つか

基盤の段階の伝え方はGreenでデータエンジニアを採るときの要点で詳しく整理しています。この記事では、求人票の各欄に何をどう書くかに絞ります。

求人タイトルと冒頭の一文

タイトルには、基盤の段階と、入社した人が最初に取り組むことを入れます。

  • 弱い例：「データエンジニア／データ基盤／リモート可」
  • 直した例：「散らばった予約と売上のデータを一つにまとめるデータエンジニア／基盤の設計から担当」

直した例は、どんなデータを、どの段階から、どこまで任せるかが一行で伝わります。

冒頭の一文には、データを使う人が困っていることを書きます。「事業部が売上の分析をするたびに、複数のシステムから手作業でデータを集めていて、数字が出るまでに時間がかかっています」のように、使う人の困りごとから入ると、使われる基盤を作ることに関心のある人が読み進めます。

データエンジニアの求人票で、基盤の段階や使う人をどう書くか。現場の話を聞くところから一緒に整理します。

運用の相談をする

仕事内容の書き方｜型と例文

仕事内容の欄は、次の順で書きます。

  1. 基盤の段階と、いま困っていること：どの段階にあり、使う人が何に困っているか
  2. 扱うデータ：どこから来るデータか、更新の頻度の感覚（数値を出せなくても「毎日まとめて」「随時」のように言葉で）
  3. 使う人と、要望の受け方：誰から、どんな形で要望が来て、優先順位をどう決めているか
  4. 入社後の最初の仕事：最初の数か月で取り組む範囲
  5. 半年後に任せたいこと：基盤の構成の方針づくり、データの定義の整理、品質の仕組みづくりなど

例文にすると、次のような形になります。

飲食店向けの予約サービスの、予約と売上のデータを扱う基盤を担当します。いまはデータが予約のシステムと会計のシステムに分かれていて、事業部が分析をするたびに手作業で集めている状態です。データを一か所にまとめる基盤を作り始めたところで、取り込みの仕組みはまだ個別に作ったものに頼っています。入社後は、取り込みの仕組みを整えるところから始めていただきます。慣れてきたら、事業部と一緒にデータの定義をそろえ、品質を保つ仕組みづくりを進めていただきたいと考えています。

この型で書くと、「何ができていて、何ができていないか」が伝わります。できていないことを書くのは気が引けるかもしれませんが、データエンジニアの候補者は、そこにこそ自分の仕事を見つけます。

エージェントベストの見解

データエンジニアの求人票の相談で多い思い込みは、「基盤がほとんどない状態では、データエンジニアは来てくれない」というものです。実際には、ゼロから設計したい人にとって、基盤がまだないことは応募する理由になります。来てもらいにくいのは、基盤がないことそのものより、「なぜ作るのか」と「誰が使うのか」が書かれていない求人です。使う人が決まっていない基盤づくりは、作っても使われないおそれがあるので、経験のある人ほど慎重になります。勧めているのは、使う人を一人か一つの部署に絞って、その人の困りごとを冒頭に書くことです。「事業部の売上の分析を、手作業から解放したい」のように、最初に届けたい相手がはっきりしていれば、基盤がない段階でも、関心を持つ人に読んでもらえます。

必須と歓迎、技術と管理の書き方

求める経験は、必須を二つか三つに絞り、自社の基盤の段階に合わせて選びます。

  • これから作る段階の必須の例：「データの取り込みと加工の仕組みを設計した経験」「データベースを使った開発の実務経験」
  • 広げる段階の必須の例：「運用中のデータ基盤の改善の経験」「データの品質の問題に対処した経験」
  • 歓迎の例：「分析の担当者や事業部と要望を整理した経験」「データの定義をそろえた経験」「バックエンドやインフラの開発の経験」

データエンジニアの仕事は、バックエンドやインフラの経験と重なる部分が多くあります。歓迎にそれらの経験を置くと、応募の幅が広がります。分析の担当者からデータエンジニアに移ってきた人も、使う人の目線を持っている点で向いていることがあります。

技術欄は、道具の名前だけでなく、次の点を添えます。

  • 選定の進め方：道具を誰が、どう選んでいるか。変える余地はあるか
  • データの管理：データの定義や権限を誰が決めているか。個人に関わるデータを扱うなら、その扱いの方針があるか
  • 運用の体制：取り込みが止まったときに誰が対応するか

個人に関わるデータの扱いは、法令で定められた事項や社内の決まりがあります。求人票には細かな決まりを書く必要はなく、「扱いの方針があり、入社後に説明します」程度で構いません。詳細は社内の担当者や公式の案内で確認してください。

条件・働き方・選考の流れの書き方

条件の欄には、給与の幅と決め方、リモートの可否と出社の考え方を書きます。扱うデータの性質によって、社外から触れられる範囲に決まりがある場合は、それも書いておくと、リモートで働きたい人とのずれを防げます。給与の書き方はGreenの求人票の年収の書き方で整理しています。

選考の流れには、各回で誰と何を話すかを書きます。

  • 一次：データエンジニアまたはリーダーと、過去に作った基盤での判断を話す
  • 使う人との面談：分析の担当者や事業部の人と話す場を置くと、候補者は誰のために作るのかを実感できる
  • 最終：データを事業にどう生かしたいかという会社の考えを、責任者と話す

求人票の作成から応募への返信、日程調整まで、作業の部分を外に出す形もあります。相談だけでも構いません。

無料で相談する

エージェントベストの見解

データエンジニアの求人を出したあとによく起きるのは、面接の段階で「分析もしてほしい」「機械学習の仕組みも作ってほしい」と、求人票にない期待が面接官から出てくることです。データに関わる仕事は社内で境目が曖昧になりやすく、面接官ごとに思い描くデータエンジニア像が違うためです。候補者から見ると、面接のたびに求められる役割が変わり、入社後の仕事が見えなくなります。勧めているのは、求人票を出す前に、面接に出る人全員で「データエンジニアがやること」と「やらないこと」を一枚にそろえることです。やらないことには、「分析そのものは分析の担当者が持つ」のように、誰が持つかまで書きます。この一枚はスカウトを送る相手を選ぶときにも使えます。スカウトの書き方はデータエンジニアへ送るスカウト文面にまとめています。

まとめ

  • データエンジニアの求人票は、基盤の段階、使う人、入社した人に任せることを先に書く
  • タイトルと冒頭で、どんなデータを、どの段階から任せるか、使う人の困りごとを伝える
  • できていないことを正直に書くと、そこに自分の仕事を見つける人が応募してくる
  • 必須は基盤の段階に合わせて選び、バックエンドやインフラの経験を歓迎に置く
  • 面接官全員で「やること」と「やらないこと」をそろえてから求人を出す

よくある質問

データ基盤がほとんどない状態でも、求人票は書けますか

書けます。なぜ作るのか、最初に誰に届けたいのかを冒頭に書き、基盤の設計から任せることを明記します。ゼロから設計したい人にとっては、応募する理由になります。

データエンジニアとデータサイエンティストを一つの求人で募集してもよいですか

仕事の中身が違うので、分けるほうが分かりやすくなります。一つにまとめると、どちらの役割を期待されているか候補者が判断しにくくなります。分ける場合は、両者の分担を両方の求人に書いておきます。

使っている道具の名前は詳しく書くべきですか

いま本番で使っているものは書いて構いません。ただ、名前だけでなく、なぜそれを選んだか、変える余地はあるかを添えると、技術への考え方が伝わります。検討中のものは混ぜないようにします。
