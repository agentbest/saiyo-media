Greenで機械学習エンジニアを採る求人票｜仕事内容と条件の書き方

機械学習エンジニアの求人票は、「AI」「深層学習」といった言葉が並ぶほど、候補者には中身が見えにくくなります。経験のある人が知りたいのは、作ったモデルが本番のどこで動き、動いたあと誰が面倒を見るのかです。結論から言うと、Greenで機械学習エンジニアを採る求人票は、仕事内容に「モデルが載る場所」「研究と実装の比重」「運用の持ち主」の三つを書き、条件はその比重に合わせて書くのが基本です。 この記事では、求人票の仕事内容と条件の欄に絞って、書く順番と型を整理します。職種の採り方の全体はGreenで機械学習エンジニアを採るにまとめています。

候補者が仕事内容の欄で確かめること

機械学習エンジニアの候補者は、仕事内容の欄で次の点を探しています。

  • モデルはどこで動くのか：プロダクトの機能として利用者に届くのか、社内の業務で使われるのか、まだ検証の段階なのか
  • 研究と実装のどちらが多いか：新しい手法を試す時間が多いのか、既存の手法を本番で安定して動かす仕事が多いのか
  • 運用は誰が持つか：本番に載せたあとの監視や作り直しを、本人が持つのか、別のチームが持つのか
  • 周りに誰がいるか：データエンジニアやバックエンドのエンジニアと、どう分担しているか

このうち、とくに見られているのが二つ目です。機械学習エンジニアの中でも、研究に近い仕事を求める人と、本番で動かす仕事を求める人では、関心が大きく違います。求人票がどちらとも取れる書き方だと、両方から応募が来て、面接で毎回すれ違いが起きます。

仕事内容の欄に書くこと

仕事内容は、次の順で書くと読み手に伝わりやすくなります。

  1. モデルが解いている課題：「問い合わせの振り分けを自動にしたい」「商品の推薦を個人ごとに変えたい」など、事業の言葉で
  2. モデルが載る場所：プロダクトのどの画面、どの業務の流れで使われるか
  3. 研究と実装の比重：大まかな配分を言葉で。「既存手法の改良と本番化が中心で、新しい手法の検証は四半期に一度程度」のように
  4. 運用の範囲：本番に載せたあと、精度の監視や再学習を誰がどこまで持つか
  5. 入社後の最初の仕事：最初の数か月で任せたいこと

書き方の例です。

問い合わせの内容を読み取り、担当部署に自動で振り分けるモデルの改良と本番運用を担っていただきます。モデルはすでにサポート業務の画面で使われており、振り分けの誤りが業務の負担に直結します。新しい手法を試すより、いまのモデルを安定して動かし、誤りの傾向を見て直す仕事が中心です。

この例のように、研究より実装・運用が中心だと書くと、研究志向の人の応募は減ります。それで構いません。求人票は、応募を増やす道具である前に、合わない人に応募を見送ってもらう道具でもあります。

研究寄りか実装寄りか、機械学習エンジニアの求人票の書き分けから相談を受けています。

無料で相談する

エージェントベストの見解

機械学習エンジニアの募集で、当社が最初に確かめるのは「本番に載せる仕組みが、いま社内にあるか」です。仕組みがない会社が「機械学習エンジニア」で募集すると、入社した人がモデルを作ったあと、本番に載せるための基盤づくりから始めることになります。それを楽しめる人もいますが、モデルの改良がしたくて入った人には想定外の仕事です。仕組みがまだない場合は、求人票の仕事内容に「モデルを本番に載せる仕組みづくりから関わる」とはっきり書くか、先にデータエンジニアやバックエンドの採用を考えるかを選びます。どちらが正しいかは会社の段階によりますが、書かずに募集するのがいちばん入社後のすれ違いを生みます。

条件の欄の書き方

条件の欄は、仕事内容に書いた比重と食い違わないように書きます。

  • 必須の経験：実装と運用が中心なら、本番でモデルを動かした経験を必須に置きます。研究が中心なら、手法の検証や論文の読み込みの経験を必須に置きます。両方を必須にすると、該当する人が限られます
  • 年収の幅：任せる範囲から決めます。運用まで一人で持つのか、チームの一員なのかで、求める経験の水準が変わるためです。幅の書き方はGreenの求人票で年収をどう書くかを参考にしてください
  • 計算の環境：学習に使う環境をどう用意しているかは、候補者がよく見る点です。細かな構成までは要りませんが、「クラウドの環境を使える」「申請の流れがある」程度は書きます
  • 学びの扱い：論文を読む時間や、外部の発表への参加をどう扱うか。研究寄りの募集ではとくに見られます

条件の欄に書く働き方は、運用の範囲とあわせて書きます。本番のモデルを持つなら、障害のときの対応がどうなっているかも候補者の関心事です。

検索で見つけてもらうための書き方

機械学習エンジニアは、データサイエンティストやバックエンドエンジニアと重なって探されることがあります。Greenで求人を探す候補者に、自分が対象だと早く分かってもらうために、次の点を意識します。

  • タイトル：職種名に、何のモデルかを短く添える。「問い合わせの自動振り分けを本番で運用する機械学習エンジニア」のように
  • 冒頭の一文：研究寄りか実装寄りかを先に書く
  • 技術の欄：本番で使っているものと、検証で使っているものを分けて書く

分析の比重が大きく、モデルを本番に載せる仕事が少ない場合は、Greenでデータサイエンティストを採る求人票の書き方のほうが合うことがあります。

選考へのつなぎ方

求人票に書いた比重は、選考でもそのまま確かめます。実装と運用が中心なら、面接では本番で起きた問題とその直し方を聞きます。研究寄りなら、手法を選んだ理由や検証の進め方を聞きます。

技術の面接には、モデルを実際に運用している現場のエンジニアが出るのが理想です。候補者にとっても、入社後に一緒に働く人と話すことで、求人票の内容が本当かを確かめられます。面接の回数や期間の決め方はGreen経由の選考フローもあわせて参考にしてください。

求人票の内容と面接で確かめることをそろえる作業も、運用の相談としてお受けしています。

運用の相談をする

エージェントベストの見解

求人票を書くときに、もう一つ決めておきたいのが「この人がいなくなったら、モデルは誰が見るか」です。機械学習エンジニアを一人だけ採る会社では、入社後にモデルの知識がその人に集まり、休みや異動のときに誰も触れなくなることがあります。候補者の側も、それを気にします。経験のある人ほど、一人で全部を抱える働き方を避けたがるからです。求人票に「モデルの設計と運用の記録を残し、バックエンドのエンジニアと分担する」と書いておくと、属人化を避けたい会社だと伝わります。逆に、一人目として全部を任せたいなら、その覚悟がある人に向けて、そうはっきり書くほうが合う人に届きます。

まとめ

  • 機械学習エンジニアは、モデルが載る場所・研究と実装の比重・運用の持ち主を見ている
  • 仕事内容は解いている課題から書き、研究寄りか実装寄りかを言葉で示す
  • 本番に載せる仕組みがまだないなら、それを仕事内容に書くか、別の職種の採用を先に考える
  • 条件の欄の必須経験と年収の幅は、任せる比重に合わせる
  • 求人票の比重と、面接で聞くことをそろえる

よくある質問

研究も実装も両方できる人を採りたいのですが、どう書けばよいですか

両方できる人は限られ、他社からも声がかかりやすい傾向があります。最初の数か月はどちらを優先してほしいかを決め、その比重で書くことを勧めます。もう一方は歓迎の経験に回し、入社後に広げていく形にすると、応募の幅を保てます。

生成AIを使った開発の募集でも、同じ書き方でよいですか

基本は同じです。既存のモデルを使って機能を作る仕事なのか、モデルそのものを作る仕事なのかで、求める経験が大きく変わります。どちらなのかを冒頭で書いておくと、すれ違いを減らせます。

スカウトはどう書けばよいですか

求人票の「モデルが載る場所」と、相手が本番で動かした経験を重ねて書き出しにします。具体的な書き出しはGreenで機械学習エンジニアへ送るスカウト文面にまとめています。
